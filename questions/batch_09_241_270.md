# C++11 第九批题目（241–270）

## 241【节点：O1.1】【概念】类、对象、类定义和对象定义分别是什么？

```cpp
class Student
{
    int score;
};

Student first;
Student second;
```

**答案：** 类是用户定义类型，对象是该类型的实例。`class Student { ... };` 定义了 `Student` 类型，本身没有定义 `Student` 对象；`Student first;` 和 `Student second;` 分别定义两个独立对象。每个对象各自拥有一份非静态数据成员，修改 `first` 的成员不会自动修改 `second`。

## 242【节点：O1.2】【代码判断】`class` 和 `struct` 能否定义同样完整的类？下面哪些成员访问合法？

```cpp
struct PointA
{
    int x;
};

class PointB
{
    int x;
};

int main()
{
    PointA a;
    a.x = 1;

    PointB b;
    b.x = 2;
}
```

**答案：** 二者都能定义包含数据成员、成员函数和构造函数等内容的完整类。`a.x = 1` 合法，因为 `struct` 的成员默认是 `public`；`b.x = 2` 不合法，因为 `class` 的成员默认是 `private`。二者的默认继承方式也不同：`struct` 默认公有继承，`class` 默认私有继承；除此之外，它们并不是“只能存数据”和“只能写函数”的两种类型。

## 243【节点：O1.3】【代码阅读】数据成员和成员函数分别属于谁？下面程序输出什么？

```cpp
#include <iostream>

class Counter
{
public:
    int value = 0;

    void increment()
    {
        ++value;
    }
};

int main()
{
    Counter first;
    Counter second;

    first.increment();
    std::cout << first.value << ' ' << second.value << '\n';
}
```

**答案：** 输出 `1 0`。非静态数据成员属于每个具体对象，所以 `first.value` 和 `second.value` 是两份独立数据；成员函数描述该类对象支持的操作，`first.increment()` 操作的是 `first`。定义在类体内部的成员函数隐含具有 `inline` 属性，但这允许它出现在多个翻译单元中的相同类定义里，并不保证编译器一定把调用展开成机器码内联。

## 244【节点：O1.4】【最小纠错】对象、对象指针分别应使用哪个成员访问运算符？

```cpp
class Student
{
public:
    int score = 0;
};

int main()
{
    Student student;
    Student* pointer = &student;

    student->score = 80;
    pointer.score = 90;
}
```

**答案：** 对象使用 `.`，指向对象的指针使用 `->`。最小修改为：

```cpp
student.score = 80;
pointer->score = 90;
```

`pointer->score` 等价于 `(*pointer).score`。其中必须先用括号完成解引用，因为成员访问运算符 `.` 的优先级高于一元解引用运算符 `*`。

## 245【节点：O1.5】【概念】`this` 指针表示什么？静态成员函数中是否存在 `this`？

```cpp
class Counter
{
    int value = 0;

public:
    Counter& set(int value)
    {
        this->value = value;
        return *this;
    }
};
```

**答案：** 在非静态成员函数中，`this` 是指向当前调用对象的隐含指针。形参 `value` 隐藏了同名数据成员，所以 `this->value` 明确表示当前对象的数据成员；`*this` 表示当前对象本身，因此函数可以返回 `Counter&`。静态成员函数不依附于某个具体对象，没有 `this`，也不能在没有对象的情况下直接访问非静态成员。

## 246【节点：O1.6】【代码补全】如何在类外定义成员函数？形参与成员同名时如何访问成员？

```cpp
class Meter
{
    int value = 0;

public:
    void set(int value);
};
```

**答案：** 类外定义时使用类作用域限定符 `Meter::`；形参隐藏同名成员时，可以使用 `this->value`：

```cpp
void Meter::set(int value)
{
    this->value = value;
}
```

`Meter::set` 表示类作用域中的成员 `set`。进入这个成员函数定义后，类成员名字也处于可查找范围内，但形参 `value` 更靠近使用位置，因此需要 `this->value` 消除歧义。

## 247【节点：O1.7】【判断】只有下面的前向声明时，哪些使用是合法的？

```cpp
class Node;

Node* pointer = nullptr;
void inspect(const Node& node);

// Node object;
// int bytes = sizeof(Node);
// pointer->next = nullptr;
```

**答案：** `Node* pointer` 和以 `const Node&` 为形参的函数声明合法，因为定义指针、引用以及仅声明相关接口通常不需要知道 `Node` 的大小和成员布局。`Node object`、`sizeof(Node)` 和通过指针访问成员都要求 `Node` 已是完整类型，因此此处不合法。前向声明只让编译器知道这是一个类名，不会提供类的大小或成员信息。

## 248【节点：O1.8】【工程组织】一个有多个成员函数的普通非模板类通常如何安排在头文件和 `.cpp` 文件中？

**答案：** 类定义和需要共享的声明通常放入带 include guard 的头文件，普通非模板成员函数的定义通常放入一个 `.cpp` 文件：

```cpp
// Counter.h
#ifndef COUNTER_H
#define COUNTER_H

class Counter
{
public:
    void increment();
    int value() const;

private:
    int value_ = 0;
};

#endif
```

```cpp
// Counter.cpp
#include "Counter.h"

void Counter::increment()
{
    ++value_;
}

int Counter::value() const
{
    return value_;
}
```

各调用方包含 `Counter.h`。头文件必须让每个需要完整类型的翻译单元看到类定义；非内联函数若直接定义在普通头文件中并被多个 `.cpp` 包含，通常会违反一处定义规则并造成重复定义。include guard 只防止同一翻译单元重复包含，不会让不同翻译单元合并成一个。

## 249【节点：O2.1】【访问控制】`public`、`private` 和 `protected` 分别允许谁访问？

**答案：** `public` 成员构成类对外开放的接口，任何满足普通名字可见规则的代码都可访问；`private` 成员只能由该类的成员和友元直接访问；`protected` 除成员和友元外，还允许派生类成员在规则许可的对象上访问。访问控制是编译期语言规则，不是操作系统提供的内存隔离；外部代码不能直接访问 `private`，但可以通过类提供的公有成员函数间接操作对象。

## 250【节点：O2.2】【设计辨析】把数据成员设为 `private`，再为它提供不受限制的 setter，是否就实现了良好封装？

```cpp
class BankAccount
{
public:
    void setBalance(int value)
    {
        balance = value;
    }

private:
    int balance = 0;
};
```

**答案：** 不一定。封装的核心是由公开接口维护对象不变量，而不只是隐藏字段。这个 `setBalance` 允许外部任意改写余额，可能绕过“不能为负数”“修改必须记录流水”等规则。更合理的接口可以是 `deposit`、`withdraw` 和只读的 `balance`，并在操作中验证条件；具体表示及规则实现保持在类内部。

## 251【节点：O2.3】【代码判断】为什么 `const` 对象可以调用 `value()`，却不能调用 `set()`？

```cpp
class Counter
{
public:
    int value() const
    {
        return value_;
    }

    void set(int value)
    {
        value_ = value;
    }

private:
    int value_ = 0;
};

int main()
{
    const Counter counter;
    int n = counter.value();
    // counter.set(3);
}
```

**答案：** 成员函数末尾的 `const` 表示该函数不会通过当前对象修改普通数据成员，因此可以在 `const Counter` 上调用。`set()` 是非 `const` 成员函数，可能修改对象，所以 `counter.set(3)` 不合法。这里的末尾 `const` 修饰成员函数对当前对象的访问约束，不是修饰函数返回值。

## 252【节点：O2.4】【概念】`mutable` 有什么作用？下面代码为什么能通过类型检查？

```cpp
class Query
{
public:
    int result() const
    {
        ++access_count_;
        return value_;
    }

private:
    int value_ = 10;
    mutable int access_count_ = 0;
};
```

**答案：** `mutable` 允许该数据成员即使处于 `const` 对象中，也能在 `const` 成员函数内修改。因此 `result()` 可以递增 `access_count_`，但仍不能修改普通成员 `value_`。它适合缓存、访问统计等不改变对象对外逻辑状态的数据，不应用来随意绕过 `const` 并改变对象的核心状态；`mutable` 本身也不提供线程安全。

## 253【节点：O2.5】【友元】下面的非成员函数为什么能访问 `Box::value_`？友元关系有哪些限制？

```cpp
#include <iostream>

class Box
{
    friend void print(const Box& box);

private:
    int value_ = 7;
};

void print(const Box& box)
{
    std::cout << box.value_ << '\n';
}
```

**答案：** 类中的 `friend` 声明授予这个 `print` 函数访问 `Box` 非公有成员的权限，所以它虽然不是成员函数，仍能读取 `value_`。友元函数没有隐含 `this`，必须通过形参取得对象。友元关系不传递、不继承，也不自动互为友元：`A` 是 `B` 的友元，并不说明 `B` 是 `A` 的友元。

## 254【节点：O2.6】【设计关系】什么是组合？为什么成员对象通常不需要外围类手工销毁？

```cpp
class Engine
{
};

class Car
{
private:
    Engine engine;
};
```

**答案：** `Car` 直接包含一个 `Engine` 成员，这种关系称为组合，表达 `Car has an Engine`。构造 `Car` 时，其 `engine` 成员会在进入 `Car` 构造函数体前自动构造；销毁 `Car` 时，`engine` 会自动析构。外围对象直接管理成员对象的生命周期，因此不需要对普通对象成员使用 `delete`；表示“拥有组成部分”时，组合通常比继承更自然。

## 255【节点：O3.1】【概念】构造函数具有什么语法和职责？它能否重载？

```cpp
class Point
{
public:
    Point()
        : x_(0), y_(0)
    {
    }

    Point(int x, int y)
        : x_(x), y_(y)
    {
    }

private:
    int x_;
    int y_;
};
```

**答案：** 构造函数与类同名，没有返回类型，负责把新对象初始化为有效状态。一个类可以按照参数列表重载多个构造函数，所以这里既能写 `Point first;`，也能写 `Point second(3, 4);`。即使写成 `void Point()` 也不会成为构造函数，而是错误的构造函数声明。

## 256【节点：O3.2】【最小纠错】为什么下面的 `User user;` 不合法？怎样恢复无实参构造能力？

```cpp
class User
{
public:
    explicit User(int id)
        : id_(id)
    {
    }

private:
    int id_;
};

int main()
{
    User user;
}
```

**答案：** `User(int)` 需要一个实参，不能无实参调用；而类已经声明了构造函数，编译器不会再为它隐式声明默认构造函数。可以显式增加默认构造函数：

```cpp
User()
    : id_(0)
{
}
```

也可以给成员提供类内初值，并使用 `User() = default;`。默认构造函数指能够无实参调用的构造函数，不等于“必然由编译器生成的构造函数”。

## 257【节点：O3.3】【分类】下面分别使用了哪些初始化形式？初始化和赋值有什么区别？

```cpp
int a;
int b{};
int c(3);
int d = 3;
int e{3};
int f = {3};

d = 8;
```

**答案：** `a` 是默认初始化，对自动存储期的局部 `int` 来说其值不确定，读取前必须先赋值；`b` 是使用空列表的直接列表初始化，结果为 `0`；`c` 是直接初始化；`d` 是复制初始化；`e` 是直接列表初始化；`f` 是复制列表初始化。最后的 `d = 8` 是赋值，它修改已经存在的对象。复制初始化仍然是初始化，并不是先默认创建对象再自动执行一次赋值。

## 258【节点：O3.4】【最小纠错】为什么引用成员和 `const` 成员必须在成员初始化列表中初始化？

```cpp
class Record
{
public:
    Record(int id, int& target)
    {
        id_ = id;
        target_ = target;
    }

private:
    const int id_;
    int& target_;
};
```

**答案：** 进入构造函数体时，所有成员的初始化阶段已经结束。`const` 成员不能在函数体中再次赋值，引用成员必须在建立时绑定且不能以后重新绑定，因此原代码不合法。应直接初始化：

```cpp
Record(int id, int& target)
    : id_(id), target_(target)
{
}
```

对普通类类型成员，初始化列表也能直接调用所需构造函数，避免先默认构造再赋值。这里的“成员初始化列表”不是 `std::initializer_list`。

## 259【节点：O3.5】【顺序判断】下面构造完成后，`first_` 和 `second_` 分别是什么值？谁先初始化？

```cpp
class Pair
{
public:
    Pair()
        : second_(first_ + 1), first_(10)
    {
    }

private:
    int first_;
    int second_;
};
```

**答案：** `first_` 先初始化为 `10`，`second_` 随后初始化为 `11`。非静态数据成员严格按照它们在类定义中的声明顺序初始化，而不是按照成员初始化列表的书写顺序。整体顺序是虚基类、直接基类、按声明顺序的数据成员，最后才执行构造函数体。应让初始化列表也按照声明顺序书写，以免误导读者或意外依赖尚未初始化的成员。

## 260【节点：O3.6】【代码阅读】下面两个对象的 `value()` 分别返回什么？

```cpp
class Counter
{
public:
    Counter()
    {
    }

    explicit Counter(int value)
        : value_(value)
    {
    }

    int value() const
    {
        return value_;
    }

private:
    int value_ = 10;
};

int main()
{
    Counter first;
    Counter second(3);
}
```

**答案：** `first.value()` 返回 `10`，因为默认构造函数没有在初始化列表中指定 `value_`，所以使用 C++11 的类内成员初始值。`second.value()` 返回 `3`，因为构造函数初始化列表对同一成员的显式初始化优先于类内初始值。类内初始值是各构造函数可以采用的默认方案，不是对象构造完成后再次进行的赋值。

## 261【节点：O3.7】【委托构造】下面的默认构造函数做了什么？委托时还能否同时初始化其他成员？

```cpp
class Point
{
public:
    Point()
        : Point(0, 0)
    {
    }

    Point(int x, int y)
        : x_(x), y_(y)
    {
    }

private:
    int x_;
    int y_;
};
```

**答案：** `Point()` 委托给 `Point(int, int)`，先由目标构造函数完成成员初始化并执行其函数体，再执行委托构造函数自己的函数体。委托构造函数的初始化列表只能指定另一个同类构造函数，不能在同一列表里再写 `x_(...)` 或其他成员初始化；构造函数之间也不能形成循环委托。

## 262【节点：O3.8】【代码判断】`explicit` 为什么使下面部分初始化和调用不合法？

```cpp
class Length
{
public:
    explicit Length(int value)
        : value_(value)
    {
    }

private:
    int value_;
};

void print(Length value);

int main()
{
    Length a(5);
    Length b{5};

    // Length c = 5;
    // print(5);
}
```

**答案：** `Length(int)` 可由一个 `int` 实参调用，但 `explicit` 禁止它被用于这里的隐式类型转换。因此直接初始化 `a(5)` 和直接列表初始化 `b{5}` 合法，复制初始化 `Length c = 5` 和需要把 `5` 隐式转换为 `Length` 的 `print(5)` 不合法。`explicit` 用于避免一个普通整数在调用者没有明确表达意图时自动变成类对象。

## 263【节点：O3.9】【代码阅读】下面两个 `vector` 的内容为什么不同？花括号初始化还有什么约束？

```cpp
#include <vector>

int main()
{
    std::vector<int> first(3, 7);
    std::vector<int> second{3, 7};

    // std::vector<int> third{3.5};
}
```

**答案：** `first` 调用接受“元素个数和元素值”的构造函数，包含三个 `7`；`second` 优先选择 `std::initializer_list<int>` 构造函数，包含两个元素 `3`、`7`。`third` 不合法，因为列表初始化禁止这里从 `double` 到 `int` 的窄化转换。`std::initializer_list` 是接收一组花括号元素的标准库类型，与构造函数冒号后的“成员初始化列表”不是同一概念。

## 264【节点：O3.10】【最小纠错】下面语句定义了对象还是声明了函数？如何明确构造对象？

```cpp
class Widget
{
};

int main()
{
    Widget object();
}
```

**答案：** `Widget object();` 被解析为一个名为 `object`、不接受参数并返回 `Widget` 的函数声明，不是局部对象定义，这称为“最令人困惑的解析”。C++11 中可用空花括号明确地默认构造对象：

```cpp
Widget object{};
```

## 265【节点：O4.1】【概念】析构函数何时调用，具有怎样的语法限制？

```cpp
class Resource
{
public:
    ~Resource()
    {
        // 释放该对象拥有的资源
    }
};
```

**答案：** 析构函数名为 `~类名`，没有返回类型、没有普通形参，并且一个类只能有一个析构函数，不能按参数重载。自动对象离开作用域、动态对象被正确 `delete`、成员所属的外围对象销毁等情况下都会调用析构函数。它负责释放对象拥有的资源，但不应释放仅借用而不拥有的资源。

## 266【节点：O4.2】【代码输出】下面程序输出什么？成员为什么按照这个顺序析构？

```cpp
#include <iostream>

class Member
{
public:
    explicit Member(int id)
        : id_(id)
    {
    }

    ~Member()
    {
        std::cout << id_;
    }

private:
    int id_;
};

class Owner
{
public:
    Owner()
        : first_(1), second_(2)
    {
    }

    ~Owner()
    {
        std::cout << 'O';
    }

private:
    Member first_;
    Member second_;
};

int main()
{
    Owner object;
}
```

**答案：** 输出 `O21`。销毁 `Owner` 时先执行 `Owner` 的析构函数体，随后数据成员按声明顺序的逆序析构，因此先销毁 `second_`，再销毁 `first_`。直接基类也在成员之后按构造逆序销毁；数组元素同样按构造顺序的逆序销毁。

## 267【节点：O4.3】【异常流程】下面程序的输出顺序是什么？为什么抛出异常后局部对象仍会析构？

```cpp
#include <iostream>

class Trace
{
public:
    explicit Trace(char name)
        : name_(name)
    {
        std::cout << '+' << name_ << ' ';
    }

    ~Trace()
    {
        std::cout << '-' << name_ << ' ';
    }

private:
    char name_;
};

void run()
{
    Trace first('A');
    Trace second('B');
    throw 1;
}

int main()
{
    try
    {
        run();
    }
    catch (...)
    {
        std::cout << "caught\n";
    }
}
```

**答案：** 输出为 `+A +B -B -A caught`，随后换行。异常离开 `run` 时发生栈展开，已经成功构造的自动对象按构造逆序析构，所以先清理 `second`，再清理 `first`。这也是 RAII 能同时处理正常返回和异常退出的基础；若某个对象自身构造尚未成功，则不会调用该完整对象的析构函数，但其已经构造成功的成员和基类仍会被清理。

## 268【节点：O4.4】【生命周期】下面两个临时 `Token` 分别存活到什么时候？

```cpp
class Token
{
};

void inspect(const Token& token);

int main()
{
    inspect(Token{});

    const Token& saved = Token{};
    // 使用 saved
}
```

**答案：** 传给 `inspect` 的临时对象至少存活到包含该调用的完整表达式结束，也就是该调用完成并到达分号后销毁。直接用于初始化局部 `const Token& saved` 的临时对象，其生命周期延长到 `saved` 的生命周期结束，即这里的 `main` 作用域结束。生命周期延长有特定规则，不能据此返回局部对象的引用；函数返回后指向其局部对象的引用仍会悬空。

## 269【节点：O4.5】【代码输出】构造和析构期间调用虚函数时，下面程序为什么不会输出 `D`？

```cpp
#include <iostream>

class Base
{
public:
    Base()
    {
        speak();
    }

    virtual ~Base()
    {
        speak();
    }

    virtual void speak()
    {
        std::cout << 'B';
    }
};

class Derived : public Base
{
public:
    void speak() override
    {
        std::cout << 'D';
    }
};

int main()
{
    Derived object;
}
```

**答案：** 输出 `BB`。执行 `Base` 构造函数时，`Derived` 部分尚未构造，虚调用只分派到当前正在构造的 `Base`；执行 `Base` 析构函数时，`Derived` 部分已经析构，虚调用同样只分派到 `Base`。构造和析构期间不能依靠虚调用访问尚未存在或已经销毁的派生类状态。

## 270【节点：O4.6】【异常安全】为什么析构函数通常不应让异常逃出？可失败的资源关闭操作应怎样设计？

**答案：** 如果程序正在因一个异常进行栈展开，而某个析构函数又让第二个异常逃出，运行库会调用 `std::terminate`；异常若逃出不允许抛出的析构函数，也会调用 `std::terminate`。因此析构函数通常应保证不向外抛出异常。需要向调用者报告失败的资源操作，可以提供显式 `close()` 等接口；析构函数只负责不能抛出异常的最终兜底清理或在内部捕获并处理错误。
