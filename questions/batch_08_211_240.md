# C++11 第八批题目（211–240）

## 211【节点：B15.1】【概念】什么是作用域？C++11 基础阶段需要认识哪些作用域？

**答案：** 作用域描述一个名字在源代码中的哪些位置可以被找到。基础阶段应认识块作用域、函数参数作用域、函数作用域、命名空间作用域和类作用域；其中函数作用域主要适用于标签名字，类作用域在类模块进一步学习。

## 212【节点：B15.1】【代码阅读】下面程序输出什么？如何访问被局部变量隐藏的全局变量？

```cpp
#include <iostream>

int value = 10;

int main()
{
    int value = 20;
    std::cout << value << ' ' << ::value << '\n';
}
```

**答案：** 输出 `20 10`。块内的局部 `value` 隐藏外层同名名字，普通 `value` 指局部变量；`::value` 使用全局命名空间限定符访问全局变量。隐藏不是删除，被隐藏名字仍可在适当限定下访问。

## 213【节点：B15.2】【概念】无链接、内部链接和外部链接分别表示什么？

**答案：** 无链接的名字只标识当前作用域中的实体，例如多数普通局部变量；内部链接的名字只在当前翻译单元标识同一实体；外部链接的名字可以在不同翻译单元中标识同一个程序实体。链接描述跨作用域或跨翻译单元的名字关系，不是链接器操作本身的同义词。

## 214【节点：B15.2】【判断】命名空间作用域的 `const int limit = 10;` 与 `int count = 0;` 默认都具有外部链接。

**答案：** 错误。在 C++11 中，命名空间作用域的普通非 `const` 对象 `count` 通常具有外部链接；未显式声明为 `extern` 的命名空间作用域 `const` 对象 `limit` 默认具有内部链接。不能把 C 的全局 `const` 规则直接套到 C++。

## 215【节点：B15.2】【跨文件】如何在两个 `.cpp` 文件中共享一个全局对象，又避免重复定义？

**答案：** 在头文件中放声明，例如 `extern int total;`；只在一个 `.cpp` 文件中放定义，例如 `int total = 0;`，各使用方包含该头文件。若把 `int total = 0;` 直接放普通头文件，多个翻译单元包含后通常造成重复外部定义；命名空间作用域 `static` 则会让每个翻译单元各有一个内部链接实体，并不是共享一个对象。

## 216【节点：B15.3】【概念】C++11 的四种存储期是什么？

**答案：** 四种存储期是自动存储期、静态存储期、线程存储期和动态存储期。它们描述对象所用存储存在多长时间，分别常见于普通局部对象、全局或静态对象、`thread_local` 对象以及通过动态分配创建的对象。

## 217【节点：B15.3】【辨析】存储期和作用域为什么不是同一概念？

**答案：** 作用域是名字在源代码中可见的区域，存储期是对象存储存在的时长。例如函数内局部静态对象的名字只有块作用域，但对象具有静态存储期并持续到程序结束附近；名字暂时不可见不代表对象已经销毁。

## 218【节点：B15.4】【代码阅读】下面程序中局部对象的析构顺序是什么？

```cpp
#include <string>

void f()
{
    std::string first("a");
    std::string second("b");
}
```

**答案：** 假设两个对象都成功构造，离开函数块时先析构 `second`，再析构 `first`，即后构造者先销毁。正常执行到块末尾、执行 `return` 或因异常离开作用域时，已成功构造的自动对象都遵循相应的逆序清理。

## 219【节点：B15.4】【最小纠错】下面函数为什么错误？给出一种安全修改。

```cpp
const int* make_value()
{
    int value = 42;
    return &value;
}
```

**答案：** `value` 是自动存储期局部对象，函数返回时其生命周期结束，返回指针立即悬空。若只需返回数值，应按值返回：

```cpp
int make_value()
{
    return 42;
}
```

不能通过把返回类型改成引用来修复，因为引用同样会悬空。

## 220【节点：B15.5】【概念】哪些基础对象通常具有静态存储期？其生命周期大致多长？

**答案：** 命名空间作用域对象、用 `static` 声明的局部对象以及静态数据成员等通常具有静态存储期。它们的存储持续整个程序运行期，先经历静态初始化，必要时再进行动态初始化，并通常在程序正常结束阶段销毁。

## 221【节点：B15.5】【工程风险】为什么不应让不同翻译单元中的全局对象在动态初始化时互相依赖？

**答案：** C++11 不提供一个可随意依赖的跨翻译单元动态初始化总顺序；一个全局对象的构造可能读取另一个尚未完成动态初始化的对象，形成“静态初始化顺序问题”。常用规避方式是减少有复杂构造的全局状态，或把对象放入函数局部静态中按首次使用初始化。

## 222【节点：B15.6】【代码阅读】下面函数被调用三次时，`next()` 分别返回什么？

```cpp
int next()
{
    static int value = 0;
    return ++value;
}
```

**答案：** 依次返回 `1`、`2`、`3`。局部静态对象 `value` 只在第一次执行到声明处时初始化，后续调用复用同一个对象；它的名字只在函数块内可见，但对象具有静态存储期。

## 223【节点：B15.6】【判断】C++11 保证局部静态对象初始化线程安全，因此对该对象之后的一切并发读写也自动安全。

**答案：** 错误。C++11 保证多个线程首次经过声明时，初始化过程只正确完成一次，其他线程会按规则等待或观察完成结果；但对象初始化完成后的普通并发读写仍需满足数据竞争规则。若多个线程无同步地修改 `value`，仍可能产生数据竞争和未定义行为。

## 224【节点：B15.7】【生命周期】临时对象通常何时销毁？常量引用能否延长其生命周期？

**答案：** 临时对象通常在包含它的完整表达式结束时销毁。某些直接用临时对象初始化局部 `const T&` 的场景可以把临时对象生命周期延长到该引用的生命周期，但这种延长不自动跨越函数返回、间接引用传递或所有成员引用场景。

## 225【节点：B15.8】【概念】RAII 如何利用对象生命周期处理正常返回和异常传播？

**答案：** RAII 在对象构造时取得资源，在析构时释放资源，把资源所有权绑定到对象生命周期。无论作用域因正常执行、`return` 还是异常传播而退出，已成功构造的自动对象都会析构，因此文件、锁和动态内存等资源可被可靠释放。

## 226【节点：B16.1】【分类】哪些问题属于编译阶段通常能够诊断的错误？

**答案：** 词法或语法错误、类型不匹配、使用未声明名字、重载二义性，以及多数违反语言约束的非良构代码，通常会在编译某个翻译单元时得到诊断。这类错误发生在尚未把所有目标文件组合成完整程序之前。

## 227【节点：B16.2】【分类】源文件已经成功编译，链接时仍可能出现哪些错误？

**答案：** 常见链接错误包括已声明并调用的函数没有可用定义、同一外部实体存在多个定义、没有链接所需库、链接了不兼容版本，以及声明和实际定义不一致导致期望符号不存在。声明足以让调用处通过编译，但不能保证链接器一定能找到匹配实体。

## 228【节点：B16.3】【分类】什么是运行时错误？给出四类例子。

**答案：** 运行时错误是程序成功生成并开始运行后遇到的失败，例如输入解析失败、文件打不开、网络或操作系统资源获取失败、动态分配抛出 `std::bad_alloc`、标准库检查后抛出异常。崩溃只是可能表现之一，很多运行时错误可以被检测并妥善报告。

## 229【节点：B16.4】【分类】什么是逻辑错误？为什么编译器不一定报告？

**答案：** 逻辑错误是程序语法和类型合法，也能编译、链接并运行，但计算结果不符合需求，例如循环少执行一次、边界条件写反或选择了错误算法。语言规则没有包含程序业务需求，因此编译器通常无法知道结果“不合需求”。

## 230【节点：B16.5】【概念】什么是未定义行为？它是否意味着程序一定崩溃？

**答案：** 未定义行为是标准不对该程序执行施加要求的情形，编译器无需维持程序员直觉中的结果。它不等于必然崩溃：程序可能看似正常、输出变化、破坏数据、被激进优化或在以后才失败；一次测试通过不能证明没有未定义行为。

## 231【节点：B16.5】【代码判断】下面两个表达式各有什么问题？

```cpp
int a[3] = {1, 2, 3};
int x = a[3];

int* p = nullptr;
int y = *p;
```

**答案：** `a[3]` 越过最后合法元素 `a[2]`，读取越界产生未定义行为；`*p` 解引用空指针也产生未定义行为。数组越界或空指针解引用不保证立刻触发硬件错误，不能依赖“能运行”。

## 232【节点：B16.5】【算术边界】有符号整数溢出、整数除以零和非法移位分别属于什么问题？

**答案：** 有符号整数结果超出类型可表示范围是未定义行为，整数除以零也是未定义行为；移位数量为负或不小于提升后左操作数的位数同样非法并导致未定义行为。无符号加减按模运算不等于所有无符号移位都自动安全。

## 233【节点：B16.5】【内存边界】读取未初始化值、重复释放和释放后使用为什么危险？

**答案：** 读取未初始化自动基本类型对象通常产生未定义行为；对同一动态分配重复释放，或对象释放后继续访问，也会产生未定义行为。把指针设为 `nullptr` 可以避免同一个指针再次误解引用，但不能自动修复其他仍指向旧对象的别名指针。

## 234【节点：B16.5】【求值规则】为什么 C++11 中下面表达式不能通过加括号修复？

```cpp
int i = 1;
int r = (i++) + (++i);
```

**答案：** `+` 的两个操作数之间没有建立求值先后关系，对同一标量对象 `i` 的两次修改彼此未排序，因此行为未定义。括号只改变语法分组，不建立求值顺序；应拆成多个完整表达式，先完成一次修改，再执行下一次。

## 235【节点：B16.6】【概念】什么是未指定行为？函数实参求值顺序如何体现这一边界？

**答案：** 未指定行为表示标准允许若干可能结果，实现不必记录或始终选择同一个结果。C++11 不规定不同函数实参的一般先后顺序；若实参彼此独立，程序不能依赖谁先执行；若它们对同一标量对象产生未排序的冲突修改，则会进一步成为未定义行为。

## 236【节点：B16.7】【概念】什么是实现定义行为？列出三个 C++11 例子。

**答案：** 实现定义行为要求具体实现选择一种允许结果并在文档中说明。例子包括普通 `char` 是有符号还是无符号、基本整数类型的实际宽度，以及负有符号整数右移的结果规则；可移植代码应查实现文档或避免依赖这些选择。

## 237【节点：B16.8】【概念】什么是非良构程序？“要求诊断”是否等于编译器必须猜出程序员意图并修复？

**答案：** 非良构程序违反 C++ 的语法或语义要求，多数情况下实现必须至少给出一条诊断。要求诊断不代表必须继续编译、自动修复或给出特定措辞；编译器报错并接受扩展模式代码，也不意味着代码符合 ISO C++11。

## 238【节点：B16.8】【ODR 边界】为什么“编译器和链接器都接受了”仍不能证明程序符合 C++11？

**答案：** 某些违反一处定义规则 ODR 的程序属于非良构但不要求诊断，问题可能分散在多个翻译单元，工具不一定发现。此类程序即使生成可执行文件也不具有标准保证，因此仍需通过正确的头文件组织和唯一、一致定义来保证合法性。

## 239【节点：B16.9】【判断】只要编译器没有警告，代码就没有未定义行为；只要出现警告，程序就一定不符合标准。

**答案：** 两项都错误。警告策略和级别由工具链决定，许多未定义行为无法静态诊断；反之，编译器也会对合法但可疑或风格不佳的代码发出警告。应启用较高警告级别并认真处理，但警告不能代替对语言规则的理解。

## 240【节点：B16.10】【工具边界】`assert`、`static_assert`、调试器和 Sanitizer 分别能做什么？测试能否证明程序没有未定义行为？

**答案：** `assert` 在启用时检查运行期条件，定义 `NDEBUG` 后通常会被移除；C++11 `static_assert` 在编译期检查常量条件。调试器帮助观察运行状态，AddressSanitizer、UndefinedBehaviorSanitizer 等能检测部分运行时问题，但属于工具而非 C++11 标准。测试和工具只能覆盖部分路径，不能把未定义行为变成正确行为，也不能一般性证明程序完全没有未定义行为。
