# C++11 第七批题目（181–210）

## 181【节点：B13.1】【概念】`std::vector<T>` 是什么？它和内建数组最基本的区别是什么？

**答案：** `std::vector<T>` 是自动管理一段连续 `T` 元素的动态长度顺序容器，长度可以在运行期增长或缩小。内建数组长度固定且不负责动态扩容；`vector` 会自动构造、移动、复制和销毁其元素，但仍不允许越界访问。

## 182【节点：B13.1】【对象生命周期】向 `std::vector<T>` 添加或删除元素时，元素对象的生命周期会发生什么？

**答案：** 添加元素会在容器存储中构造新 `T` 对象，删除元素会析构相应对象；容器自身销毁时会析构仍在其中的全部元素。发生扩容时，已有元素通常还需要被复制或移动到新存储，旧存储中的对应对象随后销毁。

## 183【节点：B13.2】【代码阅读】下面五个 `vector` 的大小和内容分别是什么？

```cpp
std::vector<int> a;
std::vector<int> b(3);
std::vector<int> c(3, 7);
std::vector<int> d{3};
std::vector<int> e{3, 7};
```

**答案：** `a` 为空；`b` 含三个值初始化的 `int`，内容为 `{0,0,0}`；`c` 为 `{7,7,7}`；`d` 只有一个元素 `{3}`；`e` 有两个元素 `{3,7}`。圆括号常表示数量构造，花括号会优先匹配 `initializer_list`。

## 184【节点：B13.2】【最小纠错】若要创建十个值均为 `3` 的 `int` 元素，下面写法为什么错误？如何修改？

```cpp
std::vector<int> v{10, 3};
```

**答案：** 花括号选择元素列表，因此它创建两个元素 `10` 和 `3`，不是十个 `3`。应使用数量和值构造：

```cpp
std::vector<int> v(10, 3);
```

## 185【节点：B13.3】【概念】`size()`、`empty()` 和 `capacity()` 分别回答什么问题？

**答案：** `size()` 返回当前实际存在的元素数量，`empty()` 等价于判断 `size() == 0`，`capacity()` 返回不重新分配存储时最多可容纳的元素数。只能访问 `[0, size())` 内的元素，`capacity()` 大于 `size()` 不代表多出的槽位已经是活对象。

## 186【节点：B13.3】【辨析】`reserve(100)` 和 `resize(100)` 有什么本质区别？

**答案：** `reserve(100)` 只请求把容量提高到至少 100，不改变元素数量；`resize(100)` 把实际元素数量改成 100，扩大时会构造新元素，缩小时会析构被移除元素。调用 `reserve` 后直接访问原 `size()` 之外的位置仍然越界。

## 187【节点：B13.3】【判断】调用 `v.clear()` 后，`v.size()` 和 `v.capacity()` 都必须变成零。

**答案：** 错误。`clear()` 删除并析构全部元素，因此 `size()` 变为零，但标准不要求它释放已分配容量，`capacity()` 可以保持不变。容量和元素数量是两个不同状态，不能根据容器为空就推断内部容量必为零。

## 188【节点：B13.4】【代码阅读】`operator[]` 与 `at()` 在越界时有什么区别？

**答案：** `operator[]` 不进行边界检查，越界访问产生未定义行为；`at()` 检查索引，越界时抛出 `std::out_of_range`。二者在索引合法时都可返回元素引用，但 `at()` 不能替代正确设计索引范围。

## 189【节点：B13.4】【判断】空 `vector` 可以安全调用 `front()`、`back()` 和解引用 `data()`。

**答案：** 错误。空容器没有首尾元素，调用 `front()` 或 `back()` 违反前置条件；`data()` 可以用于取得底层区间表示，但空容器返回值不提供可解引用的元素。只有 `size() > 0` 时才能通过这些位置访问元素。

## 190【节点：B13.5】【辨析】`push_back`、C++11 `emplace_back` 和 `pop_back` 分别做什么？

**答案：** `push_back` 把一个已有对象或可转换对象复制或移动到末尾；`emplace_back` 用给定参数在末尾构造元素；`pop_back` 析构并删除最后一个元素且不返回该值。C++11 中 `emplace_back` 的返回类型是 `void`，返回元素引用是 C++17 行为。

## 191【节点：B13.5】【最小纠错】下面代码为什么可能错误？给出安全写法。

```cpp
std::vector<int> v{1, 2, 3};
v.pop_back();
int x = v[2];
```

**答案：** `pop_back()` 后容器内容为 `{1,2}`，`size()` 为 2，合法下标只有 0 和 1，因此 `v[2]` 越界。若目的是取得并删除尾元素，应先在非空条件下保存 `back()`，再调用 `pop_back()`：

```cpp
int x = v.back();
v.pop_back();
```

## 192【节点：B13.5】【迭代器】`insert` 和 `erase` 返回的迭代器有什么用？

**答案：** `insert` 返回指向新插入元素的迭代器；`erase` 返回指向被删区间之后元素的迭代器，若删除到末尾则返回 `end()`。遍历中删除元素时应使用 `erase` 的返回值继续，而不能无条件递增已失效的旧迭代器。

## 193【节点：B13.6】【判断】只要 `vector` 尾部添加一个元素，原来的所有指针、引用和迭代器就一定失效。

**答案：** 错误。如果添加触发重新分配，则所有指向原存储的指针、引用和迭代器都失效；若未重新分配，原有元素的引用和迭代器通常保持有效，但原来的 `end()` 会改变。是否扩容可通过添加前后的容量关系判断，不能凭经验假定。

## 194【节点：B13.6】【概念】在未发生重新分配时，中间插入和删除为什么仍可能使迭代器失效？

**答案：** `vector` 必须保持连续存储，中间插入会移动插入点及其后的元素，删除也会把后续元素向前移动。因此操作点及其后的迭代器、指针和引用通常失效，即使底层缓冲区地址没有变化。

## 195【节点：B13.6、B13.7】【综合】`reserve`、`vector<bool>` 和只读传参分别应注意什么？

**答案：** 提前 `reserve` 可减少扩容次数，但不固定元素数量，也不能永久保证迭代器有效；`vector<bool>` 是位压缩特化，下标结果可能是代理对象而非真正 `bool&`，不能把它当普通连续 `bool` 数组；较大的只读 `vector<T>` 通常以 `const std::vector<T>&` 传参，避免整容器复制。

## 196【节点：B14.1】【概念】什么是指针？`&` 和 `*` 在基础指针表达式中分别做什么？

**答案：** 指针是保存某种类型对象地址的对象，例如 `int* p` 保存 `int` 对象地址。`&x` 取得对象 `x` 的地址，`*p` 解引用指针并访问其所指对象；解引用前必须保证指针确实指向仍然存活且类型、对齐均正确的对象。

## 197【节点：B14.1】【判断】只要一个指针中保存的数值没有改变，它就始终可以安全解引用。

**答案：** 错误。指针变量本身仍可保存原地址，但对应对象可能已经离开作用域、被 `delete`、因容器扩容而搬迁，或其生命周期以其他方式结束。此时指针成为悬空指针，地址数值看似存在也不能合法解引用。

## 198【节点：B14.2】【代码阅读】为什么应使用 `nullptr`，而不是用未初始化指针表示“没有对象”？

**答案：** `nullptr` 是类型为 `std::nullptr_t` 的空指针字面量，可明确转换为各种指针类型，并能避免重载中把 `0` 当整数的歧义。未初始化指针具有不确定值，不是空指针，读取或解引用它通常会产生未定义行为。

## 199【节点：B14.3】【概念】指针算术在哪个范围内有定义？尾后一位指针能做什么？

**答案：** 指针加减通常只在同一数组对象的元素范围及尾后一位位置内有定义，移动步长按所指元素大小计算。尾后一位指针可以形成、比较并作为循环终点，但它不指向元素，不能解引用。

## 200【节点：B14.3】【判断】任意两个 `int*` 都可以相减并比较大小，结果表示它们在整个进程地址空间中的先后。

**答案：** 错误。两个指针相减通常只在它们指向同一数组对象的元素或尾后一位时有定义，结果类型为 `std::ptrdiff_t`；对不相关对象做内建指针顺序比较也没有通用可移植含义。不能把机器地址布局当作 ISO C++11 的数组关系。

## 201【节点：B14.4】【概念】C++11 中 `void*` 能做什么，不能做什么？

**答案：** 对象指针可在保留 cv 限定的前提下转换为相应的 `void` 指针：`T*` 可隐式转为 `void*`，`const T*` 应转为 `const void*`，`volatile T*` 应转为 `volatile void*`；不能通过转换丢弃限定。`void*` 不能直接解引用，也不能在 C++ 中隐式转换回 `T*`。从 `const void*` 恢复时应得到相容的 `const T*`；任何恢复转换都必须确保对象类型、限定、对齐和生命周期正确，因此 `void` 指针不能代替类型安全接口。

## 202【节点：B14.5】【概念】引用与指针有哪些最基础的区别？

**答案：** 引用是已有对象的别名，定义时必须绑定，之后不能改为引用另一个对象；指针是独立对象，可以为空，也可以改为指向其他对象。语言正常用法中没有“空引用”，但引用和指针都可能因目标对象销毁而悬空。

## 203【节点：B14.5】【代码阅读】下面代码执行后 `a`、`b`、`r` 分别代表什么？

```cpp
int a = 1;
int b = 2;
int& r = a;
r = b;
```

**答案：** `r` 从始至终都是 `a` 的别名；`r = b` 是把 `b` 的值赋给被引用对象 `a`，不是让引用重新绑定。执行后 `a == 2`、`b == 2`，通过 `r` 读到的也是 `2`。

## 204【节点：B14.6】【接口选择】函数参数什么时候更适合用指针，什么时候更适合用引用？

**答案：** 当目标可选、允许“没有对象”或需要重新指向时，指针更能表达接口含义；当对象必须存在并只需为其提供别名时，引用更直接。二者本身都不自动表达资源所有权，不能仅凭参数是 `T*` 或 `T&` 判断谁负责销毁对象。

## 205【节点：B14.7】【概念】`new T` 和 `delete p` 分别完成哪两类工作？

**答案：** `new T` 先获得足够的动态存储，再在其中构造一个 `T` 对象并返回指针；`delete p` 先调用该对象的析构过程，再释放对应动态存储。它们不仅是“申请和释放若干字节”，还涉及对象生命周期。

## 206【节点：B14.7】【最小纠错】下面代码错在哪里？如何修改？

```cpp
int* p = new int[10];
delete p;
```

**答案：** `new[]` 必须与 `delete[]` 配对，使用普通 `delete` 释放数组会产生未定义行为。应改为：

```cpp
int* p = new int[10];
delete[] p;
```

实际工程中固定或动态序列通常优先使用 `std::array` 或 `std::vector`。

## 207【节点：B14.7】【判断】普通 `new` 分配失败时一定返回 `nullptr`；`delete nullptr` 会导致崩溃。

**答案：** 两项都错误。普通 `new` 分配失败时默认抛出 `std::bad_alloc`，不是以返回 `nullptr` 报告；对空指针执行 `delete` 或 `delete[]` 是安全的无操作，但非空指针仍必须与原来的分配形式正确配对。

## 208【节点：B14.7】【错误辨析】分别解释内存泄漏、重复释放和释放后使用。

**答案：** 内存泄漏是失去仍需释放资源的所有权路径，使资源无法回收；重复释放是对同一分配执行两次释放；释放后使用是在对象生命周期结束后继续通过旧指针访问它。后两者通常产生未定义行为，泄漏则可能不断耗尽资源，即使程序暂时没有崩溃。

## 209【节点：B14.8】【所有权】为什么裸指针的含义不够明确？

**答案：** `T*` 只说明它可保存一个 `T` 对象地址，不能单独说明它是拥有者还是观察者、是否允许为空、是否指向数组、由谁释放。C++11 代码应优先用值对象、RAII 容器、`unique_ptr`、`shared_ptr` 和 `weak_ptr` 明确资源关系，裸指针通常用于非拥有观察。

## 210【节点：B14.8】【版本边界】C++11 中如何表达动态对象的独占所有权？能否使用 `std::make_unique`？

**答案：** 应使用 `std::unique_ptr<T>` 表达独占所有权，它不可复制但可以移动，并在销毁时自动释放对象。`std::make_unique` 是 C++14 才加入的标准接口，严格 C++11 可写 `std::unique_ptr<T>(new T(...))`，或使用项目自行实现且明确标注的 C++11 工厂辅助函数。
