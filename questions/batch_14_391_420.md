# C++11 第十四批题目（391–420）

## 391【节点：L4.1】【生存期判断】为什么从函数返回一个按引用捕获局部变量的 Lambda 会很危险？

**答案：** 按引用捕获只把闭包与原对象关联起来，不复制对象，也不延长对象生命。函数返回后，普通局部变量已经销毁；闭包即使仍存在，其中的引用也已悬空，调用它属于未定义行为。`std::function` 保存或复制这个闭包也不会把引用自动改成值。若回调需要独立于原作用域存在，应按值保存所需数据，或使用能明确表达共享生命期的所有权对象。例如以下代码安全地保存数值快照：

```cpp
#include <functional>

std::function<int()> make_reader()
{
    int value = 7;
    return [value]() { return value; };
}

int main()
{
    return make_reader()() == 7 ? 0 : 1;
}
```

## 392【节点：L4.2】【对象生命期】捕获 `this` 为什么可能悬空？长期回调常用哪两种所有权策略？

**答案：** C++11 的 `[this]` 只复制当前对象的地址，并不复制或拥有整个对象；对象析构后，这个地址就失效。若回调必须让对象继续存在，可让对象由 `shared_ptr` 管理，并在对象已经受控后捕获 `shared_from_this()` 得到的强所有者。若回调不应延长生命，则捕获 `weak_ptr`，执行时调用 `lock()`，只有成功取得临时 `shared_ptr` 才访问对象。前者可能形成所有权环，后者需要处理对象已不存在的情况；构造函数中通常不能调用 `shared_from_this()`。

## 393【节点：L4.3】【输出推理】两个不同时刻创建的按值捕获 Lambda 会读取哪个值？

**答案：** 每次求值 Lambda 表达式都会用当时的变量值建立一个新的闭包对象。因此：

```cpp
int main()
{
    int version = 1;
    auto first = [version]() { return version; };
    version = 2;
    auto second = [version]() { return version; };
    return first() == 1 && second() == 2 ? 0 : 1;
}
```

`first` 保存 `1`，`second` 保存 `2`。但“按值”只说明复制捕获变量本身：若变量是裸指针，复制的是地址；若变量是 `shared_ptr`，复制后双方共享目标，并没有复制目标对象。

## 394【节点：L4.4】【递归】严格 C++11 中怎样让 Lambda 递归调用自己？

**答案：** 闭包类型无法在自身初始化器中直接写出，常用方法是先声明一个具有确定签名的空 `std::function`，再给它赋一个按引用捕获该包装器的 Lambda：

```cpp
#include <functional>

int main()
{
    std::function<int(int)> factorial;
    factorial = [&factorial](int n) -> int {
        return n <= 1 ? 1 : n * factorial(n - 1);
    };
    return factorial(5) == 120 ? 0 : 1;
}
```

必须先完成赋值再调用，并保证 `factorial` 活过全部递归调用。深递归仍可能耗尽调用栈；把“自身”作为 `auto` 参数传入的泛型 Lambda 写法依赖 C++14，不属于本题范围。

## 395【节点：L5.1】【算法接口】什么是谓词？一元谓词和二元谓词分别表示什么？

**答案：** 谓词是可调用对象，其返回结果能转换成 `bool`，算法用它回答某个条件是否成立。一元谓词接收一个元素，例如 `find_if` 用它寻找第一个满足条件的元素；二元谓词接收两个值，例如某些比较或相等判断。参数类型要能接收算法实际传入的元素，且不能违反算法对元素修改的限制。谓词若依赖不断变化的外部状态，可能对相同输入给出不同结果，从而破坏算法契约；空区间则不会调用谓词。

## 396【节点：L5.2】【比较规则】为什么排序比较器通常写 `<`，不能简单改成 `<=`？

**答案：** 排序比较器要表达“左值严格排在右值之前”，必须满足严格弱序。至少应有 `comp(x, x) == false`、若 `comp(a,b)` 为真则 `comp(b,a)` 为假，并保持相应传递性。`<=` 会让相等值与自身比较为真，违反第一条，标准排序和有序容器便失去所需前置条件。两个键的等价不是直接调用 `==`，而是 `!comp(a,b) && !comp(b,a)`。多字段比较应按一致的字典序规则完成，也不能在排序途中改变比较依据。

## 397【节点：L5.3】【状态与复制】为什么不能假定标准算法始终调用传入的那一个谓词对象？

**答案：** C++11 标准算法通常按值接收可调用对象，并允许在内部复制它。因此，一个在自身成员中累计次数的谓词，调用可能分散在副本上，不能仅凭传入对象的最终状态推断总调用数。若确实要同步汇总，可让闭包副本都引用一个在算法执行期间持续存在的外部对象：

```cpp
#include <algorithm>
#include <vector>

int main()
{
    std::vector<int> values{1, 2, 3};
    int calls = 0;
    std::for_each(values.begin(), values.end(),
                  [&calls](int) { ++calls; });
    return calls == 3 ? 0 : 1;
}
```

引用不会延长 `calls` 的生命；若工作被异步保存或并发执行，还必须解决生命期和同步问题。C++11 标准算法没有 C++17 的并行执行策略。

## 398【节点：S1.1】【总体模型】STL 风格代码中的容器、迭代器、算法、函数对象和分配器各负责什么？

**答案：** 容器保存元素；迭代器表示元素位置和区间边界；算法通过迭代器读取、写入或重排区间；函数对象为算法提供判断、转换和比较等可定制行为；分配器负责容器底层存储的取得与释放。算法通常不认识具体容器，只要求迭代器具备所需能力，因此同一个 `std::find` 可用于多种序列。“STL”是常用历史名称，不等于整个 C++ 标准库；实际使用还需包含相应头文件并写 `std::`。

## 399【节点：S1.2】【区间】半开区间 `[first, last)` 为什么不能解引用 `last`？

**答案：** 半开区间包含 `first` 开始的元素，但不包含边界 `last`。当 `first == last` 时区间为空；循环应先判断当前位置不等于 `last`，再解引用并前进。`last` 常表示尾后一位，只用于比较或传给接受区间的接口，没有对应元素，所以解引用它是错误。两个边界还必须来自同一序列并组成可前进到达的合法范围，不能把不同容器的迭代器随意拼成区间。

## 400【节点：S1.3】【复杂度】“`vector::push_back` 摊销 `O(1)`”是否表示每一次调用都是常数时间？

**答案：** 不是。摊销常数表示对一长串尾插操作计算总成本后，平均到每次的上界为常数。大多数调用只在已有容量中构造一个元素，但容量用完时某一次调用要申请更大存储并搬运现有全部元素，可能是 `O(n)`。复杂度符号还不描述常数因子、缓存局部性、分配成本和单次最坏延迟，因此选择容器不能只比较大 O。

## 401【节点：S1.4】【类型要求】为什么 `std::vector<std::unique_ptr<int>>` 可以移动，却不能复制？

**答案：** 容器的某项操作只有在被实际使用时，才要求元素满足相应能力。`unique_ptr` 可移动但不可复制，所以容器可以建立、尾插移动元素并整体移动；复制该容器需要逐个复制元素，因此不合法。严格 C++11 的合法示例是：

```cpp
#include <memory>
#include <utility>
#include <vector>

int main()
{
    std::vector<std::unique_ptr<int> > first;
    first.push_back(std::unique_ptr<int>(new int(7)));
    std::vector<std::unique_ptr<int> > second = std::move(first);
    return *second.front() == 7 ? 0 : 1;
}
```

用 `initializer_list` 直接列出多个 `unique_ptr` 也会遇到元素只读、无法从中移动的问题。

## 402【节点：S2.1】【基本操作】迭代器一定是裸指针吗？哪些操作不能对所有迭代器使用？

**答案：** 不一定。迭代器可以是带有运算符重载的类对象，只要它提供所属类别要求的接口。对有效可读位置通常可用 `*it`，指向类对象时可用 `it->member`，用 `++it` 前进，并与对应结束边界比较。`it + n`、`it[n]`、两个位置相减以及大小次序比较只属于能力更强的随机访问迭代器，不能对链表迭代器使用。结束、默认构造或已失效的迭代器也不能随意解引用。

## 403【节点：S2.2】【分类】C++11 的五类迭代器分别提供到什么程度的能力？

**答案：** 输入迭代器用于单向读取，可能只允许单遍；输出迭代器用于单向写入；前向迭代器在单向前进基础上支持多遍遍历；双向迭代器再增加 `--`；随机访问迭代器还能常数时间跳转、相减、下标和比较位置先后。`std::find` 只需输入能力，`std::reverse` 至少需要双向能力，`std::sort` 需要随机访问能力，所以 `std::sort(list.begin(), list.end())` 不成立，应使用 `list::sort()`。正式的连续迭代器类别到 C++20 才出现。

## 404【节点：S2.3】【只读访问】`iterator` 与 `const_iterator` 有什么关系？

**答案：** `iterator` 通常允许通过它修改元素，`const_iterator` 只允许读取。非 `const` 容器的 `begin()` 通常返回 `iterator`，常量容器返回 `const_iterator`；C++11 容器还提供成员 `cbegin()` 和 `cend()`。普通迭代器通常能转换成相应常量迭代器，反向转换不允许。`const_iterator` 只限制这条访问路径，并不永久冻结容器；两者在容器修改后遵守相同的失效规则。非成员 `std::cbegin`、`std::cend` 是 C++14 功能。

## 405【节点：S2.4】【反向位置】为什么反向迭代器 `r` 与 `r.base()` 不指向同一个元素？

**答案：** 反向迭代器要让 `[rbegin(), rend())` 仍保持半开区间规则，因此其 `base()` 保存的是当前逻辑元素后面的正向位置。对可解引用的 `r`，通用双向写法是先取得 `r.base()`，再递减一次，所得正向迭代器才对应 `*r`。例如 `rbegin().base() == end()`，而 `rbegin()` 本身指向最后一个元素。把反向位置交给 `erase` 时必须考虑这一位偏移；只有随机访问迭代器才能写 `r.base() - 1`。

## 406【节点：S2.5】【辅助函数】`advance`、`next`、`prev` 和 `distance` 的区别是什么？

**答案：** `<iterator>` 中，`std::advance(it,n)` 直接修改 `it`；`std::next(it,n)` 返回向前移动后的副本；`std::prev(it,n)` 返回向后移动后的副本；`std::distance(first,last)` 计算从 `first` 前进到 `last` 的步数。随机访问迭代器通常能常数时间完成移动和距离，链表等可能需要逐步走过而是线性时间。负向移动要求双向能力，任何移动都不能越过合法区间。`std::begin/end` 在 C++11 可统一处理容器和内建数组。

## 407【节点：S2.6】【输出位置】为什么复制到空 `vector` 时常使用 `std::back_inserter`？

**答案：** 普通输出迭代器 `target.begin()` 只表示已有元素的位置，不会在算法写入时自动增加容器大小；空容器没有可写元素。`std::back_inserter(target)` 是输出迭代器适配器，每次被赋值就调用 `push_back`，因此可以安全增长目标：

```cpp
#include <algorithm>
#include <iterator>
#include <vector>

int main()
{
    std::vector<int> source{1, 2, 3};
    std::vector<int> target;
    std::copy(source.begin(), source.end(), std::back_inserter(target));
    return target == source ? 0 : 1;
}
```

`front_inserter` 需要 `push_front`，`inserter` 使用指定插入位置。扩容和迭代器失效仍由目标容器规则决定。

## 408【节点：S3.1】【二元组合】`std::pair` 怎样保存和访问两个不同类型的值？

**答案：** `std::pair<T1,T2>` 位于 `<utility>`，有两个公开成员 `first` 和 `second`。可以直接构造、列表初始化，也可用 `std::make_pair` 推导类型；比较时先比较 `first`，必要时再比较 `second`，形成字典序。`std::map<Key,T>::value_type` 是 `std::pair<const Key,T>`，因此通过映射迭代器可以修改映射值，却不能修改键。复制或比较的成本取决于两个成员自身。

## 409【节点：S3.2】【固定多值】C++11 中怎样访问和解包 `std::tuple`？能否使用结构化绑定？

**答案：** `std::tuple<Ts...>` 位于 `<tuple>`，保存固定数量、类型可不同的元素。用 `std::get<I>(object)` 按编译期下标访问，用 `std::make_tuple` 推导元素类型；`std::tie(a,b,c) = tuple_value;` 可把各元素赋给已有变量。`I` 必须是编译期常量且不能越界。`std::tie` 形成的是引用元组，不拥有也不延长变量生命。`auto [a,b] = value;` 属于 C++17 结构化绑定，严格 C++11 不能使用。

## 410【节点：S3.3】【花括号视图】`std::initializer_list<T>` 是拥有元素的动态容器吗？

**答案：** 不是。它是对一组同类型、只读元素的轻量视图，提供 `begin()`、`end()` 和 `size()`；复制列表对象通常只复制视图，不复制底层数组。其元素表现为 `const T`，不能通过迭代器修改，也常因此不能从列表中移动不可复制对象。把指向其底层元素的指针保存到列表有效期之外会悬空；返回由短命局部列表产生的 `initializer_list` 同样危险。它适合在调用或构造时接收花括号序列，不等于 `vector`。

## 411【节点：S3.4】【引用包装】`std::reference_wrapper` 与普通引用、对象副本有何不同？

**答案：** 普通引用不能改绑，也不适合作为某些按值容器元素；`reference_wrapper<T>` 是可复制、可赋值的对象，内部仍指向原目标。`std::ref(x)` 建立可修改包装，`std::cref(x)` 建立只读包装，可用 `.get()` 取得引用。复制包装器不会复制目标，多个包装仍指向同一对象；它也不拥有目标，目标销毁后包装全部悬空。`std::bind` 默认按值保存参数，需要引用语义时也常使用 `std::ref`。

## 412【节点：S4.1】【固定容器】`std::array<T,N>` 相比内建数组提供什么？`N` 有什么类型意义？

**答案：** `std::array` 保持固定数量和连续存储，同时提供 `begin/end`、`size`、`at`、整体复制和赋值等标准容器接口。`N` 是模板实参，所以 `array<int,3>` 与 `array<int,4>` 是不同类型；元素数不能在运行时改变。C++11 常用双层花括号进行可移植的聚合初始化。`N==0` 时容器合法且 `begin()==end()`，但没有可访问元素，不能调用需要元素的 `front()`、`back()` 或解引用位置。

## 413【节点：S4.2】【动态连续容器】`vector` 的主要复杂度和失效边界是什么？

**答案：** `vector<T>` 保存连续、可变数量的元素。下标随机访问为常数，尾插为摊销常数，中间插入和删除通常是线性；`data()` 可取得连续元素区域的首地址。重新分配会让全部迭代器、指针和引用失效；即使没有重新分配，中间插入通常也会使插入点及之后的位置失效，擦除使擦除点及之后的位置失效。因此不能跨可能改变容量的操作长期保存 `data()` 或元素地址。

## 414【节点：S4.3】【两端容器】`deque` 是否能当作一整块连续数组使用？

**答案：** 不能。`deque` 支持常数时间的随机访问以及通常高效的首尾插入，但标准不保证所有元素位于一段连续内存；实现通常使用多个存储块。于是可以写 `d[i]`，却不能从 `&d[0]` 一路按指针递增访问全部元素。按 C++11 规则，在首尾插入会使全部迭代器失效，但不会使指向已有元素的引用失效；中间插入会使全部迭代器和引用失效。删除的具体影响应按对应操作单独检查。

## 415【节点：S4.4】【链表选择】为什么 `list` 的已知位置插入是 `O(1)`，却不一定比 `vector` 更快？

**答案：** `list` 是双向链表；已经持有目标位置时，只需调整少量节点链接即可插入或删除，所以是常数复杂度。按值寻找位置仍是线性，并且它没有下标、没有随机访问，`std::sort` 也不能使用其迭代器，应调用成员 `list::sort`。每个节点的额外指针、单独分配和较差的缓存局部性会增加真实成本；`vector` 虽可能搬移元素，连续访问往往更友好。因此应根据完整访问模式实测，而不是只看一个操作的大 O。

## 416【节点：S4.5】【单向链表】C++11 的 `forward_list` 为什么提供 `before_begin()`，又缺少哪些常见接口？

**答案：** 单向链表只能从一个节点走向下一个节点，删除或在某元素前插入需要知道其前驱。`before_begin()` 提供首元素之前的特殊位置，使 `insert_after`、`erase_after` 和头部操作能使用统一接口。它只有前向迭代器，提供 `push_front`，但没有 `push_back`、`back`，C++11 中也没有 `size()` 成员。已知前驱后的修改是常数时间，寻找前驱或统计元素仍是线性。

## 417【节点：S4.6】【字符串边界】C++11 的 `std::string` 与以 `'\0'` 结尾的 C 字符串有什么区别？

**答案：** `std::string` 自己保存字符数量并管理动态存储，可以含嵌入的零字符；`size()` 才是其真实长度。`c_str()` 返回只读、以额外 `'\0'` 结尾的视图，供需要 C 字符串的接口使用。C++11 的 `data()` 同样返回 `const char*`，返回可写指针是 C++17 变化。修改字符串可能重新分配，使先前的 `c_str()`、指针、引用和迭代器失效；小字符串优化只是常见实现技巧，不是 ISO C++11 保证。

## 418【节点：S5.1】【大小与容量】`vector::size()` 与 `capacity()` 分别计数什么？容量内未使用部分能否直接写入？

**答案：** `size()` 是已经构造并属于容器的元素数量；`capacity()` 是当前分配在不重分配时最多可容纳的元素数，始终有 `size() <= capacity()`。合法下标只到 `size()-1`，容量中多出的区域还没有 `T` 对象，不能用 `values[size()]` 写入。`clear()` 销毁全部元素并令大小为零，但不要求释放容量；二者单位都是元素个数，不是字节。

## 419【节点：S5.2】【容量操作】`reserve(n)` 与 `resize(n)` 的效果为什么完全不同？

**答案：** `reserve(n)` 只保证容量至少为 `n`，不会创建元素，也不改变 `size()`；只有 `n` 大于现有容量时才发生重新分配，且它不能用于缩小容量。`resize(n)` 真正改变元素数量：扩大时构造新元素，缩小时销毁尾部元素。`reserve` 重分配会使所有位置失效；`resize` 扩大也可能重分配，缩小至少使被删除元素及相关尾后位置失效。C++11 的 `shrink_to_fit()` 只是非强制请求。

## 420【节点：S5.3】【尾部构造】`push_back` 与 `emplace_back` 的语义、版本边界和常见误解是什么？

**答案：** `push_back(const T&)` 把现成对象复制到末尾，`push_back(T&&)` 可移动；`emplace_back(args...)` 转发参数，在末尾选择并调用 `T` 的构造函数。两者都会增加一个元素，都是摊销常数，触发扩容时全部位置失效。`emplace_back` 不保证更快，参数已经是 `T` 时未必省操作，还可能意外选择 `explicit` 构造函数。严格 C++11 中 `emplace_back` 返回 `void`；返回新元素引用是 C++17 的接口变化。
