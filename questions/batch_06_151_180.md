# C++11 第六批题目（151–180）

## 151【节点：B11.1】【概念】什么是内建一维数组？

**答案：** 内建一维数组是由固定数量的同类型元素连续组成的对象，例如 `int a[4];` 定义了含 4 个 `int` 元素的数组。长度通常必须能在编译期确定，下标从 `0` 开始，因此最后一个合法下标是 `3`。

## 152【节点：B11.1】【代码阅读】下面三个数组的元素初值分别是什么？

```cpp
int a[3];
int b[3] = {};
int c[3] = {1, 2};
```

假设它们都定义在函数体内。

**答案：** `a` 的三个元素被默认初始化，作为自动存储期基本类型对象，其值不确定，读取这些未初始化值通常会产生未定义行为。`b` 的三个元素都被零初始化；`c` 为 `{1, 2, 0}`，没有显式初始化的剩余元素会被值初始化为零。

## 153【节点：B11.1】【判断】标准 C++11 允许根据运行期输入定义 `int a[n];`，也允许定义 `int empty[0];`。

**答案：** 错误。变长数组 VLA 不是 ISO C++11 的组成部分，某些编译器接受它只是扩展；内建数组的长度也必须大于零，所以 `int empty[0];` 不是标准 C++11。需要运行期长度时应使用 `std::vector`，需要合法的零长度固定容器时可使用 `std::array<T, 0>`。

## 154【节点：B11.1】【最小纠错】下面循环为什么错误？给出最小修改。

```cpp
int a[3] = {10, 20, 30};
for (int i = 0; i <= 3; ++i) {
    std::cout << a[i] << '\n';
}
```

**答案：** 数组的合法下标为 `0`、`1`、`2`，当 `i == 3` 时访问越界，行为未定义。最小修改是把条件改为 `i < 3`：

```cpp
for (int i = 0; i < 3; ++i) {
    std::cout << a[i] << '\n';
}
```

## 155【节点：B11.2】【概念】`sizeof(array) / sizeof(array[0])` 为什么能计算内建数组元素数量？

**答案：** 当 `array` 在该表达式中仍是数组对象时，`sizeof(array)` 是整个数组所占字节数，`sizeof(array[0])` 是一个元素所占字节数，两者相除得到元素个数。该写法依赖编译期数组类型，不适用于已经转换成指针的表达式。

## 156【节点：B11.2】【代码阅读】下面函数中的计算为什么不能得到调用方数组的长度？

```cpp
void print(int a[])
{
    std::cout << sizeof(a) / sizeof(a[0]) << '\n';
}
```

**答案：** 函数形参中的 `int a[]` 会调整为 `int* a`，函数实际接收的是首元素指针，不包含原数组长度。因此 `sizeof(a)` 得到指针大小，而不是调用方数组大小；应额外传入长度，或使用数组引用、`std::array` 等保留长度信息的接口。

## 157【节点：B11.3】【概念】数组名在什么情况下通常转换为首元素指针？列出两个不发生转换的场景。

**答案：** 在多数表达式中，数组表达式会转换为指向首元素的指针。例如把数组传给普通指针形参时会发生转换。典型的不转换场景包括作为 `sizeof` 的操作数以及对整个数组使用取地址运算符 `&`；使用字符串字面量初始化字符数组时，也是在初始化数组元素而不是先把字面量转换成普通指针。

## 158【节点：B11.3】【类型辨析】给定 `int a[3];`，`a` 与 `&a` 的类型和移动步长有什么区别？

**答案：** 在会发生数组到指针转换的表达式中，`a` 转换为 `int*`，指向首元素；`&a` 的类型是 `int (*)[3]`，指向整个数组。`a + 1` 跨过一个 `int`，而 `&a + 1` 跨过整个含 3 个 `int` 的数组；二者地址数值起点可能相同，但类型和指针算术含义不同。

## 159【节点：B11.4】【最小纠错】为什么下面的赋值非法？如何完成逐元素复制？

```cpp
int a[3] = {1, 2, 3};
int b[3] = {};
b = a;
```

**答案：** 内建数组不支持整体赋值，数组名在这里也不是可赋值的左值。可以逐元素复制：

```cpp
for (int i = 0; i < 3; ++i) {
    b[i] = a[i];
}
```

若需要支持整体赋值的固定长度容器，可使用 `std::array<int, 3>`。

## 160【节点：B11.4】【判断】访问 `a[3]` 时，如果数组 `a` 只有三个元素，程序一定立即崩溃。

**答案：** 错误。该访问越界并产生未定义行为，但未定义行为不等于必然崩溃；程序可能输出看似合理的值、破坏其他对象、稍后崩溃，或者被编译器优化成意外结果。一次运行“正常”不能证明访问合法。

## 161【节点：B11.5】【代码阅读】下面二维数组在内存中的元素顺序是什么？

```cpp
int a[2][3] = {
    {1, 2, 3},
    {4, 5, 6}
};
```

**答案：** 二维数组本质是“含两个元素的数组”，其中每个元素又是“含三个 `int` 的数组”。其布局按行连续，顺序是 `1, 2, 3, 4, 5, 6`；`a[1][0]` 是第二行第一个元素 `4`。

## 162【节点：B11.5】【函数接口】写出一个接受列数为 3 的二维 `int` 数组及行数的 C++11 函数声明。

**答案：** 可以写成：

```cpp
void print_rows(const int a[][3], std::size_t rows);
```

其中第一维在形参中会调整掉，但编译器必须知道后续维度 `3`，才能计算 `a[i][j]` 的行步长。等价的指针形式是 `const int (*a)[3]`。

## 163【节点：B11.5】【判断】`int a[2][3]` 传入函数后可以安全地当作 `int**` 使用。

**答案：** 错误。二维内建数组的元素是 `int[3]`，转换后得到 `int (*)[3]`，即指向一整行的指针；`int**` 则指向一个 `int*` 对象，二者表示、类型和寻址方式都不同。强制把前者当后者使用不能修复类型不匹配，可能产生未定义行为。

## 164【节点：B11.6】【概念】`std::array<T, N>` 相比内建数组提供了哪些直接优势？

**答案：** `std::array<T, N>` 是固定长度的完整容器类型，支持整体复制和赋值、按值传参与返回，并提供 `size()`、`at()`、`front()`、`back()` 和迭代器等接口。它仍把元素直接存放在对象内部，长度 `N` 也是类型的一部分。

## 165【节点：B11.6】【代码阅读】下面代码是否合法？哪些操作不合法？

```cpp
std::array<int, 0> a;
std::cout << a.size() << '\n';
// std::cout << a.front() << '\n';
// std::cout << a[0] << '\n';
```

**答案：** 定义 `std::array<int, 0>` 合法，`a.size()` 返回 `0`。但它没有元素，因此不能调用 `front()`、`back()`，也不能访问 `a[0]`；这些操作都违反接口前置条件。零长度 `std::array` 合法，不代表存在一个可访问的“第零个元素”。

## 166【节点：B12.1】【概念】字符数组和 C 风格字符串有什么区别？

**答案：** 字符数组只是元素类型为字符的数组，不一定含终止空字符。C 风格字符串必须以 `'\0'` 终止；只有在可访问范围内存在该终止符时，才能安全交给 `std::strlen` 等按 C 字符串规则工作的函数。

## 167【节点：B12.1】【辨析】字符 `'0'`、整数 `0` 和字符 `'\0'` 有什么关系？

**答案：** `'0'` 是显示字符数字零的字符值，不是空字符；`'\0'` 是值为零的空字符，用作 C 风格字符串终止符。整数 `0` 和 `'\0'` 的数值相同，但书写 `'\0'` 更清楚地表达字符终止符含义。

## 168【节点：B12.1】【最小纠错】下面数组为什么不能表示字符串 `"abc"`？给出最小修改。

```cpp
char text[3] = {'a', 'b', 'c'};
```

**答案：** 三个位置已被可见字符占满，没有位置保存终止空字符，因此它只是字符数组，不是合法的 C 风格字符串。可改为：

```cpp
char text[4] = {'a', 'b', 'c', '\0'};
```

或更简单地写 `char text[] = "abc";`，让编译器自动包含第四个终止元素。

## 169【节点：B12.2】【类型与行为】C++11 中字符串字面量 `"abc"` 的类型和数组长度是什么？能否修改？

**答案：** `"abc"` 的类型是 `const char[4]`，四个元素依次为 `'a'`、`'b'`、`'c'`、`'\0'`。字符串字面量不可修改；试图通过去除 `const` 后写入会产生未定义行为。

## 170【节点：B12.2】【判断】两个内容相同的字符串字面量一定拥有不同地址，所以可以用地址判断它们是否内容相等。

**答案：** 错误。实现可以合并相同字符串字面量，也可以不合并，程序不能依赖二者地址相同或不同。比较 C 字符串内容应使用内容比较函数，比较 `std::string` 内容可使用其比较运算符。

## 171【节点：B12.3】【代码阅读】下面程序输出的两个数分别是多少？

```cpp
#include <cstring>
#include <iostream>

int main()
{
    char text[6] = "abc";
    std::cout << sizeof(text) << ' ' << std::strlen(text) << '\n';
}
```

**答案：** 输出 `6 3`。`sizeof(text)` 得到整个数组的容量，即 6 个 `char`；`std::strlen(text)` 从首元素开始查找到第一个 `'\0'`，可见字符长度为 3。数组剩余位置的零值仍计入 `sizeof`，但不计入字符串长度。

## 172【节点：B12.3】【代码阅读】下面 `sizeof` 与 `strlen` 的结果为什么不同？

```cpp
char text[] = {'a', '\0', 'b', '\0'};
```

**答案：** `sizeof(text)` 为 `4`，因为数组含四个 `char` 元素；`std::strlen(text)` 为 `1`，因为它在索引 1 的第一个 `'\0'` 处停止。C 风格字符串接口无法把后面的 `'b'` 当作同一个字符串的可见内容。

## 173【节点：B12.3】【判断】对任何 `char` 数组调用 `std::strlen` 都是安全的，因为函数能自动知道数组容量。

**答案：** 错误。`strlen` 只接收指针，不知道数组容量，会一直寻找 `'\0'`；若可访问范围内没有终止符，它会越界读取并产生未定义行为。调用前必须保证输入是正确终止的 C 风格字符串。

## 174【节点：B12.4】【概念】`std::string` 相比 C 风格字符串解决了哪些基础管理问题？

**答案：** `std::string` 自动管理字符存储和长度，支持复制、赋值、拼接、比较、查找等值语义操作，不要求调用者手工计算缓冲区容量。它仍可能重新分配内部存储，因此指向其内部字符的旧指针不一定长期有效。

## 175【节点：B12.4】【接口辨析】`size()`、`length()`、`empty()` 和 `clear()` 分别表示什么？

**答案：** 对 `std::string`，`size()` 和 `length()` 都返回当前字符元素数量；`empty()` 判断该数量是否为零；`clear()` 删除全部字符，使字符串为空。`clear()` 改变逻辑长度，但不保证把容量释放回系统。

## 176【节点：B12.4】【代码阅读】下面代码最终得到什么？

```cpp
std::string a = "hello";
std::string b = a.substr(1, 3);
std::size_t pos = a.find("ll");
std::string c = b + "!";
```

**答案：** `b` 为 `"ell"`，因为从索引 1 开始取最多 3 个字符；`pos` 为 `2`，即子串 `"ll"` 的起始位置；`c` 为 `"ell!"`。若 `find` 未找到目标，会返回 `std::string::npos`，不能假定总能得到有效下标。

## 177【节点：B12.4】【判断】`s[0]`、`s.at(0)`、`s.front()` 和 `s.back()` 对空字符串都安全。

**答案：** 错误。空字符串没有首尾字符元素，不能调用 `front()` 或 `back()`；`at(0)` 会检测越界并抛出 `std::out_of_range`。空字符串的 `s[0]` 就是 `s[s.size()]`：C++11 允许读取这里的特殊终止空字符值，但不得通过返回的引用进行任何修改。它不是字符串中的普通元素；一般元素访问仍应满足下标小于 `size()`。

## 178【节点：B12.5】【概念】`std::string` 的 `size`、`capacity`、`reserve` 和 `resize` 有什么区别？

**答案：** `size()` 是当前字符数，`capacity()` 是当前无需重新分配即可容纳的字符数；`reserve(n)` 请求至少一定容量而不创建新字符，`resize(n)` 则实际改变字符数量。把 `reserve` 当作增加可访问字符是典型越界错误。

## 179【节点：B12.5、B12.6】【指针有效性】为什么不应长期保存 `s.c_str()` 或 `s.data()` 返回的指针？

**答案：** C++11 保证 `std::string` 字符连续，`c_str()` 返回 NUL 终止的只读字符序列，`data()` 在 C++11 中也返回 `const char*`。对字符串执行可能重新分配或改变内容的操作后，旧指针可能失效；C++11 不能通过 `data()` 取得可写字符缓冲区，可写 `data()` 是 C++17 接口。

## 180【节点：B12.6、B12.7】【综合】`std::string s("a\0b", 3);` 的 `size()` 是多少？传给只识别 C 字符串的接口会看到什么？这是否说明 `char` 等于一个用户字符？

**答案：** `s.size()` 为 `3`，内容是 `'a'`、`'\0'`、`'b'`，因为带长度的构造允许内嵌空字符。若把 `s.c_str()` 传给只扫描到首个 `'\0'` 的 C 接口，该接口通常只看到 `"a"`。此外，一个 `char` 表示一个字节单位，不保证等于一个 UTF-8 用户字符；字节数、编码单元数和用户看到的字符数不能混为一谈。
