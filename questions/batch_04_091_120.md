### 091. 什么是表达式？【B6.1 表达式基础】

请说明表达式由什么构成，以及一个表达式至少具有哪两个基本属性。

**答案：** 表达式由操作数和运算符组成；操作数可以是名字、字面量或其他表达式。每个符合语言规则的表达式都有类型，并且在求值后产生一个值或表示一个对象、函数等实体。例如，`2 + 3` 的两个整数字面量是操作数，`+` 是运算符；该表达式的类型是 `int`，求值得到 `5`。有些表达式还会产生副作用，但“有副作用”不是表达式成立的必要条件。

### 092. 什么是表达式的副作用？【B6.1 表达式基础】

“表达式求值”是否只表示计算出一个数值？请解释副作用的含义。

**答案：** 不一定。表达式求值除了得到值，还可能改变程序中可观察的状态，这种改变称为副作用。例如，赋值表达式 `x = 7` 不仅有求值结果，还会修改对象 `x`；对输入输出状态的改变也可以是副作用。因此，理解表达式时要同时关注它产生的值、类型以及是否改变了状态。

### 093. 括号一定会规定先算哪一边吗？【B6.1 表达式基础】

判断：“只要给子表达式加上括号，就一定能规定各操作数在运行时的求值先后顺序。”

**答案：** 错误。括号可以改变或明确表达式的分组方式，例如把 `a + b * c` 改为 `(a + b) * c`；但分组方式不等于运行时求值顺序。C++11 中许多运算符的不同操作数之间没有固定求值顺序，因此不能把括号当成通用的“先求值”命令。

### 094. `x` 和 `42` 分别属于什么值类别？【B6.2 基础值类别】

已知：

```cpp
int x = 0;
```

在表达式中单独写 `x` 和单独写 `42`，它们通常分别是什么值类别？

**答案：** 表达式 `x` 是左值（lvalue），因为它表示一个有身份、可以定位的对象。整数字面量表达式 `42` 是纯右值（prvalue），它直接产生一个值，而不是表示一个可通过该表达式持续定位的对象。值类别描述的是表达式，不是变量声明本身。

### 095. 五个值类别术语之间是什么关系？【B6.2 基础值类别】

请说明 `lvalue`、`xvalue`、`prvalue`、`glvalue` 和 `rvalue` 的基本包含关系。

**答案：** C++11 的三个基础值类别是左值（lvalue）、将亡值（xvalue）和纯右值（prvalue）。泛左值（glvalue）包括左值和将亡值，表示具有身份、能够定位到某个实体的表达式；右值（rvalue）包括纯右值和将亡值，通常与临时值或可复用资源的对象有关。将亡值同时属于泛左值和右值，但左值不属于右值，纯右值也不属于泛左值。

### 096. `const` 对象的名字一定是右值吗？【B6.2 基础值类别】

判断下面表达式 `c` 的值类别：

```cpp
const int c = 3;
```

**答案：** `c` 是左值，不是右值。`const` 表示不能通过这个名字修改对象，并不决定表达式的值类别；表达式 `c` 仍然表示一个有身份、可定位的对象。因此，“常量等于右值”和“变量等于左值”都是不准确的说法。

### 097. 无符号整数减到零以下会发生什么？【B6.4 有符号与无符号算术】

设 `u` 是值为 `0` 的无符号整数，执行 `u = u - 1;` 后是否会得到数学意义上的 `-1`？

**答案：** 不会。具有 `N` 个值位的无符号整数按 `2^N` 取模运算，因此从 `0` 减去 `1` 会得到该无符号类型能够表示的最大值，即 `2^N - 1`。这里不能假定这个最大值固定为某个机器相关数字；标准并不保证所有实现的 `unsigned int` 都具有相同位数。

### 098. 有符号整数溢出会自然回绕吗？【B6.4 有符号与无符号算术】

判断：“当 `int` 的最大值再加 `1` 时，结果一定回到最小值。”

**答案：** 错误。有符号整数运算的数学结果如果超出其类型可表示范围，就会产生未定义行为。C++11 不保证它回绕到最小值，也不保证崩溃或给出诊断；一次运行看似回绕也不能证明程序正确。需要回绕语义时，应在设计上明确采用合适的无符号类型，并仍要检查算法是否符合需求。

### 099. 为什么负数与无符号数混合比较容易出错？【B6.4 有符号与无符号算术】

阅读下面代码并判断 `less` 的值：

```cpp
int s = -1;
unsigned int u = 1;
bool less = s < u;
```

**答案：** `less` 为 `false`。比较前会进行通常算术转换；在这里，`s` 被转换为 `unsigned int`，负值 `-1` 转换后成为该无符号类型的最大值。最大无符号值并不小于 `1`，所以比较结果与直觉中的数学比较不同。这正是混合有符号与无符号运算需要格外谨慎的原因。

### 100. 无符号倒序为什么可能无法在零以下停止？【B6.4 有符号与无符号算术】

某算法让一个无符号计数值不断减 `1`，并打算在它“小于零”时停止。这个设计有什么问题？

**答案：** 无符号类型不能表示负值，因此无符号计数值永远不会小于零。它在 `0` 上再减 `1` 时会按模运算变成该类型的最大值，算法可能因此继续运行。安全做法是重新设计停止条件，使其在执行导致回绕的减法之前结束，而不是等待无符号值变为负数。

### 101. 位运算与逻辑运算有什么区别？【B6.6 位运算】

请比较按位与 `&` 和逻辑与 `&&` 的含义。

**答案：** `&` 对整数操作数的对应二进制位逐位运算：只有两个对应位都为 `1`，结果位才为 `1`。`&&` 则把操作数按逻辑真假处理，并产生布尔结果；它不是逐位组合整数。二者的符号、结果含义和求值规则都不同，不能因为都含有“与”的含义就互换使用。

### 102. 基本位运算会得到什么结果？【B6.6 位运算】

设：

```cpp
unsigned int a = 6; // 二进制 110
unsigned int b = 3; // 二进制 011
```

分别求 `a & b`、`a | b` 和 `a ^ b` 的值。

**答案：** `a & b` 为 `2`，因为 `110 & 011` 得到 `010`；`a | b` 为 `7`，因为 `110 | 011` 得到 `111`；`a ^ b` 为 `5`，因为异或在对应位不同时产生 `1`，所以 `110 ^ 011` 得到 `101`。这些运算是在各二进制位上独立进行的。

### 103. 按位取反 `~` 做什么？【B6.6 位运算】

若 `u` 的类型是 `unsigned int` 且值为 `0`，表达式 `~u` 的结果有什么特征？

**答案：** `~` 会翻转操作数的每一位，因此 `~u` 的所有有效位都为 `1`，结果就是 `unsigned int` 的最大值。具体十进制数取决于该实现中 `unsigned int` 的位数，不能固定假设为某个常见值。使用无符号整数能使这种位模式及其算术含义更清楚。

### 104. 移位操作有哪些必须检查的边界？【B6.6 位运算】

判断表达式 `value << count` 或 `value >> count` 时，至少要检查哪些与 C++11 相关的风险？

**答案：** 移位数量 `count` 不能为负，也不能大于或等于提升后左操作数类型的位数，否则行为未定义。若提升后的左操作数是负的有符号值，左移行为未定义；负有符号整数的右移结果在 C++11 中由实现规定。即使移位数量合法，非负有符号值的左移仍受结果可表示规则限制。因此，位运算通常优先使用无符号整数，并在移位前验证数量范围。

### 105. 连续赋值如何分组？【B6.7 赋值与复合赋值】

下面语句为什么会让 `a` 和 `b` 都得到 `5`？

```cpp
int a = 0;
int b = 0;
a = b = 5;
```

**答案：** 赋值运算符具有右结合性，所以最后一行按 `a = (b = 5)` 分组。内层赋值先使 `b` 取得 `5`；赋值表达式本身也有结果，外层赋值再把相应的值赋给 `a`，因此二者最终都是 `5`。右结合性说明的是分组方式，不能推广成所有表达式都有固定的操作数求值顺序。

### 106. 复合赋值表达式有什么作用？【B6.7 赋值与复合赋值】

若 `x` 原来为 `4`，执行 `x += 3;` 后发生了什么？它与普通赋值有什么共同点？

**答案：** `x += 3` 计算加法并把结果写回 `x`，所以 `x` 变为 `7`。与 `=` 一样，`+=` 形成的赋值表达式本身也有结果，并产生修改左操作数的副作用。`-=`、`*=`、`/=`、`%=` 以及位复合赋值运算符采用相同的“运算后写回”形式。

### 107. 给一段连续修改补括号能保证安全吗？【B6.7 赋值与复合赋值】

判断：“赋值表达式有结果，因此只要用括号安排赋值表达式的嵌套，就能规定所有子表达式的实际求值顺序。”

**答案：** 错误。括号和赋值运算符的结合性可以确定语法分组，赋值表达式也确实有结果；但这些事实不等于所有操作数之间都有固定求值顺序。若多个子表达式依赖对同一对象的副作用顺序，必须另外检查 C++11 的求值顺序规则，最稳妥的做法通常是拆成多个完整表达式。

### 108. 优先级回答的是什么问题？【B6.9 优先级、结合性与求值顺序】

表达式 `a + b * c` 在没有括号时如何分组？这说明了哪一条规则？

**答案：** 乘法运算符的优先级高于加法运算符，所以表达式按 `a + (b * c)` 分组。这是优先级规则，它只回答不同运算符如何构成表达式，并不单独回答运行时先求 `a`、`b` 还是 `c`。

### 109. 结合性回答的是什么问题？【B6.9 优先级、结合性与求值顺序】

为什么 `a = b = 5` 按 `a = (b = 5)` 而不是 `(a = b) = 5` 分组？

**答案：** 因为两个 `=` 具有相同优先级，而赋值运算符是右结合的。结合性只在同优先级运算符相邻时决定分组方向。它和优先级一样属于语法分组规则，不能用来推断任意操作数在运行时的求值先后。

### 110. 求值顺序与优先级为什么不能混为一谈？【B6.9 优先级、结合性与求值顺序】

请分别说明“优先级”和“求值顺序”解决什么问题。

**答案：** 优先级决定运算符和操作数如何分组，也就是表达式的语法结构；求值顺序决定程序运行时先计算哪个操作数，以及不同副作用之间是否存在先后关系。一个子表达式在语法上嵌套得更深，并不普遍意味着它一定先被求值。C++11 中多数操作数之间没有固定求值顺序，涉及副作用时尤其不能靠优先级猜测。

### 111. C++11 会按从左到右求函数实参吗？【B6.9 优先级、结合性与求值顺序】

判断：“函数调用写成 `f(first, second)`，C++11 就保证先求值 `first`，再求值 `second`。”

**答案：** 错误。C++11 不规定不同函数实参之间固定按从左到右或从右到左求值。因此，如果两个实参通过副作用相互依赖，程序不能假定某一个先完成。应先在独立的完整表达式中计算所需值，再把已经得到的结果作为实参传入。

### 112. 为什么 `(i++) + (++i)` 仍然有问题？【B6.9 优先级、结合性与求值顺序】

阅读：

```cpp
int i = 0;
int result = (i++) + (++i);
```

括号是否让这段代码在 ISO C++11 中具有确定结果？

**答案：** 没有。这两个子表达式在同一个完整表达式中都修改标量对象 `i`，而 `+` 的两个操作数之间没有满足要求的先后排序。在 C++11 中，这种对同一标量对象进行未排序的多次修改会产生未定义行为。括号只明确分组，不能修复求值顺序问题。

### 113. 怎样最小化修正依赖副作用顺序的表达式？【B6.9 优先级、结合性与求值顺序】

若一段复杂表达式的多个部分都会修改同一个对象，而且结果依赖修改顺序，最可靠的基础修正原则是什么？

**答案：** 把各次修改拆成多个独立的完整表达式，并按需要的先后次序逐句执行；随后再使用已经保存的值进行计算。完整表达式之间存在明确的先后边界，这样不需要依赖 C++11 未规定的操作数求值顺序。单纯增加括号、调整空格或凭某次编译器运行结果判断都不能解决问题。

### 114. `sizeof` 会执行它的操作数吗？【B6.10 `sizeof` 等运算符】

阅读下面的 ISO C++11 代码：

```cpp
int i = 1;
sizeof(i = 5);
```

执行后 `i` 的值是多少？

**答案：** `i` 仍为 `1`。在这里，`sizeof` 只取得其操作数表达式类型所对应的大小，操作数 `i = 5` 不会被求值，因此赋值副作用不会发生。`sizeof` 的结果类型是 `std::size_t`；具体大小仍取决于被查询的类型和实现。

### 115. 数组、指针的 `sizeof` 与 `alignof` 有何区别？【B6.10 `sizeof` 等运算符】

阅读：

```cpp
int a[4] = {};
int* p = a;
```

`sizeof a`、`sizeof p` 和 `alignof(int)` 分别查询什么？

**答案：** `sizeof a` 查询整个数组对象占用的字节数，因此等于 `4 * sizeof(int)`；`sizeof p` 查询指针对象 `p` 本身的大小，而不是数组大小，也不能由此得到元素个数。`alignof(int)` 查询 `int` 类型的对齐要求。大小、元素数量和对齐是不同概念，不能根据某台机器上的具体数值推广到所有 ISO C++11 实现。

### 116. 什么是整数提升？【B7.1 整数提升】

`bool`、`char`、`signed char`、`unsigned char` 和 `short` 参与基础算术运算时，结果类型为什么不一定仍是原类型？

**答案：** 这些较小的整数类型在许多运算中会先进行整数提升。如果 `int` 能表示原类型的所有值，就提升为 `int`；否则提升为 `unsigned int`。因此，两个 `short` 或两个字符类型操作数参与运算时，实际计算类型通常是 `int` 或 `unsigned int`，结果类型不能仅按原操作数的写法猜测。

### 117. 什么是通常算术转换？【B7.2 通常算术转换】

两个不同算术类型的操作数共同参与运算时，语言为什么要先寻找公共计算类型？

**答案：** 为了让一个二元算术运算在统一类型中进行，C++ 会应用通常算术转换，把操作数转换到共同的计算类型。这个过程包括必要的整数提升，并根据整数的有符号性、等级以及是否含有浮点类型来确定公共类型。它解释了有符号与无符号混合时负数可能变成大无符号值，以及整数与浮点数混合时通常会在浮点类型中计算。

### 118. 整数与浮点数互相转换一定保持数值吗？【B7.3 整数与浮点转换】

判断：“只要转换语法合法，整数和浮点数互相转换就一定精确保留原数值。”

**答案：** 错误。浮点数转换为整数时会舍弃小数部分；截去小数后的值若不能由目标整数类型表示，行为未定义。整数转换为浮点数时，即使目标范围足够，也可能因为浮点精度有限而不能精确表示原整数。因此，“能够转换”和“数值完全不变”是两件不同的事。

### 119. C++ 的几种显式转换各表示什么意图？【B7.5 C++ 显式转换】

请简述 `static_cast`、`const_cast` 和 `reinterpret_cast` 的用途，并说明为什么不应把强制转换当成安全保证。

**答案：** `static_cast` 用于语言明确允许、可在类型系统中表达的显式转换，例如在可表示范围内把浮点值显式转换为整数；`const_cast` 专门改变类型的 `const` 或其他 cv 限定，若借此修改一个原本就是常量的对象，行为仍然未定义；`reinterpret_cast` 表达低层次的表示或指针解释，风险较高。任何强制转换都不会自动修复越界、对象生命周期或对齐问题。形如 `(Type)expression` 的 C 风格强制转换还会隐藏实际采用了哪类转换，因此 C++ 接口中应优先使用能表达明确意图的 C++ 转换写法。

### 120. 循环在控制流中起什么作用？【B8.4 循环】

请用零基础语言说明“循环”这一控制流概念。

**答案：** 循环让程序按照给定的重复规则，多次执行同一段语句，而不是把相同语句手工写许多遍。理解循环时要明确三件事：哪些语句会被重复、每次重复之间哪些状态发生变化，以及在什么条件下停止。若停止规则永远无法满足，循环就不会按预期结束；若重复次数边界写错，则会产生逻辑错误。
