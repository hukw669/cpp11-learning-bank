## 061.【B4.1 声明与定义】`int x;` 与 `extern int x;` 都是定义吗？

**答案：** `int x;` 既是声明也是定义，它为对象 `x` 提供存储；`extern int x;` 通常只是声明，表示 `x` 的定义位于程序的其他位置，并不在此处提供存储。在命名空间作用域，若带有初始化器，例如 `extern int x = 1;`，该声明同时构成定义。`extern` 不是“永远只声明”的同义词。

## 062.【B4.1 声明与定义】同一作用域内可以多次声明同一个对象吗？可以多次写 `int x;` 吗？

**答案：** 同一实体可以有多个彼此相容的声明，例如对具有外部链接的对象多次写相容的 `extern int x;`。但 `int x;` 本身是定义，在同一作用域再次写 `int x;` 会形成重复定义，程序非良构。判断是否允许重复时，关键不是“看起来像声明”，而是每条声明是否同时构成定义，以及它们是否指向同一实体并且类型相容。

## 063.【B4.2 初始化与赋值】初始化和赋值有什么根本区别？

**答案：** 初始化发生在对象生命期开始时，用给定信息建立对象的初始状态；赋值发生在对象已经存在之后，用新值修改其状态。初始化不是“第一次赋值”，因为执行初始化时还没有一个已经存在、等待被赋值的该对象。二者可能使用不同的语言规则，对类类型而言还可能调用不同的函数。

```cpp
int value = 3; // 初始化
value = 5;     // 赋值
```

## 064.【B4.2 初始化与赋值】“先构造对象再赋值”和“构造时直接初始化”一定等价吗？

**答案：** 不一定。构造时初始化会直接用初始化器建立对象；先构造再赋值则先产生一个初始状态，随后再执行一次赋值操作。即使对某些基本类型最终数值相同，这两个过程的含义仍不同；对类类型，它们可能调用不同的构造函数和赋值函数，成本与可用性也可能不同。因此应把所需初始值直接用于初始化，而不是把初始化解释为稍后的第一次赋值。

## 065.【B4.3 C++11 初始化形式】对基本类型而言，`int x;` 与 `int x{};` 有什么重要区别？

**答案：** `int x;` 对局部自动存储期对象进行默认初始化，此时 `x` 可能具有不确定值，不能在赋值前安全读取。`int x{};` 进行列表形式的值初始化，使 `x` 得到零。空花括号常用于明确请求一个安全的初始值，但具体初始化效果仍取决于对象类型和所在语境。

## 066.【B4.3 C++11 初始化形式】直接初始化、拷贝初始化和列表初始化分别怎样书写？

**答案：** 对 `int` 可分别写成 `int a(3);`、`int b = 3;` 和 `int c{3};`。前两种分别称为直接初始化和拷贝初始化，花括号形式是列表初始化；`int d = {3};` 也是列表初始化的一种写法。它们对简单整数常得到相同数值，但对类类型可能选择不同的构造函数，列表初始化还具有禁止部分窄化转换的额外规则。

## 067.【B4.3 C++11 初始化形式】什么是聚合初始化？下面的 `p` 如何获得初始值？

```cpp
struct Point {
    int x;
    int y;
};

Point p{2, 5};
```

**答案：** 聚合是可按成员或元素顺序直接提供初始值的一类简单复合对象；聚合初始化使用花括号中的初始化器依次初始化其成员或元素。这里的 `Point` 是聚合，`p.x` 被初始化为 `2`，`p.y` 被初始化为 `5`。聚合初始化属于列表初始化，但并非所有使用花括号的对象都是聚合；类类型还可能通过构造函数处理列表初始化。

## 068.【B4.4 未初始化对象】下面的函数能否安全返回 `value`？

```cpp
int read_value() {
    int value;
    return value;
}
```

**答案：** 不能。`value` 是自动存储期的基本类型对象，默认初始化后具有不确定值；在给它一个确定值之前读取它，通常会导致未定义行为。已经为对象分配了存储并不等于对象中已有可安全读取的值。应写成 `int value{};`，或在所有可能到达 `return` 的路径上先为它提供确定值。

## 069.【B4.4 未初始化对象】静态存储期的基本类型对象也会像普通局部变量一样留下不确定值吗？

**答案：** 不会采用同样的规则。静态存储期对象在其他初始化发生前会先进行零初始化，因此没有显式初始化器的静态存储期整数对象会从零开始。普通局部自动存储期整数 `int x;` 则可能具有不确定值。对象写法相似并不代表存储期和初始化结果相同。

```cpp
int global_count; // 静态存储期，先零初始化

void example() {
    static int saved_count; // 静态存储期，先零初始化
    int local_count;        // 自动存储期，值不确定
}
```

## 070.【B4.5 列表初始化与窄化】下面哪一行符合 ISO C++11？为什么？

```cpp
int a = 3.5;
int b{3.5};
```

**答案：** 第一行符合语法，会把 `3.5` 转换为 `int`，小数部分被舍弃，因此 `a` 得到 `3`。第二行不符合要求，因为列表初始化把浮点数转换为整数视为窄化转换并禁止，编译器必须诊断。花括号的这一限制可以在对象创建处尽早暴露可能丢失信息的转换。

## 071.【B4.5 列表初始化与窄化】为什么下面第一行不合法，而第二行合法？

```cpp
int n = 42;
unsigned char a{n};
unsigned char b{42};
```

**答案：** `a{n}` 从非常量的 `int` 值转换为不能表示所有 `int` 值的 `unsigned char`，属于列表初始化禁止的窄化转换；编译器不能因为本次运行中 `n` 恰好是 `42` 就放行。`b{42}` 的初始化器是编译期常量，而且数值 `42` 保证可由 `unsigned char` 表示，因此属于可证明安全的例外。类似地，浮点到整数始终属于这里禁止的窄化，而非常量整数到浮点也会触发窄化规则。

## 072.【B4.6 `auto`】`auto` 如何确定变量类型？能否写 `auto value;`？

**答案：** `auto` 根据初始化器在编译期推导变量的静态类型，例如 `auto value = 3;` 推导为 `int`。普通变量声明若没有初始化器，就没有可供推导的信息，因此 `auto value;` 非良构。`auto` 不是“运行时随值变化的动态类型”：类型一旦在编译时推导完成，该变量仍具有固定的 C++ 类型。

## 073.【B4.6 `auto`】普通 `auto` 会保留初始化器的引用和顶层 `const` 吗？

```cpp
const int original = 7;
const int& alias = original;
auto a = original;
auto b = alias;
```

**答案：** 这里 `a` 和 `b` 都被推导为普通 `int`。未配合 `&` 的普通 `auto` 按值形成新对象，通常丢弃初始化器类型中的引用和顶层 `const`。因此修改 `a` 或 `b` 不会修改 `original`，它们也不是只读对象。

## 074.【B4.6 `auto`】`auto&` 与 `const auto&` 分别会得到什么？

```cpp
int value = 1;
const int fixed = 2;
auto& a = value;
auto& b = fixed;
const auto& c = value;
```

**答案：** `a` 的类型是 `int&`，可通过 `a` 修改 `value`；`b` 的类型是 `const int&`，因为推导会保留被引用对象的底层 `const`；`c` 也是 `const int&`，声明中的 `const` 使它只能通过该引用读取 `value`。写出 `&` 表示需要引用绑定，而不是按值创建副本。

## 075.【B4.6 `auto`】`auto&&` 是否永远推导为右值引用？

```cpp
int value = 1;
auto&& a = value;
auto&& b = 3;
```

**答案：** 不是。在这种发生类型推导的声明中，`auto&&` 会根据初始化器的值类别调整：用已有的具名对象 `value` 初始化时，`a` 的声明类型折叠为 `int&`；用临时计算结果 `3` 初始化时，`b` 的声明类型为 `int&&`。因此不能只看两个 `&` 就断定最终一定是右值引用。

## 076.【B4.7 `decltype`】`decltype(name)` 对未加括号的名字采用什么规则？

**答案：** 当操作数是未加括号的名字表达式时，`decltype` 直接得到该实体声明时的类型，包括原声明中的引用和 `const`。例如 `const int n = 1;` 使 `decltype(n)` 为 `const int`；若 `int& r = x;`，则 `decltype(r)` 为 `int&`。这是一条针对未加括号名字的特殊规则，不按普通表达式值类别重新推导。

## 077.【B4.7 `decltype`】为什么 `decltype(value)` 与 `decltype((value))` 可能不同？

```cpp
int value = 1;
decltype(value) copy = 2;
decltype((value)) alias = value;
```

**答案：** `decltype(value)` 命中未加括号名字的特殊规则，所以结果是 `int`，`copy` 是独立整数对象。额外括号使 `decltype((value))` 按一般表达式规则处理；`(value)` 是左值表达式，因此结果是 `int&`，`alias` 引用原来的 `value`。括号在这里不只是视觉分组，它改变了 `decltype` 所采用的规则。

## 078.【B4.7 `decltype`】一般表达式的值类别怎样影响 `decltype` 的结果？

**答案：** 对不属于“未加括号名字”特殊情况的一般表达式，若表达式是左值，`decltype` 得到 `T&`；若是将亡值，得到 `T&&`；若是纯右值，得到 `T`。例如 `decltype((value))` 对具名整数左值产生 `int&`，而 `decltype(3)` 对整数纯右值产生 `int`。值类别描述表达式怎样指代或产生对象，不等同于“变量”与“常量”。

## 079.【B4.7 `decltype`】`decltype` 会执行其操作数吗？

```cpp
int i = 0;
decltype(i++) result = 0;
```

**答案：** 一般不会。`decltype` 的操作数处于不求值语境，编译器会分析 `i++` 的类型和值类别，但不会实际执行自增，所以这段代码结束后 `i` 仍为 `0`。不过操作数仍必须是语法和类型上合法、能够被分析的表达式；“不执行”不等于可以随意写非法代码。

## 080.【B4.7 `decltype`】`auto` 与 `decltype` 的类型推导规则相同吗？

**答案：** 不相同。`auto` 从初始化器推导声明中的占位类型，普通按值 `auto` 通常去掉引用和顶层 `const`；`decltype` 检查给定名字或表达式，并按其特殊名字规则或值类别规则保留、生成引用与 `const`。例如对 `const int n = 1;`，`auto x = n;` 得到 `int`，而 `decltype(n) y = 2;` 得到 `const int`。

## 081.【B4.8 类型别名】`typedef` 与 C++11 的 `using` 怎样定义类型别名？

**答案：** 两者都能给已有类型提供另一个名称。`typedef unsigned long Count;` 把 `Count` 定义为 `unsigned long` 的别名；C++11 可写成 `using Count = unsigned long;`，含义相同。`using` 的书写顺序通常更接近“别名等于某类型”，复杂类型也更容易阅读。

## 082.【B4.8 类型别名】类型别名会创建一个与原类型互不兼容的新类型吗？

**答案：** 不会。别名只是已有类型的另一个名字，不创建新的独立类型。若 `using Count = unsigned long;`，那么 `Count` 对象就是 `unsigned long` 对象，二者之间不存在需要转换的新类型边界。C++11 还支持模板别名，但那是在模板语境中按参数生成类型别名，仍不改变“别名不是新类型”这一点。

## 083.【B5.1 `const` 对象】`const` 是否表示对象一定在编译期产生？`const` 对象还有存储和生命周期吗？

**答案：** `const` 表示初始化完成后不能通过该只读名字修改对象，不保证初始化一定在编译期完成。一个 `const` 对象仍有明确的类型，也可能占用存储，并与其他对象一样具有生命周期。例如它可以用运行期才得到的值初始化；此时它在初始化后只读，但该值并未因此变成编译期常量。

## 084.【B5.2 顶层与底层 `const`】什么是顶层 `const` 和底层 `const`？按值参数上的顶层 `const` 有何影响？

**答案：** 顶层 `const` 修饰对象本身，例如 `const int value` 表示 `value` 本身只读；底层 `const` 位于指针或引用所指向的类型中，例如 `const int* p` 表示不能通过 `p` 修改所指整数。按值传参会创建一个独立的参数对象，因此参数声明上的顶层 `const` 不属于函数类型：`void f(int);` 与 `void f(const int);` 声明的是同一个函数。不过在函数定义内部，把该参数写成 `const int` 会阻止函数体修改这份局部副本。

## 085.【B5.3 指针与 `const`】怎样解释 `const int*`、`int* const` 和 `const int* const`？

**答案：** 从变量名向外读最可靠：`const int* p` 是“指向只读 `int` 的可修改指针”，可以让 `p` 改指别处，但不能写 `*p`；`int* const p` 是“指向可修改 `int` 的只读指针”，不能让 `p` 改指别处，但可以写 `*p`；`const int* const p` 的指针本身和通过它访问的整数都只读。指针的顶层 `const` 与所指对象类型中的底层 `const` 必须分开判断。

## 086.【B5.3 指针与 `const`】可修改对象的指针能否转换为指向常量的指针？反向转换为何不被隐式允许？

```cpp
int value = 1;
int* writable = &value;
const int* readable = writable;
```

**答案：** 所示转换合法，因为它只限制了通过新指针 `readable` 可进行的操作，并没有使原对象突然变成常量。反向把 `const int*` 隐式转换为 `int*` 会丢掉底层 `const`，从而可能通过新指针修改本应只读的对象，所以不被允许。即使以后使用显式手段去除 `const`，若原对象本来就定义为常量，再试图修改它会导致未定义行为。

## 087.【B5.4 引用与 `const`】`const T&` 和非常量左值引用分别能绑定到哪些对象？

```cpp
int value = 1;
const int fixed = 2;

int& a = value;
const int& b = value;
const int& c = fixed;
const int& d = 3;
```

**答案：** 非常量左值引用 `int&` 通常只能绑定到类型相容、可修改的左值，所以 `a` 合法，但不能用同样的 `int&` 绑定 `fixed` 或临时结果 `3`。`const int&` 可以绑定到可修改对象、常量对象以及这里的临时整数，因此 `b`、`c`、`d` 都合法。通过这些常量引用不能修改所绑定的整数。

## 088.【B5.4 引用与 `const`】常量引用是否保证被引用对象永远不会变化？它能否延长临时对象的生命周期？

**答案：** 常量引用只限制“通过这条引用”进行修改，不保证同一对象不能通过其他可修改名字变化。例如 `int x = 1; const int& r = x; x = 2;` 合法，此后通过 `r` 读到的是 `2`。在 `const int& r = 3;` 这样的直接绑定中，为绑定引用而产生的临时对象会把生命周期延长到局部引用 `r` 的生命周期结束；但不能把这一规则无条件推广到所有间接返回、成员引用或其他绑定场景。

## 089.【B5.5 `constexpr`】`constexpr` 对象与普通 `const` 对象有什么区别？

**答案：** `constexpr` 对象必须具有可用于该语境的常量表达式初始化器，并且对象本身也是 `const`；在满足相应规则时，它可参与要求编译期常量的语境。普通 `const` 只保证初始化后不能通过该名字修改，其初始值可以到运行期才得到。因此“编译期常量”一定具有比“只读”更严格的要求。

```cpp
constexpr int size = 8; // 初始化器是常量表达式
const int copy = size;   // 只读；这里的值同样是 8
```

## 090.【B5.5 `constexpr`】C++11 的 `constexpr` 函数只能在编译期调用吗？函数体有什么重要限制？

**答案：** 不是。`constexpr` 函数在参数和调用语境满足常量表达式要求时可以参与编译期计算，也可以像普通函数一样在运行期调用。C++11 对这类函数体限制很严格：用于计算的函数体本质上采用单一 `return` 表达式，不能套用后续标准允许的普通多语句写法，例如在函数体中加入局部变量、循环和逐步赋值。

```cpp
constexpr int square(int x) { return x * x; }

constexpr int a = square(4);
int n = 5;
int b = square(n);
```
