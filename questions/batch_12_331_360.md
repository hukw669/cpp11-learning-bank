# C++11 第十二批题目（331–360）

## 331【节点：R7.2】【控制块】为什么不能从同一个裸指针分别构造两个 `shared_ptr`？

**答案：** 从裸指针构造 `shared_ptr` 通常会新建控制块。假定 `Widget` 已完整定义，下面片段中的 `first`、`second` 互不知道对方，最终会各自删除同一对象：

```cpp
Widget* raw = new Widget;
std::shared_ptr<Widget> first(raw);
std::shared_ptr<Widget> second(raw); // 错误的第二控制块
```

正确方式是 `std::shared_ptr<Widget> second = first;`，让它们共享原控制块。`get()` 地址相等也不能证明控制块相同，尤其还存在别名构造。

## 332【节点：R7.3】【创建】`make_shared` 相比直接构造 `shared_ptr` 通常有什么优点？

**答案：** C++11 可写 `auto owner = std::make_shared<T>(args);`。它直接构造目标并返回共享所有者，避免裸指针中间状态，通常还能把对象和控制块合并为一次分配，改善效率和异常安全。边界是：对象析构后若仍有 `weak_ptr`，合并分配的整块存储可能等到弱引用也消失才释放；需要特殊删除器或特殊分配策略时可能选择直接构造。

## 333【节点：R7.4】【观察】`weak_ptr::lock()` 为什么比先 `expired()` 再使用更安全？

**答案：** `weak_ptr` 不增加强引用计数，也不能直接解引用。假定 `T` 和 `observer` 已定义，以下函数体片段用 `lock()` 原子地尝试取得一个临时 `shared_ptr`：

```cpp
if (std::shared_ptr<T> value = observer.lock())
    value->use();
```

成功后 `value` 在整个块内保持对象存活；失败返回空。先调用 `expired()` 后再另行取得对象，中间可能最后一个所有者消失，形成检查与使用之间的竞态，因此通常直接 `lock()`。

## 334【节点：R7.5】【所有权图】两个对象互相保存 `shared_ptr` 为什么会泄漏？

**答案：** 引用计数不会检查对象图中的环。如果 A 强拥有 B，B 又强拥有 A，外部所有者全部消失后，两边强计数仍至少为一，析构永远不发生。应先确定真实所有权方向，例如父对象用 `shared_ptr<Child>` 拥有孩子，孩子用 `weak_ptr<Parent>` 观察父对象。不是“随便把一侧改弱”，而是让非拥有关系使用弱引用。

## 335【节点：R7.6】【前置条件】什么时候可以调用 `shared_from_this()`？

**答案：** 类要公开继承 `std::enable_shared_from_this<T>`，并且该对象已经由合适的 `shared_ptr` 控制块管理，成员函数中才可调用 `shared_from_this()` 取得共享同一控制块的新所有者。尚未交给 `shared_ptr` 时调用，在 C++11 会抛 `std::bad_weak_ptr`，所以构造函数阶段通常不能用。它也不能阻止外部错误地从同一裸指针建立第二控制块。

## 336【节点：R7.7】【控制块扩展】`shared_ptr` 的自定义删除器和别名构造分别改变什么？

**答案：** 自定义删除器规定最后一个强所有者消失时如何释放控制块所拥有的资源，例如 `std::shared_ptr<FILE>(raw, close_file)`；删除器保存在控制块中，不像 `unique_ptr` 的删除器那样成为智能指针类型的一部分。别名构造则让“参与访问的保存指针”和“负责销毁的拥有对象”不同。假定 `Record` 已定义且含有公开的 `int id` 成员，别名构造片段可写：

```cpp
std::shared_ptr<Record> whole = std::make_shared<Record>();
std::shared_ptr<int> id(whole, &whole->id);
```

`id.get()` 指向成员 `id`，但它共享 `whole` 的控制块并让整个 `Record` 存活；最后删除的是控制块原来拥有的对象，不是简单 `delete &whole->id`。别名保存指针甚至可以为空而控制块仍拥有对象，因此比较 `get()` 或只做布尔测试都不能完整判断所有权身份。

## 337【节点：R8.1】【接口选择】值、`unique_ptr`、`shared_ptr`、`weak_ptr`、引用和裸指针通常各表达什么？

**答案：** 值成员表示对象直接拥有其值；`unique_ptr<T>` 表示唯一所有者；`shared_ptr<T>` 表示多个共同所有者；`weak_ptr<T>` 观察一个共享对象但不延长其生命；`T&` 常表示非空借用，`T*` 常表示可空借用。类型只能表达结构，接口还应说明借用有效期。不能因为“多处会访问”就使用共享所有权，多处借用并不等于多方负责销毁。

## 338【节点：R8.2】【设计】Rule of Zero 是否表示类不能拥有资源？

**答案：** 不是。它表示业务类不直接操纵底层资源，而通过有正确生命周期语义的成员拥有资源。包含 `<string>` 与 `<vector>` 后，类定义片段可写：

```cpp
class Document {
    std::string text_;
    std::vector<int> marks_;
};
```

类仍然拥有字符串和动态序列，但无需手写析构、复制和移动。成员自动组合出正确行为。若业务上禁止复制或类是多态基类，仍可明确 `= delete`、`= default` 或声明虚析构。

## 339【节点：R8.3】【工程组织】PImpl 使用 `unique_ptr<Impl>` 时，为什么析构函数常放在 `.cpp`？

**答案：** 头文件只前向声明 `class Impl;` 并保存 `std::unique_ptr<Impl> impl_;`，此时 `Impl` 尚不完整。删除目标需要在相应实例化位置看到完整类型，所以外围类析构通常只在头文件声明，在定义了 `Impl` 的 `.cpp` 中写 `Widget::~Widget() = default;`。PImpl 能减少编译依赖并隐藏实现，但带来分配和间接访问成本；`unique_ptr` 也会让外围类默认不可复制，需要值语义时应实现深复制。

## 340【节点：R8.4】【工厂】工厂函数返回值、`unique_ptr` 和 `shared_ptr` 分别传达什么？

**答案：** 普通值返回适合具有自然值语义的小对象；`std::unique_ptr<Base> make()` 表示把唯一所有权交给调用者，并可隐藏具体派生类型；`std::shared_ptr<Base> make()` 表示从创建之初就需要共同所有权。不能返回局部自动对象的地址或引用。返回多态基类智能指针时，基类应具有正确的虚析构函数。

## 341【节点：R9】【底层】placement `new` 分配内存吗？完整使用过程是什么？

**答案：** placement `new` 不分配存储，只在已有、大小和对齐都合适的地址上构造对象。下面是严格 C++11 的底层示意片段，假定 `T` 已完整定义且 `args` 是匹配的构造实参：

```cpp
#include <new>

void* raw = ::operator new(sizeof(T));
T* object = new (raw) T(args);
object->~T();
::operator delete(raw);
```

真实实现还要处理构造异常、对齐和重复使用存储的生命期规则。它适合容器或内存池实现，普通业务代码应使用 RAII 和标准容器。

## 342【节点：T1.1】【概念】模板和预处理宏的根本区别是什么？

**答案：** 模板是编译器理解的类型化蓝图，可生成一族函数或类：

```cpp
template<class T>
T maximum(T a, T b) { return a < b ? b : a; }
```

调用 `maximum(2, 3)` 形成 `int` 版本。编译器会解析类型、检查操作并参与重载决议。宏只在预处理阶段替换记号，不理解类型。模板选择发生在编译期，也不是运行时根据对象类型自动分派。

## 343【节点：T1.2】【分类】C++11 模板形参有哪三类？

**答案：** 类型形参如 `template<class T>`，代表一种类型；非类型形参如 `template<std::size_t N>`，代表符合限制的编译期值；模板模板形参如 `template<template<class> class C>`，接收另一个模板。`class T` 与 `typename T` 在类型形参位置等价。C++11 非类型形参不能直接用浮点值；`template<auto N>` 是 C++17。

## 344【节点：T1.3】【辨析】隐式实例化、显式实例化定义和 `extern template` 分别是什么？

**答案：** 使用 `Box<int> object;` 或调用函数模板会按需要触发隐式实例化。`template class Box<int>;` 是显式实例化定义，要求当前翻译单元生成该实例；`extern template class Box<int>;` 是显式实例化声明，抑制此处通常的隐式生成，并应由另一个翻译单元提供定义。实例化使用原模板生成版本，不是提供不同实现的特化。

## 345【节点：T1.4】【链接】为什么模板定义通常放在头文件？

**答案：** 调用方实例化模板时必须看到完整定义，仅看到 `template<class T> T add(T,T);` 的声明通常不够。不同 `.cpp` 独立编译，所以通用模板常把定义放进带保护的头文件，或由头文件包含 `.tpp` 实现文件。若定义放 `.cpp`，就要为允许的具体类型集中做显式实例化，否则新类型使用可能链接失败。满足规则且内容一致的模板定义可出现在多个翻译单元。

## 346【节点：T2.1】【语法】函数模板的最小结构是什么？

**答案：** 模板头写在函数声明或定义前：

```cpp
template<typename T>
T square(T value)
{
    return value * value;
}
```

`typename` 可换成 `class`，这里不要求 `T` 必须是类，`int` 也可以。只有实例化到具体类型时，函数体中依赖 `T` 的乘法才按该类型检查；模板并不会让不支持乘法的类型自动合法。

## 347【节点：T2.2】【推导】下面两次调用中 `T` 分别是什么？

```cpp
template<class T> void by_value(T) {}
template<class T> void by_reference(T&) {}

void test()
{
    const int number = 3;
    by_value(number);
    by_reference(number);
}
```

**答案：** 按值调用中顶层 `const` 被忽略，`T` 推导为 `int`；引用形参保留所引用对象的限定，`T` 推导为 `const int`，最终形参为 `const int&`。同一个 `T` 从多个形参位置推导时必须一致，所以 `larger(1, 2.0)` 通常因分别得到 `int` 和 `double` 而失败，推导不会任意插入转换来凑结果。

## 348【节点：T2.3】【用途】什么时候需要显式写函数模板实参？

**答案：** 当某个模板形参无法由函数实参推导，或调用者要指定目标类型时，写 `name<Type>(arguments...)`。下面是只展示接口与调用的片段，函数定义未展开：

```cpp
template<class Result, class Left, class Right>
Result sum_as(Left a, Right b);

double value = sum_as<double>(2, 3);
```

`Result` 显式为 `double`，后两项继续推导。只能从模板形参列表前面开始显式提供，不能任意跳过中间项。显式类型可允许正常转换，但不会修复函数体本身不合法的操作。

## 349【节点：T2.4】【重载】普通函数与函数模板同名时，普通函数是否永远优先？

**答案：** 不是。模板先推导并形成可行候选，再与普通函数按匹配等级共同进行重载决议。只有匹配质量不差等条件满足时，普通函数才可能在规则中胜出。例如 `void print(int)` 与 `template<class T> void print(T)` 面对整数时通常选普通函数，面对 `double` 则模板精确匹配。两个模板都可行时还会比较哪个形参模式更专门，如 `T*` 版本可胜过通用 `T` 版本。

## 350【节点：T3.1】【概念】`Box<int>` 与 `Box<double>` 是同一个类型吗？

**答案：** 不是。类模板描述一族类，模板实参成为类型身份的一部分：

```cpp
template<class T>
class Box { T value_; };

Box<int> integers;
Box<double> reals;
```

两者是不同完整类型，不能无条件互相赋值。C++11 在类模板外创建对象时通常必须写模板实参；`Box box(1);` 所依赖的类模板实参推导是 C++17 功能。

## 351【节点：T3.2】【语法】类模板成员在类外怎样定义？

**答案：** 必须重复模板头，并在限定类名中写模板实参：

```cpp
template<class T>
class Box {
public:
    const T& get() const;
private:
    T value_;
};

template<class T>
const T& Box<T>::get() const
{
    return value_;
}
```

漏写 `template<class T>` 或把 `Box<T>::` 写成不完整的 `Box::` 都不正确。模板成员定义通常仍需在实例化点可见。

## 352【节点：T3.3】【友元】类模板中的友元为什么必须明确授权范围？

**答案：** 可以只为每个当前实例生成对应非模板友元，也可以把一整个函数模板声明为友元。例如：

```cpp
template<class T>
class Vault {
    template<class U>
    friend void inspect(const Vault<U>&);
private:
    T value_;
};
```

这会授权 `inspect<U>` 模板的一族实例，范围可能很宽。友元不传递、不继承、不自动互为友元；写法稍有不同可能声明不同实体，因此应只授予实际需要的最小权限。

## 353【节点：T3.4】【辨析】默认模板实参与默认函数实参有什么不同？

**答案：** 默认模板实参补充类型或编译期值，例如 `template<class T, class Compare = std::less<T>> class Store;`，`Store<int>` 自动采用比较器类型。默认函数实参则补充一次运行时函数调用的参数。类模板中出现默认模板实参后，后续形参通常也需有默认值（参数包例外）；函数模板后续形参还可能由函数实参推导。同一模板形参的默认值不能在同一作用域重复给出。

## 354【节点：T3.5】【别名】别名模板会创建一种全新的类型吗？

**答案：** 不会。`template<class T> using Vec = std::vector<T>;` 只是给类型表达式另一种拼写，`Vec<int>` 与 `std::vector<int>` 完全是同一类型。别名模板适合固定或缩短复杂模板参数，但不能为别名本身增加成员，也不能在 C++11 中显式特化或偏特化。若需要按类型选择实现，应特化辅助类模板，再取其嵌套类型。

## 355【节点：T4.1】【特化】类模板全特化的语法和作用是什么？

**答案：** 先有主模板，再为完全确定的实参提供独立定义：

```cpp
template<class T>
struct Name { static const char* get() { return "other"; } };

template<>
struct Name<int> { static const char* get() { return "int"; } };
```

`Name<int>` 使用特化，其余类型使用主模板。全特化不是继承主模板成员，必须自己提供需要的完整接口；还应在第一次导致该实例隐式实例化的使用之前声明。

## 356【节点：T4.2】【规则】为什么函数模板不能偏特化？

**答案：** C++11 只允许类模板偏特化，例如：

```cpp
template<class T> struct Kind;
template<class T> struct Kind<T*> { };
```

它匹配所有指针类型。函数模板没有相应偏特化语法；需要针对参数形状时使用重载：`template<class T> void inspect(T*);`。别名模板也不能偏特化。多个类偏特化同时匹配时必须能选出更专门者，否则会二义。

## 357【节点：T4.3】【辨析】函数模板重载和显式特化在选择机制上有什么不同？

**答案：** 重载新增一个独立候选，例如 `template<class T> void f(T*);`；显式特化写 `template<> void f<int>(int);`，是某个既有主模板的专门实现。调用时先在普通函数和主模板之间完成重载决议，选定主模板后才使用它对应的特化。因此“特化一定比重载优先”不成立。针对一类形状通常用重载，针对一个完全确定的模板实例才考虑全特化。

## 358【节点：T4.4】【工程】`extern template` 怎样与显式实例化定义配合？

**答案：** 头文件可写 `extern template int twice<int>(int);`，告诉使用方不要在本翻译单元通常地隐式生成；一个源文件包含完整定义后写 `template int twice<int>(int);`，集中生成实例。漏掉后者可能链接失败。它只控制指定实参的生成位置，不改变算法；显式实例化采用主模板实现，而显式特化提供另一份实现。

## 359【节点：T5.1】【查找】模板中的依赖名和非依赖名何时查找？

**答案：** 含义不依赖模板实参的名字通常必须在模板定义处就能找到；依赖于 `T` 的成员或调用要等实例化时结合具体类型继续判断。例如 `fixed();` 是非依赖调用，定义模板前应声明 `fixed`；`value.work();` 的成员取决于 `value` 的依赖类型。依赖调用还可能在实例化时通过实参相关查找找到与类型所在命名空间相关的函数。

## 360【节点：T5.2】【语法】为什么 `typename Container::const_iterator` 前面需要 `typename`？

**答案：** `Container` 依赖模板实参，编译器在模板定义阶段不能确定 `Container::const_iterator` 是类型还是静态值。在以 `Container` 为模板形参、`values` 为相应对象的模板函数体片段中写：

```cpp
typename Container::const_iterator position = values.begin();
```

明确告诉解析器它是类型。模板头中的 `template<typename T>` 是声明类型形参，作用不同。`typename` 只能消除类型歧义，不能把实际的值成员强迫变成类型。
