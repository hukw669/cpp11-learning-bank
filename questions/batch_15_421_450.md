# C++11 第十五批题目（421–450）

## 421【节点：S5.4】【扩容机制】`vector` 扩容时为什么有时移动旧元素，有时复制旧元素？

**答案：** 扩容要取得一块更大的连续存储，并在新位置重新构造所有现有元素。若元素的移动构造保证不抛异常，移动既高效又便于保持异常安全；若移动可能抛而复制可用，实现通常选择复制，从而在失败时保留旧容器不变。类型不可复制时只能尝试移动，异常保证可能相应减弱。一次搬迁是线性成本，但一系列尾插仍可具有摊销常数复杂度。增长倍率不由 ISO C++11 固定；发生重分配后，所有旧迭代器、指针、引用和旧 `end()` 都失效。

## 422【节点：S5.5】【边界访问】`vector::operator[]` 与 `at()` 越界时有什么根本区别？

**答案：** 两者都以常数时间返回元素引用，但契约不同。`values[i]` 要求调用者先保证 `i < values.size()`，越界属于未定义行为；`values.at(i)` 会检查范围，越界时抛出 `std::out_of_range`。`at()` 有常量和非常量重载，也不能修复已经失效的容器引用。`front()`、`back()` 同样不负责检查空容器，调用前必须先确认非空。

## 423【节点：S6.1】【容器分类】`set`、`multiset`、`map` 和 `multimap` 分别保存什么？

**答案：** `set` 保存唯一键，`multiset` 保存可重复的等价键；`map` 保存唯一键到映射值的关系，`multimap` 允许同一等价键对应多个元素。它们都按比较器维护顺序，迭代时看到的是排序次序，迭代器属于双向而非随机访问。查找和插入通常为 `O(log n)`，但标准不要求实现一定使用某一种平衡树。唯一性依据比较等价，不一定依据 `operator==`。

## 424【节点：S6.2】【键等价】有序容器怎样判断两个键“等价”？为什么比较器必须稳定？

**答案：** 给定比较器 `comp`，当 `!comp(a,b) && !comp(b,a)` 时，两键属于同一等价类。唯一键容器至多保存其中一个，即使 `a == b` 的结果与此不同。比较器必须满足严格弱序，并在容器使用期间保持一致语义；若对象进入容器后，外部修改了影响排序的状态，容器内部顺序就可能被破坏。比较操作本身的成本也会乘到对数次比较上。

## 425【节点：S6.3】【插入结果】`set::insert` 返回的 `pair<iterator,bool>` 两部分各表示什么？

**答案：** 对唯一键 `set`，`iterator` 指向容器中与待插键等价的元素；`bool` 为真表示本次确实插入了新元素，为假表示等价键已存在。重复插入不会覆盖已有键。迭代器把元素当作不可修改的键，避免破坏排序；若要改变键，应擦除旧值再插入新值。插入通常不使现有元素位置失效，擦除只使被删元素的位置失效。

## 426【节点：S6.4】【键值元素】为什么 `map<Key,T>::value_type` 的键是 `const Key`，值却能修改？

**答案：** `map` 元素类型是 `std::pair<const Key,T>`。容器的树形顺序依赖键，所以禁止通过迭代器改写 `first`；`second` 不参与键位置，可以正常修改。遍历顺序由键的比较器决定，不由插入先后决定。成员 `find`、插入和删除通常是对数复杂度；插入其他键保持已有元素的迭代器和引用有效，擦除只影响被删元素。

## 427【节点：S6.5】【隐式插入】为什么只想查询时不应随便使用 `map[key]`？

**答案：** `operator[]` 返回对应映射值的可修改引用。键存在时直接返回；键不存在时，它会插入该键，并对映射值执行值初始化，再返回新值的引用。例如 `++counts["apple"]` 会先建立值为零的整数再递增。于是单纯读取 `table[key]` 也可能改变容器大小，而且该接口不能用于 `const map`。不希望插入时使用 `find`，若键必须存在可使用 `at`。

## 428【节点：S6.6】【必有键访问】`map::at` 找不到键时怎样表现？它会不会插入？

**答案：** `at(key)` 只查找已有元素，不会创建新键。成功时，非常量容器返回 `T&`，常量容器返回 `const T&`；失败时抛 `std::out_of_range`。查找通常为 `O(log n)`，无论成功或失败都不会使迭代器失效。若缺少键是日常分支而不是异常情况，先用 `find` 与 `end()` 比较通常更直观。`map::at` 已属于 C++11。

## 429【节点：S6.7】【重复键】`map::insert` 或 `emplace` 遇到已有等价键时会覆盖旧值吗？

**答案：** 不会。对 `map`、`set` 这类唯一键容器，单元素插入返回 `pair<iterator,bool>`；等价键已存在时，布尔值为假，迭代器指向旧元素，旧映射值保持不变。`emplace` 在容器内部用参数构造候选元素，但不保证重复键时完全不发生候选构造。`try_emplace` 和 `insert_or_assign` 是 C++17，严格 C++11 需要检查插入结果，再按业务决定是否修改 `second`。

## 430【节点：S6.8】【范围查找】`find`、`count`、`lower_bound`、`upper_bound` 和 `equal_range` 各返回什么？

**答案：** `find(k)` 返回某个等价元素或 `end()`；`count(k)` 返回等价元素数量，唯一键容器只可能是零或一；`lower_bound(k)` 返回第一个“不排在 `k` 之前”的位置；`upper_bound(k)` 返回第一个“排在 `k` 之后”的位置；`equal_range(k)` 返回前两者组成的半开区间。定位边界通常是对数复杂度，遍历全部匹配项还要加上匹配数量。C++20 才加入成员 `contains`，C++11 应使用这些接口。

## 431【节点：S7.1】【无序类型】四种无序关联容器与有序版本的主要区别是什么？

**答案：** C++11 提供 `unordered_set`、`unordered_multiset`、`unordered_map` 和 `unordered_multimap`，分别表示唯一键集合、可重复键集合、唯一键映射和可重复键映射。它们用哈希值组织桶，不保证按键或插入顺序遍历。分布合理时查找、插入和删除平均为常数复杂度，最坏可能退化为线性；“unordered”既不表示随机顺序，也不保证每次操作都是 `O(1)`。需要排序遍历或范围查询时通常选择有序容器。

## 432【节点：S7.2】【哈希契约】若 `key_equal(a,b)` 为真，`hasher(a)` 与 `hasher(b)` 必须满足什么关系？

**答案：** 二者必须产生相同哈希值，否则等价键可能被放进不同桶，查找逻辑失去前置条件。反方向不要求成立：不同键可以有相同哈希值，容器会在桶中继续用相等谓词区分，这叫碰撞。哈希器和相等器都必须在键位于容器期间保持稳定；哈希值不是加密摘要，也不应当成跨实现、跨运行稳定的持久化编号。

## 433【节点：S7.3】【桶规划】`load_factor`、`max_load_factor`、`reserve` 和 `rehash` 在无序容器中分别是什么意思？

**答案：** `load_factor()` 近似等于 `size()/bucket_count()`，表示平均每桶元素数；`max_load_factor()` 设置自动重哈希时参考的上限。`reserve(n)` 的参数是预计元素数量，容器据此请求足够桶数；`rehash(n)` 的参数是最少桶数。二者都可能选择比请求更合适的实际桶数并使迭代器失效。无序容器的 `reserve` 不创建元素，也不是 `vector` 那种连续元素容量；负载阈值过低浪费内存，过高则可能增加碰撞。

## 434【节点：S7.4】【确定性输出】可以依赖 `unordered_map` 的当前遍历顺序做文件格式或测试快照吗？

**答案：** 不可以。遍历次序受桶数量、哈希器、实现策略和当前元素影响；ISO C++11 不保证插入顺序、键排序或跨运行一致。插入、删除、`reserve`、`rehash` 后次序还可能变化，即使元素集合没变。本机几次输出相同也不形成标准保证。若序列化、网络协议、界面或测试需要确定顺序，应把元素复制到顺序容器后按明确规则排序，或直接使用合适的有序容器。

## 435【节点：S7.5】【失效辨析】无序容器 rehash 后，迭代器、元素指针和引用分别是否有效？

**答案：** rehash 重新组织桶，因此所有迭代器失效，旧迭代器不能再解引用、递增或比较；但 C++11 保证指向仍存在元素的指针和引用不会仅因 rehash 失效。插入只有在触发 rehash 时才使全部迭代器失效；删除则使被删元素的迭代器、指针和引用失效。`reserve` 也可能触发 rehash。保存的引用仍有效并不意味着旧迭代器有效，也不意味着元素仍在原桶或原遍历位置。

## 436【节点：S7.6】【自定义键】让自定义结构体成为 `unordered_map` 的键，需要提供哪些操作？

**答案：** 需要哈希器和相等谓词。哈希器接受 `const Key&` 并返回 `std::size_t`，相等谓词接受两个 `const Key&` 并返回布尔值；相等为真的两个键必须具有相同哈希。C++11 可把二者作为模板实参：

```cpp
#include <cstddef>
#include <unordered_map>

struct Key { int group; int id; };
struct Hash {
    std::size_t operator()(const Key& k) const
    {
        return static_cast<std::size_t>(k.group) * 131u
             + static_cast<std::size_t>(k.id);
    }
};
struct Equal {
    bool operator()(const Key& a, const Key& b) const
    {
        return a.group == b.group && a.id == b.id;
    }
};

int main()
{
    std::unordered_map<Key, int, Hash, Equal> values;
    values[Key{1, 2}] = 9;
    return values.find(Key{1, 2})->second == 9 ? 0 : 1;
}
```

键入容器后，不能通过别名修改影响哈希或相等的字段。

## 437【节点：S8.1】【栈适配器】`stack::top()` 与 `pop()` 为什么要分开调用？

**答案：** `stack` 表示后进先出。`top()` 返回顶部元素引用但不删除；`pop()` 删除顶部元素并返回 `void`。若要取得元素，应先检查非空，再复制或移动 `top()`，最后 `pop()`。分离取值和删除可以避免“删除已经发生，但返回值复制或移动随后抛异常”的含混状态。默认底层容器是 `deque`，适配器不提供迭代器或任意位置访问；空栈调用 `top()` 或 `pop()` 不满足前置条件。

## 438【节点：S8.2】【队列适配器】`queue` 的 `front`、`back`、`push` 和 `pop` 怎样体现 FIFO？

**答案：** `push` 或 `emplace` 把新元素加入队尾；`front()` 观察最早进入的元素，`back()` 观察最近加入的元素；`pop()` 删除队首且返回 `void`，因此形成先进先出。默认底层容器是 `deque`，默认操作通常为常数复杂度。`queue` 故意不提供下标、任意插入和迭代接口；空队列上调用 `front`、`back` 或 `pop` 不合法。需要按优先级而非时间顺序处理时，应选 `priority_queue`。

## 439【节点：S8.3】【优先级】默认 `priority_queue<int>` 为什么让最大值位于 `top()`？怎样建立最小优先队列？

**答案：** 默认比较器是 `std::less<int>`，适配器把“最高优先级”的元素放在顶部，因此最大值先出。最小优先队列可写：

```cpp
#include <functional>
#include <queue>
#include <vector>

int main()
{
    std::priority_queue<int, std::vector<int>, std::greater<int> > values;
    values.push(3);
    values.push(1);
    values.push(8);
    return values.top() == 1 ? 0 : 1;
}
```

`top()` 通常是常数复杂度，`push`、`emplace`、`pop` 通常是对数复杂度。比较器必须满足严格弱序；适配器不支持遍历或查找任意元素。

## 440【节点：S9.1】【失效概念】“迭代器失效”是否只表示不能解引用？`end()` 会不会失效？

**答案：** 失效表示标准不再保证该位置对象有效，不仅不能解引用，也不能继续递增、比较或传给要求有效迭代器的接口。保存的地址数值碰巧没变也不能恢复保证。`end()` 本身也是迭代器，元素范围变化后同样可能失效，并非永久稳定的特殊值。插入、删除、扩容、rehash、移动和销毁都可能造成失效，且迭代器、指针和引用的规则可能不同，必须按具体容器与操作判断。

## 441【节点：S9.2】【连续存储】没有发生重分配时，`vector` 的插入和擦除会使哪些位置失效？

**答案：** 若插入没有重分配，插入点之前的迭代器、指针和引用保持有效，插入点及之后的位置以及旧 `end()` 失效，因为元素可能向后移动。若发生重分配，则全部位置失效。`erase` 不扩大容量，但会把后继元素前移，因此删除点及之后的位置失效，删除点之前保持有效。`reserve` 只有在实际增大容量时让全部位置失效，也不能保护插入点之后的位置。

## 442【节点：S9.3】【节点稳定性】`list` 插入和 `splice` 后，已有元素迭代器通常怎样变化？

**答案：** 链表插入新节点通常不移动已有节点，所以其他元素的迭代器和引用保持有效；擦除只使被删节点相关位置失效。满足前置条件的 `list::splice` 会把节点转移到目标链表，指向被转移元素的迭代器和引用继续有效，并在操作后指向目标容器中的同一元素。它不能再当作源容器位置使用。分配器、区间归属和同一链表内插入位置等前置条件仍必须满足；容器销毁会结束全部节点生命。

## 443【节点：S9.4】【关联节点】向 `map` 插入新键会不会使旧元素迭代器失效？遍历删除应怎样写？

**答案：** `set`、`map` 及其 multi 版本使用独立节点；插入和 `emplace` 不使已有元素的迭代器与引用失效，删除只使被删元素相关位置失效。C++11 的关联容器 `erase(iterator)` 返回后继迭代器，安全循环是：

```cpp
for (std::map<int, int>::iterator it = values.begin();
     it != values.end(); )
{
    if (it->second == 0)
        it = values.erase(it);
    else
        ++it;
}
```

这是函数体片段，假定 `values` 已定义。被删除元素的指针和引用同样悬空；节点存储不意味着所有位置永久安全。

## 444【节点：S9.5】【无序位置】无序容器插入、rehash 和删除的失效规则怎样区分？

**答案：** 插入若未触发 rehash，已有迭代器、引用和指针保持有效；若插入触发 rehash，或显式调用 `rehash`、可能重哈希的 `reserve`，所有迭代器失效，但仍存在元素的引用和指针保持有效；删除只使指向被删元素的三类位置失效。预先 `reserve` 只能降低一段增长中的重哈希概率，不是永久承诺。rehash 后应通过 `find` 等重新取得迭代器。

## 445【节点：S9.6】【循环纠错】为什么 `erase(it)` 后不能无条件执行 `++it`？

**答案：** 删除当前元素后，原 `it` 通常已经失效，对它递增属于错误。多数 C++11 标准容器的相应 `erase` 返回删除位置之后的新有效迭代器，应写：

```cpp
#include <vector>

int main()
{
    std::vector<int> values{1, 2, 3, 4};
    for (std::vector<int>::iterator it = values.begin();
         it != values.end(); )
    {
        if (*it % 2 == 0)
            it = values.erase(it);
        else
            ++it;
    }
    return values.size() == 2 && values[0] == 1 && values[1] == 3 ? 0 : 1;
}
```

`forward_list` 没有当前节点的前驱链接，需维护前驱并使用 `erase_after`。

## 446【节点：S10.1】【算法模型】为什么标准算法通常接收迭代器，而不是直接接收容器？

**答案：** 迭代器把数据结构与处理逻辑分离。同一个 `algorithm(first,last,...)` 能作用于内建数组、`vector`、链表等，只要迭代器能力满足该算法要求。算法通常看不到容器对象，也无法自行扩大输出容器；向空目标写入时要先创建足够元素，或传 `back_inserter` 等插入迭代器。通用性不代表任意组合都合法，例如 `sort` 需要随机访问，不能直接用于 `list` 的双向迭代器。

## 447【节点：S10.2】【查询算法】`find_if` 找不到元素时返回什么？空区间上的三个逻辑量词结果是什么？

**答案：** `find` 和 `find_if` 找不到时返回调用时传入的 `last`，必须先与它比较，不能直接解引用。`count`、`count_if` 返回匹配数量，其类型是迭代器差值类型，不必然等于 `size_t`。对空区间，`all_of` 返回真、`any_of` 返回假、`none_of` 返回真。通用查询通常线性扫描；对 `map`、`set` 按键查询应优先用成员 `find` 或 `count`，以利用对数复杂度的内部结构。

## 448【节点：S10.3】【输出范围】`copy` 或 `transform` 向普通输出迭代器写入时，目标需要满足什么条件？

**答案：** 目标区间必须已经含有足够多的有效元素；空 `vector` 的 `begin()` 没有可写元素，不能靠算法自动扩容。可以先按所需数量构造或 `resize` 目标，也可以用 `back_inserter`。`copy_if` 只输出满足条件的项，`transform` 写入运算结果，`fill` 用同一值覆盖现有范围，`generate` 反复调用生成器。输入输出重叠还要遵守具体算法契约；向右覆盖同一区间时通常考虑 `copy_backward`，不能凭小测试假定 `copy` 安全。

## 449【节点：S10.4】【排序查询】`lower_bound`、`upper_bound` 和 `binary_search` 对输入范围有什么前置条件？

**答案：** 范围必须已经按与查询相容的比较规则排序或分区，否则结果不可靠。`lower_bound` 返回第一个“不小于目标”的位置，`upper_bound` 返回第一个“大于目标”的位置，两者界定等价范围；`binary_search` 只报告是否存在。`sort` 不保持等价元素原相对顺序，`stable_sort` 保持。排序需要随机访问迭代器；二分只做对数次比较，但在非随机访问迭代器上移动位置仍可能是线性，关联容器应优先使用成员边界查询。

## 450【节点：S10.5】【逻辑删除】为什么 `std::remove` 调用后容器的 `size()` 不变？

**答案：** `std::remove` 只接收迭代器，不知道容器对象，无法调用容器的删除接口。它把保留元素移动到区间前部，并返回新的逻辑结尾；该位置到旧结尾仍是容器中的元素，只是其具体值不应再依赖。真正缩小 `vector`、`deque` 或 `string` 要使用 erase-remove：

```cpp
#include <algorithm>
#include <vector>

int main()
{
    std::vector<int> values{1, 2, 3, 2, 4};
    values.erase(std::remove(values.begin(), values.end(), 2),
                 values.end());
    return values.size() == 3 && values[1] == 3 ? 0 : 1;
}
```

链表有会真正删除节点的成员 `remove`，关联容器则应使用成员 `erase`。
