# C++11 第十三批题目（361–390）

## 361【节点：T5.3】【语法】依赖对象调用成员模板时为什么要写 `.template`？

**答案：** 模板定义阶段不知道依赖类型是否真的把某名字声明成模板，解析器也可能把 `<` 当成小于号。因此要明确消歧：

```cpp
template<class T>
int convert(const T& service)
{
    return service.template as<int>();
}
```

指针形式写 `pointer->template as<int>()`，依赖类型的静态成员模板可写 `T::template action<int>()`。这里的 `template` 只帮助解析，不会创建模板，也不表示立刻实例化；最终类型仍必须提供匹配成员。

## 362【节点：T5.4】【查找】为什么类模板派生自依赖基类后，直接写基类成员名可能报错？

**答案：** `Base<T>` 的具体成员取决于 `T`，非限定名字查找在模板定义阶段通常不会自动进入依赖基类。假定 `Base<T>` 已定义并提供相应成员，派生类模板片段应把名字变成依赖名：

```cpp
template<class T>
struct Derived : Base<T> {
    void run()
    {
        this->log();
        this->count = 1;
    }
};
```

也可用 `Base<T>::member` 明确限定，或 `using Base<T>::log;` 引入重载。`this->` 可保留成员调用与虚派发语义，明确的基类限定调用则指定基类版本。

## 363【节点：T6.1】【概念】类型参数包、非类型参数包和函数参数包怎样声明？

**答案：** 类型包写 `template<class... Types>`，非类型包可写 `template<int... Values>`，函数参数包写在函数形参中，例如 `void accept(Args... args)`。`sizeof...(Types)` 或 `sizeof...(args)` 在编译期得到元素数量，不是字节数。参数包可为空，所以实现必须处理零参数情形；包表示一组项目，不能直接放在要求单个类型或单个表达式的位置。

## 364【节点：T6.2】【展开】`pattern...` 的省略号究竟展开什么？

**答案：** 它复制包含参数包的整个模式，而不是简单文本替换。例如：

```cpp
template<class... Args>
void relay(const Args&... args)
{
    target(args...);
}
```

若有三个实参，调用形成三个逗号分隔参数。`std::forward<Args>(args)...` 则对每一对类型和对象应用转发模式。多个包在同一个模式中逐项展开时通常要求长度一致。展开进函数实参列表不会额外规定 C++11 的实参求值顺序。

## 365【节点：T6.3】【递归】C++11 怎样在没有折叠表达式时逐个处理参数包？

**答案：** 常见做法是一个零参数终止重载，加一个处理首项并递归剩余项的模板：

```cpp
void print() {}

template<class First, class... Rest>
void print(const First& first, const Rest&... rest)
{
    use(first);
    print(rest...);
}
```

终止重载应在递归模板定义处可见。漏掉终止条件会出现无匹配调用或实例化过深。`(use(args), ...)` 是 C++17 折叠表达式，不能用于严格 C++11。

## 366【节点：T6.4】【构造陷阱】可变参数转发构造函数为什么可能“吞掉”复制构造？

**答案：** `template<class T> Person(T&& value)` 是匹配范围很广的转发构造。面对非常量 `Person` 左值时，它可推导 `T=Person&`，匹配可能优于接受 `const Person&` 的复制构造，随后却试图用 `Person` 构造成员而报错。解决方案可以是提供少量明确重载，或用 C++11 `enable_if` 与 `decay` 排除 `Person` 自身。所谓“万能构造”并不表示任何实参最终都合法。

## 367【节点：T7.1】【判断】哪些 `T&&` 是转发引用？

**答案：** 只有形参恰为本次调用正在推导的、无 `const/volatile` 限定的模板形参 `T&&` 才是转发引用：

```cpp
template<class T>
void relay(T&& value);
```

它可接收左值和右值。固定的 `Widget&&`、`const T&&`，以及类模板中由类实例已经确定的 `T&&` 都不是。发生类型推导的 `auto&&` 也遵循相似规则。必须同时检查写法和推导上下文，不能只数两个 `&`。

## 368【节点：T7.2】【规则】四种引用组合怎样折叠？

**答案：** 模板替换或别名可能间接形成引用的引用。规则是：

- `T& &`、`T& &&`、`T&& &` 都折叠为 `T&`；
- 只有 `T&& &&` 折叠为 `T&&`。

因此转发引用接收左值时，`T` 可推导为 `int&`，代入 `T&&` 后折叠成 `int&`。引用折叠只决定类型，不执行移动，也不自动保证被引用对象的生存期。

## 369【节点：T7.3】【辨析】转发模板中为什么用 `std::forward<T>(value)` 而不是直接传 `value`？

**答案：** 即使形参类型是右值引用，只要在函数体中使用具名变量 `value`，表达式就是左值。`std::forward<T>` 根据原始推导结果恢复调用方的左值或右值性质。下面是已包含 `<utility>`、且 `target` 已声明的函数模板片段：

```cpp
template<class T>
void wrapper(T&& value)
{
    target(std::forward<T>(value));
}
```

直接传 `value` 会一律按左值；`std::move(value)` 又会一律转成右值，可能误移动调用方传入的左值。`forward` 自身仍只是转换，真正移动由下游重载完成。

## 370【节点：T7.4】【边界】为什么 `relay({1,2,3})`、`relay(overloaded)` 和 `relay(bitfield)` 可能失败？

**答案：** 完美转发只能保留已经成功推导出的类型和值类别。裸花括号列表没有普通、唯一的表达式类型，可先声明 `std::initializer_list<int> values{1,2,3};`；重载函数名代表一个集合，需转换到明确函数指针类型；位域不能绑定所需的普通非常量引用，可先复制到普通变量。空指针应传 `nullptr`，因为 `0` 会被推导并转发成 `int`，不会自动保留“想表达指针”的意图。

## 371【节点：T8.1】【工具】查询型和变换型类型萃取分别怎样使用？

**答案：** 包含 `<type_traits>`。查询型通过 `value` 得到编译期布尔结果，例如 `std::is_integral<T>::value`、`std::is_same<A,B>::value`；变换型通过嵌套 `type` 得到类型，例如 `typename std::remove_reference<T>::type`、`typename std::decay<T>::type`。C++11 需要这些完整写法；`remove_reference_t` 是 C++14，`is_same_v` 是 C++17。

## 372【节点：T8.2】【编译期检查】C++11 的 `static_assert` 完整语法是什么？

**答案：** 必须写两个参数。下面是语法模板，不是可直接编译的完整语句：

```cpp
static_assert(constant_expression, "diagnostic message");
```

条件必须能在编译期求值为布尔结果。模板中的依赖条件通常在实例化相应类型时检查。`static_assert(false, "...")` 若不依赖模板形参，可能在模板未使用时就失败。省略消息的单参数形式从 C++17 才有。

## 373【节点：T8.3】【概念】SFINAE 能忽略模板函数体中的所有错误吗？

**答案：** 不能。SFINAE 只保护模板实参替换直接上下文中的特定失败，使候选从重载集合移除。例如返回类型中的 `typename std::enable_if<condition,T>::type` 在条件为假时可移除候选。若候选已经选中，随后实例化函数体才发现 `typename T::missing` 不存在，通常是硬编译错误。SFINAE 是编译期候选形成规则，不是异常处理或运行时分支。

## 374【节点：T8.4】【类型查询】`decltype` 怎样决定结果类型，`std::declval<T>()` 又为什么只能用于不求值上下文？

**答案：** `decltype(expression)` 查询表达式类型而不执行表达式。对未加括号的变量名或成员访问，它直接得到该实体声明时的类型；其他表达式按值类别得到结果：左值形成 `T&`，将亡值形成 `T&&`，纯右值形成 `T`。因此已有 `int value;` 时，`decltype(value)` 是 `int`，`decltype((value))` 是 `int&`。

`std::declval<T>()` 位于 `<utility>`，用于在 `decltype`、`sizeof` 等不求值上下文中假设存在某种值类别的 `T`，即使该类型不能默认构造。假定 `Widget` 已定义并提供 `size()`，类型查询片段可写：

```cpp
using Result =
    decltype(std::declval<const Widget&>().size());
```

这只查询表达式类型，不创建对象也不调用 `size`。运行时真正使用 `declval` 不合法。C++11 可用尾置返回 `auto f(const T& x) -> decltype(x.size())` 做表达式 SFINAE；`decltype(auto)` 是 C++14。类型查询只证明表达式形式合法，不保证运行时对象仍存活或业务操作安全。

## 375【节点：L1.1】【语法】C++11 Lambda 表达式由哪些部分组成？

**答案：** 下面是 Lambda 的语法模板，不是可直接编译的完整表达式：

```cpp
[capture](parameters) mutable -> ReturnType { body }
```

捕获列表 `[]` 和函数体必须存在；参数列表、`mutable` 和尾置返回类型按规则可省。求值 Lambda 表达式会产生一个可调用闭包对象，通常写 `auto operation = [](int x){ return x+1; };`，再用 `operation(3)` 调用。C++11 不支持泛型 Lambda 的 `auto` 形参。

## 376【节点：L1.2】【概念】Lambda 是函数还是对象？

**答案：** 每个 Lambda 表达式都会产生一个编译器定义、无法直接拼写名字的闭包类类型；求值后得到该类型的闭包对象。这个类具有调用运算符 `operator()`，捕获的数据通常保存在对象内部。局部变量用 `auto` 保存，不同位置写出的 Lambda 即使文本相同也具有不同类型。需要统一运行时接口时可考虑 `std::function`，但会有类型擦除成本。

## 377【节点：L1.3】【版本边界】下面写法为什么不是 C++11？

```cpp
auto identity = [](auto value) { return value; };
```

**答案：** `auto` Lambda 形参属于 C++14 泛型 Lambda。严格 C++11 必须写确定类型，例如 `[](int value){ return value; }`。若 C++11 需要适配多种类型，可写普通函数模板，或定义带模板 `operator()` 的函数对象。Lambda 形参可按值、指针或引用声明，但不能有默认实参。

## 378【节点：L1.4】【返回类型】复杂 C++11 Lambda 为什么常显式写尾置返回类型？

**答案：** 严格 C++11 的隐式非 `void` 返回推导比后续标准受限，只有简单返回主体最易移植。包含多个控制流分支时写：

```cpp
auto absolute = [](int value) -> int {
    if (value < 0) return -value;
    return value;
};
```

所有返回路径仍必须满足返回类型要求。C++14 放宽了返回类型推导，不能把后续规则倒推到 C++11。

## 379【节点：L2.1】【转换】什么样的 Lambda 能隐式转换为普通函数指针？

**答案：** 无捕获 Lambda 可以转换到签名兼容的普通函数指针：

```cpp
int (*square)(int) = [](int x) { return x * x; };
```

有任何捕获时都不能直接这样转换，因为普通函数指针没有位置保存闭包状态。无捕获 Lambda 仍可访问命名空间变量和静态存储期对象，因为这些名字不需要放进闭包；这不代表访问共享全局状态自动线程安全。

## 380【节点：L2.2】【快照】按值捕获是在创建时复制，还是每次调用时重新读取？

**答案：** 在创建闭包时复制：

```cpp
int main()
{
    int value = 2;
    auto read = [value]() { return value; };
    value = 9;
    return read() == 2 ? 0 : 1;
}
```

`read()` 仍返回 `2`。闭包的调用运算符默认是 `const`，因此不能直接修改这个副本，除非写 `mutable`。捕获大对象可能有复制成本；C++11 普通按值捕获也不能移动捕获 `unique_ptr`。

## 381【节点：L2.3】【生命周期】按引用捕获的主要风险是什么？

**答案：** `[&value]` 让闭包操作原对象，可以修改它并看到最新值，但闭包不拥有目标，也不延长目标生命。如果闭包被返回、长期保存或交给异步任务，在局部变量销毁后调用就会访问悬空引用。短期同步算法中引用捕获通常容易管理；异步或注册回调必须重新设计所有权，并发修改还需正确同步。

## 382【节点：L2.4】【语法】默认捕获怎样为某个变量指定例外？

**答案：** `[=]` 默认按值，可写 `[=, &sum]` 让 `sum` 按引用；`[&]` 默认按引用，可写 `[&, limit]` 让 `limit` 按值。不能写重复捕获 `[=, value]` 或 `[&, &value]`。默认捕获只处理 Lambda 中实际需要捕获的外围自动变量。长期回调使用 `[&]` 很难审计，明确列出捕获通常更安全。

## 383【节点：L2.5】【对象生命周期】C++11 中 `[this]` 捕获的是整个对象副本吗？

**答案：** 不是，它复制当前对象的 `this` 指针值，成员访问随后仍作用于原对象。`[=]` 或 `[&]` 中因使用非静态成员而隐式捕获 `this` 时，本质仍是保存指针；`[&this]` 非法。闭包若比对象活得久，指针会悬空。按对象副本捕获的 `[*this]` 是 C++17 功能，不属于 C++11。

## 384【节点：L2.6】【状态】`mutable` 修改的是外部变量还是闭包副本？

**答案：** 它让闭包的调用运算符不再默认 `const`，从而可修改按值捕获的内部副本：

```cpp
int main()
{
    int start = 0;
    auto next = [start]() mutable { return ++start; };
    return next() == 1 && start == 0 ? 0 : 1;
}
```

多次调用 `next` 得到递增内部状态，外部 `start` 仍为零。复制这个闭包还会复制当时的内部状态，两个副本以后各自变化。`mutable` 不提供并发同步。

## 385【节点：L2.7】【版本边界】为什么 `[p = std::move(p)]` 不能出现在 C++11 题目中？

**答案：** 这是初始化捕获，从 C++14 才标准化。C++11 的普通 `[p]` 要从外围变量复制捕获成员，而 `unique_ptr` 不可复制，所以无法用这种语法把它移入 Lambda。严格 C++11 可编写一个含 `unique_ptr` 成员、实现 `operator()` 的显式函数对象，或改用符合真实所有权需求的可复制共享对象，不能偷偷使用 C++14 语法。

## 386【节点：L3.1】【类型】两个文本完全相同的 Lambda 能否互相赋值？

**答案：** 不同位置的 Lambda 是不同、匿名的闭包类型，因此通常不能互相赋值：

```cpp
auto first = [] { return 1; };
auto second = [] { return 1; };
// first = second; // 类型不同
```

从同一个闭包对象复制得到 `auto copy = first;` 才是同一类型。若只需统一签名，可使用无捕获函数指针或 `std::function`；类型擦除不是免费的。

## 387【节点：L3.2】【回调】有捕获 Lambda 为什么不能直接作为 C 风格函数指针回调？

**答案：** 普通函数指针只保存代码地址，没有携带闭包对象和捕获数据的位置。无捕获 Lambda 可转成匹配的 `R (*)(Args...)`，有捕获 Lambda 不可。旧式 C 回调常另接收 `void* context`，可通过明确的静态桥接函数传递对象，但还必须管理上下文生存期、转换正确性和 C ABI；仅靠 Lambda 语法不能自动完成。

## 388【节点：L3.3】【类型擦除】`std::function` 能保存什么？空对象调用会怎样？

**答案：** `std::function<R(Args...)>` 可统一保存签名兼容的普通函数、函数对象和 Lambda，并用 `wrapper(args...)` 调用。它为空时布尔测试为假；调用空对象会抛 `std::bad_function_call`。C++11 要求所存目标满足复制构造等条件，因此不能直接保存只移动、不可复制的闭包。它还可能产生间接调用和动态分配成本。

## 389【节点：L3.4】【绑定】`std::bind` 默认按值还是按引用保存绑定参数？

**答案：** 默认按值保存。`std::bind(function, bound_args...)` 创建函数对象，`std::placeholders::_1` 等表示以后调用时提供的位置。若确实要引用原对象，使用 `std::ref(value)` 或 `std::cref(value)`；引用包装仍不会延长生命。占位符还能重排参数，但复杂 `bind` 表达式难读，简单适配通常 Lambda 更清楚。

## 390【节点：L3.5】【成员函数指针】非静态成员函数指针怎样调用和包装？

**答案：** 它不包含对象，原始调用必须同时提供对象。假定 `Counter` 已定义，`object` 是其对象且 `pointer` 指向它，调用片段可写：

```cpp
int (Counter::*member)(int) const = &Counter::add;
int a = (object.*member)(3);
int b = (pointer->*member)(3);
```

包含 `<functional>` 后可用 `auto call = std::mem_fn(member); call(object, 3);`，也可用 `std::bind` 或 Lambda 包装。成员函数指针不是普通函数指针；若目标成员有重载，通常要用显式类型转换选择所需签名。包装器保存对象引用或指针时还必须保证对象存活。
