## 001.【B0.1 程序、源文件和可执行文件】写好一个 `.cpp` 文本文件后，操作系统通常能直接把它当作可执行程序启动吗？

**答案：** 不能。`.cpp` 文件中保存的是供人阅读和供 C++ 工具处理的源代码。它通常要经过预处理、编译、汇编和链接，才能形成可由操作系统加载的可执行文件。源文件和可执行文件属于不同阶段的产物，二者不能仅凭改文件名互相替代。

## 002.【B0.1 程序、源文件和可执行文件】在“源文件、头文件、目标文件、可执行文件”中，哪一种通常是编译后但尚未完成最终链接的中间产物？

**答案：** 目标文件。源文件通常保存程序员编写的 C++ 代码；头文件通常保存需要共享的声明以及允许放入头文件的定义；目标文件来自某个翻译单元的编译和汇编，里面已有低级代码但通常还不能独立运行；链接器再把所需目标文件和库组合成可执行文件。

## 003.【B0.1 程序、源文件和可执行文件】判断：两个不同的 `.cpp` 文件一定属于两个完全无关的程序。

**答案：** 错误。一个 C++ 程序可以由多个源文件组成，每个源文件通常形成自己的翻译单元并独立编译，之后再由链接器把它们组合起来。是否属于同一个程序取决于构建和链接方式，而不是只看源文件数量。

## 004.【B0.1 程序、源文件和可执行文件】ISO C++11 是否强制源文件必须使用 `.cpp` 扩展名，并规定头文件必须放在某个固定目录？

**答案：** 不强制。ISO C++11 规定 C++ 语言结构和程序行为，但不规定项目目录布局，也不要求某一种文件扩展名。`.cpp`、`.h`、`.hpp` 等是常见工具和项目约定；具体编译器接受哪些文件名形式，应查看该工具的使用说明。

## 005.【B0.3 必须先掌握的术语】在 `total`、`user_count` 和 `2nd` 中，哪些可以作为普通 C++ 标识符？

**答案：** `total` 和 `user_count` 可以；`2nd` 不可以，因为标识符不能以数字开头。标识符是源码中的一种记号，常用来写对象、函数或类型的名字。名字用于指代程序实体，而标识符是书写名字时最常见的形式。

## 006.【B0.3 必须先掌握的术语】“编译器报告少了一个分号”和“程序启动后根据输入计算结果”分别发生在编译期还是运行期？

**答案：** 缺少分号属于源代码语法问题，通常在编译期被发现；程序已经启动并根据输入进行计算，属于运行期。编译期关注源代码能否按语言规则被翻译，运行期关注已生成程序实际执行时发生的行为。能通过编译只说明没有发现相应的编译错误，不保证计算结果一定正确。

## 007.【B1.1 实际工具链流程】把下列阶段按通常先后顺序排列：链接、预处理、加载与运行、汇编、编译。

**答案：** 通常顺序是：预处理 → 编译 → 汇编 → 链接 → 加载与运行。实际编译器驱动程序可能用一条命令连续完成前四个阶段，但每个阶段的职责仍然不同。区分它们有助于判断一条错误信息究竟来自哪里。

## 008.【B1.1 实际工具链流程】指令 `#include "config.h"` 主要在哪个阶段处理？它是否表示运行程序时再打开该头文件？

**答案：** 它主要在预处理阶段处理，不是运行时文件读取操作。预处理器会把指定头文件的内容纳入当前源文件的处理结果，再形成交给编译器的翻译单元。如果找不到该头文件，通常在源代码尚未进入正式编译前就会报告问题。

## 009.【B1.1 实际工具链流程】编译阶段最基本的任务是什么？

**答案：** 编译阶段按 C++ 语言规则检查翻译单元中的词法、语法和类型关系，并把合法代码转换为更低级的表示。少写必要记号、使用尚未声明的名字或违反类型规则，通常会在此阶段得到诊断。编译一个翻译单元成功，不等于整个程序已经链接成功。

## 010.【B1.1 实际工具链流程】汇编阶段通常产生什么？该产物一般已经是最终可执行文件吗？

**答案：** 汇编阶段通常产生目标文件。目标文件包含该翻译单元对应的机器级代码和供链接器使用的信息，但其中对其他翻译单元或库的引用可能尚未解析，因此一般还不是最终可执行文件。它还需要进入链接阶段。

## 011.【B1.1 实际工具链流程】链接器为什么需要同时查看多个目标文件和库？

**答案：** 因为一个翻译单元可能调用在另一个翻译单元或库中定义的函数，也可能使用在那里定义的对象。链接器负责组合这些目标文件和库，并把名字对应的符号引用解析到实际定义。找不到所需定义和找到了多个不允许并存的定义，都会使链接失败，但两者是不同问题。

## 012.【B1.2 翻译单元】源文件 `main.cpp` 包含 `settings.h` 后，翻译单元只包含 `main.cpp` 原来可见的那些行吗？

**答案：** 不是。翻译单元是以某个源文件为起点、经过预处理后得到的内容，其中包含由 `#include` 纳入的头文件内容，并反映宏和条件编译的处理结果。因此，“源文件原始文本”和“交给编译器的翻译单元”不是完全相同的概念。

## 013.【B1.2 翻译单元】判断：头文件是一个会被操作系统单独启动的运行单元。

**答案：** 错误。头文件通常通过 `#include` 成为翻译单元的一部分，本身不是独立运行单元。同一个头文件可以被多个源文件包含，于是它的内容会分别进入多个翻译单元；这也是头文件内容必须考虑重复包含和单一定义规则的原因。

## 014.【B1.3 声明、定义与分离编译】下面两行代码中，哪一行只是函数声明，哪一行是函数定义？

```cpp
int add(int, int);
int add(int left, int right) { return left + right; }
```

**答案：** 第一行是声明：它告诉编译器存在名为 `add` 的函数，该函数接收两个 `int` 参数并返回 `int`。第二行带有函数体，真正提供了函数实体，所以是定义。调用方通常只需先看到声明；程序最终仍要能链接到相应定义。

## 015.【B1.4 头文件保护】Include guard 的基本结构是什么？它与 `#pragma once` 的标准地位相同吗？

```cpp
#ifndef APP_SETTINGS_H
#define APP_SETTINGS_H

int read_setting();

#endif
```

**答案：** `#ifndef` 检查保护宏尚未定义，`#define` 随后定义它，`#endif` 结束条件区域。这样，同一头文件在一个翻译单元中被多次包含时，主体只会展开一次。`#pragma once` 常被工具支持并能达到类似目的，但它不是 ISO C++11 标准指令，不能把某个编译器的支持当作语言标准保证。

## 016.【B1.5 单一定义规则 ODR】一个普通函数只有声明却没有所需定义，与它在两个 `.cpp` 文件中各有一个不允许重复的定义，分别是什么问题？

**答案：** 前者通常在链接时表现为“未定义引用”：编译器知道如何检查调用，却没有可供链接的函数实体。后者通常表现为“重复定义”，因为普通非 `inline` 外部函数通常只能在整个程序中有一个定义。类、模板和 `inline` 定义在满足内容一致等规则时可以出现在多个翻译单元中，这正是部分定义可以放头文件的原因。

## 017.【B2.3 命名空间】下面代码中的 `school` 是什么？`school::count` 为什么带有 `::`？

```cpp
namespace school {
    int count = 0;
}

int saved = school::count;
```

**答案：** `school` 是命名空间，它为其中的名字提供一个命名区域。`school::count` 是限定名，`::` 指明应到 `school` 命名空间中查找 `count`。这样，不同命名空间可以各自拥有同名实体而不必直接冲突。

## 018.【B2.3 命名空间】`std::cout` 中的 `std` 表示什么？`using std::cout;` 与 `using namespace std;` 的影响范围有何不同？

**答案：** `std` 是 C++ 标准库使用的命名空间，`std::cout` 明确限定从该命名空间查找 `cout`。`using std::cout;` 只引入指定名字；`using namespace std;` 则让 `std` 中许多名字参与当前作用域的名字查找，更容易造成重名和二义性。普通头文件尤其应避免在全局作用域写 `using namespace std;`，以免影响所有包含者。

## 019.【B2.4 基本字面量】判断：`nullptr` 是拼写特殊的整数零。

**答案：** 错误。`nullptr` 是 C++11 的空指针字面量，具有专门的类型 `std::nullptr_t`，不是整数。它表示空指针意图，可转换为相应指针类型；与整数 `0` 或实现定义的宏 `NULL` 相比，它能更明确地告诉编译器和读者“这里需要的是指针”。

## 020.【B2.4 基本字面量】字符字面量 `'\n'`、`'\t'` 和 `'\\'` 分别表示什么？

**答案：** `'\n'` 表示换行字符，`'\t'` 表示水平制表字符，`'\\'` 表示反斜杠字符本身。反斜杠在普通字符和字符串字面量中会启动转义序列，所以要表示一个普通反斜杠需要写两个反斜杠。字符字面量用单引号，而字符串字面量用双引号。

## 021.【B2.4 基本字面量】下面的原始字符串中，`\n` 会被解释成换行字符吗？

```cpp
R"(first\nsecond)"
```

**答案：** 不会。C++11 原始字符串字面量的内容不会按普通转义规则处理，因此这里的 `\n` 是反斜杠和字母 `n` 两个字符。原始字符串适合书写含有许多反斜杠、引号或多行内容的文本，可减少手工转义。

## 022.【B2.5 预处理器基础】为什么说宏只是记号替换，不是理解 C++ 类型的函数？

**答案：** `#define` 定义的宏在正式编译前由预处理器展开，它不会进行 C++ 参数类型检查，也不具备普通函数的作用域和调用规则。函数式宏若在替换文本中多次写出参数，传入的表达式可能被求值多次。`#if`、`#ifdef` 等则用于条件编译。能用有类型的 `const`、`constexpr`、`inline` 或函数表达需求时，通常比宏更容易检查和维护。

## 023.【B3.1 布尔和字符类型】`bool ready = false;` 中，`bool`、`ready` 和 `false` 分别是什么？

**答案：** `bool` 是布尔类型；`ready` 是对象的名字，也是一个标识符；`false` 是布尔字面量。布尔类型只表示 `false` 和 `true` 两个逻辑值，适合记录“否/是”“失败/成功”等二选一状态。`false` 不带引号，因此不是字符串。

## 024.【B3.1 布尔和字符类型】普通 `char` 与 `signed char`、`unsigned char` 是否完全相同？C++11 还提供哪些相关字符类型？

**答案：** `char`、`signed char` 和 `unsigned char` 是三个不同类型。`signed char` 与 `unsigned char` 明确有符号性，而普通 `char` 表现为有符号还是无符号由实现决定。相关基本类型还包括 `wchar_t`，以及 C++11 的 `char16_t` 和 `char32_t`；拥有这些类型不代表程序会自动完成字符编码转换。

## 025.【B3.2 整数类型】从较短到较长的常见整数类型名称有哪些？每一种都有无符号版本吗？

**答案：** 基本序列包括 `short`、`int`、`long` 和 `long long`，标准对它们规定最小范围和相对大小关系。它们都有对应的无符号类型，例如 `unsigned short`、`unsigned int`、`unsigned long` 和 `unsigned long long`。具体占用多少字节由实现决定，所以不能把某台机器上 `int` 的大小当作所有平台的标准答案。

## 026.【B3.2 整数类型】`sizeof(char)` 在所有符合 C++11 的实现中都是多少？这是否证明一个字节恒等于 8 位？

**答案：** `sizeof(char)` 永远是 `1`，因为 `sizeof` 使用 C++ 自己定义的“字节”作为计量单位。但这不证明一个字节一定有 8 位；每字节位数由实现决定，可查看 `<climits>` 中的 `CHAR_BIT`。因此“1 个 C++ 字节”和“固定 8 位”不是同一个保证。

## 027.【B3.4 浮点类型】`float`、`double` 和 `long double` 用于表示什么？为什么很多十进制小数不能被精确保存？

**答案：** 它们是三种浮点类型，用于表示带小数部分或范围较大的实数近似值，具体精度、范围和舍入方式由实现提供并满足标准下限。常见二进制浮点表示无法有限、精确地表示许多十进制小数，所以存储和计算会发生舍入。由此，浮点计算不能普遍假定数学上相等的结果一定具有完全相同的机器表示。

## 028.【B3.5 `void` 与空指针类型】`void`、`void*` 和 `std::nullptr_t` 是同一个类型吗？

**答案：** 不是。`void` 表示无值或不完整类型，不能直接定义普通 `void` 对象；`void*` 是指针类型，但转换必须保留 cv 限定：`T*` 可隐式转为 `void*`，`const T*` 应转为 `const void*`，`volatile T*` 应转为 `volatile void*`。这些指针不能直接解引用，也不能在 C++ 中隐式转回具体对象指针；显式恢复类型时也不能非法丢弃限定。`std::nullptr_t` 是空指针字面量 `nullptr` 的类型，直接使用该类型名时应包含 `<cstddef>`。三者用途不同，不能互换概念。

## 029.【B3.6 大小、范围和对齐】想分别查询“对象占多少字节”“类型需要怎样对齐”“数值类型能表示多大范围”，应使用什么？

**答案：** 使用 `sizeof` 查询类型或对象占用的 C++ 字节数，其结果类型为 `std::size_t`；使用 C++11 的 `alignof` 查询类型的对齐要求；包含 `<limits>` 后，可用 `std::numeric_limits<T>` 查询数值类型的范围和表示特征。大小、对齐、位数和可表示范围是不同概念，不能只知道其中一个就推出其余全部。

## 030.【B3.7 枚举基础】普通 `enum` 和 C++11 的 `enum class` 在名字作用域与整数转换方面有什么基础区别？

```cpp
enum Color { red, green };
enum class State : unsigned { off, on };

Color color = red;
State state = State::off;
```

**答案：** 普通 `enum` 的枚举常量进入外围作用域，所以这里直接写 `red`；它还可以隐式转换为整数。`enum class` 的枚举常量位于枚举自己的作用域，必须写 `State::off`，并且不会隐式转换为整数，类型检查更严格。示例还用 `: unsigned` 显式指定了 `State` 的底层整数类型。
