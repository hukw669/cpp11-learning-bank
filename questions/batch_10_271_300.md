# C++11 第十批题目（271–300）

## 271【节点：O5.1】【概念】C++11 中六类特殊成员函数分别负责什么？

**答案：** 六类函数是默认构造函数 `T()`、析构函数 `~T()`、复制构造函数 `T(const T&)`、复制赋值运算符 `T& operator=(const T&)`、移动构造函数 `T(T&&)` 和移动赋值运算符 `T& operator=(T&&)`。它们分别负责默认建立对象、结束对象生命、用旧对象建立新对象、修改已有对象，以及从可放弃当前值的对象转移状态。编译器可能隐式声明其中一些，但成员或基类不支持相应操作时，生成的函数可能被定义为删除；不能把“可能自动生成”理解成“六个一定都能调用”。

## 272【节点：O5.2】【代码判断】下面三条语句分别调用复制构造还是复制赋值？

```cpp
Widget first;
Widget second(first);
Widget third = first;
second = first;
```

**答案：** `second(first)` 和 `third = first` 都是在定义新对象，因此调用复制构造函数；复制初始化中的等号不是赋值运算。`second = first` 发生在 `second` 已经存在以后，调用复制赋值运算符。判断标准是“是否正在建立新对象”，而不是表面上有没有等号。代码是片段，假定 `Widget` 已完整定义并且相应操作可访问。

## 273【节点：O5.3】【推理】为什么编译器默认复制一个裸指针成员可能造成重复释放？

**答案：** 默认复制按成员分别处理。数值成员复制数值，`std::string` 调用自己的复制操作，而裸指针只复制地址。若类把指针解释为独占资源：

```cpp
class Owner {
public:
    explicit Owner(int value) : pointer_(new int(value)) {}
    ~Owner() { delete pointer_; }
private:
    int* pointer_;
};
```

默认复制会让两个 `Owner` 保存同一个地址，两个析构函数随后都执行 `delete`，产生未定义行为。解决办法不是“禁止所有指针复制”，而是明确所有权：优先把成员改为 `std::unique_ptr<int>`，需要值语义时实现深复制，需要共享时使用正确的共享所有权类型。

## 274【节点：O5.4】【语法】`= default` 表达什么？它能否强迫不可复制的类变得可复制？

**答案：** `= default` 明确要求编译器按照语言规则生成默认实现，例如：

```cpp
class Item {
public:
    Item() = default;
    Item(const Item&) = default;
};
```

它常用于在声明了其他构造函数后恢复默认构造，或公开表达“采用成员式复制”。它不能绕过成员能力：如果 `Item` 含有不可复制的 `std::unique_ptr`，默认化的复制构造仍会被定义为删除，调用仍然报错。

## 275【节点：O5.5】【重载判断】被 `= delete` 的函数还会不会参与重载选择？

**答案：** 会。删除函数仍是已声明的候选；若它成为最佳匹配，编译器会报告“使用已删除函数”，不会退而选择匹配更差的版本。例如：

```cpp
void process(int);
void process(double) = delete;

void process(int) {}

int main()
{
    process(1);   // 合法
    // process(1.5); // 最佳匹配是已删除的 double 版本，错误
}
```

禁止复制也可写 `T(const T&) = delete; T& operator=(const T&) = delete;`。这比把函数设为私有更直接地表达“任何位置都不允许调用”。

## 276【节点：O5.6】【设计】复制赋值为什么必须考虑自赋值和异常安全？

**答案：** `object = object` 是合法调用。如果实现先释放目标旧资源，再从右侧读取资源，自赋值时右侧资源已经被自己释放。若释放旧资源后分配新资源又抛异常，目标还会丢失原值。常见的强保证写法是先复制，再提交。下面是类内成员函数片段，假定 `T` 就是当前类且 `swap` 已正确实现：

```cpp
T& operator=(const T& other)
{
    T temporary(other); // 失败时当前对象尚未变化
    swap(temporary);     // swap 应设计为不抛
    return *this;
}
```

临时对象最终析构并清理旧资源。这种 copy-and-swap 不是唯一实现，但清楚展示了“先准备，后提交”。

## 277【节点：O5.7】【概念】Rule of Three、Five 和 Zero 分别提醒什么？

**答案：** 它们是设计经验，不是三个语言关键字。直接管理资源的类若自定义析构、复制构造、复制赋值中的一项，通常应一起检查三项，这叫 Rule of Three；C++11 再加入移动构造和移动赋值，形成 Rule of Five。更推荐 Rule of Zero：业务类使用 `std::string`、`std::vector`、智能指针和专用 RAII 句柄作为成员，不亲自管理底层资源，让成员自动提供正确的复制、移动和析构。

## 278【节点：O5.8】【判断】只要使用 C++11，一个类就必然自动拥有移动构造函数吗？

**答案：** 不必然。编译器只有在用户没有声明会冲突的复制操作、移动操作和析构函数等条件满足时，才可能隐式声明移动操作；某个成员或基类不能移动时，默认移动还可能被删除。例如用户自己写了析构函数，往往会抑制隐式移动构造。若设计确实需要移动，应明确检查成员能力，并可在类定义中写以下声明片段：

```cpp
T(T&&) = default;
T& operator=(T&&) = default;
```

另外，“可以用右值构造”也不一定证明存在移动构造，因为 `const T&` 复制构造同样能接收右值。

## 279【节点：O6.1】【链接】静态数据成员为什么通常还要在类外提供一次定义？

**答案：** 静态数据成员属于类本身，所有对象共享同一个实体，不存放在每个对象内部。类内通常只是声明：

```cpp
class Counter {
public:
    static int count;
};

int Counter::count = 0; // 一个源文件中的定义
```

C++11 没有 inline 变量，因此需要实体的普通静态数据成员通常必须在一个 `.cpp` 中定义一次，否则可能链接失败。它可用 `Counter::count` 访问，也通常不计入 `sizeof(Counter)`。

## 280【节点：O6.2】【判断】静态成员函数为什么不能直接访问非静态数据成员？

**答案：** 静态成员函数不依附于某个调用对象，没有隐含 `this` 指针，所以不知道应访问哪一个对象的非静态成员。它可以直接操作静态成员：

```cpp
class Counter {
public:
    static int objects() { return count_; }
private:
    static int count_;
};
```

若要处理普通成员，必须显式接收对象、指针或引用。静态成员函数也不能声明成 `const` 或虚函数，因为这两种性质都依赖对象。

## 281【节点：O6.3】【并发边界】C++11 对函数局部静态对象的初始化保证了什么？

**答案：** `static T object;` 的名字只有块作用域，但对象拥有静态存储期，并在控制第一次到达声明时初始化。C++11 保证多个线程并发首次到达时，成功初始化只完成一次；若初始化抛异常，之后再次到达可以重试。这个保证只覆盖初始化过程，不保证对象以后所有成员访问自动线程安全。共享可变状态仍需互斥量、原子操作或其他正确同步。

## 282【节点：O6.4】【概念】嵌套类型是否自动拥有外围类对象？

**答案：** 不会。类作用域中可以声明嵌套类、枚举和类型别名：

```cpp
class Tree {
public:
    class Node;
    using size_type = unsigned long;
};
```

类外使用时写 `Tree::Node`、`Tree::size_type`。嵌套类只是名字位于外围类作用域中的独立类类型，并不自动保存外围对象的 `this`；若它需要访问某个 `Tree` 对象的普通成员，必须显式取得该对象的引用或指针。

## 283【节点：O7.1】【规则】C++ 运算符重载能改变哪些内容，不能改变哪些内容？

**答案：** 可为类或枚举类型定义现有运算符的行为，例如 `Number operator+(Number, Number);`。至少一个操作数必须是类或枚举类型。不能创造新运算符，不能改变操作数个数、优先级或结合性，也不能重定义两个内置类型之间的运算。`.`、`.*`、`::`、`?:`、`sizeof` 等不能重载。重载解决调用语法，不应破坏运算符通常表达的语义。

## 284【节点：O7.2】【设计】对称的二元运算符为什么常写成非成员函数？

**答案：** 成员版本 `T::operator+(const U&)` 把左操作数固定为 `*this`；非成员版本 `operator+(const T&, const U&)` 显式接收两侧，使两侧都能按允许规则参与转换。假定 `Number` 已定义并提供 `+=`，常见的非成员函数片段是：

```cpp
Number operator+(Number left, const Number& right)
{
    left += right;
    return left;
}
```

`operator=、operator[]、operator()、operator->` 必须是非静态成员。非成员若确需访问私有状态，可被声明为友元，但不应无理由扩大友元权限。

## 285【节点：O7.3】【辨析】前置和后置自增运算符的签名与返回值为什么不同？

**答案：** 惯例与内置类型保持一致。下面是类内声明片段，其中 `T` 表示当前类：

```cpp
T& operator++();    // 前置
T operator++(int);  // 后置，int 是区分签名的哑元
```

前置形式先修改当前对象并返回 `*this` 的引用；后置形式要保存旧值、修改当前对象，再按值返回旧副本。赋值和复合赋值通常返回 `T&`，从而支持 `a = b = c`。按值产生的新算术结果不能返回局部对象的引用。

## 286【节点：O7.4】【代码阅读】`explicit operator bool()` 解决了什么问题？

**答案：** 转换运算符没有显式返回类型，C++11 可写：

```cpp
class Handle {
public:
    explicit operator bool() const { return valid_; }
private:
    bool valid_;
};
```

对象可用于 `if (handle)` 等需要布尔判断的上下文，却不会轻易继续转换成整数并参与算术。它比旧式隐式 `operator bool()` 更能限制意外转换。转换构造函数和转换运算符若形成多条竞争路径，还可能造成重载二义性。

## 287【节点：O7.5】【判断】重载 `operator&&` 后还会保持内置短路求值吗？

**答案：** 不会。重载运算符实质上是函数调用，其实参按函数调用规则求值；它无法保留内置 `&&` 和 `||` 的条件短路机制。因此 `left && expensive()` 即使 `left` 表示假，`expensive()` 仍可能执行。重载逗号运算符也不会保留内置逗号的排序语义。这类重载非常容易误导读者，通常应避免。

## 288【节点：O8.1】【概念】公有继承表达什么关系？派生对象中有什么？

**答案：** 公有继承应表达“派生对象可以当作基类对象使用”的 `is-a` 关系。假定 `Base` 已定义，派生类声明片段是：

```cpp
class Derived : public Base { };
```

每个 `Derived` 对象都含一个 `Base` 子对象。构造时先构造基类，再构造派生类成员和派生部分；析构时顺序相反。基类的私有成员仍存在于派生对象中，但派生类不能直接访问。若关系只是“拥有一个组件”，组合通常更合适。

## 289【节点：O8.2】【访问控制】公有、保护和私有继承分别怎样改变基类接口？

**答案：** `class D : public B` 保持基类 `public`、`protected` 成员在派生层次中的相应可访问级别，并支持外部的可访问无歧义向上转换。保护继承把基类的公开和保护接口都变为派生类的 `protected`；私有继承把它们变为 `private`。基类自身的 `private` 成员无论哪种继承都不能由派生类直接访问。继承方式与成员原有访问权限是两个维度。

## 290【节点：O8.3】【最小纠错】为什么派生类的一个同名函数会隐藏基类全部同名重载？

```cpp
struct Base {
    void print(int);
    void print(double);
};

struct Derived : Base {
    void print(const char*);
};
```

**答案：** 名字查找在 `Derived` 找到 `print` 后，不会自动把 `Base` 中的同名集合合并进来，所以 `Derived d; d.print(1);` 会只考虑派生版本并失败。这是名字隐藏，不要求函数为虚函数。可在派生类定义中加入以下声明片段：

```cpp
using Base::print;
```

这样基类重载被引入当前重载集合。名字隐藏、同一作用域的重载和虚函数覆盖是三个不同概念。

## 291【节点：O8.4】【多态】动态绑定成立需要哪些条件？

**答案：** 基类先把函数声明为虚函数，例如 `virtual void draw() const;`；派生类提供匹配覆盖；调用必须经基类指针或引用作用于实际派生对象。假定 `Shape` 已定义，下面是调用函数片段：

```cpp
void paint(const Shape& shape)
{
    shape.draw();
}
```

传入 `Circle` 时可调用 `Circle::draw()`。若按值接收 `Shape`，对象会切片；明确写 `shape.Shape::draw()` 是限定调用，也不会执行普通动态分派。

## 292【节点：O8.5】【纠错】为什么覆盖虚函数时应写 `override`？

**答案：** `override` 让编译器核对该函数确实覆盖某个基类虚函数。若基类是 `virtual void f() const;`，派生类误写 `void f() override;` 会因缺少 `const` 立刻报错，而不是悄悄创建一个新函数。`final` 可写在虚函数后阻止更深层覆盖，也可写 `class Leaf final : public Base` 阻止继续派生。`override` 不会凭空创建虚机制，目标在基类中必须已经是虚函数。

## 293【节点：O8.6】【概念】纯虚函数和抽象类是什么？纯虚析构函数需要定义吗？

**答案：** 纯虚函数写作 `virtual double area() const = 0;`。只要类仍有未被最终覆盖的纯虚函数，它就是抽象类，不能直接定义对象，但可以声明其指针或引用作为接口。派生类实现所有纯虚函数后才能成为具体类。纯虚函数可以存在类外定义；纯虚析构函数尤其必须提供定义，因为销毁派生对象时最终仍会执行基类析构部分。

## 294【节点：O8.7】【未定义行为】为什么多态基类通常需要虚析构函数？

**答案：** 假定 `Base` 与 `Derived` 已定义，若程序中可能执行以下片段：

```cpp
Base* pointer = new Derived;
delete pointer;
```

则 `Base` 的析构函数必须是虚函数，例如 `virtual ~Base() = default;`。这样 `delete` 才会先销毁完整 `Derived`，再销毁基类子对象。若基类析构非虚，经基类指针删除实际派生对象是未定义行为。完全不允许经基类删除的实现基类，可把非虚析构设为受保护来阻止这种调用。

## 295【节点：O8.8】【代码判断】把派生对象放入 `std::vector<Base>` 会发生什么？

**答案：** 发生对象切片。按值把 `Derived` 转成 `Base` 时，只复制其中的基类子对象，派生类新增状态被丢弃；容器中实际存放的是独立 `Base` 对象，之后虚调用也无法恢复已丢失的派生部分。异构多态集合通常使用 `std::vector<std::unique_ptr<Base>>`，并保证基类有虚析构函数。引用容器不能直接存在，可考虑指针或 `reference_wrapper`，并明确生存期。

## 296【节点：O8.9】【RTTI】`dynamic_cast` 的指针形式和引用形式失败时分别怎样表现？

**答案：** 对多态基类进行受检查向下转换时，可在 `Base`、`Derived` 和 `base_pointer` 已定义的上下文中写以下语句片段：

```cpp
Derived* d = dynamic_cast<Derived*>(base_pointer);
```

不兼容时返回 `nullptr`。引用形式 `dynamic_cast<Derived&>(base_reference)` 失败时抛 `std::bad_cast`。安全、无歧义的公有向上转换通常无需显式转换。`static_cast` 向下不会运行时检查，判断错误后使用可能导致未定义行为；频繁向下转换也常说明虚接口设计不足。

## 297【节点：O8.10】【结构】虚继承怎样解决菱形继承中的重复基类子对象？

**答案：** 普通菱形中，左右两条继承路径通常各含一个共同基类子对象。假定 `Base` 已定义，中间类和最派生类可写成以下声明片段：

```cpp
class Left  : virtual public Base { };
class Right : virtual public Base { };
class Diamond : public Left, public Right { };
```

则最派生的 `Diamond` 共享一个 `Base` 虚基类子对象，并由最派生类负责初始化它。多重继承仍可能带来名字歧义、布局和构造顺序复杂性，不能把虚继承当成普通代码复用工具。

## 298【节点：O9.1】【类型性质】“标准布局”“平凡”和 POD 是否表示完全相同的性质？

**答案：** 不相同。C++11 把传统 POD 相关要求拆成多个独立性质，可通过 `<type_traits>` 查询，例如 `std::is_trivial<T>::value`、`std::is_standard_layout<T>::value`、`std::is_pod<T>::value` 和与字节复制更直接相关的 `std::is_trivially_copyable<T>::value`。标准布局不保证没有填充或跨平台布局一致；POD 也不能消除对齐、字节序、生存期和文件格式问题。

## 299【节点：O9.2】【推理】为什么 `sizeof(struct)` 可能大于成员大小之和？

**答案：** 每种类型有对齐要求。实现可在成员之间加入内部填充，也可在对象尾部加入尾部填充，使成员和数组中的下一个对象都位于合法地址。C++11 用 `alignof(T)` 查询对齐，用 `alignas(N)` 请求更强对齐。例如 `struct S { char c; int i; };` 的 `sizeof(S)` 常大于两成员大小之和，但具体值由实现决定。调整成员顺序可能改变大小，也会改变 ABI。

## 300【节点：O9.3】【工程判断】为什么不能把任意类对象的原始字节直接作为长期文件格式？

**答案：** 类对象可能含填充、指针、虚函数实现数据和非平凡成员；地址只在当前进程有意义，布局还可能随编译器、选项和平台改变。即使在输出流 `out` 和对象 `object` 已定义的上下文中，下面这个语句片段能通过类型检查：

```cpp
out.write(reinterpret_cast<const char*>(&object), sizeof object);
```

它也只复制当前实现的对象表示，不会自动形成可移植协议。稳定持久化应逐字段规定整数宽度、字节序、字符串长度与编码、版本及校验，并在读取时验证边界。
