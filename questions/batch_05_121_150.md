### 121. 函数声明和函数定义分别做什么？【B9.1 函数声明与定义】

阅读：

```cpp
int add(int left, int right);

int add(int left, int right)
{
    return left + right;
}
```

哪一部分是声明，哪一部分是定义？

**答案：** 第一行是函数声明，它告诉编译器函数名为 `add`、返回类型为 `int`，并接受两个 `int` 参数。后面的完整结构是函数定义：它再次给出函数的类型信息，并通过函数体提供实际行为。定义同时也是声明。函数定义中的主要组成部分是返回类型、函数名、参数列表和函数体。

### 122. 函数可以声明多次、定义多次吗？【B9.1 函数声明与定义】

判断：“只要每次写法一致，一个普通的非 `inline` 外部函数就可以在程序中定义任意多次。”

**答案：** 错误。相容的函数声明可以出现多次，让不同调用位置知道函数的类型；但一个普通的非 `inline` 外部函数应当只有一个程序级定义，否则会违反单一定义规则。还要注意，在 C++ 中声明 `void f();` 明确表示 `f` 不接受参数，不能把它理解为“参数情况未知”。

### 123. 什么是实参和形参？【B9.2 函数调用】

阅读：

```cpp
int add(int left, int right);
int result = add(2, 3);
```

指出形参和实参。

**答案：** 函数声明中的 `left` 和 `right` 是形参，它们描述函数被调用时接收的数据及其类型。调用表达式中的 `2` 和 `3` 是实参，它们是在本次调用中提供给函数的具体表达式。编译器会检查实参与形参的数量和类型是否能够匹配；调用结束后，返回值用于初始化 `result`。

### 124. 两个函数实参会从左到右求值吗？【B9.2 函数调用】

阅读：

```cpp
void use(int first, int second);

int i = 0;
use(i++, i++);
```

这段调用在 ISO C++11 中是否具有确定结果？

**答案：** 没有。C++11 不规定不同实参之间的求值顺序，而两个实参都修改同一个标量对象 `i`，这些修改之间没有所需的先后排序，因此行为未定义。不能根据实参书写位置推断先修改哪一次。应先在多个独立的完整表达式中得到两个值，再调用 `use`。

### 125. 按值传递会修改调用者的对象吗？【B9.3 参数传递方式】

阅读：

```cpp
void set_to_nine(int value)
{
    value = 9;
}

int number = 1;
set_to_nine(number);
```

调用后 `number` 是多少？

**答案：** `number` 仍为 `1`。按值传递会用实参的值初始化独立的形参对象 `value`，函数体修改的是这个形参副本，而不是调用者的 `number`。对于复制成本较高的类型，按值传递还会涉及复制成本；是否需要副本应由接口意图决定。

### 126. 指针参数表达什么接口特征？【B9.3 参数传递方式】

一个函数接收 `int* value`，并打算通过 `*value` 修改调用者的整数对象。为什么它在解引用前必须确认 `value` 不是 `nullptr`？

**答案：** 指针参数可以表示“不指向任何对象”，其空值写作 `nullptr`。只有指针确实指向一个仍然存在的 `int` 对象时，才能通过 `*value` 修改该对象；解引用空指针会产生未定义行为。这个接口允许调用者传入空值，因此函数在解引用前进行了检查。指针形参本身按值传入，但它所指向的对象可以通过解引用被修改。

### 127. 非 `const` 左值引用参数表达什么意图？【B9.3 参数传递方式】

阅读：

```cpp
void set_to_nine(int& value)
{
    value = 9;
}

int number = 1;
set_to_nine(number);
```

调用后 `number` 是多少？引用参数与指针参数在接口含义上有何基础区别？

**答案：** `number` 变为 `9`，因为形参 `value` 是调用者对象的别名，对它赋值就是对 `number` 赋值。正常的左值引用参数表示调用时必须提供一个可绑定的对象，语言层面不存在可正常使用的“空引用”；指针参数则可以为空。引用初始化后也不能改为引用另一个对象。

### 128. 什么时候适合使用 `const` 左值引用参数？【B9.3 参数传递方式】

一个函数只需读取调用者提供的对象，并且不希望为参数制作可能昂贵的副本，哪种基础传递方式合适？它提供什么保证？

**答案：** 通常可以使用 `const T&` 形式的常量左值引用参数。它不按值复制整个实参对象，并且函数不能通过这个引用修改所绑定的对象；它还可以绑定到常量对象、非常量对象和部分临时对象。这个 `const` 只限制通过该引用进行修改，并不保证该对象绝不会通过其他途径发生变化。

### 129. 返回局部对象的值安全吗？【B9.4 返回类型】

阅读：

```cpp
int make_value()
{
    int local = 7;
    return local;
}
```

函数返回后局部对象会销毁，这段代码为何仍然安全？

**答案：** 函数返回的是 `local` 的值，而不是让调用者继续访问 `local` 本身。返回过程会把需要的值交给调用表达式；随后局部对象销毁不会使已经返回的值悬空。因此，返回局部对象的值是正常且安全的做法，不能把它与返回局部对象的地址或引用混为一谈。

### 130. 为什么不能返回局部对象的指针或引用？【B9.4 返回类型】

阅读：

```cpp
int& bad_reference()
{
    int local = 7;
    return local;
}
```

问题是什么？

**答案：** `local` 具有自动存储期，函数返回、离开其作用域后便被销毁。返回的引用随后不再绑定到一个仍然存在的对象，成为悬空引用；使用它访问原对象会产生未定义行为。返回指向该局部对象的指针也有相同问题。修正方向是返回值，或者让引用、指针所指对象的生命周期明确长于调用者的使用期。

### 131. 返回值函数和 `void` 函数有什么区别？【B9.4 返回类型】

函数返回类型写成 `void` 表示什么？它与返回 `int` 等值类型的函数有何区别？

**答案：** `void` 表示函数不向调用者返回一个普通值；这种函数可以执行操作，并可用不带表达式的 `return;` 提前返回。返回类型为 `int` 等非 `void` 类型的函数则通过返回值把计算结果交给调用表达式。返回类型还可以是引用或指针，但此时必须保证所引用或指向的对象在使用期间仍然存在。

### 132. 普通数组形参真的接收整个数组吗？【B9.5 数组参数】

阅读声明：

```cpp
void inspect(int values[]);
```

形参 `values` 在函数类型中会被怎样调整？

**答案：** 在函数形参中，`int values[]` 会调整为 `int* values`。函数并没有按值接收整个数组，也不会仅凭这种形参自动得到数组长度。即使方括号内写了一个数，普通数组形参仍按相应指针处理，不能把该写法当作运行期边界保证。

### 133. 为什么数组形参上的 `sizeof` 得不到原数组长度？【B9.5 数组参数】

阅读：

```cpp
void inspect(int values[])
{
    sizeof(values);
}
```

这里的 `sizeof(values)` 查询的是什么？

**答案：** 因为数组形参已经调整为指针，所以 `sizeof(values)` 查询的是指针对象的大小，不是调用者原数组占用的总大小，也不能据此计算元素个数。若函数需要长度，基础做法是把长度作为另一个参数显式传入。还不能假设指针大小等于某个固定字节数。

### 134. 怎样让数组形参保留长度信息？【B9.5 数组参数】

比较下面两个声明：

```cpp
void first(int values[]);
void second(int (&values)[4]);
```

它们对数组长度信息的处理有何不同？

**答案：** `first` 的数组形参调整为 `int*`，不保留调用者数组的长度。`second` 的形参是“对含四个 `int` 元素的数组的引用”，因此只能绑定到对应类型和长度的数组，长度 `4` 是形参类型的一部分。`std::array` 和 `std::vector` 作为参数时也不会发生这种普通内建数组形参调整，它们各自通过容器接口提供大小信息。

### 135. 能否只按返回类型重载函数？【B9.6 函数重载】

下面两个声明能否构成合法重载？

```cpp
int convert(int value);
double convert(int value);
```

**答案：** 不能。两个函数具有相同的函数名和相同的参数列表，只有返回类型不同；C++ 不允许仅靠返回类型区分重载。调用 `convert(1)` 时，语言不能仅从调用表达式决定要选哪一个返回类型。合法重载需要参数列表存在可用于重载决议的差异。

### 136. 重载匹配中的“精确、提升、转换”有何作用？【B9.6 函数重载】

阅读：

```cpp
void pick(int value);
void pick(long value);

short number = 1;
pick(number);
```

会选择哪个重载？

**答案：** 会选择 `pick(int)`。`short` 实参到 `int` 属于整数提升，而到 `long` 属于一般转换；基础匹配等级中，提升优于一般转换。总体上，精确匹配优于提升，提升又优于一般转换。重载决议会比较可行候选所需的转换质量，而不是简单选择“看起来更大”的类型。

### 137. 隐式转换怎样造成重载二义性？【B9.6 函数重载】

阅读：

```cpp
void choose(long value);
void choose(double value);

choose(1);
```

这个调用能否唯一选出重载？

**答案：** 不能。实参 `1` 的类型是 `int`；`int` 到 `long` 和 `int` 到 `double` 在这里都属于一般转换，没有一个候选因为转换等级更好而胜出，所以调用二义，程序非良构，编译器需要诊断。可以通过提供更精确的重载，或在调用处明确转换到所需类型来消除二义性。

### 138. 默认实参与重载为何可能共同造成二义性？【B9.6 函数重载】

阅读：

```cpp
void show(int value);
void show(int value, int width = 0);

show(1);
```

调用是否合法？

**答案：** 调用二义。第一个重载直接接受一个 `int`；第二个重载也可以用一个 `int` 调用，因为第二个形参有默认实参。两个候选对显式提供的实参都是精确匹配，无法唯一选出更好的函数。修正时应调整重载集合或默认实参设计，使一个调用形式只对应一个最佳候选。

### 139. 默认实参为什么只能省略尾部参数？【B9.7 默认实参】

给定：

```cpp
void configure(int width, int height = 10, int depth = 20);
```

哪些尾部实参可以省略？能否只省略 `height` 而显式提供 `depth`？

**答案：** 可以调用 `configure(5)`，让 `height` 和 `depth` 都使用默认值；也可以调用 `configure(5, 6)`，只让 `depth` 使用默认值；还可以提供三个实参。不能跳过中间的 `height` 而只为 `depth` 提供普通位置实参，因为调用中的实参按位置依次对应形参，默认实参只能补足省略的尾部形参。

### 140. 默认实参在什么位置确定？【B9.7 默认实参】

判断：“默认实参属于函数定义运行时计算出的固定部分，所以调用点看不到声明中的默认值也没有关系。”

**答案：** 错误。默认实参在调用点根据该处可见的声明确定，调用处必须能看到相应默认值。默认值通常写在声明处；同一作用域中不能为同一个形参重复提供同一个默认实参。定义和声明的组织必须避免重复指定，同时确保需要省略实参的调用点能看到默认值。

### 141. `inline` 是否保证生成内联机器码？【B9.8 `inline`】

判断：“函数写了 `inline`，编译器就必须消除函数调用并把函数体复制到调用处。”

**答案：** 错误。`inline` 不保证编译器采用某种机器码内联优化；是否做这种优化由实现根据情况决定。`inline` 的主要语言作用与单一定义规则有关，使符合要求的一致定义可以出现在多个翻译单元中。因此，不应把它当成强制性能指令。

### 142. 为什么 `inline` 函数定义通常放在头文件？【B9.8 `inline`】

多个源文件都要调用同一个 `inline` 函数时，为什么通常把定义放入带保护的头文件？

**答案：** 每个使用该 `inline` 函数的翻译单元通常都需要看到其定义。把定义放在头文件中可让多个源文件包含同一份定义文本；语言允许 `inline` 函数在多个翻译单元中出现定义，但这些定义必须满足一致性要求。头文件保护解决同一翻译单元中的重复包含问题，而 `inline` 的 ODR 规则处理符合要求的跨翻译单元定义。

### 143. `constexpr` 函数只能在编译期调用吗？【B9.9 C++11 `constexpr` 函数】

阅读：

```cpp
constexpr int square(int value)
{
    return value * value;
}

constexpr int fixed = square(4);
int input = 5;
int ordinary = square(input);
```

两个调用是否合法？

**答案：** 都合法。`square(4)` 满足常量表达式所需条件，可以用于初始化 `constexpr` 对象 `fixed`；`square(input)` 也可以作为普通函数调用，用于初始化非 `constexpr` 对象 `ordinary`，语言不要求它成为编译期常量。`constexpr` 表示函数在满足条件时能够参与常量表达式，而不是禁止运行期调用。

### 144. C++11 的 `constexpr` 函数体可以任意写多条语句吗？【B9.9 C++11 `constexpr` 函数】

下面定义是否符合 ISO C++11？

```cpp
constexpr int double_value(int value)
{
    int result = value * 2;
    return result;
}
```

若不符合，请给出满足本题功能的最小改写。

**答案：** 不符合。C++11 对 `constexpr` 函数体限制严格，不能直接套用后续标准放宽后的多语句写法。本题可改为单一返回表达式：

```cpp
constexpr int double_value(int value)
{
    return value * 2;
}
```

这个写法是 ISO C++11 的 `constexpr` 函数形式，并且仍然可以在不要求常量表达式的场合普通调用。

### 145. 递归函数为什么必须有终止条件？【B9.10 递归】

什么是递归调用？若递归过程从不达到终止条件，会发生什么？

**答案：** 递归调用是函数在解决问题的过程中再次调用自身。正确的递归需要终止条件，并且每次递归都应朝着该条件推进；到达终止条件后，不再继续递归，已有调用才能逐层返回。若永远达不到终止条件，调用会持续增加并消耗栈空间，最终程序通常无法正常继续，但 C++11 不规定一种统一、可靠的“无限递归结果”供程序依赖。

### 146. C++11 保证尾递归优化吗？【B9.10 递归】

判断：“只要递归调用位于函数返回前的最后一步，ISO C++11 就保证它不再占用额外栈空间。”

**答案：** 错误。C++11 不保证尾递归优化。即使某种实现能够优化特定尾递归，程序也不能把这种优化当作语言保证；递归深度仍应按可能消耗栈空间来评估。递归是否终止以及最大深度是否合理，都是算法本身需要处理的问题。

### 147. 如何声明并调用一个函数指针？【B9.11 函数指针】

阅读：

```cpp
int add(int left, int right)
{
    return left + right;
}

int (*operation)(int, int) = &add;
int result = operation(2, 3);
```

`operation` 的类型和 `result` 的值分别是什么？

**答案：** `operation` 是一个函数指针：它指向“接受两个 `int` 参数并返回 `int`”的函数。初始化时把函数 `add` 的地址存入该指针；通过 `operation(2, 3)` 可以调用所指函数，所以 `result` 为 `5`。函数指针类型必须与目标函数的参数类型和返回类型相容。

### 148. 函数指针怎样形成基础回调接口？【B9.11 函数指针】

阅读：

```cpp
int apply(int left, int right, int (*operation)(int, int))
{
    return operation(left, right);
}
```

形参 `operation` 让调用者具有什么能力？

**答案：** 调用者可以把一个类型相容的函数地址传给 `apply`，由 `apply` 在内部通过该指针调用所选函数。这就是基础回调：被调用函数接收“接下来要调用哪一个函数”的信息，而不必把具体运算写死。这里的指针目标必须是接受两个 `int` 并返回 `int` 的函数。

### 149. `'\n'` 与 `std::endl` 有什么区别？【B10.5 换行与刷新】

两者都能用于输出换行，它们的关键差异是什么？

**答案：** `'\n'` 是换行字符，输出它通常只表达“在此处换行”；`std::endl` 会输出换行，并额外刷新输出缓冲区。普通换行一般不要求立即刷新，因此不应无条件把每个 `'\n'` 都换成 `std::endl`。是否刷新是输出时机和性能方面的选择，不是说其中一个写法在语言正确性上天然更高级。

### 150. 普通逐行输出应优先选择哪种换行方式？【B10.5 换行与刷新】

如果程序连续输出许多行，且每一行后都不要求内容立刻送出，下面哪种写法通常更合适？

```cpp
std::cout << "done" << '\n';
```

```cpp
std::cout << "done" << std::endl;
```

**答案：** 通常第一种更合适，因为它表达换行而不要求每行都额外刷新缓冲区。第二种也能正确输出换行，但 `std::endl` 还会刷新缓冲区；只有确实需要立即刷新时，这个额外行为才是选择它的理由。二者的差异不应被误解为 C++11 语言正确性差异。
