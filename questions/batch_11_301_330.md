# C++11 第十一批题目（301–330）

## 301【节点：R1.1】【概念】“取得一段存储”和“其中已经存在一个对象”为什么不是一回事？

**答案：** 存储只是满足一定大小与对齐要求的内存区域；对象还要求相应类型的生存期已经开始。普通 `T object(args);` 会为对象提供存储并完成初始化。底层的 `::operator new(sizeof(T))` 只取得原始存储，尚未产生 `T`；还需 placement `new` 构造，结束时显式析构并按原方式释放。仅分配或清零字节不能代替任意类的构造。业务代码应优先让普通对象、容器和智能指针管理这些细节。

## 302【节点：R1.2】【分类】下面各对象分别具有什么存储期？

```cpp
int global_value;
thread_local int thread_value;

void run(int parameter)
{
    int local;
    static int calls;
    int* pointer = new int(3);
    delete pointer;
}
```

**答案：** `global_value` 和局部 `calls` 是静态存储期；`thread_value` 是线程存储期；形参 `parameter`、局部 `local` 和指针变量 `pointer` 是自动存储期；`new int(3)` 创建的整数使用动态存储期存储。名字作用域与存储期不同：`calls` 的名字只在函数块内可见，但其对象持续到程序结束。标准规定的是四种存储期，“栈”和“堆”只是常见实现术语。

## 303【节点：R1.3】【概念】为什么 RAII 不只用于动态内存？

**答案：** 资源是任何必须成对获取和释放的有限能力，包括内存、文件、Socket、锁、线程、数据库连接和平台句柄。每类资源都有不同清理协议，例如文件关闭、互斥量解锁、线程 `join`。RAII 的共同做法是把获取放进构造，把对应释放放进析构。这样无论正常返回还是异常离开作用域，都能走统一清理路径，而不仅仅是替代 `delete`。

## 304【节点：R2.1】【代码判断】`new int`、`new int()` 和 `new int(7)` 得到的初值有何不同？

**答案：** `new int` 对该基础类型执行默认初始化，整数值不确定，赋值前不能读取；`new int()` 执行值初始化，结果为 `0`；`new int(7)` 直接初始化为 `7`。`new` 表达式先分配动态存储，再构造或初始化对象，并返回类型化指针。普通分配失败默认抛 `std::bad_alloc`；包含 `<new>` 后使用 `new (std::nothrow) T` 才是失败返回空指针的另一形式。

## 305【节点：R2.2】【未定义行为】哪些指针可以传给 `delete`？

**答案：** `delete p;` 要求 `p` 为空，或指向由相容的单对象 `new` 表达式得到且尚未释放的动态对象；允许经基类指针删除派生对象时，基类还必须满足虚析构等删除要求。数组 `new[]` 必须使用 `delete[]`。`delete nullptr` 安全且无效果。不能删除自动对象地址、对象内部成员地址、已经释放的地址，也不能重复删除。`delete` 先调用析构再释放存储，但不会自动把原指针变量改为 `nullptr`，其他保存同一地址的别名也不会自动清空。

## 306【节点：R2.3】【纠错】下面动态数组代码有什么错误？更推荐怎样表示动态序列？

以下是某个函数体中的待纠错片段：

```cpp
int* values = new int[10]();
// 使用 values
delete values;
```

**答案：** `new int[10]()` 使用数组形式，必须与 `delete[] values;` 配对；原代码错用单对象 `delete`，行为未定义。裸指针还不记录数组长度，也不检查下标。日常可变长度序列优先写 `std::vector<int> values(10);`，它保存长度并自动释放。确需只有数组所有权时可用 C++11 的 `std::unique_ptr<int[]>`。

## 307【节点：R2.4】【辨析】内存泄漏、悬空指针、释放后使用和重复释放分别是什么？

**答案：** 泄漏是仍占有资源却失去最后一个可释放它的所有权路径；悬空指针是目标对象生命已经结束、指针仍保存旧地址；释放后使用是继续解引用这种指针；重复释放是对同一动态对象执行两次释放。`new/delete`、`new[]/delete[]`、`malloc/free` 必须各自配对，不能混用。把一个指针设为 `nullptr` 只改变该变量，无法修复其他别名。

## 308【节点：R2.5】【接口设计】裸指针 `T*` 能表达哪些信息，不能表达哪些信息？

**答案：** 它表达一个地址以及目标静态类型，可作为可空观察者、数组首位置或底层接口参数；它本身不说明谁负责释放、是否指向数组、数组长度、能否为空或目标还能活多久。只读可空借用常写 `void inspect(const T*)`，确定非空借用常写 `void inspect(const T&)`，所有权转移则应优先用智能指针等明确类型。看到裸指针不能擅自调用 `delete`。

## 309【节点：R3.1】【概念】RAII 的构造和析构分别应承担什么责任？

**答案：** RAII 对象的构造要么成功取得资源并建立完整有效状态，要么抛异常而不留下可用的半成品；析构在对象生命结束时安全释放当前真正拥有的资源，通常不能传播异常。下面是结构示意片段，`acquire` 与 `release` 代表已经声明的资源 API：

```cpp
class Guard {
public:
    Guard() { acquire(); }
    ~Guard() noexcept { release(); }
};
```

RAII 不要求资源一定在堆上，它利用的是 C++ 自动调用析构函数的生命期规则。

## 310【节点：R3.2】【控制流】哪些离开作用域的方式会析构已经构造成功的自动对象？

**答案：** 顺序到达块末尾，或因 `return`、`break`、`continue`、跳出作用域的 `goto` 和异常展开而离开相应作用域时，已成功构造的自动类对象都会按构造逆序析构。这叫确定性清理。若对象构造本身尚未成功，不调用该完整对象析构，但已构造的成员和基类会清理。`std::abort`、崩溃等异常终止路径不能保证执行所有普通局部析构，所以 RAII 也不是进程灾难恢复机制。

## 311【节点：R3.3】【设计题】一个独占文件句柄 RAII 类至少要决定哪些语义？

**答案：** 它要定义无效句柄值、获取失败处理、析构时如何关闭、复制是深复制还是禁止、移动后源状态、显式关闭失败怎样报告。独占句柄通常在类定义中加入以下声明片段来删除复制：

```cpp
Handle(const Handle&) = delete;
Handle& operator=(const Handle&) = delete;
```

并提供 `noexcept` 移动，把句柄转给目标后将源设为无效值。获取和释放必须使用同一资源 API。可失败的关闭最好另有显式 `close()`，析构只做不抛兜底。

## 312【节点：R3.4】【概念】基本保证、强保证和不抛保证分别承诺什么？

**答案：** 基本保证要求操作失败后无资源泄漏、对象仍满足不变量并可继续使用，但值可能改变；强保证要求失败后保持调用前状态，像事务回滚；不抛保证承诺异常不会逃出，常用 `noexcept` 表达。实现强保证的常见思路是先在临时对象中准备全部新状态，成功后用不抛操作一次提交。并非每个接口都必须提供强保证，但必须明确承诺。

## 313【节点：R3.5】【异常设计】资源释放可能失败时，为什么只依靠析构函数不够？

**答案：** 析构可能在异常展开期间运行，也通常没有方便的调用者接收错误；让异常从析构函数逃出可能导致 `std::terminate`，静默吞错又可能隐藏数据丢失。合理设计是提供显式 `close()`、`commit()` 或 `join()`，让正常流程主动调用并处理错误；析构检查资源是否仍持有，并执行不能抛出的最终清理或记录策略。关键持久化操作应在析构前显式确认成功。

## 314【节点：R4.1】【分类】表达式 `x`、`std::move(x)` 和 `T{}` 分别属于哪种值类别？

**答案：** 具名对象表达式 `x` 通常是左值 `lvalue`；`std::move(x)` 是将亡值 `xvalue`；临时构造表达式 `T{}` 在 C++11 中是纯右值 `prvalue`。基本类别是 lvalue、xvalue、prvalue；`glvalue = lvalue + xvalue`，`rvalue = prvalue + xvalue`。值类别属于表达式，不是对象永远固定的附加类型；同为 `int` 类型的表达式也可有不同类别。

## 315【节点：R4.2】【引用绑定】`T&` 与 `const T&` 的主要绑定范围有什么差别？

**答案：** 非常量左值引用 `T&` 通常绑定类型相容、可修改的左值；`const T&` 还可绑定常量对象、转换结果和临时对象。引用定义时必须初始化，之后不能改绑；给引用赋值是在修改所绑定对象。直接用局部 `const T&` 绑定临时可按规则延长临时生命。返回局部变量引用仍会悬空，引用也不应被当作可空指针。

## 316【节点：R4.3】【易错点】为什么有名字的右值引用变量在表达式中是左值？

**答案：** 声明 `Widget&& reference = Widget();` 中变量的类型是右值引用，但表达式 `reference` 有稳定名字和身份，所以它是左值。调用重载时，`use(reference)` 会选择左值入口；若确定可放弃其当前值，要写 `use(std::move(reference))`。`T&&` 只说明绑定和类型规则，不会自动移动数据；模板推导中的特定 `T&&` 还可能是转发引用。

## 317【节点：R4.4】【生命周期】引用变量活得更久，是否必然让被引用对象也活得更久？

**答案：** 不必然。只有标准规定的直接绑定情形才延长临时生命，例如局部 `const T& r = T{};`。把引用复制给另一个引用、经函数参数转交、从函数返回引用，通常不会再次延长目标生命。`const T& bad() { return T{}; }` 返回后就是悬空引用。必须分别检查引用对象自身的存储期和目标对象的生命期。

## 318【节点：R5.1】【概念】`std::move` 是否会亲自移动资源？

**答案：** 不会。包含 `<utility>` 后，`std::move(expression)` 主要把表达式转换为可匹配右值重载的将亡值形式。真正的资源转移由随后选择的移动构造、移动赋值或其他 `T&&` 重载完成。如果类型没有移动操作，调用仍可能退回复制。对 `const T` 使用 `std::move` 通常得到 `const T&&`，不能交给需要修改来源的普通移动构造，因此也常发生复制。

## 319【节点：R5.2】【实现】移动构造函数接管独占指针后必须怎样处理源对象？

**答案：** 典型签名是 `Buffer(Buffer&& other) noexcept`。目标取得 `other` 的指针和长度后，要把源指针设为 `nullptr`、长度设为 `0`，使源仍能安全析构而不会重复释放。移动后的精确值由类型契约决定；标准库类型通常保证“有效但状态未指定”，并不保证一定为空。自定义类型至少必须维持自己公开承诺和可安全销毁。

## 320【节点：R5.3】【实现】移动赋值与移动构造相比多了哪项责任？

**答案：** 移动赋值的目标对象已经存在，可能拥有旧资源，所以必须先正确处理旧资源，再接管来源，并返回 `*this`。对应的类内声明片段是：

```cpp
T& operator=(T&& other) noexcept;
```

实现还应考虑 `object = std::move(object)` 这种自移动，不能因接管和释放顺序错误而重复释放。移动构造的目标尚无旧状态，因此没有“先清理目标旧资源”这项责任。

## 321【节点：R5.4】【判断】标准库对象移动后是否必然为空？还能做什么？

**答案：** 不必然。通常保证是“有效但状态未指定”：对象不变量仍成立，可安全析构，也可执行没有额外前置条件的操作，最稳妥的恢复方式是重新赋值。不能断言原元素、大小或资源一定保持或一定清空，除非该类型文档另有明确保证。“状态未指定”仍受标准约束，不等同于未定义行为。

## 322【节点：R5.5】【容器关系】为什么移动构造的 `noexcept` 会影响 `vector` 扩容？

**答案：** 扩容要把旧元素搬到新存储。若移动中途抛异常，部分旧元素可能已被改变，容器难以保持强异常保证；因此当复制可用而移动可能抛时，实现通常复制旧元素。若移动构造真实地声明为 `noexcept`，容器可放心移动。`noexcept` 不是吞异常：被标记函数若仍让异常逃出，会调用 `std::terminate`，所以不能为了性能虚假标注。

## 323【节点：R5.6】【优化】返回局部对象时是否应该写 `return std::move(local);`？

**答案：** 通常不应该。`return local;` 可能触发 NRVO，让 `local` 直接在调用方目标存储中构造；强行 `std::move(local)` 往往阻止这种具名返回值优化。C++11 的复制消除在相关场景通常是允许而非 C++17 式全面强制，因此仍应存在可访问的复制或移动路径。先写清楚的按值返回，让编译器应用消除，是常见正确做法。

## 324【节点：R6.1】【概念】`std::unique_ptr<T>` 的“独占所有权”意味着什么？

**答案：** 同一时刻只有一个 `unique_ptr` 负责通过其删除器释放目标。它不可复制，但可用 `std::move` 转移；离开作用域时若非空会自动清理。可用 `*owner`、`owner->member` 访问目标，用 `if (owner)` 判断是否非空。独占所有权不禁止临时裸指针观察，但观察者不得删除目标，也不得比所有者管理的对象活得更久。

## 325【节点：R6.2】【版本边界】严格 C++11 怎样创建 `unique_ptr`？为什么不能写 `make_unique`？

**答案：** 假定 `Widget` 已定义，且 `args` 表示与其构造函数匹配的实参，C++11 的构造表达式片段可写：

```cpp
std::unique_ptr<Widget> owner(new Widget(args));
```

也可默认构造为空。`std::make_unique` 从 C++14 才进入标准库，所以严格 `-std=c++11` 不能依赖它。应在同一个简单表达式中立即把新对象交给所有者，不要长期保留中间裸指针；复杂函数实参中可先分别建立好 RAII 对象，再调用函数。

## 326【节点：R6.3】【接口辨析】`get()`、`release()` 和 `reset()` 分别改变所有权吗？

**答案：** `get()` 只返回当前裸指针供观察，所有权不变；`release()` 返回裸指针并让 `unique_ptr` 放弃所有权，但不删除对象，调用者必须立刻安排新的所有者或正确释放；`reset(p)` 删除旧目标并接管新指针，无参 `reset()` 清空。把 `owner.get()` 交给另一个智能指针会制造双重所有权；忽略 `release()` 返回值会泄漏。

## 327【节点：R6.4】【数组】`unique_ptr<T>` 和 `unique_ptr<T[]>` 有何不同？

**答案：** `unique_ptr<T>` 默认使用单对象 `delete`，`unique_ptr<T[]>` 是动态数组特化，使用 `delete[]` 并提供 `operator[]`。假定 `count` 是合法的非负数组长度，使用片段是：

```cpp
std::unique_ptr<int[]> values(new int[count]());
values[0] = 3;
```

数组特化仍不保存长度、也不检查下标。大多数已知大小或可变大小序列使用 `std::vector<T>` 更安全、接口更完整，不能混用两种 `unique_ptr` 形式。

## 328【节点：R6.5】【资源管理】如何让 `unique_ptr` 管理 `FILE*`？

**答案：** 自定义删除器把非 `delete` 资源的清理函数封装进类型：

```cpp
#include <cstdio>
#include <memory>

struct CloseFile {
    void operator()(std::FILE* file) const
    {
        if (file) std::fclose(file);
    }
};

std::unique_ptr<std::FILE, CloseFile> file(std::fopen("data.txt", "r"));
```

删除器类型是 `unique_ptr` 类型的一部分，并可能影响智能指针大小。获取失败时 `file` 为空，析构不会错误关闭。

## 329【节点：R6.6】【接口设计】函数参数怎样区分接管、借用和修改 `unique_ptr` 本身？

**答案：** 按值 `void consume(std::unique_ptr<T> value)` 表示接管，调用方必须 `consume(std::move(owner))`；只使用目标对象时传 `const T&`，可空借用传 `const T*`；只有函数要重置或替换调用方的智能指针时才传 `std::unique_ptr<T>&`。仅观察目标却传 `const unique_ptr<T>&` 会把所有权实现细节不必要地暴露给接口。

## 330【节点：R7.1】【概念】`shared_ptr` 的共享计数保护了什么，不保护什么？

**答案：** 复制 `std::shared_ptr<T>` 会共享同一控制块并增加强引用计数，移动只转移一个拥有者，最后一个拥有者消失时删除对象。控制块的所有权管理允许不同线程操作各自的 `shared_ptr` 副本，但不保证 `T` 的普通业务字段线程安全；并发修改目标仍需同步。共享所有权也有计数和生命周期复杂度，只有确实存在多个共同所有者时才应使用。
