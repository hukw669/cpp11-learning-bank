# C++11 第十六批题目（451–480）

## 451【节点：S10.6】【相邻去重】`std::unique` 能否删除区间中所有重复值并缩小容器？

**答案：** 它只压缩“相邻且等价”的元素组，把每组保留一个并返回新的逻辑结尾；它不认识容器，不能改变 `size()`。例如序列 `1,1,2,2,1` 经 `unique` 后逻辑结果是 `1,2,1`，最后的 `1` 因原本不相邻而保留。顺序容器还要调用 `erase(new_end,end())` 才真正缩小。若要按值全局去重，常先排序，再执行 `unique` 和 `erase`；这会改变原顺序。`list::unique` 是成员函数，会直接删除相邻重复节点。

## 452【节点：S10.7】【重排辨析】`reverse`、`rotate`、`partition` 和 `stable_partition` 分别怎样改变区间？

**答案：** `reverse` 颠倒整个范围；`rotate(first,middle,last)` 把后段 `[middle,last)` 移到前面，并保持两段各自内部次序；`partition` 把谓词为真的元素放在假的元素之前，但不保证两组内部原顺序；`stable_partition` 在分组时保留内部顺序。它们通常不改变容器大小，只改变元素位于哪些位置。`reverse` 通常至少需要双向迭代器，`rotate` 和 `partition` 可使用前向迭代器。C++11 的 `rotate` 返回原 `first` 元素旋转后的新位置。

## 453【节点：S10.8】【堆流程】使用堆算法加入和移除顶部元素时，为什么还要调用容器的 `push_back`、`pop_back`？

**答案：** 堆算法只重排随机访问区间，不改变容器大小。先用 `make_heap` 建堆；加入元素时先 `push_back` 把新元素放到末尾，再对整个范围调用 `push_heap`；取出顶部时先 `pop_heap`，它把顶部移到末尾并使前缀继续成堆，然后读取末尾并由容器 `pop_back` 删除。默认是最大堆，所有步骤必须使用相容比较器。`make_heap` 为线性级，`push_heap`、`pop_heap` 为对数级；`sort_heap` 排序后，范围不再保持原堆结构。

## 454【节点：S10.9】【累加类型】为什么对 `vector<double>` 调用 `accumulate(..., 0)` 可能丢失小数？

**答案：** `accumulate` 的累加器类型由初始值类型决定。字面量 `0` 是 `int`，每一步结果会转换回整数累加器，小数部分可能被截断；应按目标类型写 `0.0` 或显式的 `double` 初值。`accumulate`、`inner_product`、`partial_sum`、`adjacent_difference` 和 `iota` 位于 `<numeric>`，不在 `<algorithm>`。输出型数值算法要求目标已有足够元素，`inner_product` 的第二输入虽只给起点，调用者仍须保证长度足够。

## 455【节点：S10.10】【随机重排】C++11 中怎样让 `shuffle` 的结果可复现？`random_device` 是否必然是真随机硬件？

**答案：** 构造随机引擎时使用并记录固定种子，例如 `std::mt19937 engine(12345);`，再把引擎传给 `std::shuffle`，相同实现和状态下便可复现实验。需要变化种子时可用 `std::random_device` 产生种子，但它是否连接非确定性来源由实现决定，不能一概称为硬件真随机。引擎应保留状态，不要每次操作都用相同种子重新建立。`shuffle` 需要随机访问迭代器，也不承诺密码学安全；新代码不应依赖后来被移除的 `random_shuffle`。

## 456【节点：S11.1】【可调用类】什么是函数对象？它比普通函数指针多表达什么？

**答案：** 定义了 `operator()` 的类对象可以写成 `object(args...)`，称为函数对象或仿函数。它既能被算法调用，又能用数据成员保存阈值、配置或状态：

```cpp
struct GreaterThan {
    explicit GreaterThan(int limit) : limit_(limit) {}
    bool operator()(int value) const { return value > limit_; }
private:
    int limit_;
};

int main()
{
    GreaterThan test(10);
    return test(12) ? 0 : 1;
}
```

Lambda 产生的闭包也是匿名函数对象。算法可能复制函数对象，保存引用时还要保证目标存活；只读调用通常把 `operator()` 声明为 `const`。

## 457【节点：S11.2】【标准函数对象】严格 C++11 中 `std::less<int>`、`std::greater<int>` 和 `std::plus<int>` 各做什么？

**答案：** `<functional>` 提供把常见运算包装成对象的模板。`std::less<int>()(a,b)` 计算 `a < b`，`std::greater<int>()` 计算 `a > b`，`std::plus<int>()` 计算加法；还有减、乘、除、取模、相等和逻辑等类型。它们便于把运算作为值传给算法和容器，但不会改变整数溢出、整数除法等基础规则。C++11 必须写具体类型；透明的 `std::less<>` 是 C++14，不能混入严格 C++11 示例。

## 458【节点：S11.3】【比较契约】严格弱序必须满足哪些核心性质？违反后只是排序不好看吗？

**答案：** 比较器 `comp(a,b)` 表示“a 严格排在 b 前面”。它必须非自反，即 `comp(a,a)` 为假；非对称，即 `comp(a,b)` 为真时反向为假；具有传递性；由双向都不成立得到的等价关系也要传递。写 `a <= b` 会立即破坏非自反。比较器也不能依赖会在调用间任意变化的状态。违反这些性质不是普通的“排序偏好不同”，而是破坏算法或有序容器前置条件，可能产生错误结果甚至未定义行为。

## 459【节点：S11.4】【调用合同】编译成功是否证明标准算法的区间和前置条件都正确？

**答案：** 不能。类型检查通常无法证明两个迭代器来自同一有效范围、输出区间容量足够、二分范围已经按相同比较器排序、堆算法所需前缀真的是堆、输入输出重叠合法，或元素在运行时仍存活。算法也通常不会为了检查全部合同而付出额外成本。调用者应靠数据结构不变量、断言和测试建立前置条件。违反后的结果由具体合同决定，可能是未定义行为或无意义结果，并不统一表现为抛异常。

## 460【节点：S12.1】【性能判断】`emplace_back` 为什么不保证比 `push_back` 更快？

**答案：** `emplace_back(args...)` 有机会直接在目标位置构造元素，省去一个临时元素的移动或复制；但参数仍需计算，构造函数内部仍可能分配，`vector` 扩容仍要搬迁旧元素，而廉价移动和复制消除可能已经让 `push_back` 足够高效。若手头已有一个 `T`，写 `push_back(value)` 往往更清楚。两者尾插都是摊销常数，扩容规律相同。严格 C++11 的 `vector::emplace_back` 返回 `void`，返回 `T&` 是 C++17。

## 461【节点：S12.2】【构造路径】为什么 `tokens.emplace_back(7)` 可能合法，而 `tokens.push_back(7)` 不合法？

**答案：** 若元素类型只有 `explicit Token(int)`，`emplace_back(7)` 对元素执行直接初始化，可以选择该显式构造函数；`push_back(7)` 要先把整数隐式转换成 `Token`，而 `explicit` 禁止这种转换。显式写 `push_back(Token(7))` 则合法，并更明显地表达目标类型。`emplace` 不会绕过私有访问、删除函数或参数类型检查，只是改变构造发生的位置。它也可能意外选择调用者没有注意到的构造重载，所以不是机械替换规则。

## 462【节点：S12.3】【资源陷阱】唯一键容器 `emplace` 失败时，传入的右值资源一定保持原样吗？

**答案：** 不能作这种普遍保证。唯一键已存在时，容器不会覆盖旧元素，返回值会报告失败；但实现可能在确认重复前已经构造候选对象，从而移动了实参。严格 C++11 没有 `try_emplace`，若失败后必须保留昂贵或独占资源，可先 `find`，确认缺失后再移动并检查插入结果。不过“先查再插”不是并发原子操作，外部并发访问仍需同步。`try_emplace`、`insert_or_assign` 都是 C++17 功能。

## 463【节点：S12.4】【移动后状态】写过 `container.push_back(std::move(source))` 后，`source` 是否已经死亡或必为空？

**答案：** 都不是。`std::move` 只把表达式转换成可选择移动重载的形式；若确实移动，源对象生命仍继续。标准库类型通常保证源对象“有效但状态未指定”：可以析构、重新赋值，或调用不要求特定当前值的操作，但不能擅自断言其内容或是否为空。某些类型另有更强合同，例如移动后的 `unique_ptr` 明确为空。若没有可用移动重载，代码还可能执行复制；对标量使用 `move` 通常没有资源转移意义。

## 464【节点：S13.1】【底层存储】分配器的 `allocate` 与对象构造为什么是两个不同步骤？

**答案：** 分配器是容器取得和归还原始存储的策略。`allocate(n)` 只取得足以容纳 `n` 个元素且满足要求的存储，其中还没有活着的 `T` 对象；随后要在具体地址构造对象，结束时先析构对象，再用兼容的分配器和正确数量 `deallocate`。这种分离允许内存池、共享内存或调试统计等策略。普通代码应让容器完成异常安全的组合，不要把分配器当垃圾回收器，也不能读取尚未构造的存储。

## 465【节点：S13.2】【统一接口】`allocator_traits<Alloc>` 为泛型容器解决什么问题？

**答案：** 不同分配器可能省略可推导的辅助类型或操作，`std::allocator_traits` 在 C++11 中提供统一访问和默认适配。泛型代码可通过 `Traits::pointer`、`allocate`、`construct`、`destroy`、`deallocate` 等接口工作，并用 `rebind_alloc<U>` 把同一分配策略用于内部节点类型 `U`。生产代码必须精确记录哪些对象已经构造，否则异常清理可能漏析构或重复析构。后续标准调整过部分分配器接口，不能把新版示例默认当成 C++11。

## 466【节点：S13.3】【有状态分配器】容器复制赋值、移动赋值和交换时，为什么要考虑分配器传播？

**答案：** 有状态分配器可能代表不同内存池，由池 A 取得的存储不能错误交给池 B 释放。C++11 用 `propagate_on_container_copy_assignment`、`propagate_on_container_move_assignment` 和 `propagate_on_container_swap` 三个布尔类型声明传播策略。移动赋值时，若分配器不传播且两者不相等，容器可能必须逐个移动元素，不能直接接管存储；交换时若不传播且分配器不相等，调用 `swap` 不满足 C++11 合同，行为未定义。`allocator_traits::is_always_equal` 是 C++17，不属于这里。

## 467【节点：X01】【易混复习】类和对象是不是同一个概念？

**答案：** 不是。类是类型说明，规定成员及可执行操作；对象是该类型的一次实际实例，拥有自己的状态和生命周期。定义 `class Student { public: int score; };` 只定义类型，`Student alice{};` 才创建对象，另一个 `Student bob{}` 具有独立的 `score`。对象也不限于类实例，`int number;` 中的 `number` 同样是对象。类名本身不能像对象一样读写非静态成员。这一类型与对象区分是 ISO C++11 语言规则，不依赖特定编译器。

## 468【节点：X02】【易混复习】声明和定义是什么关系？头文件与 `.cpp` 的安排是不是 ISO 强制布局？

**答案：** 声明把名字和类型信息介绍给翻译单元，例如 `int add(int,int);` 或 `extern int total;`；定义还提供函数体、对象实体或完整类体，例如 `int add(int a,int b){ return a+b; }`。定义同时具有声明作用，声明不必是定义；`class Node;` 是前向声明，完整类体才是类定义。声明、定义和 ODR 是 ISO C++11 规则；把共享声明放头文件、唯一非内联定义放 `.cpp` 是配合分离编译的工程组织惯例，文件扩展名本身不是标准强制。

## 469【节点：X03】【易混复习】带等号的 `T second = first;` 为什么仍可能是初始化而不是赋值？

**答案：** 判断标准是是否正在建立新对象。声明中的 `T second = first;` 是复制初始化，通常调用复制构造；对象已经存在后写 `second = first;` 才是复制赋值。初始化建立对象的初始状态，赋值替换已有状态。引用、`const` 成员等必须在初始化阶段正确建立，不能留到构造函数体再赋值。这是 ISO C++11 的对象初始化语义，不是编译器优化习惯。

## 470【节点：X04】【易混复习】“默认构造函数”和“编译器生成的构造函数”是同一分类吗？

**答案：** 不是。默认构造函数指能够不传实参调用的构造函数，例如 `Widget()`，甚至 `Widget(int value = 0)` 也可成为默认构造函数；“编译器隐式生成”描述函数来源。程序员声明的 `Widget() = default;` 仍是明确声明后请求默认实现。一旦用户声明某些构造函数，隐式无参构造可能不再产生；`Widget object();` 又是函数声明而非对象。以上均是 ISO C++11 语法与生成规则。

## 471【节点：X05】【易混复习】构造函数成员初始化列表与 `std::initializer_list` 有什么区别？

**答案：** 成员初始化列表位于构造函数参数后的冒号处，例如 `Box(int n) : value_(n) {}`，用于初始化基类和成员；`std::initializer_list<T>` 是标准库视图类型，可让构造函数接收花括号元素序列，例如 `Numbers(std::initializer_list<int>)`。两者名字相似但机制不同。花括号重载决议会优先考虑可行的 `initializer_list` 构造并检查窄化；冒号列表的书写顺序又不能改变成员真实初始化顺序。这些是 ISO C++11 规则。

## 472【节点：X06】【易混复习】成员初始化顺序由初始化列表顺序决定吗？

**答案：** 不由。先初始化基类，再严格按数据成员在类体中的声明顺序初始化，最后进入构造函数体；初始化列表只是提供各项初始化表达式。因此若先声明 `first_` 再声明 `second_`，即使列表写 `second_(...), first_(...)`，仍先构造 `first_`。应让列表书写顺序与声明顺序一致，并避免后声明成员被先声明成员的初始化读取。顺序本身是 ISO C++11 规则；开启重排警告属于编译器工程措施。

## 473【节点：X07】【易混复习】复制构造与复制赋值在资源责任上有何不同？

**答案：** 复制构造用旧对象建立新对象，典型签名 `T(const T&)`；复制赋值修改已经存在的目标，典型签名 `T& operator=(const T&)`。后者还必须妥善处理目标旧资源、自赋值和失败时的状态；前者没有目标旧状态。`T b(a)` 与 `T b = a` 都是构造，先有 `b` 再写 `b=a` 才是赋值。调用区分和特殊成员语义属于 ISO C++11；Rule of Three/Five 是建立在这些规则上的设计经验。

## 474【节点：X08】【易混复习】`= default` 与 `= delete` 是否都意味着“不用自己写函数体”？

**答案：** 表面都没有普通函数体，但含义相反。`= default` 请求编译器依语言规则生成某个特殊成员的默认实现；成员或基类不支持该操作时，它仍可能被定义为删除。`= delete` 则声明函数存在但禁止调用，且它仍参与重载决议；若成为最佳匹配，程序报错而不会退到较差候选。两种语法和重载效果都是 ISO C++11 规则，不是编译器私有扩展。

## 475【节点：X09】【易混复习】重载、隐藏和覆盖怎样快速区分？

**答案：** 重载发生在同一作用域，同名函数具有不同参数列表并共同参与选择；隐藏是内层或派生作用域出现同名声明，使外层同名集合在普通名字查找中不可见，签名无需相同；覆盖是派生虚函数与基类虚函数正确匹配，参与动态分派。`using Base::f;` 可重新引入被隐藏的基类重载，`override` 可检查覆盖。三者的名字查找和虚调用规则属于 ISO C++11；用命名规范避免混淆是工程实践。

## 476【节点：X10】【易混复习】`virtual` 和 `override` 分别建立、检查什么？

**答案：** 基类中的 `virtual` 建立虚调用机制；派生类的匹配函数即使不重复写 `virtual` 仍保持虚性。C++11 的 `override` 要求编译器验证该声明确实覆盖基类虚函数，能发现遗漏 `const`、参数不一致等错误；它不会把原本非虚函数变虚。`final` 可阻止后续覆盖或派生。这些关键字语义是 ISO C++11；项目统一要求写 `override` 属于有益的编码规范。

## 477【节点：X11】【易混复习】什么时候优先组合，什么时候公有继承才合适？

**答案：** 组合把另一个对象作为成员，表达“拥有一个组件”；公有继承应表达派生对象能在需要基类的位置保持同一契约，即可替换的 `is-a`。只为复用实现就公有继承，常引入不必要的虚析构、切片、动态分派和耦合问题，业务资源复用通常先考虑组合。成员和继承的对象模型是 ISO C++11；“优先组合”和 `has-a/is-a` 是设计指导，不是标准强制架构。

## 478【节点：X12】【易混复习】已经取得 `sizeof(T)` 字节，是否就能立刻把它当作 `T` 使用？

**答案：** 不能。存储只是满足大小与对齐要求的一片字节；还必须按规则开始 `T` 的对象生命，例如在合适地址执行 placement `new`。结束时先调用析构，再用匹配方式释放存储。未构造就调用成员、手工析构后继续使用或忽略对齐都会违反对象生命期。存储与活对象的区别是 ISO C++11 规则；把内存称作“栈/堆”及具体布局多为实现术语，普通代码应交给 RAII 和容器。

## 479【节点：X13】【易混复习】看到函数参数 `T*`，能否断定调用者把所有权交给函数？

**答案：** 不能。裸指针只编码地址和静态目标类型，本身不说明是否拥有、能否为空、是否为数组、长度和释放责任。C++11 的 `unique_ptr<T>` 可明确表达独占转移，`shared_ptr<T>` 表达共同所有权；`const T*` 常被接口设计成可空只读借用，但这仍是项目约定而非裸指针类型强制语义。指针和智能指针行为属于 ISO C++11；“裸指针默认观察者”的解释是现代接口设计惯例，仍需文档说明生命期。

## 480【节点：X14】【易混复习】为什么 `std::move(source)` 本身没有移动任何字节或资源？

**答案：** `std::move` 主要是一次类型和值类别转换，让后续表达式有机会选择接收右值的重载。真正的资源转移发生在被选中的移动构造、移动赋值或其他函数中；若类型只有复制构造，仍可能复制。对 `const T` 调用通常产生 `const T&&`，不能绑定常见的 `T(T&&)`，也常退回复制。转换和重载选择是 ISO C++11 规则；移动后是否为空由具体类型合同决定，不能靠实现观察猜测。
