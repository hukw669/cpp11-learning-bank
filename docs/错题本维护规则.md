# 错题本维护规则

错题本不仅记录做错的题，也记录主动追问和已经出现过的概念误区。

## 1. 自动记录条件

满足任意条件时，应记录或更新错题本：

- 用户主动提出技术问题。
- 用户回答错误或理由不完整。
- 用户表示“不知道”“不会”或只回复问号。
- 用户对已有答案继续追问“为什么”。
- 用户指出原答案可能存在错误或歧义。
- 用户明确要求写入错题本。

## 2. 去重规则

1. 先搜索现有 `WNNN` 条目。
2. 同一知识点的后续追问优先补充原条目。
3. 问题虽然相关但考查核心不同，才创建新编号。
4. 修正旧答案时保留最终正确结论，不保留误导性表述。

例如：

- “普通 `char` 为什么有符号？”应补充已有字符类型条目。
- “`int&` 是什么类型？”与字符类型无关，应创建新的引用条目。

## 3. 编号

- 使用 `W001`、`W002`……连续编号。
- 不重复使用已经存在的编号。
- 删除条目时原则上不重排历史编号；若尚未发布，可统一整理并重新验证。

## 4. 标准条目模板

```markdown
## W013：知识点标题

**问题：** 用户问题的整理版本。

**核心答案：** 一段可独立复述的结论。

### 1. 概念

详细解释。

### 2. 最小示例

```cpp
// 严格 C++11 示例
```

### 3. 易错点

- 易错点一。
- 易错点二。

**关联节点：** Bx.x

**一句话记忆：** 最短复习结论。
```

## 5. 内容质量

- 从零解释，不把 C 作为前置知识。
- 先回答用户真正困惑的地方。
- 代码示例保持最小并符合 C++11。
- 将标准保证和常见实现行为分开。
- 必要时说明错误发生在编译、链接、装载还是运行阶段。
- 若问题源于旧答案表述不准确，应明确修正。

## 6. 复习方法

1. 遮住核心答案，先口头复述。
2. 独立写出最小示例。
3. 说明一个正确用法和一个错误用法。
4. 一天后、三天后、一周后分别回看。
5. 能准确解释边界后，将该条目标记为已掌握；仓库仍保留历史记录。

## 7. 标准维护提示词

```text
将本轮技术疑问整理进错题本。
先检查是否与已有条目重复；重复则更新原条目，否则使用下一个连续 W 编号。
给出核心答案、最小 C++11 示例、易错点和一句话记忆。
不要复制原始聊天，不要写入本机路径或个人信息。
```
