# 错题本维护规则

错题本不仅记录做错的题，也记录主动追问和已经出现过的概念误区。本仓库按 C++、操作系统和计算机网络分开维护；同一问题只能有一份完整规范答案。

## 0. 文件、前缀与路由

| 学科 | 文件 | 编号与锚点前缀 |
|---|---|---|
| C++/STL/编译链接/动态库/C++并发 | `wrongbook/wrongbook.md` | `WNNN` / `wNNN` |
| 操作系统 | `wrongbook/os_wrongbook.md` | `OSWNNN` / `oswNNN` |
| 计算机网络 | `wrongbook/network_wrongbook.md` | `NETWNNN` / `netwNNN` |

先按问题的主要考查内容选择一个主错题本。跨学科问题仅在主错题本写完整条目；次要学科用相对 Markdown 链接指向主条目，并说明其关联节点，不能复制完整答案。操作系统条目关联 `OS1–OS10`，网络条目关联 `NET1–NET10`。

## 1. 自动记录条件

满足任意条件时，应记录或更新错题本：

- 用户主动提出技术问题。
- 用户回答错误或理由不完整。
- 用户表示“不知道”“不会”或只回复问号。
- 用户对已有答案继续追问“为什么”。
- 用户指出原答案可能存在错误或歧义。
- 用户明确要求写入错题本。

## 2. 去重规则

1. 先在路由后的目标文件搜索现有条目。
2. 同一知识点的后续追问优先补充原条目。
3. 问题虽然相关但考查核心不同，才创建新编号。
4. 修正旧答案时保留最终正确结论，不保留误导性表述。

例如：

- “普通 `char` 为什么有符号？”应补充已有字符类型条目。
- “`int&` 是什么类型？”与字符类型无关，应创建新的引用条目。

## 3. 编号

- 三个文件分别使用 `W001`、`OSW001`、`NETW001` 等编号；前缀和序列均不得跨文件混用。
- 每个文件独立使用其 Git 历史中从未出现过的最大编号加一。不得填补删除留下的空号，也不得复用已经删除的编号。
- 不重复使用已经存在的编号；删除条目时不重排历史编号。

## 5. 内容质量

- 从零解释，不把 C 作为前置知识。
- 先回答用户真正困惑的地方。
- 代码示例保持最小并符合 C++11。
- 将标准保证和常见实现行为分开。
- 必要时说明错误发生在编译、链接、装载还是运行阶段。
- 若问题源于旧答案表述不准确，应明确修正。
- OS 内容区分通用操作系统概念与 Linux/POSIX 专有行为；网络内容区分 RFC 规范、历史协议和实际部署策略。
- 优先引用标准、RFC、官方文档或教材等可核对的一手/权威来源；二手综述只能辅助解释，不能替代关键结论的来源。

## 6. 复习方法

1. 遮住核心答案，先口头复述。
2. 独立写出最小示例。
3. 说明一个正确用法和一个错误用法。
4. 一天后、三天后、一周后分别回看。
5. 能准确解释边界后，将该条目标记为已掌握；仓库仍保留历史记录。
