# 操作系统八股知识图谱

> 约定：以下“教材模型”描述通用操作系统概念；标有“POSIX/Linux”的内容是接口或 Linux 实现事实，不能反推为所有系统都如此。

## OS1 内核态、用户态、中断、异常与系统调用

- **定义：** CPU 以不同特权级运行代码；用户态程序须通过受控入口请求内核服务。
- **核心机制：** 系统调用由陷入指令进入内核，再由内核校验参数、执行服务并返回。中断通常来自外设且可异步；异常由当前指令触发，例如缺页或除零。
- **面试区分：** 系统调用是软件约定的受控请求，不等于中断；异常与中断都可能导致特权级切换，但触发来源不同。
- **常见边界/错误：** 用户态不能直接执行特权 I/O；“发生系统调用一定发生进程切换”错误，许多调用在同一进程上下文完成。
- **前置/关联：** 关联 OS2 的上下文切换、OS6 的缺页异常。
- **POSIX/Linux：** POSIX 规定接口语义；Linux 的 `syscall` ABI、具体特权级和中断实现属于平台/内核实现。

## OS2 进程、线程、状态与上下文切换

- **定义：** 进程是资源与地址空间的隔离单位；线程是进程内可被调度的执行流。
- **核心机制：** 调度器保存当前线程寄存器、栈指针和必要的 CPU 状态，恢复目标线程状态；切换进程通常还涉及地址空间与资源上下文。
- **面试区分：** 线程共享同进程地址空间和多数资源，进程默认隔离；“线程切换一定比进程切换快”不是语义保证，只是常见实现趋势。
- **常见边界/错误：** 进程状态是教材抽象，实际内核可能用更多状态；阻塞线程不等于整个进程一定不能运行。
- **前置/关联：** 前置 OS1；关联 OS3 调度与 OS9 IPC。
- **POSIX/Linux：** POSIX 有进程、线程和 `fork`/`pthread` 接口；Linux 用任务结构统一表示调度实体的细节不是通用教材定义。

## OS3 CPU 调度

- **定义：** CPU 调度是在可运行执行流之间分配处理器时间，以平衡响应、吞吐、公平与实时性。
- **核心机制：** 抢占式调度依靠时钟中断或更高优先级任务触发重选；常见指标包括周转时间、等待时间和响应时间。
- **面试区分：** 长作业优先优化平均等待时间但可能饥饿；时间片轮转改善交互响应却增加切换开销。
- **常见边界/错误：** 调度策略不是“越公平越快”；多核还涉及负载均衡、亲和性和共享缓存，不能只按单核公式判断。
- **前置/关联：** 前置 OS2；关联 OS4 的优先级反转。
- **POSIX/Linux：** POSIX 定义部分调度接口；Linux 的 CFS、实时调度类及其参数是 Linux 行为，不是教材必然实现。

## OS4 并发、临界区与同步原语

- **定义：** 并发执行会竞争共享状态；临界区是一次只能由满足条件的执行流访问的代码区域。
- **核心机制：** 互斥锁提供排他，条件变量等待状态变化，信号量计数资源；原子操作与内存序为无锁协议提供基础。
- **面试区分：** 互斥锁解决互斥，不自动表达“条件已满足”；条件变量必须配合谓词循环，不能把通知当作状态本身。
- **常见边界/错误：** `volatile` 不能替代同步；持锁执行耗时或调用未知代码会扩大临界区并可能死锁。
- **前置/关联：** 前置 OS2；关联 OS5 死锁、C++ 并发原子与内存模型。
- **POSIX/Linux：** `pthread_mutex`、`pthread_cond` 是 POSIX 接口；Linux futex 是常见底层支撑，不是 POSIX 对实现的要求。

## OS5 死锁

- **定义：** 一组执行流彼此等待对方持有的资源，且没有外力时无法继续推进。
- **核心机制：** 经典必要条件是互斥、占有并等待、不可抢占、循环等待；可通过预防、避免、检测恢复或资源顺序打破循环。
- **面试区分：** 死锁、活锁和饥饿不同：活锁在变化但不推进，饥饿是个体长期得不到机会。
- **常见边界/错误：** 四条件是经典资源死锁的必要条件，不是所有“程序卡住”都能直接套用；固定加锁顺序只解决能被统一排序的资源。
- **前置/关联：** 前置 OS4；关联 OS3 的优先级反转及 OS9 的跨进程锁。
- **POSIX/Linux：** POSIX mutex 可配置错误检测等属性；Linux 不会自动为应用层任意锁图消除死锁。

## OS6 地址空间与虚拟内存

- **定义：** 虚拟内存让每个进程看到独立的虚拟地址空间，并把虚拟页映射到物理页或后备存储。
- **核心机制：** MMU 经页表翻译地址，TLB 缓存翻译；缺页异常交给内核装入页面或判定非法访问，替换策略管理有限内存。
- **面试区分：** 虚拟地址不等于物理地址；缺页是可恢复的正常机制，非法访问则可能导致进程终止。
- **常见边界/错误：** 页面置换不是“每次访问都读磁盘”；写时复制在首次写入时才复制，`fork` 后并非立即复制全部内存。
- **前置/关联：** 前置 OS1；关联 OS2 地址空间切换、OS7 文件页缓存。
- **POSIX/Linux：** POSIX 有 `mmap` 等接口；Linux 的 overcommit、页回收与 `/proc` 指标是具体实现策略。

## OS7 文件与文件系统

- **定义：** 文件系统把持久化块设备组织为名字、目录、元数据与文件内容，并提供一致的访问接口。
- **核心机制：** 路径解析定位目录项与 inode/等价元数据；文件描述符引用内核打开文件对象，缓存和日志帮助性能与一致性。
- **面试区分：** 文件名、inode（或同类对象）、文件描述符分别是目录映射、元数据对象、进程句柄；硬链接不是复制文件内容。
- **常见边界/错误：** `close` 不等于数据已落盘，持久化语义需看 `fsync` 与文件系统/设备保证；删除目录项后，仍被打开的文件可继续存在。
- **前置/关联：** 前置 OS6；关联 OS8 缓存与 DMA。
- **POSIX/Linux：** POSIX 定义 `open`/`read`/`write` 等接口；Linux VFS、ext4 inode 与 page cache 是 Linux 实现细节。

## OS8 I/O、设备、DMA 与缓存

- **定义：** I/O 子系统协调 CPU、驱动、控制器与设备，在吞吐、延迟和一致性间取舍。
- **核心机制：** 轮询由 CPU 主动查询；中断由设备通知；DMA 允许设备与内存直接搬运数据，完成后再通知 CPU。缓存减少慢设备访问。
- **面试区分：** DMA 减少 CPU 的逐字节搬运，不等于完全没有 CPU 参与；缓冲区偏重传输协调，缓存偏重复用已读数据。
- **常见边界/错误：** CPU cache、内核 page cache、磁盘控制器缓存不是同一层；DMA 与 CPU 并发访问内存时仍需考虑一致性和所有权。
- **前置/关联：** 前置 OS1、OS6；关联 OS7 文件 I/O、OS10 `epoll`。
- **POSIX/Linux：** POSIX 描述 I/O 接口；Linux 驱动模型、DMA 映射与 page cache 具体行为是实现相关。

## OS9 进程间通信

- **定义：** IPC 是不同进程交换数据、通知事件或协作同步的机制。
- **核心机制：** 管道/消息队列传递字节或消息；共享内存直接共享映射但需额外同步；socket 可在本机或网络端点间传输。
- **面试区分：** 共享内存通常数据路径最短，但同步责任最大；管道天然适合单向流，不等于任意大小消息都有边界。
- **常见边界/错误：** 进程隔离不意味着不能共享物理页；把共享内存当成“免锁高速容器”会引入数据竞争。
- **前置/关联：** 前置 OS2、OS4；关联 OS10 socket、网络 NET10。
- **POSIX/Linux：** POSIX 规定 pipe、共享内存、消息队列等接口族；Unix domain socket 和 Linux namespace 的具体特征需要单独确认。

## OS10 Linux 面试连接点

- **定义：** 把通用操作系统原理映射到 Linux 可观测接口与常见工程问题。
- **核心机制：** 进程创建可联系 `fork`、`exec`、写时复制；I/O 多路复用可联系阻塞模型、就绪通知和事件循环；内存问题可联系页、映射与 OOM。
- **面试区分：** `select`/`poll`/`epoll` 是 I/O 多路复用接口或实现路径，不等于“一个线程处理所有请求”；就绪通知也不等于一次 `read` 必然读到完整应用消息。
- **常见边界/错误：** 不把 `/proc` 单次采样当精确因果证明；Linux 命令输出、内核版本和文件系统会改变可观测细节。
- **前置/关联：** 汇总 OS1–OS9；与 NET3、NET10 共同构成服务器面试链路。
- **POSIX/Linux：** 本节点特指 Linux；POSIX 只保证其标准化接口与语义子集，未规定 `/proc`、`epoll` 等 Linux 扩展。
