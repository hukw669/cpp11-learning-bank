# 计算机网络八股知识图谱

> 端到端链路先记成一条线：应用产生**消息** → 传输层按**端口**交付给进程 → IP 以源/目的 **IP 地址**进行端到端转发 → 每一跳链路层用当跳 **MAC 地址**封装帧。路由器转发时会拆旧帧、查 IP 路由、再封装新帧，MAC 因而逐跳变化。

## NET1 网络分层、封装与寻址

- **定义：** 分层把应用语义、进程交付、跨网转发和单链路传输分开，各层为上层提供服务。
- **核心机制：** 消息加上 UDP/TCP/QUIC 的传输信息，再加 IP 包头，最后以当前链路的帧发送；接收端反向解封装。
- **面试区分：** 应用消息没有天然“包边界”；端口标识主机内的传输端点；IP 地址用于端到端寻址；MAC 只在一段二层链路上投递。
- **常见边界/错误：** “源 MAC 一直是发送主机、目的 MAC 一直是服务器”错误；经过路由器后下一跳帧的 MAC 会重写。TCP 是字节流，不能把一次 `send` 等同一次 `recv`。
- **前置/关联：** 关联 NET3 端口、NET5 IP、NET8 二层帧和 NETW001。
- **协议边界：** 分层是模型，隧道、NAT、QUIC 等会跨越传统实现边界，不能据此否定各层职责。

## NET2 应用层协议

- **定义：** 应用层规定业务消息的语义、格式、状态和错误处理，例如 DNS、HTTP、SMTP、DHCP。
- **核心机制：** DNS 将名称解析为记录；HTTP 定义请求/响应语义；DHCP 为主机分配或租用配置。应用协议选择其下的传输承载。
- **面试区分：** DNS 并非“只能 UDP”：普通查询常用 UDP，但截断、区域传送及现代部署可使用 TCP；RFC 7766 规定 DNS 实现必须支持 TCP。
- **常见边界/错误：** HTTP 并非“只能 TCP”：HTTP/1.1、HTTP/2 常跑在 TCP 上，而 HTTP/3 使用 QUIC（通常承载于 UDP）。DNS 解析结果也不是永久可信，需考虑 TTL、缓存与失败。
- **前置/关联：** 前置 NET1；关联 NET3 的 UDP/TCP/QUIC、NET9 代理。
- **协议边界：** DNS 传输行为见 RFC 7766，HTTP 语义见 RFC 9110，HTTP/3 映射见 RFC 9114；实现部署可因服务策略不同而变化。

## NET3 UDP、TCP、QUIC 与端口

- **定义：** UDP、TCP、QUIC 是端到端传输/传输承载协议；端口帮助主机把收到的数据交给正确 socket/进程。
- **核心机制：** UDP提供无连接报文交付；TCP 提供有序字节流和可靠传输机制；QUIC 在 UDP 之上实现连接、多路复用、加密握手等能力。
- **面试区分：** 端口不是“应用唯一编号”，一个连接通常由协议、源 IP、源端口、目的 IP、目的端口等元组区分；UDP 有报文边界，TCP 没有。
- **常见边界/错误：** UDP 不等于不可靠就不能用，实时业务常在应用层权衡丢包与时延；QUIC 使用 UDP 作为承载不等于它只提供 UDP 的能力。
- **前置/关联：** 前置 NET1；关联 NET2 DNS/HTTP 选择、NET4 TCP、NET10 socket。
- **协议边界：** 端口是传输层概念，IP 路由不根据端口决定下一跳；NAT/防火墙可能检查或改写端口。

## NET4 TCP 可靠性、控制与连接管理

- **定义：** TCP 在不可靠 IP 网络上向应用提供有序字节流，并通过确认、重传、流量控制和拥塞控制管理传输。
- **核心机制：** 序号与确认定位已收数据；超时或重复确认触发重传；接收窗口限制接收端承受量，拥塞窗口限制发送端对网络的注入量；三次握手建立双方状态。
- **面试区分：** 流量控制保护接收端，拥塞控制保护网络；可靠性是 TCP 协议层承诺，不是 IP 的承诺。
- **常见边界/错误：** TCP 可靠不保证应用消息语义、时限或恰好一次处理；连接建立后仍可能被重置、超时或半关闭。
- **前置/关联：** 前置 NET3；关联 NET6 MTU、NET10 非阻塞 I/O。
- **协议边界：** 拥塞控制算法和默认参数会随操作系统与版本变化；协议目标不等于某一次网络条件下的性能保证。

## NET5 IP、CIDR、子网与转发

- **定义：** IP 提供跨网络的数据报寻址与转发；CIDR 以前缀长度表达网络范围和聚合。
- **核心机制：** 主机与路由器按目的 IP 查路由表；最长前缀匹配选出最具体的可达路由，再把包交给对应下一跳。
- **面试区分：** IP 地址是端到端逻辑地址，MAC 是本跳链路地址；子网掩码/前缀用于判断范围与路由，端口不参与 IP 最长前缀匹配。
- **常见边界/错误：** A/B/C 类地址是历史分类法，现代 IPv4 路由与分配以 CIDR 为主；IP 是尽力而为的数据报服务，不保证送达、顺序、去重或可靠性。
- **前置/关联：** 前置 NET1；关联 NET6 ARP/NDP、NET7 路由、NET9 NAT。
- **协议边界：** IPv4 见 RFC 791，IPv6 见 RFC 8200；二者的分片、地址与邻居发现等细节不同。

## NET6 ARP/NDP、ICMP、MTU 与分片

- **定义：** ARP（IPv4）和 NDP（IPv6）把“本链路要交给谁”的网络层地址映射到链路层邻居；ICMP 报告控制与差错信息；MTU 是一跳链路可承载的最大帧负载约束。
- **核心机制：** 发送主机先由路由确定下一跳 IP，再用 ARP/NDP 得到该下一跳的 MAC；路径 MTU 发现依靠 ICMP 报文与发送端调整包大小。
- **面试区分：** ARP 不是“把任意远端 IP 直接变成 MAC”，它只解析本地链路的下一跳；RARP 已被 BOOTP/DHCP 等机制取代，不应当作现代主机配置方案。
- **常见边界/错误：** IPv4 路由器在允许时可分片，IPv6 路由器不分片；“ICMP 都可以忽略”会破坏诊断或路径 MTU 发现，但生产网络也可能限速或过滤它。
- **前置/关联：** 前置 NET5；关联 NET8 二层、NET4 MSS 与重传。
- **协议边界：** 以太网 ARP 仅对应 IPv4；IPv6 使用 NDP。具体分片策略和防火墙策略是部署行为，不是单一结论。

## NET7 路由协议与最长前缀匹配

- **定义：** 控制平面用静态配置或路由协议形成路由表；数据平面依据表项转发数据包。
- **核心机制：** 转发对目的地址应用最长前缀匹配；路由协议交换可达性和度量以更新表项，默认路由覆盖未知更具体目的地。
- **面试区分：** 路由协议负责“学到路由”，最长前缀匹配负责“选哪一条已知路由”；二者不是同一件事。
- **常见边界/错误：** 更长前缀通常优先于更短前缀，但相同前缀还需看管理距离、度量等实现策略；路由器不必知道最终主机的 MAC。
- **前置/关联：** 前置 NET5；关联 NET6 下一跳解析、NET9 多路径与负载均衡。
- **协议边界：** RIP、OSPF、BGP 服务的网络范围和策略不同，不能用“动态路由一定更快/更可靠”概括。

## NET8 以太网、交换、VLAN 与链路层

- **定义：** 链路层在同一链路/广播域内以帧传输数据；交换机根据 MAC 表决定端口转发，VLAN 划分二层广播域。
- **核心机制：** 交换机从源 MAC 学习入端口，对已知目的单播转发，对未知目的或广播泛洪（受 VLAN 边界约束）。
- **面试区分：** 交换机主要按 MAC 表转发，路由器主要按 IP 路由表转发；VLAN 不是子网的同义词，但经常一对一规划。
- **常见边界/错误：** MAC 地址不是全网端到端路由标识；环路会造成广播风暴，需依靠生成树或其他无环/多路径控制。
- **前置/关联：** 前置 NET1；关联 NET6 邻居解析、NET9 网络边界。
- **协议边界：** MAC 学习、VLAN 标签、STP 等属于链路层协议/设备实现；无线链路的寻址与介质访问细节不同于以太网。

## NET9 NAT、代理、防火墙与负载均衡

- **定义：** 这些中间设备/功能改变地址、转发路径、访问策略或请求分配，以满足地址复用、安全和扩展需求。
- **核心机制：** NAT 映射或改写地址/端口；代理代表客户端或服务端发起连接；防火墙按规则允许/拒绝；负载均衡在多个后端间分流。
- **面试区分：** NAT 不是防火墙，代理不必改写 IP，负载均衡可在四层或七层工作；它们可能组合部署但职责不同。
- **常见边界/错误：** NAT 打破端到端透明性并可能影响协议；“有 NAT 就安全”错误，访问控制仍取决于规则、身份和实现。
- **前置/关联：** 前置 NET3、NET5；关联 NET2 HTTP 代理、NET10 连接池。
- **协议边界：** L4 负载均衡理解连接/五元组，L7 负载均衡理解协议语义；TLS 终止位置会影响可见性与安全责任。

## NET10 Socket 与 C++ 网络编程连接点

- **定义：** Socket 是应用使用网络栈的操作系统接口抽象，C++ 程序以字节缓冲区、事件循环和协议编解码实现网络服务。
- **核心机制：** 服务端通常 `socket`、`bind`、`listen`、`accept`，连接后通过 `send`/`recv` 或异步接口收发；应用维护自己的消息边界和状态机。
- **面试区分：** `accept` 得到的是新连接 socket，不是监听 socket；TCP 的一次读写不对应一条业务消息，需长度字段、分隔符或状态机拆包/粘包处理。
- **常见边界/错误：** 非阻塞 socket 返回“暂时不可读/写”不等于连接失败；不要从网络直接反序列化不受信任长度或对象内存布局。
- **前置/关联：** 汇总 NET1–NET9；与 OS8 I/O、OS10 `epoll`/事件循环相连。
- **POSIX/Linux：** BSD/POSIX socket API 与 `epoll`、io_uring 等 Linux 扩展应分开讨论；跨平台 C++ 网络库会屏蔽部分系统差异但不会消除协议边界。
