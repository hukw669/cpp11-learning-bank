# C++11 零基础知识图谱：异常、内存、并发、I/O 与 Linux 工程

> 本图只覆盖 **ISO C++11 及其以前已纳入标准的内容**。  
> 工具链、CMake 和 Linux/POSIX 内容单独标注，不把它们误称为 C++11 语言特性。

## 标记说明

- `【C++11·语言】`：ISO C++11 核心语言规则。
- `【C++11·标准库】`：ISO C++11 标准库。
- `【C++11·新增】`：相对 C++03 在 C++11 中新增。
- `【工程概念】`：通用工程知识，不由 ISO C++ 标准规定。
- `【工具链】`：编译器、链接器、CMake 等工具知识。
- `【Linux/POSIX】`：Linux 或 POSIX 接口，不可直接当作可移植 C++。
- `前置`：学习该节点前应先掌握的节点。

## 跨模块前置节点

这些内容应由完整知识图谱的基础部分先覆盖：

- `BASE-01`：源代码、程序、变量、对象和值的基本概念。
- `BASE-02`：基本类型、表达式、运算符和控制流。
- `BASE-03`：函数声明、函数定义、参数、返回值和作用域。
- `BASE-04`：指针、引用、数组、`const` 和对象生存期。
- `BASE-05`：类、构造函数、析构函数、成员函数和封装。
- `BASE-06`：拷贝构造、拷贝赋值、移动语义和右值引用。
- `BASE-07`：模板、函数对象、Lambda 和可调用对象。
- `BASE-08`：标准容器、迭代器和算法。
- `BASE-09`：RAII 与资源所有权。
- `BASE-10`：预处理器和头文件的最基本用法。

# EX：异常与错误处理

模块依赖：

```text
BASE-03 函数
   ↓
BASE-05 类与析构
   ↓
BASE-09 RAII
   ↓
EX-01～EX-18
```

- [ ] `EX-01` **错误、异常和程序缺陷的区别** `【工程概念】`  
  区分可恢复运行时错误、不可恢复错误、调用者违反前置条件以及程序自身逻辑错误。前置：`BASE-01`、`BASE-03`

- [ ] `EX-02` **`throw`、`try`、`catch` 的基本语法** `【C++11·语言】`  
  理解抛出异常、建立处理区以及捕获异常的基本控制流。前置：`BASE-03`

- [ ] `EX-03` **异常对象如何产生** `【C++11·语言】`  
  `throw expression` 会初始化异常对象；异常对象具有独立于局部变量的生存期。前置：`BASE-05`、`BASE-06`

- [ ] `EX-04` **异常处理器匹配规则** `【C++11·语言】`  
  掌握精确类型、基类引用、指针转换、`catch(...)` 及处理器排列顺序；异常匹配不会任意执行普通隐式转换。前置：`EX-02`、继承与多态

- [ ] `EX-05` **按 `const` 引用捕获异常** `【C++11·语言】`  
  按值捕获可能复制或切片对象，通常应写成 `catch (const T& e)`。前置：`BASE-04`、继承与多态、`EX-04`

- [ ] `EX-06` **异常传播与栈展开** `【C++11·语言】`  
  异常沿调用链寻找处理器；离开作用域时，已经构造完成的自动对象会依次析构。前置：`BASE-03`、`BASE-05`、`EX-02`

- [ ] `EX-07` **RAII 为什么能防止异常泄漏资源** `【C++11·语言/工程概念】`  
  将文件、锁、动态内存等资源绑定到对象析构过程。前置：`BASE-09`、`EX-06`

- [ ] `EX-08` **重新抛出异常** `【C++11·语言】`  
  `throw;` 保留当前异常对象；`throw e;` 可能创建新异常对象并导致类型切片。前置：`EX-04`、`EX-05`

- [ ] `EX-09` **标准异常类型体系** `【C++11·标准库】`  
  认识 `std::exception`、`std::logic_error`、`std::runtime_error`、`std::bad_alloc`、`std::out_of_range` 等类型。前置：继承与虚函数、`EX-04`

- [ ] `EX-10` **构造函数失败与函数 try 块** `【C++11·语言】`  
  构造函数不能通过普通返回值表示构造失败；理解部分构造对象的清理和函数 try 块。前置：`BASE-05`、`EX-06`

- [ ] `EX-11` **析构函数与异常** `【C++11·语言】`  
  若析构函数在另一个异常进行栈展开时让第二个异常逃出，程序必定调用 `std::terminate`；析构函数可在内部处理失败，但通常不应让异常逃出。前置：`BASE-05`、`EX-06`

- [ ] `EX-12` **`noexcept` 与 `noexcept(expression)`** `【C++11·新增】`  
  掌握不抛异常承诺、条件式 `noexcept`、`noexcept` 运算符，以及违反承诺时调用 `std::terminate`。前置：`BASE-03`、`EX-06`

- [ ] `EX-13` **`noexcept` 与移动操作的关系** `【C++11·新增】`  
  理解标准容器为何更愿意使用不会抛异常的移动构造，以及 `std::move_if_noexcept` 的目的。前置：`BASE-06`、`EX-12`、标准容器

- [ ] `EX-14` **异常安全保证** `【工程概念】`  
  区分无泄漏保证、基本保证、强保证和不抛保证；理解“先构造临时结果，成功后提交”。前置：`BASE-06`、`BASE-09`、`EX-07`

- [ ] `EX-15` **`std::error_code` 与 `std::system_error`** `【C++11·新增/标准库】`  
  学习错误码、错误类别、错误条件以及异常式系统错误报告；理解异常和错误码的适用边界。前置：类、枚举、`EX-09`

- [ ] `EX-16` **跨线程保存和重新抛出异常** `【C++11·新增/标准库】`  
  使用 `std::exception_ptr`、`std::current_exception`、`std::rethrow_exception`；异常不会自动从子线程传播到创建线程。前置：`EX-06`、`TH-01`～`TH-06`

- [ ] `EX-17` **嵌套异常** `【C++11·新增/标准库】`  
  认识 `std::nested_exception`、`std::throw_with_nested` 和 `std::rethrow_if_nested`。前置：`EX-08`、`EX-09`

- [ ] `EX-18` **异常与 C ABI 等接口边界** `【工程概念】`  
  `extern "C"` 主要规定语言链接，并不单独形成“禁止抛异常”的语言规则；但不能把异常逃出真实 C 调用方、插件 ABI、共享库接口或线程入口作为可移植契约，应在边界内捕获并转换成稳定的错误协议。前置：`EX-06`、`BUILD-12`

# MEM：对象、存储与动态内存

模块依赖：

```text
BASE-01～BASE-05
       ↓
MEM-01～MEM-12
       ↓
BASE-06 + BASE-09
       ↓
MEM-13～MEM-28
```

- [ ] `MEM-01` **对象、地址、字节和存储的区别** `【C++11·语言】`  
  对象具有类型、生存期和值；存储只提供放置对象的字节区域。前置：`BASE-01`

- [ ] `MEM-02` **作用域、链接和存储期不是同一概念** `【C++11·语言】`  
  名字可见范围、跨翻译单元身份和对象存在时长必须分别理解。前置：`BASE-03`

- [ ] `MEM-03` **四种存储期** `【C++11·语言】`  
  自动存储期、静态存储期、线程存储期和动态存储期；`thread_local` 是 C++11 新增。前置：`MEM-02`

- [ ] `MEM-04` **“栈”和“堆”是实现模型，不是完整标准术语** `【工程概念】`  
  自动对象通常位于线程栈，动态对象通常来自堆，但 ISO C++ 只规定语义，不固定底层布局。前置：`MEM-03`

- [ ] `MEM-05` **初始化与未初始化对象** `【C++11·语言】`  
  区分默认初始化、值初始化、零初始化、直接初始化和列表初始化；读取某些未初始化标量可能产生未定义行为。前置：基本类型、构造函数

- [ ] `MEM-06` **对象生存期开始和结束** `【C++11·语言】`  
  存储存在不代表对象已经存在；构造开始生存期，析构或存储释放结束生存期。前置：`BASE-05`、`MEM-01`

- [ ] `MEM-07` **空指针、悬空指针和野指针** `【C++11·语言】`  
  区分 `nullptr`、未初始化指针、对象销毁后的指针以及越界指针。前置：`BASE-04`、`MEM-06`

- [ ] `MEM-08` **原始指针不自动表达所有权** `【工程概念】`  
  单凭 `T*` 无法判断是否负责释放资源，需要接口约定或所有权类型。前置：`BASE-04`

- [ ] `MEM-09` **`new`、`delete`、`new[]`、`delete[]`** `【C++11·语言】`  
  理解分配存储、构造对象、析构对象和释放存储的组合过程；分配与释放形式必须匹配。前置：`BASE-04`、`BASE-05`、`MEM-06`

- [ ] `MEM-10` **分配失败** `【C++11·标准库】`  
  普通 `new` 失败时抛出 `std::bad_alloc`；`new (std::nothrow)` 失败时返回空指针。前置：`MEM-09`、`EX-09`

- [ ] `MEM-11` **`malloc`、`calloc`、`realloc`、`free` 在 C++ 中的边界** `【C++11·标准库】`  
  它们只管理原始存储，不调用 C++ 构造和析构；不得与 `new/delete` 混用。前置：`MEM-06`、`MEM-09`

- [ ] `MEM-12` **放置 new 与显式析构** `【C++11·语言】`  
  在已有存储中构造对象，并负责正确结束对象生存期；属于底层容器和内存池知识。前置：`MEM-06`、`MEM-09`

- [ ] `MEM-13` **RAII 所有权模型** `【C++11·工程核心】`  
  获取资源后立即交给对象管理，以析构完成自动释放。前置：`BASE-05`、`BASE-09`

- [ ] `MEM-14` **`std::unique_ptr` 独占所有权** `【C++11·新增/标准库】`  
  不可拷贝、可移动；掌握 `release`、`reset`、`get` 及数组特化。前置：`BASE-06`、`MEM-13`

- [ ] `MEM-15` **C++11 没有 `std::make_unique`** `【版本边界】`  
  `std::make_unique` 是 C++14；严格使用 C++11 时需直接构造 `unique_ptr` 或自行编写受控辅助函数。前置：`MEM-14`

- [ ] `MEM-16` **`std::shared_ptr` 共享所有权** `【C++11·新增/标准库】`  
  理解托管对象、控制块、强引用计数、复制和销毁成本。前置：`BASE-06`、`MEM-13`

- [ ] `MEM-17` **`std::make_shared`** `【C++11·新增/标准库】`  
  认识一次分配、异常安全和对象与控制块生存期耦合等特点。前置：`MEM-16`、`EX-14`

- [ ] `MEM-18` **`std::weak_ptr` 与循环引用** `【C++11·新增/标准库】`  
  弱引用不增加强计数；通过 `lock()` 临时取得 `shared_ptr`。前置：`MEM-16`

- [ ] `MEM-19` **智能指针自定义删除器** `【C++11·标准库】`  
  用于文件句柄、套接字、C 库对象等非 `delete` 资源；理解删除器对类型和对象大小的影响。前置：`BASE-07`、`MEM-14`、`MEM-16`

- [ ] `MEM-20` **`enable_shared_from_this`** `【C++11·标准库】`  
  它允许已经由 `shared_ptr` 管理的对象取得共享原控制块的 `shared_ptr`；它不会阻止调用者再次用同一裸指针错误地创建另一个控制块。前置：`MEM-16`

- [ ] `MEM-21` **`std::allocator` 与 `allocator_traits`** `【C++11·标准库】`  
  区分分配原始存储和构造对象；初学阶段理解容器底层分配器接口即可。前置：模板、`MEM-06`、`MEM-12`

- [ ] `MEM-22` **对齐、`alignof` 和 `alignas`** `【C++11·新增】`  
  对象地址必须满足其类型对齐要求；认识标准对齐工具和错误对齐的风险。前置：`MEM-01`、结构体布局

- [ ] `MEM-23` **C++11 对过度对齐对象分配的限制** `【版本边界】`  
  C++17 才提供标准的对齐版 `operator new`；C++11 的扩展对齐需求通常依赖平台接口或自定义分配器。前置：`MEM-09`、`MEM-22`

- [ ] `MEM-24` **对象表示、填充字节和可平凡复制类型** `【C++11·语言】`  
  结构体可能含填充；只有满足规则的类型才适合通过 `memcpy` 复制对象表示。前置：结构体、`MEM-01`

- [ ] `MEM-25` **严格别名与字节观察** `【C++11·语言】`  
  不能随意用不相关类型指针读取对象；可通过 `char` 或 `unsigned char` 查看对象表示。`std::byte` 不属于 C++11。前置：`BASE-04`、`MEM-24`

- [ ] `MEM-26` **`volatile` 的真正含义** `【C++11·语言】`  
  `volatile` 主要用于具有特殊访问语义的对象，不提供线程间原子性、互斥或顺序保证。前置：`BASE-04`

- [ ] `MEM-27` **常见内存错误** `【工程概念】`  
  内存泄漏、越界、重复释放、释放后使用、错误释放器、悬空引用以及异常路径泄漏。前置：`MEM-07`～`MEM-19`

- [ ] `MEM-28` **内存诊断工具** `【工具链】`  
  AddressSanitizer、LeakSanitizer、UndefinedBehaviorSanitizer、Valgrind；它们不是 C++11 标准组成部分。前置：`MEM-27`、`BUILD-16`

# TH：线程与同步设施

模块依赖：

```text
BASE-03 + BASE-05 + BASE-06 + BASE-07
                    ↓
                TH-01～TH-07
                    ↓
          TH-08～TH-15 基于锁同步
                    ↓
          AT-01～AT-21 原子与内存模型
```

- [ ] `TH-01` **进程、线程和并发的基本概念** `【工程概念】`  
  线程共享进程地址空间，但有各自的调用栈和执行状态；并发不等于一定并行。前置：`BASE-01`

- [ ] `TH-02` **`std::thread` 创建线程** `【C++11·新增/标准库】`  
  使用普通函数、函数对象、Lambda 和成员函数作为线程入口。前置：`BASE-03`、`BASE-07`

- [ ] `TH-03` **线程参数的复制、移动与 `std::ref`** `【C++11·标准库】`  
  `std::thread` 默认保存衰减后的参数副本；引用传递需显式使用 `std::ref`，并保证生存期。前置：引用、移动语义、`TH-02`

- [ ] `TH-04` **`joinable`、`join` 和 `detach`** `【C++11·标准库】`  
  线程对象析构时若仍可连接会调用 `std::terminate`；理解等待和分离的生命周期责任。前置：`TH-02`

- [ ] `TH-05` **`std::thread` 是可移动但不可复制对象** `【C++11·标准库】`  
  线程所有权可以转移；移动赋值覆盖仍可连接线程会产生严重后果。前置：`BASE-06`、`TH-04`

- [ ] `TH-06` **线程入口异常处理** `【C++11·语言/标准库】`  
  未捕获异常逃出线程入口会调用 `std::terminate`，不会自动传播给创建线程。前置：`EX-06`、`TH-02`

- [ ] `TH-07` **共享状态与数据竞争** `【C++11·语言】`  
  两线程对同一内存位置发生冲突访问、至少一个为写且没有正确同步时，程序具有未定义行为。前置：`TH-01`、`MEM-06`

- [ ] `TH-08` **互斥量类型** `【C++11·新增/标准库】`  
  `std::mutex`、`std::recursive_mutex`、`std::timed_mutex`、`std::recursive_timed_mutex`。前置：`TH-07`

- [ ] `TH-09` **锁的 RAII 管理** `【C++11·标准库】`  
  `std::lock_guard` 用于简单作用域锁；`std::unique_lock` 支持延迟加锁、移动、解锁和条件变量。前置：`BASE-09`、`TH-08`

- [ ] `TH-10` **`std::lock` 与多个互斥量** `【C++11·标准库】`  
  学习 `defer_lock`、`adopt_lock`、`try_to_lock` 和避免循环等待的基本策略。前置：`TH-09`

- [ ] `TH-11` **死锁、活锁与饥饿** `【工程概念】`  
  识别锁顺序不一致、持锁等待外部操作、嵌套锁和过度竞争。前置：`TH-08`～`TH-10`

- [ ] `TH-12` **条件变量** `【C++11·新增/标准库】`  
  掌握 `std::condition_variable`、等待谓词、虚假唤醒、通知，以及等待时原子地释放并重新获取锁。前置：`TH-09`

- [ ] `TH-13` **丢失唤醒与谓词状态** `【工程概念】`  
  条件变量不是事件存储器；正确性来自受互斥量保护的共享谓词。前置：`TH-12`

- [ ] `TH-14` **一次初始化** `【C++11·新增/标准库】`  
  `std::once_flag`、`std::call_once`，以及 C++11 对函数局部静态对象初始化的线程安全保证。前置：局部静态对象、`TH-07`

- [ ] `TH-15` **线程局部存储 `thread_local`** `【C++11·新增】`  
  每个线程拥有独立对象实例；理解初始化、析构和对象访问范围。前置：`MEM-03`、`TH-01`

- [ ] `TH-16` **`future`、`promise` 与异步结果** `【C++11·新增/标准库】`  
  使用 `std::future`、`std::promise` 传递值或异常；理解共享状态和一次性 `get()`。前置：移动语义、`EX-16`、`TH-02`

- [ ] `TH-17` **`std::async` 与启动策略** `【C++11·新增/标准库】`  
  区分 `std::launch::async`、`std::launch::deferred` 和默认组合策略；不能假定默认调用必定创建新线程。前置：`TH-16`

- [ ] `TH-18` **`std::packaged_task` 与 `std::shared_future`** `【C++11·新增/标准库】`  
  将可调用对象和异步结果连接，或允许多个观察者读取同一共享结果。前置：`BASE-07`、`TH-16`

- [ ] `TH-19` **超时、睡眠和时钟** `【C++11·标准库】`  
  `sleep_for`、`sleep_until`、条件变量超时和 `std::chrono::steady_clock`。前置：`std::chrono`、`TH-12`

- [ ] `TH-20` **标准容器的并发访问边界** `【C++11·标准库规则】`  
  不同容器对象可并发访问；同一容器结构性修改通常必须同步；不同元素并发修改也有具体限制，`vector<bool>` 尤其特殊。前置：`BASE-08`、`TH-07`

- [ ] `TH-21` **C++11 中的协作式停止** `【工程概念】`  
  C++11 没有 `std::jthread` 和 `stop_token`，需使用受同步保护的停止标志、条件变量和明确的线程收尾协议。前置：`TH-04`、`TH-12`、`AT-06`

- [ ] `TH-22` **生产者—消费者、任务队列和线程池** `【工程模式】`  
  线程池不是 C++11 标准库组件，而是用线程、锁、条件变量和任务对象组合出的工程设施。前置：`TH-02`～`TH-18`

- [ ] `TH-23` **原生线程句柄** `【C++11·接口/平台相关】`  
  `native_handle()` 是标准库提供的接口，但返回类型和可执行操作由实现及操作系统决定。前置：`TH-02`

# AT：原子操作与 C++11 内存模型

- [ ] `AT-01` **为什么需要内存模型** `【C++11·语言】`  
  编译器、CPU 和缓存都可能改变观察到的执行顺序；源码先后顺序不足以描述线程间可见性。前置：`TH-07`

- [ ] `AT-02` **内存位置和冲突访问** `【C++11·语言】`  
  明确哪些访问作用于同一内存位置，以及读—写、写—写为何可能冲突。前置：`MEM-01`、`TH-07`

- [ ] `AT-03` **`sequenced-before`** `【C++11·语言】`  
  描述单线程内求值之间的先后关系，区分未排序求值与跨线程关系。前置：表达式求值顺序

- [ ] `AT-04` **`synchronizes-with` 和 `happens-before`** `【C++11·语言】`  
  理解解锁—加锁、发布—获取等同步边如何使先前写入对另一线程可见。前置：`TH-08`、`AT-03`

- [ ] `AT-05` **数据竞争为什么是未定义行为** `【C++11·语言】`  
  数据竞争并不只是“结果偶尔不对”，编译器可基于无数据竞争假设进行优化。前置：`AT-02`、`AT-04`

- [ ] `AT-06` **`std::atomic<T>` 与 `std::atomic_flag`** `【C++11·新增/标准库】`  
  对原子对象执行原子操作不会因这些操作彼此冲突而形成数据竞争；若对同一存储混入未同步的非原子访问，仍可能产生数据竞争。掌握 `load`、`store`、`exchange`，并注意除 `atomic_flag` 外不保证实现无锁。前置：模板、`TH-07`

- [ ] `AT-07` **原子读—改—写操作** `【C++11·标准库】`  
  `fetch_add`、`fetch_sub`、位运算以及前后置增减的原子语义。前置：`AT-06`

- [ ] `AT-08` **比较交换** `【C++11·标准库】`  
  `compare_exchange_weak`、`compare_exchange_strong`、期望值参数更新和循环重试模式。前置：`AT-06`

- [ ] `AT-09` **原子对象的修改顺序** `【C++11·语言】`  
  每个原子对象的所有修改存在一致的全序，但这不自动为其他对象建立全局顺序。前置：`AT-06`

- [ ] `AT-10` **默认顺序一致 `memory_order_seq_cst`** `【C++11·语言】`  
  最容易推理但限制较强；初学并发应先掌握默认顺序。前置：`AT-04`、`AT-06`

- [ ] `AT-11` **释放—获取语义** `【C++11·语言】`  
  `release` 发布之前的写入，读取相应值的 `acquire` 建立同步和可见性。前置：`AT-04`、`AT-09`

- [ ] `AT-12` **`memory_order_acq_rel`** `【C++11·语言】`  
  适用于既读取又修改的原子读—改—写操作。前置：`AT-07`、`AT-11`

- [ ] `AT-13` **`memory_order_relaxed`** `【C++11·语言】`  
  只保证目标原子对象本身操作的原子性和修改顺序，不负责发布普通数据。前置：`AT-09`～`AT-11`

- [ ] `AT-14` **`memory_order_consume`** `【C++11·语言/实务谨慎】`  
  理论上依赖数据依赖关系，实际编译器支持和可移植推理困难；学习时以“能识别、通常避免手写”为目标。前置：`AT-11`

- [ ] `AT-15` **内存栅栏** `【C++11·标准库】`  
  `atomic_thread_fence` 和 `atomic_signal_fence`；栅栏必须与合适的原子操作配合才能建立同步。前置：`AT-11`～`AT-13`

- [ ] `AT-16` **安全发布与消息传递** `【工程模式】`  
  正确发布对象、一次性初始化、标志位与数据之间的同步关系。前置：`AT-04`、`AT-11`

- [ ] `AT-17` **原子引用计数不等于对象线程安全** `【C++11·标准库规则】`  
  不同 `shared_ptr` 实例共享控制块时引用计数操作安全，但被指向对象的普通字段仍需同步。前置：`MEM-16`、`AT-05`

- [ ] `AT-18` **`shared_ptr` 的原子自由函数** `【C++11·标准库】`  
  C++11 提供针对 `shared_ptr` 的 `atomic_load`、`atomic_store` 等自由函数；`std::atomic<std::shared_ptr<T>>` 特化不是 C++11 内容。前置：`MEM-16`、`AT-06`

- [ ] `AT-19` **无锁不等于更快** `【工程概念】`  
  认识 `is_lock_free`、忙等、缓存争用、ABA 问题和复杂度成本。前置：`AT-06`～`AT-13`

- [ ] `AT-20` **伪共享与缓存行** `【硬件/性能工程】`  
  不同变量位于同一缓存行也可能相互干扰；C++11 没有标准缓存行干扰大小常量。前置：`AT-01`

- [ ] `AT-21` **ThreadSanitizer** `【工具链】`  
  用动态检测工具发现部分数据竞争；工具没有报告不等于程序已被形式化证明正确。前置：`AT-05`、`BUILD-16`

# IO：标准文件与流式 I/O

- [ ] `IO-01` **流、设备和缓冲区的抽象** `【C++11·标准库】`  
  理解程序通过流接口读写控制台、文件和内存字符串。前置：`BASE-01`、`BASE-03`

- [ ] `IO-02` **流类与头文件** `【C++11·标准库】`  
  `istream`、`ostream`、`iostream`、`ifstream`、`ofstream`、`fstream`、`stringstream`。前置：类与继承

- [ ] `IO-03` **标准流对象** `【C++11·标准库】`  
  `std::cin`、`std::cout`、`std::cerr`、`std::clog`，以及它们在缓冲和诊断用途上的区别。前置：`IO-01`

- [ ] `IO-04` **格式化输出** `【C++11·标准库】`  
  插入运算符、宽度、精度、进制、布尔格式及 `<iomanip>` 操纵器。前置：运算符重载、`IO-03`

- [ ] `IO-05` **格式化输入** `【C++11·标准库】`  
  提取运算符会按类型解析并通常跳过前导空白；读取失败时设置流状态。前置：`IO-03`

- [ ] `IO-06` **流状态位** `【C++11·标准库】`  
  `goodbit`、`eofbit`、`failbit`、`badbit`，以及 `good()`、`eof()`、`fail()`、`bad()`、`clear()`。前置：`IO-05`

- [ ] `IO-07` **正确的输入循环** `【C++11·标准库】`  
  使用 `while (stream >> value)`；不要使用 `while (!stream.eof())` 作为读取成功条件。前置：`IO-05`、`IO-06`

- [ ] `IO-08` **按词读取与按行读取** `【C++11·标准库】`  
  `operator>>` 与 `std::getline` 的区别；混用时处理缓冲区中遗留的换行符。前置：`IO-05`、字符串

- [ ] `IO-09` **文件流打开和关闭** `【C++11·标准库】`  
  构造打开、`open()`、`is_open()`、`close()`，以及文件流析构时自动关闭资源。前置：RAII、`IO-02`

- [ ] `IO-10` **文件打开模式** `【C++11·标准库】`  
  `in`、`out`、`app`、`ate`、`trunc`、`binary` 及组合含义。前置：`IO-09`

- [ ] `IO-11` **文本模式与二进制模式** `【C++11·标准库/实现相关】`  
  文本模式可能进行换行等转换；`binary` 抑制实现规定的文本转换，但不会自动解决端序和格式兼容。前置：`IO-10`

- [ ] `IO-12` **无格式块读写** `【C++11·标准库】`  
  `read`、`write`、`get`、`put`、`gcount`，以及读取不足时状态变化。前置：`IO-06`、`IO-09`

- [ ] `IO-13` **文件位置** `【C++11·标准库】`  
  `tellg`、`seekg`、`tellp`、`seekp` 和输入、输出位置的区别。前置：`IO-09`

- [ ] `IO-14` **缓冲、刷新与 `std::endl`** `【C++11·标准库】`  
  `'\n'` 只写换行，`std::endl` 还会刷新；频繁刷新会影响性能。前置：`IO-03`

- [ ] `IO-15` **流绑定及与 C I/O 同步** `【C++11·标准库】`  
  `tie()`、`sync_with_stdio(false)`；关闭同步后混用 C 与 C++ I/O 时必须特别谨慎。前置：`IO-03`、`IO-14`

- [ ] `IO-16` **流异常掩码** `【C++11·标准库】`  
  默认使用状态位报告错误；可通过 `exceptions(mask)` 配置在指定错误状态时抛出 `ios_base::failure`。前置：`EX-02`、`IO-06`

- [ ] `IO-17` **字符串流** `【C++11·标准库】`  
  `istringstream`、`ostringstream`、`stringstream` 用于内存中的格式化和解析。前置：字符串、`IO-04`、`IO-05`

- [ ] `IO-18` **Locale、字符集与编码边界** `【C++11·标准库/工程概念】`  
  C++11 流和 locale 不等于完整 Unicode 解决方案；文件名与文本编码仍受操作系统、库和约定影响。前置：字符类型、`IO-11`

- [ ] `IO-19` **为什么不能直接把普通结构体写入文件作为通用格式** `【工程概念】`  
  填充、端序、类型宽度、编译器 ABI、指针成员和版本变化都会破坏可移植性。前置：`MEM-24`、`IO-11`、`IO-12`

- [ ] `IO-20` **显式序列化格式** `【工程概念】`  
  明确定义字段、长度、字节序、字符编码、版本和错误检查；序列化库不属于 C++11 核心标准。前置：`IO-19`

- [ ] `IO-21` **C 标准 I/O 在 C++ 中的接口** `【C++11·标准库】`  
  `<cstdio>`、`FILE*`、`fopen`、`fclose`、`fread`、`fwrite`、`printf`；资源可用 RAII 包装。前置：指针、格式字符串、`MEM-19`

- [ ] `IO-22` **C++11 没有 `std::filesystem`** `【版本边界】`  
  `std::filesystem` 属于 C++17；C++11 处理目录、路径、权限通常使用平台 API 或第三方库。前置：`IO-09`

- [ ] `IO-23` **文件流、`FILE*` 和文件描述符的层次** `【工程/Linux】`  
  C++ 流是高级对象，`FILE*` 是 C 缓冲流，Linux 文件描述符是内核资源编号；三者不能随意混用。前置：`IO-09`、`IO-21`、`LINUX-11`

# BUILD：翻译、编译、链接和库

- [ ] `BUILD-01` **源文件、头文件和程序的关系** `【C++11·语言/工程概念】`  
  C++ 标准规定翻译单元和程序语义，但不强制 `.cpp`、`.hpp` 等文件后缀。前置：`BASE-01`、`BASE-10`

- [ ] `BUILD-02` **预处理、编译、汇编、链接** `【语言概念/工具链】`  
  预处理展开指令；编译分析 C++；汇编生成机器目标代码；链接组合目标文件和库，实际工具可以合并其中若干步骤。前置：`BUILD-01`

- [ ] `BUILD-03` **翻译单元** `【C++11·语言】`  
  一个源文件经预处理后的结果构成翻译单元；头文件通常被纳入多个翻译单元。前置：`BUILD-02`

- [ ] `BUILD-04` **声明、定义与 ODR** `【C++11·语言】`  
  声明引入名字；定义提供实体；理解一个定义规则及允许多次相同定义的特殊实体。前置：`BASE-03`、`BUILD-03`

- [ ] `BUILD-05` **作用域、内部链接、外部链接和无链接** `【C++11·语言】`  
  理解命名空间作用域对象、`static`、`extern`、匿名命名空间和局部名字。前置：作用域、`BUILD-04`

- [ ] `BUILD-06` **头文件放声明、源文件放普通定义** `【工程惯例】`  
  调用方包含声明；一个源文件提供唯一的非内联外部定义。前置：`BUILD-04`、`BUILD-05`

- [ ] `BUILD-07` **为什么模板定义通常放在头文件** `【C++11·语言/工程惯例】`  
  实例化点通常需要看到完整定义；也可使用显式实例化设计，但管理成本更高。前置：模板、`BUILD-03`

- [ ] `BUILD-08` **`inline` 与 ODR** `【C++11·语言】`  
  `inline` 的核心作用包括允许满足条件的相同定义出现在多个翻译单元；不等于保证机器代码内联。前置：`BUILD-04`

- [ ] `BUILD-09` **头文件保护** `【C++11·预处理器】`  
  include guard 属于标准预处理写法；`#pragma once` 常见但不是 ISO C++11 标准要求。前置：`BASE-10`、`BUILD-03`

- [ ] `BUILD-10` **编译错误与链接错误** `【工具链】`  
  语法、类型和声明问题多在编译期发现；未定义引用、重复定义和缺库通常在链接期发现。前置：`BUILD-02`、`BUILD-04`

- [ ] `BUILD-11` **名字修饰与函数重载** `【ABI/工具链】`  
  C++ 编译器通常把命名空间、类和参数类型编码进符号名；具体编码方式不由 ISO C++ 固定。前置：重载、`BUILD-05`

- [ ] `BUILD-12` **`extern "C"` 语言链接** `【C++11·语言】`  
  用于声明 C 语言链接接口；它不自动解决类型布局、异常、分配器和 ABI 的全部兼容问题。前置：`BUILD-11`

- [ ] `BUILD-13` **ABI 的含义** `【工程概念】`  
  调用约定、名称修饰、对象布局、异常机制、标准库实现和二进制接口共同影响兼容性。前置：`BUILD-11`

- [ ] `BUILD-14` **目标文件、可执行文件和符号表** `【工具链】`  
  这些是具体工具链和操作系统格式，不由 C++11 规定。前置：`BUILD-02`

- [ ] `BUILD-15` **静态库和动态库** `【工程概念】`  
  静态库通常在链接时抽取目标代码；动态库通常由可执行文件记录依赖并在装载或运行时解析。前置：`BUILD-10`、`BUILD-14`

- [ ] `BUILD-16` **调试、优化和诊断编译选项** `【工具链】`  
  调试信息、优化级别、警告、Sanitizer 和是否启用语言扩展均由编译器控制。前置：`BUILD-02`

- [ ] `BUILD-17` **指定 C++11 模式** `【工具链】`  
  GCC/Clang 常用 `-std=c++11`；`-std=gnu++11` 还允许 GNU 扩展。MSVC 使用自己的标准选项体系。前置：`BUILD-16`

- [ ] `BUILD-18` **链接顺序和依赖闭包** `【工具链】`  
  GNU 静态链接中库的位置可能影响符号解析；目标最终必须获得所有所需定义。前置：`BUILD-10`、`BUILD-15`

- [ ] `BUILD-19` **标准库与运行库** `【工具链】`  
  编译器前端、C++ 标准库和 ABI 运行库是不同层次，例如 GCC、libstdc++、libgcc。前置：`BUILD-13`

- [ ] `BUILD-20` **编译选项和宏必须保持 ABI 一致** `【工程概念】`  
  架构、调试模式、结构体布局、运行库选择和条件宏不一致可能产生链接或运行时错误。前置：`BUILD-13`、`BUILD-16`

# CMAKE：CMake 工程组织

> CMake **不属于 C++11**。它负责生成构建系统并组织编译、链接、测试和安装。  
> 动态库、编译和链接不是“CMake 的知识”，CMake 只是调用相应工具完成这些工作。

- [ ] `CMAKE-01` **CMake 在工具链中的位置** `【工具链】`  
  源代码 → CMake 配置/生成 → Ninja、Make 或 Visual Studio 构建 → 编译器和链接器。前置：`BUILD-02`

- [ ] `CMAKE-02` **配置、生成与构建三个阶段** `【工具链】`  
  `cmake -S ... -B ...`、生成底层构建文件、`cmake --build ...`。前置：`CMAKE-01`

- [ ] `CMAKE-03` **最小工程结构** `【工具链】`  
  `cmake_minimum_required`、`project`、`add_executable`，以及源目录和构建目录。前置：`CMAKE-02`

- [ ] `CMAKE-04` **Target 是核心抽象** `【工具链】`  
  可执行目标、库目标以及每个目标的源码、包含路径、编译选项和链接依赖。前置：`BUILD-15`、`CMAKE-03`

- [ ] `CMAKE-05` **声明 C++11 要求** `【工具链】`  
  使用 `target_compile_features(target PRIVATE cxx_std_11)`，或正确配置 `CXX_STANDARD 11`、`CXX_STANDARD_REQUIRED YES`、`CXX_EXTENSIONS NO`。前置：`BUILD-17`、`CMAKE-04`

- [ ] `CMAKE-06` **目标源码与包含目录** `【工具链】`  
  `target_sources`、`target_include_directories`；避免依赖全局 `include_directories`。前置：`BUILD-06`、`CMAKE-04`

- [ ] `CMAKE-07` **编译定义和编译选项** `【工具链】`  
  `target_compile_definitions`、`target_compile_options`，并区分宏定义与普通编译器参数。前置：`BUILD-16`、`CMAKE-04`

- [ ] `CMAKE-08` **创建不同类型的库** `【工具链】`  
  `add_library(... STATIC|SHARED|OBJECT|INTERFACE)`；理解它们与最终链接方式的关系。前置：`BUILD-15`、`CMAKE-04`

- [ ] `CMAKE-09` **链接依赖** `【工具链】`  
  `target_link_libraries` 将库依赖附加到目标，并可能向下游传播使用要求。前置：`BUILD-18`、`CMAKE-08`

- [ ] `CMAKE-10` **`PRIVATE`、`PUBLIC`、`INTERFACE`** `【工具链】`  
  区分目标自身使用要求和需要传递给使用者的要求。前置：`CMAKE-06`、`CMAKE-09`

- [ ] `CMAKE-11` **查找依赖和导入目标** `【工具链】`  
  `find_package`、Imported Target，以及为什么优先链接命名目标而不是手工拼接路径。前置：`CMAKE-09`

- [ ] `CMAKE-12` **单配置与多配置生成器** `【工具链】`  
  Ninja/Unix Makefiles 常见为单配置，Visual Studio 常见为多配置；理解 Debug、Release 配置选择。前置：`BUILD-16`、`CMAKE-02`

- [ ] `CMAKE-13` **源码外构建** `【工程惯例】`  
  将生成物放入独立构建目录，避免污染源码树并支持多套配置。前置：`CMAKE-02`

- [ ] `CMAKE-14` **测试** `【工具链】`  
  `enable_testing`、`add_test`、CTest；测试框架本身可另选。前置：`CMAKE-04`

- [ ] `CMAKE-15` **安装、导出和包配置** `【工具链】`  
  `install`、导出 targets、生成可被其他工程使用的包；属于进阶工程发布知识。前置：`CMAKE-08`～`CMAKE-11`

- [ ] `CMAKE-16` **线程库的可移植链接方式** `【工具链】`  
  使用 `find_package(Threads REQUIRED)` 和 `Threads::Threads`，避免把 Linux 的 `-pthread` 硬编码到所有平台。前置：`TH-02`、`CMAKE-09`

# LINUX：Linux C++ 工程基础

> 本模块不是 ISO C++11，但对 Linux C++ 网络、数据库和高并发开发非常重要。

- [ ] `LINUX-01` **GCC、Clang、汇编器和链接器的分工** `【Linux/工具链】`  
  编译驱动程序会按需要调用预处理器、编译器、汇编器和链接器。前置：`BUILD-02`

- [ ] `LINUX-02` **常用编译命令与选项** `【Linux/工具链】`  
  `-std=c++11`、警告、调试信息、优化、包含路径、库路径和输出文件。前置：`BUILD-16`、`BUILD-17`

- [ ] `LINUX-03` **ELF 文件与节、段、符号** `【Linux/工具链】`  
  目标文件、可执行文件和共享对象通常使用 ELF；初期理解概念即可。前置：`BUILD-14`

- [ ] `LINUX-04` **静态库 `.a`** `【Linux/工具链】`  
  使用归档工具组织目标文件；理解静态库的符号抽取和 GNU 链接顺序。前置：`BUILD-15`、`BUILD-18`

- [ ] `LINUX-05` **共享库 `.so`** `【Linux/工具链】`  
  使用位置无关代码、共享链接和稳定导出接口；共享库并不是 C++11 标准对象。前置：`BUILD-13`、`BUILD-15`

- [ ] `LINUX-06` **PIC、SONAME 和库版本** `【Linux/工具链】`  
  `-fPIC`、SONAME、真实文件与符号链接之间的典型关系。前置：`LINUX-05`

- [ ] `LINUX-07` **动态装载器和库搜索** `【Linux/工具链】`  
  认识 `ld.so`、RUNPATH/RPATH、系统缓存和 `LD_LIBRARY_PATH`；避免把临时环境变量当作稳定发布方案。前置：`LINUX-05`

- [ ] `LINUX-08` **符号检查工具** `【Linux/工具链】`  
  `nm`、`readelf`、`objdump`、`c++filt`、`ldd` 用于检查对象、依赖和 C++ 修饰名。前置：`BUILD-11`、`LINUX-03`

- [ ] `LINUX-09` **`-pthread` 的作用** `【Linux/工具链】`  
  它可能同时影响编译宏和链接选项，不应简单理解为只等于 `-lpthread`。前置：`TH-02`、`LINUX-02`

- [ ] `LINUX-10` **GDB、core dump 和调用栈** `【Linux/工具链】`  
  设置断点、查看线程、栈帧、变量和崩溃现场。前置：`BUILD-16`

- [ ] `LINUX-11` **文件描述符** `【Linux/POSIX】`  
  文件、管道、终端、套接字等都可通过文件描述符访问；文件描述符有独立生命周期。前置：`IO-01`、`IO-09`

- [ ] `LINUX-12` **`open/read/write/close`** `【Linux/POSIX】`  
  系统调用可能发生短读、短写和 `EINTR`；返回值必须检查。前置：`LINUX-11`

- [ ] `LINUX-13` **阻塞、非阻塞和 I/O 多路复用** `【Linux/POSIX】`  
  认识 `fcntl`、`select`、`poll`、`epoll` 的层次；深入内容应放入 Linux 高并发网络模块。前置：`LINUX-11`、`TH-01`

- [ ] `LINUX-14` **`std::thread` 与 pthread 的关系** `【实现/平台】`  
  Linux 标准库实现通常基于 pthread，但 ISO C++ 不保证该实现方式；优先使用标准线程接口，确有平台需求时再下沉。前置：`TH-02`、`TH-23`

- [ ] `LINUX-15` **进程接口** `【Linux/POSIX】`  
  `fork`、`exec`、`wait`、管道和进程退出状态；它们不属于 C++11。前置：`TH-01`、`LINUX-11`

- [ ] `LINUX-16` **信号边界** `【Linux/POSIX】`  
  信号处理函数可安全执行的操作非常有限；不能把普通 C++ 并发代码直接搬进信号处理器。前置：`AT-15`、操作系统基础

- [ ] `LINUX-17` **`mmap`、`msync`、`fsync` 与持久化边界** `【Linux/POSIX】`  
  映射内存、用户态缓冲、内核页缓存和真正持久化不是同一件事。前置：`LINUX-11`、虚拟内存基础

- [ ] `LINUX-18` **Linux 内存与并发诊断工具** `【Linux/工具链】`  
  Valgrind、ASan、TSan、`perf` 分别用于内存错误、数据竞争和性能分析。前置：`MEM-27`、`AT-21`、`BUILD-16`

- [ ] `LINUX-19` **可移植层与平台层隔离** `【工程设计】`  
  将 ISO C++11 代码与 Linux/POSIX 代码分层，避免平台细节扩散到业务逻辑。前置：全部 BUILD、CMAKE 和基础 Linux 节点

# 明确排除的 C++14/17/20 内容

以下内容不得混进 C++11 题库正文，只能作为版本边界提示：

- `std::make_unique`：C++14。
- 泛型 Lambda 参数 `auto`：C++14。
- `std::shared_timed_mutex`：C++14。
- `std::shared_mutex`、`std::scoped_lock`：C++17。
- `std::filesystem`：C++17。
- `std::byte`：C++17。
- 标准对齐版 `operator new`：C++17。
- 并行 STL 算法：C++17。
- `std::uncaught_exceptions()`：C++17。
- `std::atomic<std::shared_ptr<T>>` 特化：C++20。
- `std::jthread`、`stop_token`、信号量、闩锁和屏障：C++20。
- `atomic_wait`/`atomic_notify`：C++20。
