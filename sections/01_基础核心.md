# C++11 零基础知识点图谱：基础与核心语言

> 前提：不假定学过 C，也不假定学过旧版 C++。所有概念从 C++ 本身讲起。  
> 标准边界：只按 ISO C++11；编译示例应启用 `-std=c++11`。  
> 本图谱不把 C 当作前置课程，也不混入 C++14/17。

## B0. 学习起点与基本术语

### B0.1 程序、源文件和可执行文件

**语法/接口：** C++ 源文件常命名为 `main.cpp`，头文件常命名为 `name.hpp`；GCC/Clang 示例命令是 `g++ -std=c++11 main.cpp -o app`。文件后缀、命令和可执行文件格式属于工具链惯例，不是 ISO C++11 语法。

**定义与用途：** 源代码是程序员编写的文本；程序是共同完成任务的一组翻译单元和库；目标文件是一个翻译单元产生、尚待链接的机器代码；可执行文件是链接后的平台产物。一个程序可以由多个 `.cpp` 文件组成，头文件用于共享声明。

```cpp
// main.cpp
#include <iostream>

int main()
{
    std::cout << "hello\n";
}
```

**C++11 精确语义：** 托管环境程序从 `main` 开始执行；标准规定合法程序的可观察行为，但不规定项目目录、扩展名、目标文件格式或操作系统如何启动文件。

**常见错误与边界：** 头文件不是运行时“导入模块”，也通常不单独运行；源码存在不代表已经生成可执行文件。`.o/.obj`、ELF、PE 等均是平台事实。

**前置节点：** 无。


### B0.3 必须先掌握的术语

**语法/接口：** `int count = 3;` 中 `int` 是类型，`count` 是标识符引入的名字，`count` 对应一个对象，`3` 是字面量，整条声明以 `;` 结束。术语本身没有独立关键字。

**定义与用途：**

- 标识符是由允许字符组成的记号；名字是程序中表示实体的标识。
- 类型规定值的表示及允许操作；对象是一段具有类型和生命周期的存储。
- 表达式计算值并可能产生副作用；语句控制执行；声明把名字介绍给程序。
- 编译期是翻译程序的阶段，运行期是生成的程序执行阶段。

```cpp
int count = 3;       // 声明并定义对象
count = count + 1;   // 表达式语句；修改对象
```

**C++11 精确语义：** 名字不等于对象：类型名、函数名和命名空间名也都是名字。值也不等于存储地址；同一数值可存在于多个对象。编译期常量可影响数组长度和模板实例，运行期输入通常不能。

**常见错误与边界：** 不要把“变量”理解为所有名字，也不要把编译器优化后的实现细节当语言语义。泛型 Lambda 和 Lambda 初始化捕获属于 C++14，不是 C++11。

**前置节点：** B0.1。

## B1. 从源代码到程序运行

### B1.1 实际工具链流程

**语法/接口：** GCC/Clang 可分别使用 `g++ -E a.cpp -o a.ii`、`g++ -S -std=c++11 a.ii -o a.s`、`g++ -c a.s -o a.o`、`g++ a.o b.o -o app`。这些命令不是 ISO C++11。

**定义与用途：** 常见流程为预处理 → 编译 → 汇编 → 链接 → 装载运行。预处理处理 `#include/#define/#if`；编译解析 C++ 并检查类型；汇编产生目标文件；链接解析跨文件引用；操作系统装载最终产物。

```cpp
#include <iostream> // 预处理阶段纳入头文件内容

int main()
{
    std::cout << "ok\n"; // 编译阶段检查名字和类型
}
```

**C++11 精确语义：** 标准描述九个翻译阶段及程序执行语义，但“编译器/汇编器/链接器”这种可执行工具划分是常见实现。模板实例化、优化和代码生成可能跨内部阶段完成。

**常见错误与边界：** 头文件找不到通常是预处理诊断；缺分号、类型不匹配是编译诊断；未定义引用、重复定义是链接诊断；共享库找不到可能到装载时才失败。某些 ODR 违反不要求诊断。

**前置节点：** B0.1、B0.3。

### B1.2 翻译单元

**语法/接口：** 一个源文件通过 `#include "api.hpp"` 文本包含头文件；GCC/Clang 用 `g++ -E source.cpp` 可近似观察预处理结果。翻译单元没有运行期导入语法。

**定义与用途：** 翻译单元是一个源文件经过预处理后的结果，是声明可见性、模板实例化和独立编译的主要边界。同一个头文件可进入多个翻译单元。

```cpp
// api.hpp
int add(int, int);

// main.cpp
#include "api.hpp"
int main() { return add(1, 2); }
```

**C++11 精确语义：** `main.cpp` 与它包含的头内容共同构成一个翻译单元；另一个 `.cpp` 包含同一头时形成另一份翻译单元。宏只在相应预处理流程内生效。

**常见错误与边界：** 头文件不会自动生成一个共享目标文件。不同宏令两个翻译单元看到不同类定义，可能违反 ODR 且不要求诊断。

**前置节点：** B1.1。

### B1.3 声明、定义与分离编译

**语法/接口：** 函数声明 `int add(int, int);`；函数定义 `int add(int a, int b) { return a + b; }`；对象外部声明 `extern int total;`；对象定义 `int total = 0;`。

**定义与用途：** 声明让当前翻译单元知道名字和类型；定义还提供函数体、对象存储或完整类信息。分离编译让调用方只需包含公共声明，定义可在另一个源文件。

```cpp
// add.hpp
int add(int, int);

// add.cpp
#include "add.hpp"
int add(int a, int b) { return a + b; }

// main.cpp
#include "add.hpp"
int main() { return add(3, 4); }
```

**C++11 精确语义：** 函数定义同时也是声明。相容声明可以多次出现；普通非 `inline` 外部函数通常在整个程序需要唯一相应定义。

**常见错误与边界：** 只有声明会让调用方通过编译，却可能在链接时报未定义引用；声明与定义的参数类型不一致会形成不同函数。实现文件应包含自己的头以检查一致性。

**前置节点：** B1.2。

### B1.4 头文件保护

**语法/接口：**

```cpp
#ifndef PROJECT_COUNTER_HPP
#define PROJECT_COUNTER_HPP

int next_counter();

#endif
```

**定义与用途：** include guard 用唯一宏防止同一翻译单元经多条包含路径重复处理一个头文件，避免类重定义等问题。

**C++11 精确语义：** `#ifndef`、`#define`、`#endif` 是标准预处理指令。guard 只影响当前预处理过程，不会阻止该头进入其他翻译单元。

**常见错误与边界：** 两个头误用同一保护宏会让后者被跳过；guard 不能修复头文件中普通全局变量定义造成的跨翻译单元重复定义。`#pragma once` 常被支持，但不由 ISO C++11 保证。

**前置节点：** B1.2、B1.3。

### B1.5 单一定义规则 ODR

**语法/接口：** 普通外部定义放一个 `.cpp`：`int global = 0;`；允许头文件重复出现的定义包括 `inline int f(){...}`、类定义和模板定义，但各翻译单元中的对应定义必须满足 ODR 一致性要求。

**定义与用途：** 单一定义规则确保所有翻译单元对同一实体的类型、布局和行为理解一致。需要使用的非内联函数或变量通常在整个程序有且仅有一个定义。

```cpp
// square.hpp
inline int square(int value)
{
    return value * value;
}
```

**C++11 精确语义：** 类、模板和 `inline` 实体可在多个翻译单元定义，但必须满足相同记号序列及相关名字查找等条件，并表示同一实体。某些违反 ODR 的程序不要求实现诊断。

**常见错误与边界：** “重复定义”是提供过多不允许的定义；“未定义引用”是链接找不到所需定义。静态库、动态库、ABI、编译参数和 CMake 属于工具链/工程知识，不是 C++11 语法。

**前置节点：** B1.3、B1.4。

## B2. 词法、基本语法与名字

### B2.3 命名空间

**语法/接口：** 定义 `namespace app { int value = 1; }`；限定访问 `app::value`；引入一个名字 `using std::cout;`；引入命名空间 `using namespace std;`；全局限定符写 `::value`。

**定义与用途：** 命名空间为名字分组，减少不同库之间的冲突。标准库名字位于 `std` 命名空间。

```cpp
#include <iostream>

namespace first { int value = 1; }
namespace second { int value = 2; }

int main()
{
    std::cout << first::value + second::value << '\n';
}
```

**C++11 精确语义：** 同名命名空间声明可以扩展同一命名空间。`using` 声明引入指定名字；using-directive 让非限定查找考虑整个命名空间，但不复制实体。

**常见错误与边界：** 头文件顶层 `using namespace std;` 会污染每个包含者并产生歧义；不要向 `std` 添加普通声明，标准仅允许极少数针对用户定义类型的特化。`::name` 从全局命名空间开始查找。

**前置节点：** B0.3、B1.2。

### B2.4 基本字面量

**语法/接口：** 整数 `42`、`0xff`、`0b...`（注意二进制字面量是 C++14）、浮点 `3.14`、字符 `'A'`、字符串 `"text"`、布尔 `true/false`、空指针 `nullptr`；原始字符串 `R"(a\nb)"`。

**定义与用途：** 字面量直接在源代码中表示值。后缀影响类型，例如 `42u` 是无符号整数，`1.0f` 是 `float`，普通 `1.0` 是 `double`。

```cpp
#include <iostream>

int main()
{
    const char newline = '\n';
    const char* path = R"(C:\temp\file.txt)";
    int* pointer = nullptr;
    std::cout << path << newline << (pointer == nullptr);
}
```

**C++11 精确语义：** `"abc"` 的类型是 `const char[4]`，包含终止空字符；`'0'` 是字符零，`'\0'` 是数值为零的空字符。`nullptr` 的类型是 `std::nullptr_t`，可转换到指针类型但不是整数。

**常见错误与边界：** 转义序列由反斜线开始；原始字符串不处理普通转义。`0b1010` 和数字分隔符是 C++14，不属于 C++11。

**前置节点：** B3.1 可在学习字符细节时回看。

### B2.5 预处理器基础

**语法/接口：** `#include <header>`、`#include "local.hpp"`、`#define NAME replacement`、`#define SQUARE(x) ((x) * (x))`、`#if/#ifdef/#else/#endif`、`#undef NAME`。

**定义与用途：** 预处理器在 C++ 语法分析前处理指令和宏。对象式宏替换一个名字，函数式宏按记号替换参数；条件编译选择是否保留一段记号。

```cpp
#define FEATURE 1

#if FEATURE
const int limit = 10;
#endif
```

**C++11 精确语义：** 宏不理解类型、作用域或求值次数。宏参数每在替换列表出现一次，都可能令对应实参表达式再次出现。

```cpp
#define BAD_SQUARE(x) ((x) * (x))
// BAD_SQUARE(i++) 会修改 i 两次，并可能产生未定义行为
```

**常见错误与边界：** 函数式宏的整体和每个参数用途通常都要加括号，但括号不能消除重复求值。常量优先 `const/constexpr`，操作优先普通或 `inline` 函数。预定义宏和包含搜索路径有实现/工具链边界。

**前置节点：** B1.1、B1.4。

## B3. 基本类型与数据表示

### B3.1 布尔和字符类型

**语法/接口：** `bool ready = true;`、`char ch = 'A';`、`signed char s = -1;`、`unsigned char byte = 255;`、`wchar_t`、C++11 的 `char16_t` 与 `char32_t`。

**定义与用途：** `bool` 表示 `true/false`。字符类型存放整数编码单元；`char` 常用于窄字符和原始字节序列，`signed char`/`unsigned char` 明确算术符号性。三者是不同类型。

```cpp
#include <iostream>

int main()
{
    char letter = 'A';
    unsigned char byte = 65;
    std::cout << letter << ' ' << static_cast<unsigned int>(byte) << '\n';
}
```

**C++11 精确语义：** 普通 `char` 与 `signed char`、`unsigned char` 都不同；普通 `char` 是有符号还是无符号由实现定义。`sizeof(char)` 恒为 1，但一个字节的位数由 `CHAR_BIT` 决定。`bool` 转整数得到 0 或 1；非零算术值转 `bool` 为 `true`。

**常见错误与边界：** 文本最终仍由数值编码单元表示，所以字符类型有整数范围和符号性；高位字节用负 `char` 传给 `<cctype>` 函数会越界，通常先转 `unsigned char`。字符数不等于用户看到的 Unicode 字符数。

**前置节点：** B2.4。

### B3.2 整数类型

**语法/接口：** `short`、`int`、`long`、`long long` 及对应的 `unsigned` 类型；范围宏在 `<climits>`，类型化查询可用 `<limits>` 的 `std::numeric_limits<T>`.

**定义与用途：** 整数类型表示离散整数。标准保证相对最小范围与 `sizeof(short) <= sizeof(int) <= sizeof(long) <= sizeof(long long)`，但允许实现选择更宽表示。

```cpp
#include <climits>
#include <iostream>
#include <limits>

int main()
{
    std::cout << sizeof(int) << ' '
              << std::numeric_limits<int>::min() << ' '
              << INT_MAX << ' ' << CHAR_BIT << '\n';
}
```

**C++11 精确语义：** `int` 至少能表示 `-32767..32767`，不保证恰好 32 位或 4 字节。`long long` 至少 64 位。无符号类型范围从 0 到 `2^N-1`，运算按模 `2^N`。有符号整数溢出是未定义行为。

**常见错误与边界：** 不要用 `sizeof(int)==4` 作为可移植假设；字节不是固定等于 8 位。需要协议固定宽度时可检查 `<cstdint>` 中 `std::int32_t` 等是否由实现提供，但它们也不是在所有实现上必有。

**前置节点：** B3.1。

### B3.4 浮点类型

**语法/接口：** `float f = 1.0f;`、`double d = 1.0;`、`long double ld = 1.0L;`；范围与精度查 `std::numeric_limits<T>`，宏如 `FLT_MAX/DBL_MAX` 位于 `<cfloat>`。

**定义与用途：** 浮点类型表示近似实数，具有有限有效位、指数范围和舍入。`double` 通常比 `float` 精度不少，`long double` 精度不少于 `double`，但具体格式由实现决定。

```cpp
#include <iomanip>
#include <iostream>

int main()
{
    double value = 0.1 + 0.2;
    std::cout << std::setprecision(17) << value << '\n';
}
```

**C++11 精确语义：** 十进制 `0.1` 通常不能被二进制浮点精确表示，算术每步可能舍入。标准不强制所有实现采用 IEEE 754；是否支持无穷大、NaN 可由 `numeric_limits` 查询。

**常见错误与边界：** 不应普遍用 `a == b` 判断计算结果；应根据业务尺度选择绝对/相对容差，但容差也不是万能规则。浮点转整数和溢出另见 B7.3。浮点数不能直接使用位运算符。

**前置节点：** B3.2、B6.1。

### B3.5 `void` 与空指针类型

**语法/接口：** 无返回值函数 `void log();`；通用对象指针 `void* raw = &object;`；空指针 `T* pointer = nullptr;`；`nullptr` 的类型可写 `std::nullptr_t`（`<cstddef>`）。

**定义与用途：** `void` 表示没有值，也是不完整类型，不能定义普通 `void` 对象。`void*` 可保存对象指针的类型擦除表示，但不能直接解引用。`nullptr` 是专用空指针字面量。

```cpp
int value = 3;
void* erased = &value;   // int* 隐式转 void*
int* restored = static_cast<int*>(erased);
```

**C++11 精确语义：** 对象指针可隐式转为 `void*` 并在正确类型下显式转回；C++ 不允许 `void*` 隐式转具体对象指针。`nullptr` 可转任意指针和成员指针；整数 `0` 也可作空指针常量，但参与重载时仍是整数。

**常见错误与边界：** `NULL` 通常是实现宏，可能是整数，易选错重载；C++11 优先 `nullptr`。从 `void*` 转成错误类型并解引用会违反类型、对齐或生命周期规则。

**前置节点：** B2.4、B14.1。

### B3.6 大小、范围和对齐

**语法/接口：** `sizeof(Type)`、`sizeof expression`、`alignof(Type)`；`std::numeric_limits<T>::min()/max()/digits`；`sizeof` 结果类型为 `std::size_t`。

**定义与用途：** 大小是对象表示占多少字节；位数是字节或类型的二进制位数量；范围是可表示值集合；对齐是对象地址需满足的倍数约束。四者相关但不同。

```cpp
#include <iostream>
#include <limits>

int main()
{
    std::cout << sizeof(double) << ' '
              << alignof(double) << ' '
              << std::numeric_limits<double>::max() << '\n';
}
```

**C++11 精确语义：** `sizeof(char)==1`；完整对象类型的大小至少 1。结构体大小可能含填充，对齐由实现和 ABI 决定。大多数 `sizeof` 操作数不求值。

**常见错误与边界：** 指针大小不是所指对象大小；`sizeof(array)` 是整个数组，而数组形参处得到指针大小。不要将本机输出当跨平台常量。变长数组不是标准 C++11。

**前置节点：** B3.1、B3.2；数组细节见 B11.2。

### B3.7 枚举基础

**语法/接口：** 普通枚举 `enum Color { red, green };`；作用域枚举 `enum class State : unsigned char { idle, busy };`；访问写 `State::idle`，转整数写 `static_cast<unsigned char>(state)`。

**定义与用途：** 枚举定义一组命名的离散常量。C++11 `enum class` 把枚举量限制在枚举作用域内，并禁止到整数的隐式转换，能减少名字冲突和误算术。

```cpp
enum class Status { ok, failed };

int main()
{
    Status value = Status::ok;
    return value == Status::ok ? 0 : 1;
}
```

**C++11 精确语义：** 可显式指定底层整数类型；作用域枚举默认底层类型为 `int`。普通枚举的枚举量进入外围作用域，并可隐式转整数。

**常见错误与边界：** `enum class` 不是类，不能定义成员函数；不同枚举类型不能直接比较。序列化时应显式约定底层编码，不能仅依赖实现选择。

**前置节点：** B3.2、B7.5。

## B4. 变量、初始化和类型推导

### B4.1 声明与定义

**语法/接口：** `int x;` 通常声明并定义对象；`extern int x;` 通常只声明；`int f(int);` 声明函数；带函数体的 `int f(int n){ return n; }` 是定义。

**定义与用途：** 声明把名字及其类型介绍给作用域；定义还建立对象、函数体或完整类。所有定义都是声明，但并非所有声明都是定义。

```cpp
extern int total; // 声明
int total = 0;    // 定义

int add(int, int); // 声明
int add(int a, int b) { return a + b; } // 定义
```

**C++11 精确语义：** 同一作用域可重复相容声明，但不能重复定义同一普通对象。`extern int x = 1;` 因带初始化器仍是定义。类前向声明 `class Node;` 不提供完整布局。

**常见错误与边界：** `int x; int x;` 在同一块作用域是重复定义；跨文件仅声明不提供定义会链接失败。声明与定义必须类型相容。

**前置节点：** B1.3、B1.5。

### B4.2 初始化与赋值

**语法/接口：** 初始化出现在定义中：`T value(argument);`、`T value = argument;`、`T value{argument};`；赋值写在已有对象上：`value = argument;`。

**定义与用途：** 初始化建立对象的初始状态并开始其正常生命周期；赋值调用已有对象的赋值语义，替换当前值。初始化不是“对象先存在后做的第一次赋值”。

```cpp
#include <string>

int main()
{
    std::string first("A"); // 初始化
    std::string second = first; // 仍是初始化
    second = "B"; // 赋值
}
```

**C++11 精确语义：** 类对象初始化选择构造函数；赋值选择赋值运算符。`const` 对象和引用必须初始化，之后不能用普通赋值改变其绑定/只读状态。

**常见错误与边界：** `T b = a;` 是拷贝初始化，不是先默认构造再赋值。成员在进入构造函数体前已经初始化；在函数体中写 `member = value` 不能代替对引用、`const` 或无默认构造成员的初始化。

**前置节点：** B4.1、对象生命周期见 B15.8。

### B4.3 C++11 初始化形式

**语法/接口：** 默认初始化 `T x;`；值初始化 `T x{};`；直接初始化 `T x(args);`；拷贝初始化 `T x = value;`；列表初始化 `T x{args};`；聚合初始化 `Aggregate a{members...};`。

**定义与用途：** 不同形式控制零初始化、构造函数选择、`explicit` 可用性和窄化检查。C++11 `{}` 提供统一语法，但不是所有形式都完全等价。

```cpp
struct Point {
    int x;
    int y;
};

int main()
{
    int a;         // 默认初始化：自动局部 int 值不确定
    int b{};       // 值初始化为 0
    int c(3);      // 直接初始化
    int d = 3;     // 拷贝初始化
    int e{3};      // 列表初始化
    Point p{1, 2}; // 聚合初始化
    (void)a; (void)b; (void)c; (void)d; (void)e; (void)p;
}
```

**C++11 精确语义：** 列表初始化优先考虑可行的 `std::initializer_list` 构造函数并禁止特定窄化。拷贝初始化不使用 `explicit` 构造函数，直接/列表直接初始化可以。

**常见错误与边界：** `T object();` 声明函数，不是默认构造对象（最令人困惑的解析）；改写 `T object{};`。类是否为聚合受严格规则约束，不能只看“成员公开”。

**前置节点：** B4.2、B4.5。

### B4.4 未初始化对象

**语法/接口：** 危险形式 `int value;`、`int* pointer;`；安全的零初始化形式 `int value{};`、`int* pointer = nullptr;`。

**定义与用途：** 自动存储期的基础类型进行默认初始化时通常没有初始化器，其值不确定；先初始化可建立明确程序状态。

```cpp
#include <iostream>

int main()
{
    int safe{};
    // int unsafe;
    // std::cout << unsafe; // 读取不确定值：未定义行为
    std::cout << safe << '\n';
}
```

**C++11 精确语义：** 静态存储期对象先零初始化；类对象即使写 `T object;` 也会按构造规则初始化成员，但其构造函数仍可能漏初始化基础类型成员。分配到原始存储不等于其中已经存在可读对象。

**常见错误与边界：** 调试环境碰巧填零不构成保证；读取未初始化基础值通常是未定义行为。赋值前可以先声明，但所有控制流必须在读取前赋值；更简单的做法是定义时初始化。

**前置节点：** B4.3、B15.3。

### B4.5 列表初始化与窄化

**语法/接口：** `T value{expression};` 或 `T value = {expression};`；若转换属于列表窄化，程序非良构并要求诊断。

**定义与用途：** 列表初始化用编译期规则阻止可能丢失范围或精度的隐式转换，帮助在对象创建处尽早发现错误。

```cpp
int main()
{
    int good{3};
    // int bad1{3.5};          // 浮点到整数：窄化
    // unsigned char bad2{300}; // 常量超出范围：窄化

    const int small = 42;
    unsigned char ok{small};   // 常量表达式且值可表示
    (void)good; (void)ok;
}
```

**C++11 精确语义：** 浮点到整数、浮点类型间可能降级、整数到不能完整表示的整数类型，以及多数整数到浮点转换都受限制；某些整数常量表达式若值可由目标类型表示则允许。

**常见错误与边界：** 圆括号或 `=` 初始化可能允许相同转换并产生截断/取模，但这不说明数值安全。列表规则只检查标准所列窄化，不能防止运行时算术溢出或业务范围错误。

**前置节点：** B3.2、B3.4、B4.3。

### B4.6 `auto`

**语法/接口：** `auto value = expression;`、`auto& reference = object;`、`const auto& read_only = expression;`、`auto&& forwarding = expression;`。普通变量 `auto` 必须有初始化器。

**定义与用途：** `auto` 让编译器在编译期按模板推导式规则确定静态类型，适合冗长迭代器类型和类型显然的表达式。

```cpp
const int original = 7;
const int& alias = original;

auto a = original;  // int：丢弃顶层 const
auto b = alias;     // int：按值，不保留引用
auto& c = original; // const int&
const auto d = 3;   // const int
```

**C++11 精确语义：** 普通 `auto` 按值推导，通常去掉引用和顶层 cv；底层 `const`（例如所指对象的 const）会保留。`auto&` 保留引用关系；`auto&&` 在推导上下文中按引用折叠，可绑定左值或右值。`auto` 只是类型占位符，不是运行时动态类型。

```cpp
int value = 1;
auto&& left = value; // 最终 int&
auto&& right = 3;    // 最终 int&&
```

**常见错误与边界：** `const auto x;` 不合法，因为无法推导且 const 对象需初始化；`auto list{1,2}` 在 C++11 涉及 `initializer_list` 推导，规则与后续标准细节不同。函数普通返回类型写 `auto f(){...}` 的自动推导是 C++14；C++11 仅支持尾置返回类型形式。

**前置节点：** B4.3、B5.2、B6.2。

### B4.7 `decltype`

**语法/接口：** `decltype(entity_name)`、`decltype(expression)`；类型别名可写 `using Type = decltype(expression);`。操作数通常处于不求值上下文。

**定义与用途：** `decltype` 查询名字或表达式的类型，并在一般表达式形式下把值类别编码成引用，适合泛型返回类型和精确保留 cv/引用。

```cpp
#include <type_traits>

int main()
{
    int value = 1;
    const int fixed = 2;

    static_assert(std::is_same<decltype(value), int>::value, "int");
    static_assert(std::is_same<decltype(fixed), const int>::value, "const");
    static_assert(std::is_same<decltype((value)), int&>::value, "lvalue");
}
```

**C++11 精确语义：** 对未加括号的标识符表达式或成员访问，`decltype(name)` 直接得到实体声明类型。其他表达式：左值结果为 `T&`，将亡值结果为 `T&&`，纯右值结果为 `T`。额外括号把 `value` 变成一般左值表达式，所以 `decltype((value))` 是 `int&`，不是“变量本身这种类型”。

**常见错误与边界：** `decltype` 通常不执行表达式，但表达式仍需语法上合法；不要与普通 `auto` 的按值推导混用。`decltype(auto)` 是 C++14。

**前置节点：** B4.6、B6.2。

### B4.8 类型别名

**语法/接口：** 传统形式 `typedef unsigned long Count;`；C++11 形式 `using Count = unsigned long;`；别名模板 `template<class T> using Ptr = T*;`。

**定义与用途：** 类型别名给已有类型增加另一种拼写，用于表达含义、缩短复杂类型和隔离实现细节。

```cpp
#include <vector>

using Count = unsigned long;
using IntList = std::vector<int>;

int main()
{
    Count n = 3;
    IntList values{1, 2, 3};
    return static_cast<int>(n + values.size());
}
```

**C++11 精确语义：** 别名不会创建新类型；`Count` 与 `unsigned long` 完全相同，重载不能仅靠别名区分。`using` 对复杂函数指针和模板别名通常比 `typedef` 易读。

**常见错误与边界：** 别名不提供类型安全封装；需要真正不同的类型应定义类或结构体。别名模板属于 C++11，但不能偏特化。

**前置节点：** B0.3、模板细节见 T3.5。

## B5. `const`、`constexpr` 与只读接口

### B5.1 `const` 对象

**语法/接口：** `const int limit = 10;` 与 `int const limit = 10;` 等价；const 对象通常必须初始化。

**定义与用途：** `const` 表示不能通过该 const 访问路径修改对象，用于表达只读意图和建立接口约束。

```cpp
int read()
{
    const int limit = 10;
    // limit = 11; // 编译错误
    return limit;
}
```

**C++11 精确语义：** const 对象仍有类型、地址、存储期和生命周期。`const` 不自动表示编译期常量；例如 `const int n = runtime();` 的值在运行期取得。某些由常量表达式初始化的 const 整数可用于整数常量表达式场景，但 `constexpr` 表意更明确。

**常见错误与边界：** 另一个非 const 别名可能仍能修改原本非 const 的对象；“通过 const 引用不可改”不等于对象物理上永远不变。用 `const_cast` 修改原本定义为 const 的对象会产生未定义行为。

**前置节点：** B4.2、B4.3。

### B5.2 顶层与底层 `const`

**语法/接口：** `int* const pointer` 的 const 作用于指针对象本身（顶层）；`const int* pointer` 的 const 作用于所指类型（底层）；`const int* const pointer` 同时具有二者。

**定义与用途：** 顶层 const 限定当前对象不能修改；底层 const 是复合类型的一部分，限制通过指针或引用修改其指向对象。区别决定赋值、参数和类型推导。

```cpp
int value = 1;
int* const fixed_pointer = &value; // 指针不能改指向
const int* read_pointer = &value;  // 不能通过它改 value

*fixed_pointer = 2; // 合法
// *read_pointer = 2; // 错误
```

**C++11 精确语义：** 按值复制时顶层 const 通常不影响函数类型，`void f(int)` 与 `void f(const int)` 不能重载；底层 const 会保留。普通 `auto` 按值推导通常丢弃顶层 const。

**常见错误与边界：** “const 在左还是右”不是完整判断方法，应从声明符向名字读；`const int*` 与 `int const*` 相同。多级指针的 const 转换更严格，不能把 `int**` 直接转成 `const int**`。

**前置节点：** B5.1、B14.1。

### B5.3 指针与 `const`

**语法/接口：** `const T* p`/`T const* p` 是指向 const 的指针；`T* const p = &object` 是 const 指针；`const T* const p = &object` 两者皆 const。

**定义与用途：** 两个 const 位置分别约束“能否通过指针修改对象”和“指针变量能否重新指向”。这使接口能表达只读借用与固定句柄。

```cpp
int first = 1;
int second = 2;

const int* p = &first;
p = &second;        // 可重新指向
// *p = 3;          // 不可通过 p 修改

int* const q = &first;
*q = 3;             // 可修改对象
// q = &second;     // q 本身不可改
```

**C++11 精确语义：** `int*` 可隐式转 `const int*`，增加底层 const；反向需要显式 `const_cast`，但它只改变访问类型，不改变原对象是否实际为 const。

**常见错误与边界：** 对实际定义为 `const int` 的对象去 const 后写入是未定义行为。返回内部可写指针会破坏封装；只读接口通常返回 `const T*`。

**前置节点：** B5.2、B14.1。

### B5.4 引用与 `const`

**语法/接口：** 可修改左值引用 `T& ref = object;`；const 左值引用 `const T& ref = expression;`。引用本身必须初始化且不能重新绑定。

**定义与用途：** 引用是已有对象的别名。`const T&` 允许只读访问，既避免按值复制，又能绑定 const 对象、非 const 对象及合适的临时对象。

```cpp
int value = 1;
const int fixed = 2;

int& a = value;
const int& b = value;
const int& c = fixed;
const int& d = 3; // 临时 int 生命周期延长到 d 的作用域结束

a = 4;
// b = 5; // 错误
```

**C++11 精确语义：** 非 const 左值引用通常只能绑定类型相容的可修改左值。const 引用绑定临时对象时，在特定直接绑定场景可延长临时生命周期；这种延长不会在任意传递、返回或成员引用情况下继续传播。

**常见错误与边界：** `const T&` 只限制通过该引用修改；若原对象非 const，其他别名仍可修改。返回对局部对象的引用会悬空，即使返回类型是 const 引用。

**前置节点：** B5.1、B6.2、B14.5。

### B5.5 `constexpr`

**语法/接口：** `constexpr int size = 16;`；C++11 constexpr 函数典型形式 `constexpr int square(int x) { return x * x; }`。

**定义与用途：** `constexpr` 声明对象或函数可参与编译期常量表达式。constexpr 对象必须由常量表达式初始化，并且本身是 const。

```cpp
constexpr int square(int value)
{
    return value * value;
}

int main()
{
    constexpr int n = square(4);
    int data[n] = {};
    return data[0];
}
```

**C++11 精确语义：** constexpr 函数也可以用运行期实参调用，此时结果在运行期计算。C++11 非构造 constexpr 函数体要求非常严格，核心上只能包含一条 `return` 语句（另有少量允许项），且返回表达式满足规则。

**常见错误与边界：** `const int n = runtime();` 不是常量表达式；`constexpr` 也不保证一定生成“编译时机器码结果”，它保证在所需且条件满足时可常量求值。多语句循环 constexpr 函数是 C++14 放宽内容。

**前置节点：** B4.3、B5.1、B9.9。

## B6. 表达式、运算符和求值规则

### B6.1 表达式基础

**语法/接口：** 常见表达式包括 `a + b`、`f(argument)`、`object.member`、`condition ? x : y`、`value = 3`；表达式后加 `;` 可形成表达式语句。

**定义与用途：** 表达式由操作数和运算符组成，具有类型、值和值类别，并可能产生副作用，例如修改对象、执行 I/O 或调用函数。

```cpp
int a = 2;
int b = 3;
int result = a + b; // a+b 是 int 纯右值表达式
++a;                // 值计算并修改 a
```

**C++11 精确语义：** 完整表达式通常是未作为其他表达式子表达式的表达式，例如表达式语句、初始化器和 `return` 的操作数。完整表达式结束是许多临时对象销毁和副作用排序的重要边界。

**常见错误与边界：** 括号只改变语法分组，例如 `(a+b)*c`，不会普遍规定先求哪个函数实参或 `+` 的哪个操作数。不能因数学表达式无副作用就忽略 C++ 求值规则。

**前置节点：** B0.3、B4.2。

### B6.2 基础值类别

**语法/接口：** 典型左值：具名对象 `value`、解引用 `*pointer`；典型纯右值：字面量 `3`、算术结果 `a+b`；典型将亡值：`std::move(value)`。分类本身没有声明关键字。

**定义与用途：**

- `lvalue`（左值）：有身份、通常可取地址的表达式。
- `xvalue`（将亡值）：有身份但资源可被复用的表达式。
- `prvalue`（纯右值）：主要用于计算或初始化的值。
- `glvalue = lvalue + xvalue`；`rvalue = prvalue + xvalue`。

```cpp
#include <utility>

int value = 1;
int* pointer = &value;

int& left = value;                   // value 是左值
int&& right = 3;                     // 3 是纯右值
int&& expiring = std::move(value);   // std::move(value) 是将亡值
(void)pointer; (void)left; (void)right; (void)expiring;
```

**C++11 精确语义：** 值类别属于表达式，不是对象永久属性。具名右值引用变量的表达式仍是左值；`std::move` 通常只做转换，真正移动由随后选中的操作完成。

**常见错误与边界：** 左值不等于“能放在赋值号左边”，const 左值不能赋值；右值不等于“常量”。不要把将亡值理解为对象已经销毁，它仍处于生命周期中。

**前置节点：** B6.1、B14.5。
### B6.4 有符号与无符号算术

**语法/接口：** 用 `unsigned int` 或后缀 `u` 明确无符号值，如 `1u`；范围用 `std::numeric_limits<T>::max()`；跨类型运算前可显式检查并转换。

**定义与用途：** 无符号整数适合位掩码和按模算术；有符号整数适合表达可为负的普通数量。两类运算具有不同溢出规则。

```cpp
#include <limits>

int main()
{
    unsigned int x = std::numeric_limits<unsigned int>::max();
    ++x; // 按模 2^N，结果为 0
    return static_cast<int>(x);
}
```

**C++11 精确语义：** N 位无符号运算结果按 `2^N` 取模，因为它的可表示值集合就是 `0..2^N-1`，标准明确规定这种模算术。有符号结果超出类型范围是未定义行为，编译器可假定它不发生。

```cpp
int negative = -1;
unsigned int one = 1u;
bool surprising = negative < one; // negative 可能先转成很大的 unsigned
```

**常见错误与边界：** `for (std::size_t i=n-1; i>=0; --i)` 永不因 `i<0` 结束；可写 `for (std::size_t i=n; i-- > 0; )`。不能依赖 `INT_MAX+1` 回绕。无符号回绕虽有定义，也不代表业务上正确或能避免分配大小漏洞。

**前置节点：** B3.2、B7.2。
### B6.6 位运算

**语法/接口：** 按位与 `a & b`、或 `a | b`、异或 `a ^ b`、取反 `~a`、左移 `a << n`、右移 `a >> n`；置位 `mask |= (1u << k)`，清位 `mask &= ~(1u << k)`，测试位 `mask & (1u << k)`。

**定义与用途：** 位运算逐二进制位处理整数，用于掩码、协议字段和底层标志。`&/|` 与逻辑 `&&/||` 不同：后者产生布尔结果并短路。

```cpp
unsigned int flags = 0;
const unsigned int bit = 1u << 3;
flags |= bit;             // 置第 3 位
bool set = (flags & bit) != 0;
flags &= ~bit;            // 清第 3 位
```

**C++11 精确语义：** 小整数操作数先整数提升。移位数为负或不小于提升后左操作数位数是未定义行为。无符号左移按可表示位宽取模；无符号右移相当于除以 `2^n`。负有符号数左移有未定义行为，负有符号数右移结果由实现定义。

**常见错误与边界：** `1u << (sizeof(unsigned int)*CHAR_BIT)` 的移位数等于位数，行为未定义。位运算只适用于整数或枚举经转换后的值，浮点数不能直接位运算；观察浮点对象表示应通过字节复制而不是违反别名规则。“同或”没有独立 C++ 运算符，可写 `~(a ^ b)` 并按需要掩掉高位。

**前置节点：** B3.2、B7.1。

### B6.7 赋值与复合赋值

**语法/接口：** 简单赋值 `left = right`；算术复合赋值 `+= -= *= /= %=`；位复合赋值 `&= |= ^= <<= >>=`。

**定义与用途：** 赋值修改已存在的左操作数。复合赋值表达 `x op= y` 的数值效果类似 `x = x op y`，但左操作数只求值一次。

```cpp
int a = 0;
int b = 0;
a = (b = 5); // b=5 的结果再赋给 a；两者最终都是 5
a += 2;      // a 变为 7
```

**C++11 精确语义：** `=` 右结合，因此 `a=b=5` 分组为 `a=(b=5)`。内建赋值表达式结果是引用左操作数的左值，所以可继续参与表达式。赋值会执行所需隐式转换。

**常见错误与边界：** 复合赋值不是原子操作；多线程共享对象仍需同步。`if (a = b)` 是赋值而非比较，虽可合法转换为 bool，但常是错误。结合性只决定分组，不概括所有子表达式的运行顺序。

**前置节点：** B4.2、B6.1。

### B6.9 优先级、结合性与求值顺序

**语法/接口：** 用括号明确分组；用独立语句、`&&`、`||`、内建逗号运算符或条件运算符规定的边界建立所需顺序。不存在通用“从左到右求值”关键字。

**定义与用途：** 优先级决定不同运算符如何分组；结合性决定同优先级运算符如何分组；求值顺序决定运行时先计算哪个子表达式。三者必须分开。

```cpp
int value = 1 + 2 * 3; // 优先级分组为 1 + (2 * 3)
int a, b;
a = b = 5;             // 右结合：a = (b = 5)
```

**C++11 精确语义：** 多数二元运算符的两个操作数以及不同函数实参之间没有规定固定先后。若对同一标量对象进行彼此未排序的多次修改，或修改与读取冲突，行为未定义。

```cpp
int i = 1;
// int r = (i++) + (++i); // 未定义行为

int left = i++;
int right = ++i;
int r = left + right;     // 拆成完整表达式，顺序明确
```

**常见错误与边界：** 给 `(i++) + (++i)` 加更多分组括号不能建立顺序；括号只改语法树。`f(i++, i++)` 在 C++11 同样不能依赖顺序且涉及未排序修改。短路 `&&/||` 会先完整求左侧，再按需求右侧。

**前置节点：** B6.1、B6.7。

### B6.10 `sizeof` 等运算符

**语法/接口：** `sizeof(Type)`、`sizeof expression`、`alignof(Type)`；结果类型是 `std::size_t`。数组元素数常写 `sizeof(array) / sizeof(array[0])`。

**定义与用途：** `sizeof` 给出类型或对象表示占用的字节数，`alignof` 给出类型的对齐要求；常用于静态布局检查和固定数组长度计算。

```cpp
#include <cstddef>
#include <iostream>

int main()
{
    int array[5] = {};
    int* pointer = array;
    std::cout << sizeof(array) / sizeof(array[0]) << ' '
              << sizeof(pointer) << ' ' << alignof(int) << '\n';
}
```

**C++11 精确语义：** `sizeof` 的操作数是不求值操作数；`sizeof(i++)` 不增加 `i`。数组对象在 `sizeof` 中不发生数组到指针转换，因此得到整个数组大小；指针表达式只得到指针对象大小。

**常见错误与边界：** 函数数组形参已调整为指针，函数内 `sizeof(parameter)` 得到指针大小。不能对不完整类型或 `void` 求标准 `sizeof`；某些编译器接受是扩展。

**前置节点：** B3.6、B11.2、B11.3。

## B7. 隐式转换与显式转换

### B7.1 整数提升

**语法/接口：** 提升通常隐式发生；可用 `static_cast<int>(small)` 明确结果类型，用 `decltype(+small)` 观察一元 `+` 后的提升类型。

**定义与用途：** `bool`、字符类型和 `short` 等整数等级较低的类型参与多数算术/位运算前，会提升为 `int`；若 `int` 不能表示原类型全部值，则提升为 `unsigned int`。

```cpp
int main()
{
    unsigned char a = 200;
    unsigned char b = 100;
    auto sum = a + b; // 类型为 int 或 unsigned int，而不是 unsigned char
    return sum == 300 ? 0 : 1;
}
```

**C++11 精确语义：** 在 `int` 能表示 `unsigned char` 全部值的实现上，两者先提升为 `int`，所以和可以是 300，而不是先按 8 位回绕。结果再赋给小类型时才进行转换。

**常见错误与边界：** 上述 `static_assert` 依赖实现的 `int`/`unsigned char` 范围；在极少数实现可能提升为 `unsigned int`。`~unsigned_char` 的结果也通常是提升后的 `int`，高位会参与取反。

**前置节点：** B3.1、B3.2。

### B7.2 通常算术转换

**语法/接口：** 混合表达式如 `left + right` 隐式选择公共类型；要求特定语义时先写 `static_cast<T>(operand)`，并在转换前检查范围。

**定义与用途：** 通常算术转换把二元算术/比较操作数转换到共同类型，使运算只需按一个类型执行。浮点等级、整数提升、整数等级和符号性共同决定结果。

```cpp
double real = 2.5;
int integer = 2;
auto result = real + integer; // integer 转 double，结果 double
```

**C++11 精确语义：** 若一侧是更高等级浮点类型，另一侧转到该类型。纯整数先做整数提升，再按有符号/无符号的等级和可表示范围选择共同类型；较高等级无符号类型常使负有符号值转为大无符号值。

```cpp
int negative = -1;
unsigned int positive = 1;
bool result2 = negative < positive; // 常见实现结果为 false
```

**常见错误与边界：** “有 signed 就得到 signed”是错误规则。不要通过盲目强转隐藏告警；先决定负值是否业务合法，再统一类型。不同实现宽度可能改变共同类型。

**前置节点：** B6.4、B7.1。

### B7.3 整数与浮点转换

**语法/接口：** 隐式形式 `int i = floating;`，显式形式 `int i = static_cast<int>(floating);`；安全代码先用 `<limits>` 检查范围和有限性。

**定义与用途：** 两类数值表示不同，转换用于接口适配，但可能丢弃小数、精度或范围。

```cpp
#include <iostream>

int main()
{
    double value = 3.9;
    int integer = static_cast<int>(value); // 向零截断，得到 3
    long long large = 9007199254740993LL;
    double again = static_cast<double>(large); // 实现精度不足时会舍入
    std::cout << integer << ' ' << again << '\n';
}
```

**C++11 精确语义：** 有限浮点转整数会舍弃小数部分；若截断后的值不能由目标整数类型表示，行为未定义。整数转浮点若不能精确表示，会选择相邻可表示值，舍入方向由实现相关规则决定；若超出范围，行为也有标准规定的边界。

**常见错误与边界：** `static_cast` 只让转换显式，不使越界安全。NaN/无穷大转整数不可依赖。用浮点保存 ID、字节计数等大整数可能悄然丢精度。

**前置节点：** B3.2、B3.4。

### B7.5 C++ 显式转换

**语法/接口：** `static_cast<T>(expression)`、`const_cast<T>(expression)`、`reinterpret_cast<T>(expression)`；多态转换 `dynamic_cast<T>(expression)` 在继承模块学习。

**定义与用途：** 命名转换把不同意图分开：`static_cast` 做受语言检查的数值/层次等转换；`const_cast` 只调整 cv 限定；`reinterpret_cast` 表达低层表示重解释。

```cpp
double value = 3.5;
int integer = static_cast<int>(value);

const int fixed = 1;
const int* read = &fixed;
int* writable_type = const_cast<int*>(read);
// *writable_type = 2; // 未定义行为：原对象实际是 const
```

**C++11 精确语义：** 转换表达式必须满足相应操作符允许的类别。`reinterpret_cast` 不保证结果满足对齐、有效类型或对象生命周期要求；它通常仅改变编译器看待位模式/地址的方式。

**常见错误与边界：** C 风格转换可能组合多种转换，隐藏风险，应优先命名转换。强转不能修复数组越界、悬空指针、错误对象类型或数值超范围。`dynamic_cast` 依赖多态类型和 RTTI。

**前置节点：** B3.5、B5.3、B14.4。

## B8. 语句与控制流

### B8.4 循环

**语法/接口：** `while (condition) statement`；`do statement while (condition);`；`for (init; condition; increment) statement`；C++11 范围 for：`for (T element : range) statement`；控制用 `break`、`continue`。

**定义与用途：** 循环重复执行语句。`while` 先检查条件；`do-while` 至少执行一次；传统 `for` 集中写初始化、条件和步进；范围 for 遍历数组或提供 `begin/end` 的范围。

```cpp
#include <iostream>
#include <vector>

int main()
{
    std::vector<int> values{1, 2, 3};
    int sum = 0;
    for (int value : values)
        sum += value;
    std::cout << sum << '\n';
}
```

**C++11 精确语义：** 条件按语境转换为 bool。`break` 退出最内层循环或 switch；`continue` 跳到本轮结束，传统 `for` 随后执行增量表达式。范围 for 中 `auto&` 可修改元素，`const auto&` 只读且避免复制。

**常见错误与边界：** 循环体没有花括号时只控制下一条语句；浮点相等作终止条件易受舍入影响。无符号倒序 `i>=0` 永真；可写 `for (std::size_t i=n; i-- > 0;)`。遍历容器时修改容器可能使迭代器失效。

**前置节点：** B6.1、B6.4、B13.6。

## B9. 函数

### B9.1 函数声明与定义

**语法/接口：** 声明 `Return name(ParameterType parameter, ...);`；定义 `Return name(ParameterType parameter, ...) { statements }`；无参数可写 `f()` 或 `f(void)`，C++ 中都表示不接受参数。

**定义与用途：** 函数把一段操作命名，声明提供调用所需的类型契约，定义提供函数体。

```cpp
int add(int, int); // 声明

int add(int left, int right) // 定义
{
    return left + right;
}

int main()
{
    return add(2, 3);
}
```

**C++11 精确语义：** 返回类型、函数名和参数类型构成函数类型相关信息；参数名在纯声明中可省略。相容声明可多次出现，普通非 inline 外部函数在程序中应有唯一相应定义。

**常见错误与边界：** C++ 的 `f()` 与 C 旧式“参数未知”不同。调用前没有可见声明是编译错误；只有声明没有定义常在链接时报错。不能在另一个函数内部定义普通函数。

**前置节点：** B1.3、B4.1。

### B9.2 函数调用

**语法/接口：** `result = function(argument1, argument2);`；声明中的变量是形参，调用括号中提供的是实参。

**定义与用途：** 调用表达式计算被调用实体和实参，按参数类型初始化形参，执行函数体，并产生返回值或 `void` 结果。

```cpp
int square(int value)
{
    return value * value;
}

int main()
{
    int input = 4;
    int output = square(input);
    return output;
}
```

**C++11 精确语义：** 编译器根据可见声明检查参数数量、转换和重载。按值形参是由实参初始化的新对象。C++11 不规定不同实参的求值顺序，且彼此可能未排序。

**常见错误与边界：** `f(i++, i++)` 涉及同一标量的未排序修改，在 C++11 是未定义行为；先用多个完整语句计算实参。调用成功编译不保证跨文件定义存在。

**前置节点：** B6.9、B9.1。

### B9.3 参数传递方式

**语法/接口：** 按值 `void f(T value)`；指针 `void f(T* pointer)`；可修改引用 `void f(T& object)`；只读引用 `void f(const T& object)`。

**定义与用途：** 参数形式表达复制、别名、可修改性和可空性。按值获得独立对象；引用/指针可操作调用者对象；const 引用提供只读借用。

```cpp
void increment(int& value) { ++value; }
void maybe_increment(int* value)
{
    if (value != nullptr)
        ++*value;
}
int copy(int value) { return ++value; }
```

**C++11 精确语义：** C++ 只有按值传递；所谓“按引用传递”是形参类型本身为引用，形成别名。指针也按值复制，但复制的地址可指向调用者对象。大对象只读通常用 `const T&` 避免复制。

**常见错误与边界：** 引用通常表达目标必须存在，但仍可能悬空；指针可用 `nullptr` 表达可选目标。不要返回或保存指向短命实参/局部对象的别名。按值传指针不让函数自动拥有所指资源。

**前置节点：** B5.4、B14.1、B14.5。

### B9.4 返回类型

**语法/接口：** 返回值 `T f(){ return expression; }`；无返回值 `void f(){ return; }`；返回引用 `T& f();`；返回指针 `T* f();`。

**定义与用途：** 返回类型规定调用表达式产生的结果。按值返回创建/初始化调用方结果；引用和指针返回别名，不延长普通局部对象生命周期。

```cpp
#include <string>

std::string make_name()
{
    std::string local = "Ada";
    return local; // 按值返回安全；可复制、移动或复制消除
}
```

**C++11 精确语义：** 非 void 函数到达结尾而未返回值通常是未定义行为（`main` 有特殊规则）。`return expression;` 按返回类型初始化结果。返回局部对象的值是正常做法。

```cpp
// 错误：
// const std::string& bad() {
//     std::string local = "x";
//     return local; // 返回后引用悬空
// }
```

**常见错误与边界：** `void` 函数中只能 `return;`，不能 `return 0;`。返回引用/指针前必须明确所指对象在调用后仍存活。不要为“避免复制”而返回局部引用，C++11 已有移动与复制消除。

**前置节点：** B9.1、B15.8。

### B9.5 数组参数

**语法/接口：** 普通形式 `void f(int array[], std::size_t length)` 实际调整为 `void f(int* array, std::size_t length)`；保留编译期长度可写 `template<std::size_t N> void f(int (&array)[N])`。

**定义与用途：** 内建数组不能按值作为函数形参。形参声明中的 `T a[]` 和 `T a[N]` 都调整为 `T*`，所以长度必须另传或用数组引用编码。

```cpp
#include <cstddef>

int sum(const int* data, std::size_t length)
{
    int result = 0;
    for (std::size_t i = 0; i < length; ++i)
        result += data[i];
    return result;
}

int main()
{
    int values[3] = {1, 2, 3};
    return sum(values, 3);
}
```

**C++11 精确语义：** 参数列表中的数组类型调整发生在形成函数类型时；写出的第一维数字不参与函数类型。函数内 `sizeof(array_parameter)` 是指针大小。

**常见错误与边界：** 二维数组只调整最外层，后续维度必须保留，如 `int (*p)[3]`。`std::array<T,N>` 和 `std::vector<T>` 是类类型，不发生这种调整。

**前置节点：** B11.2、B11.3、B14.3。

### B9.6 函数重载

**语法/接口：** 在同一作用域声明 `void print(int); void print(double); void print(const char*);`；调用时编译器按实参选择最佳可行重载。

**定义与用途：** 重载允许同一操作名处理不同参数类型或数量，同时保留静态类型检查。

```cpp
#include <iostream>

void print(int)    { std::cout << "int\n"; }
void print(double) { std::cout << "double\n"; }

int main()
{
    print(1);
    print(1.5);
}
```

**C++11 精确语义：** 候选函数先经过名字查找，再判断可行性并比较转换序列。精确匹配通常优于提升，提升优于一般标准转换；还要考虑模板等规则。

**常见错误与边界：** 不能仅按返回类型重载，因为调用选择不由接收结果类型普遍决定。`f(long)` 与 `f(double)` 面对 `int` 可能产生二义性。默认实参与重载组合也可能让同一调用匹配多个函数。

**前置节点：** B7.1、B7.2、B9.2。

### B9.7 默认实参

**语法/接口：** `void log(int level, const char* message = "default");`；调用可写 `log(1)` 或 `log(1, "text")`。

**定义与用途：** 默认实参允许调用者省略尾部参数，编译器在调用点把对应默认表达式补入调用。

```cpp
#include <iostream>

void repeat(char ch, int count = 2)
{
    for (int i = 0; i < count; ++i)
        std::cout << ch;
}

int main() { repeat('A'); }
```

**C++11 精确语义：** 默认实参不是函数类型的一部分，通常在声明处提供，并在每个调用点根据当时可见声明确定。一个参数有默认值后，右侧参数通常也必须有默认值。

**常见错误与边界：** 不能跳过中间参数；同一作用域不能重复给同一参数提供默认实参。默认表达式可能每次调用都求值。虚函数默认实参按静态类型选择，与虚派发不同。

**前置节点：** B9.1、B9.2。

### B9.8 `inline`

**语法/接口：** `inline int square(int x) { return x * x; }`；类定义内部的成员函数定义隐式 inline。

**定义与用途：** `inline` 的核心语言作用是允许满足 ODR 条件的同一函数定义出现在多个翻译单元，方便把定义放头文件。

```cpp
// math.hpp
inline int twice(int value)
{
    return value * 2;
}
```

**C++11 精确语义：** 多个翻译单元中的 inline 定义必须满足 ODR 一致性，并在使用它的翻译单元中可达相应定义。最终表示同一实体。

**常见错误与边界：** `inline` 不命令优化器把调用展开；未写 inline 的函数也可被优化器内联。把不同宏条件生成的不同函数体放各翻译单元会违反 ODR。

**前置节点：** B1.5、B9.1。

### B9.9 C++11 `constexpr` 函数

**语法/接口：** `constexpr Return function(parameters) { return constant-expression-capable-expression; }`；例如 `constexpr int cube(int x) { return x*x*x; }`。

**定义与用途：** constexpr 函数可在实参和调用上下文满足条件时于编译期求值，也可以作为普通函数在运行期调用。

```cpp
constexpr int twice(int value)
{
    return value * 2;
}

int main()
{
    constexpr int size = twice(3);
    int array[size] = {};
    int runtime = 4;
    return twice(runtime) + array[0];
}
```

**C++11 精确语义：** C++11 constexpr 非构造函数必须满足严格函数体与返回要求；调用进入常量表达式还要求实参和实际求值操作合法。运行期调用不要求实参为常量。

**常见错误与边界：** 含普通循环、局部变量和多条执行语句的 constexpr 函数是 C++14 放宽规则，不能混入。`constexpr` 不等于强制编译器在所有调用处折叠。

**前置节点：** B5.5、B9.1。

### B9.10 递归

**语法/接口：** 函数可在函数体中按名字调用自身；必须设置使问题趋向终止条件的参数变化。

**定义与用途：** 递归把问题拆成规模更小的同类问题，适合树遍历、分治等结构。

```cpp
unsigned int factorial(unsigned int n)
{
    if (n <= 1)
        return 1;
    return n * factorial(n - 1);
}

int main() { return static_cast<int>(factorial(5)); }
```

**C++11 精确语义：** 每次调用都有独立形参和自动局部对象。实现通常使用调用栈，但标准不规定具体栈结构或可递归深度。

**常见错误与边界：** 终止条件不可达会无限递归，最终常因资源耗尽失败；即使会终止，也可能先发生整数溢出。C++11 不保证尾递归优化，不能用它证明常量空间。

**前置节点：** B8.4、B9.2、B15.4。

### B9.11 函数指针

**语法/接口：** `Return (*pointer)(ParameterTypes) = &function;`；调用可写 `pointer(arguments)` 或 `(*pointer)(arguments)`；别名写 `using Operation = int (*)(int,int);`。

**定义与用途：** 函数指针保存与指定签名兼容的函数地址，用于回调和运行期选择操作。

```cpp
int add(int a, int b) { return a + b; }
int multiply(int a, int b) { return a * b; }

using Operation = int (*)(int, int);

int apply(Operation operation, int a, int b)
{
    return operation(a, b);
}

int main() { return apply(&add, 2, 3); }
```

**C++11 精确语义：** 声明 `int (*operation)(int,int)` 中括号令 `*operation` 先结合，表示“operation 是指针”；若写 `int* operation(int,int)` 则是“返回 int* 的函数”。函数名在多数表达式中可转换为函数指针。

**常见错误与边界：** 空函数指针不能调用；签名必须兼容。非静态成员函数指针语法为 `Return (Class::*)(...)`，还需对象调用。无捕获 Lambda 可转兼容函数指针，有捕获 Lambda 不可以。

**前置节点：** B3.5、B9.1、B6.9。

## B10. 基础输入输出


### B10.5 换行与刷新

**语法/接口：** 输出换行 `stream << '\n';`；换行并刷新 `stream << std::endl;`；仅刷新 `stream << std::flush;`，接口位于 `<ostream>`/`<iostream>`。

**定义与用途：** 输出流通常使用缓冲减少系统调用。换行是字符；刷新要求缓冲内容尽快交给下层设备。

```cpp
#include <iostream>

int main()
{
    std::cout << "normal line" << '\n';
    std::cout << "visible now" << std::endl;
}
```

**C++11 精确语义：** `std::endl` 插入换行字符并调用刷新；`'\n'` 只插入字符。流还可能在程序正常结束、缓冲满、显式 flush 或与其他流绑定时刷新。

**常见错误与边界：** 在高频循环中机械使用 `endl` 可能造成不必要开销；交互提示、日志关键点或崩溃前需要可见性时刷新有意义。刷新用户态流不等于文件已经持久化到存储介质。

**前置节点：** B2.4、B6.1。


## B11. 内建数组与 `std::array`

### B11.1 内建一维数组

**语法/接口：** `ElementType array[N];`；列表初始化 `int values[3] = {1,2,3};` 或 `int values[3]{};`；自动推断长度 `int values[] = {1,2,3};`。

**定义与用途：** 内建数组是固定数量、同类型元素组成的连续对象。长度 `N` 是数组类型的一部分，并须在标准 C++11 中为适当的编译期常量。

```cpp
#include <iostream>

int main()
{
    int values[3] = {10, 20, 30};
    for (int i = 0; i < 3; ++i)
        std::cout << values[i] << '\n';
}
```

**C++11 精确语义：** 下标从 0 开始，最后合法下标为 `N-1`。数组元素按下标顺序排列且无元素间空洞；数组本身可能作为更大对象成员参与外部填充。

**常见错误与边界：** 标准内建数组长度不能为 0；运行期长度的 VLA 是某些编译器扩展，不是 C++11。越界访问是未定义行为；数组不会自行记录一个可在运行期查询的长度。

**前置节点：** B3.2、B4.3。

### B11.2 数组长度

**语法/接口：** 在数组仍是数组对象的作用域中写 `sizeof(array) / sizeof(array[0])`；可封装为 `template<class T, std::size_t N> constexpr std::size_t length(T (&)[N]) { return N; }`。

**定义与用途：** `sizeof(array)` 给出整个数组的字节数，除以单个元素大小即可得到元素数量。

```cpp
#include <cstddef>
#include <iostream>

int main()
{
    int values[5]{};
    const std::size_t count = sizeof(values) / sizeof(values[0]);
    std::cout << count << '\n'; // 5
}
```

**C++11 精确语义：** `sizeof` 操作数中的数组不转换为指针，所以保留完整 `T[N]` 类型。公式对任何完整元素类型成立。

**常见错误与边界：** 数组传入普通函数形参后已调整为指针，函数内同一公式得到“指针大小/元素大小”，不是长度。动态数组和 `vector` 也不能用此公式。`std::size` 是 C++17。

**前置节点：** B6.10、B11.1。

### B11.3 数组到指针转换

**语法/接口：** `int* first = array;` 触发到首元素指针的转换；`int (*whole)[3] = &array;` 取得整个数组的地址；数组引用写 `int (&ref)[3] = array;`。

**定义与用途：** 在多数需要值的表达式中，数组表达式转换为指向首元素的指针，使下标和指针遍历能工作；数组对象本身并未变成指针。

```cpp
int main()
{
    int a[3] = {1, 2, 3};
    int* element = a;       // int*，指向 a[0]
    int (*array)[3] = &a;   // int (*)[3]，指向整个数组

    ++element; // 跨过一个 int
    ++array;   // 跨过整个 int[3]；形成尾后一位指针
}
```

**C++11 精确语义：** `a+1` 按 `int` 步长，`&a+1` 按 `int[3]` 步长。起始地址的数值表示可能相同，但类型和允许的指针算术不同。`sizeof a`、`&a`、引用绑定及 `decltype(a)` 等语境不会进行通常的数组到指针转换。

**常见错误与边界：** 不能因地址看起来相同就把 `int*` 与 `int (*)[3]` 混用。函数数组形参会调整；强制转换不能修复错误步长或二维数组与 `int**` 的布局差异。

**前置节点：** B11.1、B14.3。

### B11.4 数组限制

**语法/接口：** 元素逐个赋值 `destination[i] = source[i];`；需要完整值语义时使用 `std::array<T,N>`；函数借用内建数组用指针+长度或 `T (&array)[N]`。

**定义与用途：** 内建数组是基础语言的固定布局对象，但没有普通类容器的整体赋值、按值传参与按值返回接口。

```cpp
int main()
{
    int source[3] = {1, 2, 3};
    int destination[3] = {};

    for (int i = 0; i < 3; ++i)
        destination[i] = source[i];

    // destination = source; // 编译错误
}
```

**C++11 精确语义：** 数组类型不可作为函数按值返回类型，函数形参数组会调整为指针。数组的有效元素恰为 `[0,N)`；尾后一位地址可形成但不可解引用。

**常见错误与边界：** `memcpy` 只适用于满足对象表示要求的类型和正确字节数，不能作为所有类数组的通用赋值。数组越界即使“读到邻居变量”也是未定义行为。

**前置节点：** B11.1、B11.2、B9.5。

### B11.5 多维数组

**语法/接口：** `T matrix[Rows][Columns];`；指向一行的指针 `T (*row)[Columns] = matrix;`；形参可写 `void f(T (*matrix)[Columns], std::size_t rows)`。

**定义与用途：** 内建多维数组是“数组的数组”。`T[M][N]` 含 M 个 `T[N]` 行对象，元素按行连续排列。

```cpp
#include <iostream>

int main()
{
    int matrix[2][3] = {{1,2,3}, {4,5,6}};
    std::cout << matrix[1][2] << '\n'; // 6

    int (*row)[3] = matrix;
    ++row; // 指向第二行
    std::cout << (*row)[0] << '\n'; // 4
}
```

**C++11 精确语义：** `matrix` 在多数表达式中转换为 `int (*)[3]`，不是 `int**`。计算 `matrix[i][j]` 先定位第 i 个行数组，再定位行内第 j 个元素。

**常见错误与边界：** `int**` 指向一个 `int*` 对象序列，布局与连续二维数组不同；强转后解引用可能未定义。函数参数可省第一维，但后续维度必须从类型得知。

**前置节点：** B11.3、B14.3。

### B11.6 `std::array`

**语法/接口：** `std::array<T,N> values{{elements...}};`（C++11 常用双花括号以兼容聚合层次）；接口有 `size()`、`operator[]`、`at()`、`front()`、`back()`、`data()`、`begin()/end()`。

**定义与用途：** `std::array` 是固定长度的标准容器包装，长度属于类型，保留连续存储，同时支持整体赋值和按值返回。

```cpp
#include <array>
#include <iostream>

int main()
{
    std::array<int, 3> values{{1, 2, 3}};
    std::array<int, 3> copy = values;
    copy[0] = 9;
    std::cout << values.size() << ' ' << copy.at(0) << '\n';
}
```

**C++11 精确语义：** `std::array<T,3>` 与 `std::array<T,4>` 是不同类型。`operator[]` 不检查边界；`at` 越界抛 `std::out_of_range`。迭代器满足连续元素相应能力。

**常见错误与边界：** `std::array<T,0>` 合法，但 `front()`、`back()` 和 `operator[](0)` 不合法；`begin()==end()`。传入函数不会退化为指针，除非显式调用 `data()`。

**前置节点：** B11.1、B11.4。

## B12. 字符、C 风格字符串与 `std::string`

### B12.1 字符数组和字符串

**语法/接口：** 字符数组 `char buffer[capacity];`；C 风格字符串必须在容量内包含 `'\0'`；可初始化为 `char text[] = "abc";`。

**定义与用途：** 字符数组只是 `char` 元素序列；C 风格字符串是其中以第一个空字符 `'\0'` 终止的协议。不是每个字符数组都是合法字符串。

```cpp
#include <iostream>

int main()
{
    char text[4] = {'a', 'b', 'c', '\0'};
    char bytes[3] = {'a', 'b', 'c'}; // 不是 C 字符串
    std::cout << text << '\n';
    (void)bytes;
}
```

**C++11 精确语义：** 字符串长度不包含终止空字符，但数组容量必须为它留一个位置。字符 `'0'` 是数字字符，值通常非零；`'\0'` 是值为 0 的字符。

**常见错误与边界：** 将未终止的 `bytes` 传给要求 C 字符串的函数会越过数组寻找零，产生越界和未定义行为。缓冲区容量与当前字符串长度必须分开维护。

**前置节点：** B3.1、B11.1。

### B12.2 字符串字面量

**语法/接口：** 普通字面量 `"abc"`，宽字面量 `L"abc"`，C++11 UTF 前缀 `u8"abc"`、`u"abc"`、`U"abc"`，原始字符串 `R"(a\b)"`。

**定义与用途：** 字符串字面量创建静态存储期的 const 字符数组，并自动附加终止空字符。

```cpp
#include <iostream>

int main()
{
    const char* pointer = "abc";
    char copy[] = "abc"; // 复制到可修改数组
    copy[0] = 'A';
    std::cout << pointer << ' ' << copy << '\n';
}
```

**C++11 精确语义：** `"abc"` 的类型是 `const char[4]`。相同内容字面量是否共享存储不应依赖；其对象持续到程序结束。

**常见错误与边界：** C++ 不允许标准地把字面量赋给 `char*`；通过强转修改字面量是未定义行为。`u8` 字面量在 C++11 类型仍是 `const char[N]`，其编码单元数不等于用户字符数。

**前置节点：** B2.4、B12.1、B15.5。

### B12.3 `sizeof` 与字符串长度

**语法/接口：** `sizeof(array)` 查询数组对象字节数；`std::strlen(c_string)` 位于 `<cstring>`，从指针开始扫描到第一个 `'\0'`，返回 `std::size_t`。

**定义与用途：** `sizeof` 是编译期类型/对象大小操作；`strlen` 是运行期 C 字符串协议操作。容量、对象大小和文本长度是三个不同概念。

```cpp
#include <cstring>
#include <iostream>

int main()
{
    char text[10] = "abc";
    std::cout << sizeof(text) << ' '   // 10
              << std::strlen(text) << '\n'; // 3

    const char* pointer = text;
    std::cout << sizeof(pointer) << '\n'; // 指针对象大小，不是字符串长度
}
```

**C++11 精确语义：** `sizeof("abc")==4`，包含终止空字符；`strlen("abc")==3`，不包含终止字符。`strlen` 时间与终止位置线性相关。

**常见错误与边界：** 对未在可访问范围内包含 `'\0'` 的序列调用 `strlen` 是未定义行为；指针无法告诉它容量。含内嵌零时 `strlen` 只看到前缀，而 `std::string::size()` 可记录全部字符。

**前置节点：** B6.10、B12.1、B12.2。

### B12.4 `std::string` 基础

**语法/接口：** `std::string text = "abc";`（`<string>`）；常用 `size()/length()`、`empty()`、`clear()`、`+=`、比较、`operator[]`、`at()`、`front()/back()`、`substr()`、`find()`。

**定义与用途：** `std::string` 是管理窄字符序列的值类型，自动管理存储，支持复制、赋值、拼接和查询，通常比裸字符缓冲区安全。

```cpp
#include <iostream>
#include <string>

int main()
{
    std::string text = "C++";
    text += "11";
    if (text.find("++") != std::string::npos)
        std::cout << text.substr(0, 3) << ' ' << text.size() << '\n';
}
```

**C++11 精确语义：** `size()` 与 `length()` 等价并返回字符元素数；可以包含内嵌 `'\0'`。`operator[]` 对普通有效索引不检查；`at()` 越界抛 `std::out_of_range`。

**常见错误与边界：** 空字符串不能调用 `front()`/`back()`。`find` 失败返回 `std::string::npos`，不是 `-1` 的业务整数。`size()` 是字节/代码单元数量，不保证是 Unicode 字符数。

**前置节点：** B12.1、B4.3。

### B12.5 `std::string` 容量和存储

**语法/接口：** `size()` 查元素数，`capacity()` 查不重新分配可容纳量，`reserve(n)` 请求容量，`resize(n[,ch])` 改元素数，`data()/c_str()` 取得只读连续字符指针。

**定义与用途：** string 分开维护实际字符数和已分配容量，以支持高效增长。C++11 保证字符连续存储。

```cpp
#include <iostream>
#include <string>

int main()
{
    std::string text = "abc";
    text.reserve(100); // size 仍为 3
    text.resize(5, 'x'); // 现在 "abcxx"
    std::cout << text.size() << ' ' << text.capacity() << '\n';
}
```

**C++11 精确语义：** `reserve` 不创建字符；`resize` 会创建或删除字符。`c_str()` 和 `data()` 返回与字符序列关联的指针，C++11 的非 const string `data()` 仍返回 `const char*`。重新分配或许多非 const 操作可使旧指针、引用和迭代器失效。

**常见错误与边界：** 不能用 `reserve` 后直接写 `text[50]`；合法索引取决于 `size`。小字符串优化是常见实现，不是标准保证。可写 `data()` 是 C++17。

**前置节点：** B12.4、B13.3。

### B12.6 与 C 接口连接

**语法/接口：** 只读 C 字符串参数传 `text.c_str()`；需要长度感知接口时同时传 `text.data(), text.size()`；需要可写缓冲区时在 C++11 使用 `std::vector<char>` 或正确大小的字符数组。

**定义与用途：** `c_str()` 为要求 NUL 终止 `const char*` 的 C 接口提供视图；`data()+size()` 适合显式长度接口。

```cpp
#include <cstdio>
#include <string>

int main()
{
    std::string text = "hello";
    std::printf("%s\n", text.c_str());
}
```

**C++11 精确语义：** `c_str()` 指向以 `'\0'` 终止的连续序列；返回指针不转移所有权。string 可以保存内嵌零，传统 `%s`/`strlen` 等只处理第一个零之前部分。

**常见错误与边界：** 修改 string 后旧 `c_str()` 指针可能失效；不得写入 C++11 `data()/c_str()` 返回的 const 缓冲区。C 函数若保存指针超过调用期，必须另行管理生命周期。

**前置节点：** B12.3、B12.5、B14.6。

### B12.7 字符编码边界

**语法/接口：** C++11 字面量前缀：`u8"text"` 产生 `const char[]` UTF-8 代码单元，`u"text"` 对应 `char16_t[]`，`U"text"` 对应 `char32_t[]`，`L"text"` 对应 `wchar_t[]`。

**定义与用途：** 字符编码规定字节/代码单元如何表示文本。C++ 字符和 string 类型主要管理代码单元，不自动完成 Unicode 分段、正规化或用户字符计数。

```cpp
#include <iostream>
#include <string>

int main()
{
    std::string utf8 = u8"\u4F60\u597D";
    std::cout << utf8.size() << '\n'; // 代码单元字节数，不是“2”的可移植承诺
}
```

**C++11 精确语义：** `char16_t`、`char32_t` 是独立基础类型。执行字符集、源字符集和具体库转换受实现及环境影响；标准前缀只规定相应编码形式边界。

**常见错误与边界：** `char` 的一个元素不等于一个 Unicode 字符；按字节截断 UTF-8 可能破坏序列。`<codecvt>` 在 C++11 提供部分设施但接口复杂且后来弃用，不应假设自动可靠转换。

**前置节点：** B3.1、B12.4。

## B13. `std::vector`

### B13.1 动态长度顺序容器

**语法/接口：** `std::vector<T> values;`（`<vector>`）；追加 `push_back/emplace_back`，删除尾部 `pop_back`，元素数 `size()`，迭代 `begin()/end()`。

**定义与用途：** vector 是运行期可变长度、连续存储的同类型元素容器，自动构造、移动/复制和销毁元素，通常是动态序列的首选。

```cpp
#include <iostream>
#include <vector>

int main()
{
    std::vector<int> values;
    values.push_back(10);
    values.push_back(20);
    std::cout << values[0] << ' ' << values.size() << '\n';
}
```

**C++11 精确语义：** 除 `vector<bool>` 特化外，元素连续存储，可用 `data()` 与需要连续 `T` 序列的接口连接。容器拥有元素并管理其生命周期。

**常见错误与边界：** 动态长度不表示允许越界；合法下标仍是 `[0,size())`。增长可能重新分配，使旧指针、引用和迭代器失效。

**前置节点：** B11.1、B15.8。

### B13.2 初始化差异

**语法/接口：** 空容器 `vector<T> v;`；数量 `vector<T> v(n);`；数量和值 `vector<T> v(n,value);`；元素列表 `vector<T> v{elements...};`。

**定义与用途：** vector 的圆括号构造与花括号 `initializer_list` 构造含义不同，必须根据“元素数量”还是“列出元素”选择。

```cpp
#include <iostream>
#include <vector>

int main()
{
    std::vector<int> a(10);    // 十个 0
    std::vector<int> b(10, 3); // 十个 3
    std::vector<int> c{10};    // 一个元素：10
    std::vector<int> d{10, 3}; // 两个元素：10、3
    std::cout << a.size() << ' ' << c.size() << '\n';
}
```

**C++11 精确语义：** 列表初始化会优先考虑可行的 `initializer_list` 构造函数，并禁止窄化；`vector<int>{10}` 不是数量构造。

**常见错误与边界：** 将 `()` 机械换成 `{}` 可能改变含义。`vector<std::string>{10}` 因 int 不能作为 string 元素，可能回到数量构造的可行性判断；应写清意图而非猜重载。

**前置节点：** B4.3、B4.5。

### B13.3 大小与容量

**语法/接口：** `size()`、`empty()`、`capacity()`、`reserve(n)`、`resize(n[,value])`、`clear()`、`shrink_to_fit()`。

**定义与用途：** size 是当前活元素数；capacity 是不重新分配时可容纳到的元素数。分离二者让 vector 以摊销方式增长。

```cpp
#include <iostream>
#include <vector>

int main()
{
    std::vector<int> values;
    values.reserve(100);
    std::cout << values.size() << ' ' << values.capacity() << '\n';
    values.resize(3);
    values.clear();
    std::cout << values.size() << '\n';
}
```

**C++11 精确语义：** `reserve` 只请求容量至少为 n，不创建元素；`resize` 改变 size 并构造/销毁元素；`clear` 销毁全部元素但不保证减少 capacity。`shrink_to_fit` 是非绑定请求。

**常见错误与边界：** `reserve(100)` 后不能访问 `values[0]`；未用容量不是对象。增大 reserve 会重新分配并使所有位置失效，较小 reserve 不强制收缩。

**前置节点：** B13.1、B15.8。

### B13.4 元素访问

**语法/接口：** `values[index]`、`values.at(index)`、`values.front()`、`values.back()`、`values.data()`。

**定义与用途：** 下标和 at 随机访问元素；front/back 访问两端；data 取得连续存储首地址。

```cpp
#include <iostream>
#include <stdexcept>
#include <vector>

int main()
{
    std::vector<int> values{10, 20};
    std::cout << values.front() << ' ' << values.at(1) << '\n';
}
```

**C++11 精确语义：** `operator[]` 不检查范围，越界导致未定义行为；`at()` 检查并抛 `std::out_of_range`。非 const 容器返回可修改引用。

**常见错误与边界：** 空容器上 `front()`/`back()` 不满足前置条件；`data()` 对空 vector 的返回值不能解引用。边界检查不能替代正确业务索引。

**前置节点：** B13.1、B16.5。

### B13.5 修改操作

**语法/接口：** `push_back(value)`、`emplace_back(args...)`、`pop_back()`、`insert(position,value)`、`erase(position)`、`erase(first,last)`。

**定义与用途：** 修改接口创建、移动或删除元素。insert/erase 使用迭代器位置并返回有助于继续遍历的位置。

```cpp
#include <vector>

int main()
{
    std::vector<int> values{1, 3};
    values.insert(values.begin() + 1, 2);
    values.push_back(4);
    values.pop_back();
    values.erase(values.begin());
}
```

**C++11 精确语义：** `push_back` 复制或移动一个元素；`emplace_back` 从参数在末尾构造，C++11 返回 `void`；`pop_back` 销毁末元素但不返回值。空 vector 调 `pop_back` 不合法。

**常见错误与边界：** emplace 不保证总更快，且可调用 explicit 构造。插入/删除可能移动大量元素并使迭代器失效；需要先取值再 pop。

**前置节点：** B13.2、B13.6。

### B13.6 迭代器失效

**语法/接口：** 修改后接住新位置：`it = values.erase(it);`；预估增长时先 `values.reserve(expected)`；不要跨可能重分配的操作保存 `data()`、指针、引用或迭代器。

**定义与用途：** 失效表示旧位置对象不再被标准保证可用于解引用、递增或比较。vector 连续布局导致扩容时必须整体迁移元素。

```cpp
#include <vector>

int main()
{
    std::vector<int> values{1, 2, 3, 4};
    for (std::vector<int>::iterator it = values.begin();
         it != values.end(); )
    {
        if (*it % 2 == 0)
            it = values.erase(it);
        else
            ++it;
    }
}
```

**C++11 精确语义：** 重新分配使全部迭代器、引用和指针失效；未重分配的插入使插入点及之后位置失效；erase 使删除点及之后位置失效。旧 `end()` 也可能失效。

**常见错误与边界：** 删除后再 `++it` 会操作失效迭代器；应使用 erase 返回值。reserve 只降低重分配次数，不保护插入点之后的位置，也不固定 size。

**前置节点：** B13.3、B13.5、B14.3。

### B13.7 特殊边界

**语法/接口：** 普通只读传参 `void inspect(const std::vector<T>& values)`；`std::vector<bool>` 可像容器使用，但其 `operator[]` 返回代理类型，不保证为 `bool&`。

**定义与用途：** vector 的一般规则有一个标准特化边界：`vector<bool>` 可按位压缩存储，因此元素访问通过代理实现。

```cpp
#include <vector>

int main()
{
    std::vector<bool> flags(3);
    flags[0] = true;
    bool value = flags[0]; // 代理可转换为 bool
    (void)value;
}
```

**C++11 精确语义：** `vector<bool>` 不保证 `data()` 提供普通连续 `bool*` 语义，元素引用类型也可能不是 `bool&`。其他 `vector<T>` 连续保存真实 T 对象。

**常见错误与边界：** 需要真实可寻址布尔对象、原子元素或 C 接口缓冲时不要选 `vector<bool>`，可用字节类型。大 vector 按值传参会复制，通常只读传 `const&`；所有权转移另用移动语义。

**前置节点：** B3.1、B13.1、B9.3。

## B14. 指针、引用和动态对象

### B14.1 地址与指针

**语法/接口：** `T* pointer = &object;` 取地址；`*pointer` 解引用；成员指针访问对象写 `pointer->member`；指针变量自身也可取地址为 `T**`。

**定义与用途：** 指针是保存对象或函数地址表示的对象，类型描述它预期指向什么。解引用产生所指对象的左值。

```cpp
#include <iostream>

int main()
{
    int value = 3;
    int* pointer = &value;
    *pointer = 4;
    std::cout << value << '\n';
}
```

**C++11 精确语义：** `&value` 得到指向 value 的指针；只在指针指向其类型允许访问的活对象/函数时才能按规则解引用。指针复制不会复制所指对象，也不表达所有权。

**常见错误与边界：** 未初始化指针是野指针；对象销毁后旧指针悬空。地址数值非零也不证明对象仍活着、类型正确或对齐满足。

**前置节点：** B4.4、B6.2。

### B14.2 空指针

**语法/接口：** `T* pointer = nullptr;`；检查 `if (pointer != nullptr) { ... }`；重置观察指针 `pointer = nullptr;`。

**定义与用途：** 空指针值明确表示“不指向任何对象或函数”，适合表达可选目标。

```cpp
void increment(int* value)
{
    if (value != nullptr)
        ++*value;
}

int main()
{
    int number = 1;
    increment(&number);
    increment(nullptr);
}
```

**C++11 精确语义：** `nullptr` 是 `std::nullptr_t` 的纯右值，可转换为任意指针/成员指针类型。空指针可比较和赋值，但不可解引用。

**常见错误与边界：** 未初始化指针不是自动等于 nullptr；读取它本身就有问题。`0`/`NULL` 可能选择整数重载，C++11 优先 `nullptr`。`delete nullptr` 安全，但普通解引用、成员访问和指针算术不安全。

**前置节点：** B3.5、B14.1。

### B14.3 指针算术

**语法/接口：** `pointer + n`、`pointer - n`、`++pointer`、`end - begin`；差值类型为 `std::ptrdiff_t`（`<cstddef>`）。

**定义与用途：** 指针算术按所指元素大小移动，用于遍历数组的 `[begin,end)` 范围。

```cpp
#include <cstddef>

int main()
{
    int values[3] = {1,2,3};
    int* begin = values;
    int* end = values + 3; // 尾后一位

    int sum = 0;
    for (int* p = begin; p != end; ++p)
        sum += *p;

    std::ptrdiff_t count = end - begin;
    return sum + static_cast<int>(count);
}
```

**C++11 精确语义：** 合法算术限于同一数组对象（单个对象可视作长度 1 数组）及尾后一位。尾后一位可形成、比较和相减，但不能解引用。

**常见错误与边界：** 对不相关对象指针相减或用 `<` 做通用顺序比较没有可移植定义；越过尾后一位即使不解引用也不合法。`&array+1` 与 `array+1` 步长不同。

**前置节点：** B11.3、B14.1。

### B14.4 `void*`

**语法/接口：** `void* erased = object_pointer;`；恢复必须显式 `T* restored = static_cast<T*>(erased);`；const 对象使用 `const void*`。

**定义与用途：** `void*` 是擦除具体对象类型的通用对象指针，常见于 C ABI 的回调上下文和低层内存接口。

```cpp
int main()
{
    int value = 3;
    void* erased = &value;
    int* restored = static_cast<int*>(erased);
    return *restored;
}
```

**C++11 精确语义：** 对象指针可隐式转为适当 cv 的 `void*`，并在正确类型下显式转回得到原地址。`void` 大小未知，故 `void*` 不能直接解引用或做标准指针算术。

**常见错误与边界：** 恢复成错误类型并访问可能违反对齐、有效类型和生命周期。C++ 与 C 不同，`void*` 不能隐式转 `T*`。类型安全 C++ 接口优先模板、重载或明确类。

**前置节点：** B3.5、B7.5、B14.1。

### B14.5 引用基础

**语法/接口：** 左值引用 `T& alias = object;`；const 左值引用 `const T& alias = expression;`；右值引用 `T&& alias = rvalue`。

**定义与用途：** 引用是已有对象或函数的别名，语法上像原对象使用，常用于参数和返回别名。

```cpp
int main()
{
    int first = 1;
    int second = 2;
    int& alias = first;

    alias = second; // 把 second 的值赋给 first，不是重新绑定
    return first;
}
```

**C++11 精确语义：** 引用必须初始化，初始化后不能重新绑定。语言没有可正常形成和使用的空引用；引用表达式通常直接表示所绑定对象。

**常见错误与边界：** 引用不自动延长所有对象生命周期，可能悬空。通过解引用空指针“制造引用”已经违反前置条件。引用通常不表达所有权。

**前置节点：** B6.2、B14.1。

### B14.6 指针与引用选择

**语法/接口：** 必须存在且不换目标：`void use(T& object)`；可选目标：`void use(T* object)` 并检查 nullptr；只读分别用 `const T&` 和 `const T*`。

**定义与用途：** 选择应表达接口语义：引用通常表示调用时对象必须存在；指针可以为空、可重新指向，也适合数组遍历和 C 接口。

```cpp
void set_required(int& value) { value = 1; }
void set_optional(int* value)
{
    if (value)
        *value = 1;
}
```

**C++11 精确语义：** 指针和引用都只是访问方式，不自动取得资源所有权。const 限定表达可修改性，不表达寿命。

**常见错误与边界：** 用指针却不说明能否为空，会令调用者猜测；用引用保存短命对象同样可悬空。数组通常还需长度；所有权应由容器、RAII 类或智能指针表达。

**前置节点：** B9.3、B14.2、B14.5。

### B14.7 原始动态内存

**语法/接口：** 单对象 `T* p = new T(args); delete p;`；数组 `T* p = new T[n]; delete[] p;`；失败默认抛 `std::bad_alloc`（`<new>`）。

**定义与用途：** new 表达式取得动态存储并构造对象；delete 表达式析构对象并释放匹配存储。动态对象寿命独立于创建它的块。

```cpp
int main()
{
    int* value = new int(42);
    int result = *value;
    delete value;
    value = nullptr;
    return result;
}
```

**C++11 精确语义：** `new T` 必须配 `delete`，`new T[n]` 必须配 `delete[]`；混用是未定义行为。`delete nullptr` 无效果且安全。构造失败时相应 new 表达式会释放已取得存储。

**常见错误与边界：** 忘记释放会泄漏；重复 delete、释放后使用、删除非 new 所得地址均为未定义行为。数组长度乘法可能溢出。业务代码优先 vector 和智能指针。

**前置节点：** B14.1、B15.3、B16.5。

### B14.8 所有权边界

**语法/接口：** 独占所有权 `std::unique_ptr<T> owner(new T(args));`；共享所有权 `std::shared_ptr<T> owner = std::make_shared<T>(args);`；非拥有观察通常用 `T*`/`T&` 并记录寿命。

**定义与用途：** 所有权回答谁负责让资源继续存在及最终释放。用类型表达所有权可避免裸指针“到底该不该 delete”的歧义。

```cpp
#include <memory>

std::unique_ptr<int> make_value()
{
    return std::unique_ptr<int>(new int(42));
}

int main()
{
    std::unique_ptr<int> value = make_value();
    return *value;
}
```

**C++11 精确语义：** `unique_ptr` 不可复制但可移动；`shared_ptr` 复制共享控制块，最后一个强所有者销毁对象；`weak_ptr` 不增加强所有权。原始指针本身不编码所有权。

**常见错误与边界：** 不要从同一裸指针独立创建多个 shared_ptr 控制块；循环 shared_ptr 需 weak_ptr 打断。`std::make_shared` 属于 C++11，`std::make_unique` 属于 C++14。

**前置节点：** B14.6、B14.7、B15.8。

## B15. 作用域、链接、存储期和生命周期

### B15.1 作用域

**语法/接口：** 块 `{ int local; }`；函数参数 `void f(int parameter)`；命名空间 `namespace app { int value; }`；类 `class C { int member; };`；限定访问 `app::value`、`C::member`、全局 `::value`。

**定义与用途：** 作用域回答“一个名字可在源代码哪些位置由非限定或限定方式找到”。不同声明产生块、函数参数、函数、命名空间和类作用域。

```cpp
#include <iostream>

int value = 1;

int main()
{
    int value = 2; // 隐藏全局 value
    {
        int value = 3; // 隐藏外层局部 value
        std::cout << value << ' ' << ::value << '\n';
    }
}
```

**C++11 精确语义：** 块作用域从声明点附近开始到块结束；参数作用域覆盖函数声明/定义的相应区域；函数作用域主要用于标签；命名空间和类成员可用 `::` 限定。

**常见错误与边界：** 内层同名声明隐藏外层，而不是修改外层。作用域不等于生命周期或链接：局部 static 名字只有块作用域，但对象有静态存储期。

**前置节点：** B2.3、B4.1。

### B15.2 链接属性

**语法/接口：** 外部链接声明 `extern int shared;` 配一个 `int shared = 0;` 定义；内部链接 `static int local;` 或匿名命名空间 `namespace { int local; }`；块内普通局部名无链接。

**定义与用途：** 链接决定不同作用域或翻译单元中的声明能否表示同一实体。外部链接允许跨翻译单元关联；内部链接只在当前翻译单元；无链接的名字不能这样关联。

```cpp
// shared.hpp
extern int shared;

// shared.cpp
// #include "shared.hpp"
// int shared = 0;
```

**C++11 精确语义：** 命名空间作用域普通非 const 对象和函数通常有外部链接；命名空间作用域非 `extern` const 对象默认内部链接；`static` 在命名空间作用域赋予内部链接。局部 static 的 `static` 主要改变存储期，不提供跨文件链接。

**常见错误与边界：** 每个 `.cpp` 都写 `static int x;` 会得到多个不同对象。头文件定义普通外部变量会重复定义；应写 extern 声明并在一个源文件定义。链接与名字可见作用域是不同维度。

**前置节点：** B1.2、B1.5、B15.1。

### B15.3 存储期

**语法/接口：** 普通局部 `int local;` 为自动存储期；命名空间对象或 `static int value;` 为静态存储期；`thread_local int value;` 为线程存储期；`new T` 创建动态存储期对象。

**定义与用途：** 存储期回答对象占用的存储存在多久。C++11 四类是自动、静态、线程和动态存储期。

```cpp
int global_value;                 // 静态
thread_local int thread_value;    // 线程

void function(int parameter)      // parameter 自动
{
    int local = 0;                // 自动
    static int calls = 0;         // 静态
    int* pointer = new int(5);    // pointer 自动，*pointer 动态
    delete pointer;
}
```

**C++11 精确语义：** 同一声明中指针对象与所指对象可有不同存储期。存储期描述存储，不等于名字作用域，也需与对象生命周期区分；对象可能在已有存储中稍后开始生命周期。

**常见错误与边界：** 自动存储期不由标准保证“位于栈”，动态存储期不由标准命名为“堆”；这些是典型实现。`thread_local` 每线程一份，但不让其他共享对象自动线程安全。

**前置节点：** B15.1、B14.7。

### B15.4 自动存储期对象

**语法/接口：** 块内未写 `static`、`thread_local`、`extern` 的普通局部对象通常为自动存储期；函数参数也具有自动存储期。

**定义与用途：** 自动对象随一次块执行或函数调用建立，离开相应块时自动销毁，适合短期计算和 RAII 资源句柄。

```cpp
#include <string>

void function()
{
    std::string first = "A";
    {
        std::string second = "B";
    } // second 在这里销毁
} // first 在这里销毁
```

**C++11 精确语义：** 局部对象每次控制执行到声明时初始化；正常离开、`return` 或异常传播离开作用域都会销毁已完成构造的自动对象，通常按完成构造的逆序。

**常见错误与边界：** 返回局部对象的指针/引用会在函数退出后悬空；按值返回安全。基础类型自动对象未显式初始化时值可能不确定。递归的每次调用有独立自动对象。

**前置节点：** B4.4、B9.4、B15.3。

### B15.5 静态存储期对象

**语法/接口：** 命名空间作用域对象 `T global;`、类静态数据成员、局部 `static T object;` 以及字符串字面量具有静态存储期。

**定义与用途：** 静态存储期的存储覆盖整个程序执行，适合程序级状态、常量和一次性共享对象。

```cpp
#include <iostream>

int global_count; // 先零初始化

int next()
{
    static int local_count = 0;
    return ++local_count;
}

int main()
{
    std::cout << global_count << ' ' << next() << ' ' << next() << '\n';
}
```

**C++11 精确语义：** 静态存储期对象先经历静态初始化（含零初始化/常量初始化），必要时再动态初始化。非局部对象在正常程序终止时按规则销毁。

**常见错误与边界：** 不同翻译单元中非局部对象的动态初始化相对顺序通常不能依赖，可能形成“静态初始化顺序问题”；可用函数局部 static 按首次使用构造。异常终止或 `_Exit` 等平台/库路径不保证正常析构流程。

**前置节点：** B15.3、B1.2。

### B15.6 局部静态对象

**语法/接口：** `T& instance() { static T object(args); return object; }`；名字为块作用域，对象为静态存储期。

**定义与用途：** 局部 static 将延迟初始化与单一程序级对象结合，常用于按需创建缓存或单例式资源。

```cpp
int next_id()
{
    static int id = 0;
    return ++id;
}

int main()
{
    int first = next_id();
    int second = next_id();
    return first + second; // 两次调用复用同一个 id
}
```

**C++11 精确语义：** 初始化在控制第一次经过声明时进行；若并发线程同时到达，初始化只执行一次，其他线程等待完成。若初始化抛异常，本次未完成，之后经过可重试。

**常见错误与边界：** 初始化线程安全不等于后续读写对象线程安全；上例并发调用仍对 `id` 数据竞争。初始化过程中递归再次进入同一声明会导致未定义行为。析构阶段仍可能有跨对象顺序问题。

**前置节点：** B15.5、并发概念见 TH/AT 模块。

### B15.7 临时对象

**语法/接口：** 临时常由 `T(args)`、按值运算或转换产生；直接绑定 `const T& reference = T(args);` 可在特定规则下延长该临时的生命周期。

**定义与用途：** 临时对象保存表达式中间结果或按值结果，通常无需名字，编译器负责在规定时间销毁。

```cpp
#include <iostream>
#include <string>

int main()
{
    const std::string& text = std::string("temporary");
    std::cout << text << '\n'; // 直接绑定使临时活到 text 作用域结束
}
```

**C++11 精确语义：** 未被特定规则延长的临时通常在创建它的完整表达式结束时销毁。引用绑定可延长部分临时，但规则取决于初始化形式，不会沿引用参数和返回任意传递。

**常见错误与边界：** 返回绑定到函数内部临时的引用会悬空；引用成员初始化、条件表达式和转换存在细节，不能靠“有 const& 就延长”概括。容器重新分配也可让指向旧元素的别名悬空。

**前置节点：** B6.1、B6.2、B5.4。

### B15.8 生命周期与 RAII

**语法/接口：** RAII 类在构造函数取得资源，在析构函数 `~Type()` 释放；使用者定义自动对象 `Resource guard(args);`，不手工编写每条退出路径的清理。

**定义与用途：** 生命周期是对象可以按其类型合法使用的时间段。RAII（资源获取即初始化）把资源寿命绑定到对象寿命，实现确定性清理。

```cpp
#include <fstream>

void write_file()
{
    std::ofstream output("result.txt");
    if (!output)
        return;
    output << "data\n";
} // output 析构并关闭文件
```

**C++11 精确语义：** 对象在初始化完成后进入正常生命周期，析构开始/存储被复用时结束。自动 RAII 对象在正常离开和异常栈展开时析构；只完成构造的子对象才会析构。

**常见错误与边界：** 原始 `new`/文件描述符若无 RAII 包装，早退和异常易泄漏。析构函数通常不应让异常逃逸。存储仍存在不代表对象生命周期仍在，反之类型访问必须尊重已开始的对象。

**前置节点：** B14.8、B15.3、B15.4。

## B16. 错误类型与程序行为分类

### B16.1 编译错误

**语法/接口：** 用工具链单独编译一个翻译单元，例如 GCC/Clang `g++ -std=c++11 -pedantic-errors -Wall -Wextra -c source.cpp -o source.o`；命令和诊断文字不是 ISO C++11。

**定义与用途：** 编译错误表示某翻译单元在预处理、词法、语法或语义检查中不符合需要诊断的规则，无法正常产生目标文件。

```cpp
int main()
{
    // int value = "text"; // 类型不匹配
    // missing = 1;        // 名字未声明
}
```

**C++11 精确语义：** 常见类别有非法记号、缺分号、类型错误、访问控制失败、模板实例化失败和重载二义性。实现必须对许多非良构程序发出至少一条诊断，但诊断措辞不标准化。

**常见错误与边界：** 头文件不存在通常在预处理阶段；某些 ODR 违反不要求诊断。编译器接受扩展不表示代码符合 ISO C++11，严格学习应关闭或报错处理扩展。

**前置节点：** B1.1、B16.8。

### B16.2 链接错误

**语法/接口：** 先 `g++ -std=c++11 -c a.cpp -o a.o`、`g++ -std=c++11 -c b.cpp -o b.o`，再 `g++ a.o b.o -o app`；链接库常以构建 target 或平台 `-lfoo` 提供。

**定义与用途：** 链接错误发生在组合目标文件和库、解析外部实体时。每个翻译单元可独立合法，但整个程序仍可能缺定义或有冲突。

```cpp
// main.cpp
int calculate(int); // 有声明
int main() { return calculate(3); }
// 若程序没有 int calculate(int) 的定义，通常链接报未定义引用
```

**C++11 精确语义：** odr-use 的普通外部实体通常必须在程序中有相应定义。普通实体定义过多、声明/定义签名不一致、漏链接目标或库都会反映为平台链接问题。

**常见错误与边界：** 声明只让编译器检查调用，不提供实现。链接错误名称受 ABI 名字修饰影响。共享库缺失可能推迟到装载时；某些 ODR 错误甚至可能链接成功而不要求诊断。

**前置节点：** B1.3、B1.5、B9.1。

### B16.3 运行时错误

**语法/接口：** 运行期通过返回值/状态、流状态、异常处理表达失败，例如 `if (!stream) ...`、`try { ... } catch (const std::exception& e) { ... }`。

**定义与用途：** 运行时错误是程序已经编译链接并开始执行后，输入、资源、环境或操作无法满足要求。它可能是可恢复失败，也可能导致终止。

```cpp
#include <fstream>
#include <iostream>

int main()
{
    std::ifstream input("missing.txt");
    if (!input) {
        std::cerr << "open failed\n";
        return 1;
    }
}
```

**C++11 精确语义：** 标准库可用状态位、返回值或异常报告失败；例如 `new` 默认失败抛 `std::bad_alloc`，`vector::at` 越界抛 `std::out_of_range`。

**常见错误与边界：** 崩溃只是可能表现，不是运行时错误定义；错误也可能被正确检测并报告。未定义行为不是可靠的“运行时异常”，编译器无义务抛出或诊断。操作系统错误接口属于平台层。

**前置节点：** B13.4、B14.7。

### B16.4 逻辑错误

**语法/接口：** 没有专用语言语法；用可执行测试、`assert(expected_condition)` 和明确输入输出规格发现。例如 `assert(sum({1,2}) == 3);`。

**定义与用途：** 逻辑错误是程序语法和执行机制都合法，但实现的结果不符合需求，如错误公式、少循环一次或遗漏边界条件。

```cpp
int sum_to(int n)
{
    int result = 0;
    for (int i = 1; i <= n; ++i)
        result += i;
    return result;
}
```

**C++11 精确语义：** 语言标准不能知道业务期望，故逻辑错误通常不会由编译器诊断。测试要覆盖正常、边界、空输入和失败路径。

**常见错误与边界：** “程序没有崩溃”不能证明逻辑正确；测试通过也只覆盖已执行案例。逻辑错误可与未定义行为同时存在，应先消除 UB 再分析结果。

**前置节点：** B8.4、B16.10。

### B16.5 未定义行为

**语法/接口：** 未定义行为没有可捕获的统一接口；必须在代码中满足前置条件，并可用编译器警告、断言、AddressSanitizer/UndefinedBehaviorSanitizer 等非标准工具辅助发现。

**定义与用途：** 未定义行为（UB）表示标准对程序执行不施加要求。它允许实现高效假设，但要求程序员避免违反规则。

```cpp
#include <limits>

int main()
{
    int array[2] = {1, 2};
    // int bad = array[2]; // 越界：未定义行为
    // int overflow = std::numeric_limits<int>::max() + 1; // 有符号溢出
    return array[0];
}
```

**C++11 精确语义：** 常见 UB 包括有符号溢出、越界、解引用空/悬空指针、读取不确定值、重复释放、释放后使用、整数除零、不合法移位、数据竞争及同一标量未排序冲突访问。

**常见错误与边界：** UB 不等于必然崩溃、随机结果或抛异常；编译器可假定它从未发生并据此优化。某次输出正常、加日志后正常或调试版正常都不能证明安全。

**前置节点：** B4.4、B6.4、B6.9、B14.7。

### B16.6 未指定行为

**语法/接口：** 没有选择某个结果的标准语法；代码必须接受标准允许的所有结果，或用多个完整表达式、规定顺序的运算符和同步显式建立顺序。

**定义与用途：** 未指定行为表示标准允许若干可能行为，实现无需记录每次选择哪一个。它不同于 UB：结果集合仍受标准约束。

```cpp
#include <iostream>

int first()  { std::cout << 'A'; return 1; }
int second() { std::cout << 'B'; return 2; }
void use(int, int) {}

int main()
{
    use(first(), second()); // C++11 不规定先输出 A 还是 B
}
```

**C++11 精确语义：** 函数实参求值顺序是典型相关场景；若实参彼此无冲突，可能顺序不同但程序仍有定义。若出现同一标量未排序修改，则进一步成为 UB。

**常见错误与边界：** 不要把本编译器当前的从右到左/从左到右当契约。未指定行为不要求实现文档固定选择，这与实现定义行为不同。

**前置节点：** B6.9、B16.5。

### B16.7 实现定义行为

**语法/接口：** 没有跨实现强制选择的语法；用 `<limits>`、`<climits>`、`sizeof` 等查询当前实现，并查编译器/ABI 文档。例如 `std::numeric_limits<char>::is_signed`。

**定义与用途：** 实现定义行为要求实现从允许选项中选择一种，并记录其选择，从而允许适配不同硬件和 ABI。

```cpp
#include <iostream>
#include <limits>

int main()
{
    std::cout << std::numeric_limits<char>::is_signed << ' '
              << sizeof(int) << '\n';
}
```

**C++11 精确语义：** 普通 char 的符号性、基本整数类型大小、某些字符集属性，以及负有符号整数右移结果属于常见实现相关边界。

**常见错误与边界：** “我的机器是这样”只能描述一个实现。可移植代码应避免依赖选择，或在配置/`static_assert` 中明确要求。实现定义不同于未指定：前者必须文档化。

**前置节点：** B3.1、B3.2、B6.6。

### B16.8 非良构程序

**语法/接口：** 用严格标准模式检查，例如 GCC/Clang `g++ -std=c++11 -pedantic-errors source.cpp`；“非良构”是标准分类，没有可在源码中声明接受它的关键字。

**定义与用途：** 非良构程序违反 C++ 的语法或可诊断语义要求，如类型不匹配、非法声明或访问控制失败。

```cpp
int main()
{
    // int value = "text"; // 非良构：没有所需转换
}
```

**C++11 精确语义：** 对大多数非良构程序，实现须发出至少一条诊断，之后仍可选择继续翻译。某些 ODR 违反明确“不要求诊断”。

**常见错误与边界：** 编译器接受并生成程序不一定说明符合 ISO C++11，可能是扩展或漏诊断边界；“有警告但生成文件”也不自动使程序良构。应区分非良构与良构程序运行时 UB。

**前置节点：** B1.5、B16.1。

### B16.9 警告与诊断

**语法/接口：** GCC/Clang 常用 `-Wall -Wextra -Wpedantic -Wconversion`，必要时 CI 用 `-Werror`；MSVC 常用 `/W4`。选项集合和措辞都是工具链接口。

**定义与用途：** 诊断是实现报告问题的消息；警告通常指出可疑但可能合法的代码。高警告级别能及早发现未使用值、符号转换和可疑控制流。

```cpp
int main()
{
    int unused = 0; // 高警告级别通常报告未使用
    (void)unused;   // 明确表示有意不使用
}
```

**C++11 精确语义：** 标准要求某些非良构情况“发出诊断”，但不规定必须叫 error 还是 warning，也不规定文本。警告不是程序行为分类。

**常见错误与边界：** 无警告不证明正确；警告也可能有误报或依项目策略取舍。`-Werror` 在受控 CI 有用，但第三方头和编译器升级需隔离管理。

**前置节点：** B16.1、B16.8。

### B16.10 基础错误检查工具

**语法/接口：** 运行期断言 `assert(condition)`（`<cassert>`）；C++11 编译期断言 `static_assert(condition, "message");`；工具链可配调试器、警告和 Sanitizer。

**定义与用途：** 不同工具覆盖不同阶段：static_assert 检查编译期假设，assert 检查调试运行时不变量，测试验证需求，调试器观察状态，Sanitizer 检测部分内存/UB。

```cpp
#include <cassert>
#include <climits>

int divide(int value, int divisor)
{
    assert(divisor != 0);
    return value / divisor;
}

static_assert(CHAR_BIT >= 8, "unsupported byte width");

int main() { return divide(6, 2); }
```

**C++11 精确语义：** 定义 `NDEBUG` 时标准 assert 宏会禁用检查，因此 assert 不应用来执行必需副作用。C++11 static_assert 必须提供消息；单参数形式是 C++17。

**常见错误与边界：** 测试和工具只能发现执行/建模到的部分错误，不能把 UB 变正确。AddressSanitizer、UBSan、GDB 等不是 ISO C++11，支持情况依编译器和平台。外部输入错误应正常处理而非只 assert。

**前置节点：** B5.5、B16.3、B16.5。
