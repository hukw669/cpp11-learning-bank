# C++11 零基础知识点图谱：基础与核心语言

> 前提：不假定学过 C，也不假定学过旧版 C++。所有概念从 C++ 本身讲起。  
> 标准边界：只按 ISO C++11；编译示例应启用 `-std=c++11`。  
> 本图谱不把 C 当作前置课程，也不混入 C++14/17。

## B1. 从源代码到程序运行

### B1.1 实际工具链流程

1. 预处理：处理 `#include`、`#define`、条件编译
2. 编译：检查 C++ 语法和类型并生成低级代码
3. 汇编：生成目标文件
4. 链接：组合目标文件和库，解析符号
5. 加载与运行：操作系统启动可执行程序

### B1.2 翻译单元

- 一个源文件经过头文件展开后形成一个翻译单元
- 每个翻译单元通常独立编译
- 头文件不是独立运行单元
- 同一个头文件可被多个翻译单元包含

### B1.3 声明、定义与分离编译

- 声明让编译器知道名字及类型
- 定义真正提供对象或函数实体
- 函数声明通常放头文件
- 函数定义通常放一个 `.cpp` 文件
- 调用方包含声明所在的头文件
- 声明正确不代表链接时一定能找到定义

### B1.4 头文件保护

- Include guard
- 同一头文件被多次包含的问题
- `#pragma once` 常见但不是 ISO C++ 标准指令
- 不应在普通头文件中放会造成重复定义的非 `inline` 函数定义或普通全局变量定义

### B1.5 单一定义规则 ODR

- 一个实体何时只能有一个定义
- 类定义、模板和 `inline` 定义为什么常放头文件
- 多个翻译单元中的定义必须满足一致性要求
- “重复定义”和“未定义引用”是不同问题


- 编译、声明、链接规则属于 C++ 学习内容
- 静态库、动态库属于工具链和操作系统知识
- CMake 是构建系统，不是 C++11 语言组成部分
- 编译器参数、链接器参数和 ABI 不是 C++ 语法

## B4. 变量、初始化和类型推导

### B4.1 声明与定义

- `int x;`
- `extern int x;`
- 一个声明是否同时构成定义
- 同一作用域中的重复定义
- 多个相容声明与唯一实体

### B4.2 初始化与赋值

- 初始化发生在对象生命期开始时
- 赋值修改已经存在的对象
- 初始化不是“第一次赋值”
- 构造对象时初始化与先构造再赋值的区别

### B4.3 C++11 初始化形式

- 默认初始化：`int x;`
- 值初始化：`int x{};`
- 直接初始化：`int x(3);`
- 拷贝初始化：`int x = 3;`
- 列表初始化：`int x{3};`
- 聚合初始化
- 不同初始化语法可能调用不同构造函数

### B4.4 未初始化对象

- 自动存储期基本类型对象默认初始化后可能具有不确定值
- 读取未初始化基本类型通常导致未定义行为
- 静态存储期对象会先进行零初始化
- “申请到内存”不等于“对象具有可安全读取的值”

### B4.5 列表初始化与窄化

- `{}` 是 C++11 统一初始化语法
- 列表初始化禁止部分窄化转换
- 浮点到整数
- 大整数到小整数
- 非常量整数到浮点数
- 编译期可证明安全时的例外

### B4.6 `auto`

- 根据初始化器推导类型
- 普通 `auto` 通常丢弃引用和顶层 `const`
- `auto&`
- `const auto&`
- `auto&&` 的基础含义
- 不能用无初始化器的普通变量推导 `auto`
- `auto` 不代表动态类型

### B4.7 `decltype`

- `decltype(name)` 的特殊规则
- `decltype((expression))` 与额外括号
- 表达式值类别会影响结果
- `decltype` 一般不执行其操作数
- `auto` 和 `decltype` 的推导规则不同

### B4.8 类型别名

- `typedef`
- C++11 `using Alias = Type;`
- 类型别名不会创建全新的独立类型
- 模板别名属于 C++11，但可放到模板模块深入讲解

## B5. `const`、`constexpr` 与只读接口

### B5.1 `const` 对象

- 初始化后不能通过该名字修改
- `const` 不等于一定在编译期求值
- `const` 对象仍然具有类型、存储和生命周期
- `mutable` 与物理只读、逻辑只读放到类模块讲解

### B5.2 顶层与底层 `const`

- 对象本身是常量
- 指针指向的对象是常量
- 参数按值传递时顶层 `const` 的影响
- 类型推导中顶层 `const` 的保留与丢弃

### B5.3 指针与 `const`

- `const int*`
- `int* const`
- `const int* const`
- 从可修改对象指针转换为指向常量的指针
- 不能通过去除 `const` 修改原本就是常量的对象

### B5.4 引用与 `const`

- `const T&` 可以绑定到常量、非常量和部分临时对象
- 非常量左值引用通常只能绑定到可修改左值
- 常量引用不代表被引用对象在所有途径下都不可修改
- 常量引用可延长部分临时对象的生命周期

### B5.5 `constexpr`

- 要求对象可在满足条件时用于常量表达式
- `constexpr` 对象本身也是 `const`
- `constexpr` 与普通 `const` 的区别
- C++11 `constexpr` 函数的函数体限制比后续标准严格
- 不采用 C++14 放宽后的 `constexpr` 规则

### B6.4 有符号与无符号算术

### B6.6 位运算

- `& | ^ ~`

### B6.7 赋值与复合赋值

- `=`
- `+= -= *= /= %=`

### B6.9 优先级、结合性与求值顺序

必须严格区分：

- 优先级：表达式如何分组
- 结合性：同优先级运算符如何分组
- 求值顺序：运行时先计算哪个操作数
- C++11 中多数操作数之间没有固定求值顺序
- C++11 中函数实参求值顺序不确定
- 对同一标量对象进行未排序的多次修改可能产生未定义行为
- `(i++) + (++i)` 加括号仍然不能修复
- 安全做法是拆分为多个完整表达式

### B6.10 `sizeof` 等运算符

- `sizeof(type)`

### B9.4 返回类型

- 返回值

### B9.7 默认实参

- 默认值通常在声明处提供
- 调用处可省略尾部实参
- 默认实参在调用点确定
- 不能跳过中间参数
- 同一作用域不能重复提供同一个默认实参

### B9.8 `inline`

### B9.9 C++11 `constexpr` 函数

- 可在满足条件时参与常量表达式

### B9.10 递归

## B11. 内建数组与 `std::array`

### B11.1 内建一维数组

- 元素类型
- 编译期长度
- 初始化
- 下标从 `0` 开始
- 最后合法下标为 `N - 1`
- 长度不能为零
- 变长数组 VLA 不是标准 C++11

### B11.2 数组长度

- `sizeof(array) / sizeof(array[0])`
- 只在表达式中的操作数仍是数组对象时成立
- 传入普通函数参数后数组已调整为指针
- `std::size` 是 C++17，不能用于纯 C++11 课程

### B11.3 数组到指针转换

- 多数表达式中数组名转换为首元素指针
- `sizeof array` 时不转换
- 对数组取地址时不转换
- 字符串字面量初始化数组等场景
- 数组首元素指针与数组指针不是同一类型

### B11.4 数组限制

- 内建数组不能整体赋值
- 内建数组通常不能按值传递或返回
- 访问越界是未定义行为
- 数组本身不保存可查询的运行期长度

### B11.5 多维数组

- 本质是“数组的数组”
- 行优先连续布局
- `T[M][N]`
- 除第一维外，作为参数时通常需要知道后续维度
- 二维数组不能当成 `T**`

### B11.6 `std::array`

- `<array>`
- 固定长度容器
- 长度属于类型的一部分
- 支持整体赋值和按值返回
- `size`
- `operator[]`
- `at`
- `front`、`back`
- 迭代器
- `std::array<T, 0>` 合法，但不能访问元素

## B12. 字符、C 风格字符串与 `std::string`

### B12.1 字符数组和字符串

- 字符数组不一定是字符串
- C 风格字符串以空字符 `'\0'` 终止
- 字符 `'0'` 与空字符 `'\0'` 不同
- 数组容量必须包含终止空字符的位置

### B12.2 字符串字面量

- `"abc"` 的类型是 `const char[4]`
- 包含隐含终止空字符
- 修改字符串字面量导致未定义行为
- 相同内容的字面量是否合并不应依赖

### B12.3 `sizeof` 与字符串长度

- `sizeof` 查看对象占用的字节数
- `std::strlen` 查找到第一个 `'\0'` 前的字符数
- 字符数组容量可能大于当前字符串长度
- 对非 NUL 终止字符序列调用 C 字符串函数有越界风险

### B12.4 `std::string` 基础

- `<string>`
- 自动管理字符存储
- 构造、拷贝、赋值
- `size` 和 `length`
- `empty`
- `clear`
- 拼接和比较
- `operator[]` 与 `at`
- `front`、`back`
- `substr`
- `find`

### B12.5 `std::string` 容量和存储

- `size`
- `capacity`
- `reserve`
- `resize`
- C++11 保证字符连续存储
- 重新分配可能使指针、引用和迭代器失效
- 不能长期保存一个可能被修改的字符串的内部地址

### B12.6 与 C 接口连接

- `c_str()` 返回 NUL 终止字符序列
- C++11 中非 `const std::string` 的 `data()` 仍返回 `const char*`
- 可写 `data()` 是 C++17 才加入的接口
- `std::string` 可以包含内嵌 `'\0'`
- C 接口可能只识别第一个 `'\0'` 之前的内容

### B12.7 字符编码边界

- `char` 不自动代表 UTF-8 字符
- 字节数不等于用户看到的字符数
- C++11 提供 `u8`、`u`、`U` 等字面量前缀
- 编码转换不应在零基础字符串模块中假装自动完成

## B13. `std::vector`

### B13.1 动态长度顺序容器

- `<vector>`
- 元素类型
- 连续存储
- 运行时可变长度
- 自动管理元素对象生命周期
- `std::vector` 不是“可以随便越界的动态数组”

### B13.2 初始化差异

- `std::vector<int> v;`
- `std::vector<int> v(10);`
- `std::vector<int> v(10, 3);`
- `std::vector<int> v{10};`
- `std::vector<int> v{10, 3};`
- 圆括号表示数量构造，花括号常优先匹配 `initializer_list`
- `{10}` 是一个值为 `10` 的元素，不是十个元素

### B13.3 大小与容量

- `size`
- `empty`
- `capacity`
- `reserve`
- `resize`
- `clear`
- `reserve` 不改变元素数量
- `resize` 会改变元素数量
- `clear` 不保证释放容量

### B13.4 元素访问

- `operator[]`
- `at`
- `front`
- `back`
- `data`
- 空容器不能调用 `front` 或 `back`
- `operator[]` 不做边界检查
- `at` 越界会抛出异常

### B13.5 修改操作

- `push_back`
- C++11 `emplace_back`
- `pop_back`
- `insert`
- `erase`
- 插入位置和返回迭代器
- `pop_back` 不返回被删除元素

### B13.6 迭代器失效

- 扩容可能使全部指针、引用和迭代器失效
- 插入和删除可能使指定位置之后的迭代器失效
- 修改容器时不能无条件继续使用旧迭代器
- `reserve` 可降低重新分配次数，但不固定容器大小

### B13.7 特殊边界

- `std::vector<bool>` 是空间优化特化，元素访问不一定返回真正的 `bool&`
- 不应将 `vector<bool>` 当作普通连续 `bool` 数组
- 大对象通常通过 `const std::vector<T>&` 只读传参
- 需要转移所有权时再学习移动语义

## B14. 指针、引用和动态对象

### B14.1 地址与指针

- 取地址 `&`
- 解引用 `*`
- 指针的类型
- 指针变量本身也是对象
- 指针保存地址不代表该地址始终对应活对象

### B14.2 空指针

- `nullptr`
- 空指针不能解引用
- 空指针可用于表示“不指向对象”
- `nullptr` 能避免整数 `0` 在重载中的歧义
- 未初始化指针不是空指针

### B14.3 指针算术

- 只在同一数组对象及尾后一位范围内进行
- 尾后一位指针可形成和比较，但不能解引用
- 指针加减按元素步长移动
- 两指针相减结果为 `std::ptrdiff_t`
- 不相关对象的指针相减或顺序比较不具有通用定义

### B14.4 `void*`

- 可容纳对象指针的通用表示
- 对象指针可隐式转换为 `void*`
- C++ 中 `void*` 不能隐式转换回具体对象指针
- `void*` 不能直接解引用
- 不能用 `void*` 替代类型安全接口

### B14.5 引用基础

- 引用是已有对象的别名
- 引用必须初始化
- 引用初始化后不能改为引用另一对象
- 对引用赋值是在给被引用对象赋值
- 语言层面不存在可正常使用的“空引用”
- 引用可能悬空

### B14.6 指针与引用选择

- 指针可以为空、可重新指向
- 引用通常表示对象必须存在
- 指针适合可选目标和遍历
- 引用适合参数别名和操作已有对象
- 二者都不自动负责对象所有权

### B14.7 原始动态内存

- `new`
- `delete`
- `new[]`
- `delete[]`
- 配对规则
- 分配失败默认抛出 `std::bad_alloc`
- `delete nullptr` 安全
- 重复释放、释放后使用、内存泄漏
- `new[]` 必须对应 `delete[]`

### B14.8 所有权边界

- 原始指针可能只是观察者，也可能拥有资源，语义不明确
- C++11 应优先用 RAII 容器和智能指针表达所有权
- `std::unique_ptr`、`std::shared_ptr`、`std::weak_ptr` 在资源管理模块详细学习
- `std::make_unique` 不属于 C++11

## B15. 作用域、链接、存储期和生命周期

### B15.1 作用域

- 块作用域
- 函数参数作用域
- 函数作用域
- 命名空间作用域
- 类作用域在类模块展开
- 内层名字隐藏外层同名名字
- `::` 限定访问

### B15.2 链接属性

- 无链接
- 内部链接
- 外部链接
- 命名空间作用域的普通非 `const` 对象通常具有外部链接
- 命名空间作用域非 `extern const` 对象默认具有内部链接
- `static` 在命名空间作用域可赋予内部链接
- `extern` 用于声明跨翻译单元实体

### B15.3 存储期

- 自动存储期
- 静态存储期
- C++11 线程存储期 `thread_local`
- 动态存储期
- 存储期描述存储存在多长时间
- 存储期不等同于名字作用域

### B15.4 自动存储期对象

- 通常在进入声明所在的块时创建
- 离开作用域时销毁
- 后创建的局部对象通常先销毁
- 不能返回指向已销毁局部对象的指针或引用

### B15.5 静态存储期对象

- 程序开始前完成静态初始化阶段
- 生命周期通常持续到程序结束
- 全局对象、命名空间对象和局部静态对象
- 跨翻译单元动态初始化顺序不能随意依赖

### B15.6 局部静态对象

- 第一次执行到声明处时初始化
- 之后调用复用同一对象
- C++11 保证函数局部静态对象的初始化具有线程安全语义
- 对象本身仍可能在后续并发访问中产生数据竞争

### B15.7 临时对象

- 表达式可能创建临时对象
- 临时对象通常在完整表达式结束时销毁
- 某些引用初始化可以延长临时生命周期
- 返回、成员引用和容器内部地址都可能产生悬空问题

### B15.8 生命周期与 RAII

- 对象生命周期开始与结束
- 构造和析构确定资源取得与释放
- 作用域退出包括正常返回和异常传播
- RAII 是后续类、异常和智能指针模块的共同基础

## B16. 错误类型与程序行为分类

### B16.1 编译错误

- 词法错误
- 语法错误
- 类型错误
- 找不到声明
- 重载二义性
- 违反需要诊断的语言规则

### B16.2 链接错误

- 未定义引用
- 重复定义
- 链接了错误版本的库
- 声明与实际定义不一致
- 源文件成功编译不代表整个程序可以链接

### B16.3 运行时错误

- 输入失败
- 文件或资源获取失败
- 动态分配失败
- 标准库抛出异常
- 操作系统报告错误
- 崩溃只是运行时错误的一种外在表现

### B16.4 逻辑错误

- 程序能编译、链接并运行，但结果不符合需求
- 边界条件错误
- 循环次数错误
- 错误算法
- 逻辑错误不保证产生任何诊断

### B16.5 未定义行为

常见来源：

- 有符号整数溢出
- 越界访问
- 解引用空指针或悬空指针
- 读取未初始化值
- 重复释放
- 使用释放后的对象
- 除以零
- 不合法移位
- 对同一对象进行未排序的冲突访问

关键边界：

- 未定义行为不等于“必然崩溃”
- 编译器不需要为未定义行为保持直觉结果
- 某次运行结果正常不能证明程序正确

### B16.6 未指定行为

- 标准允许若干结果，但实现不必说明固定选择
- C++11 中许多表达式的求值顺序属于此类规则范围
- 不能依赖某次编译器观察到的顺序

### B16.7 实现定义行为

- 实现必须选择一种行为并记录
- 普通 `char` 的有符号性
- 基本整数类型宽度
- 负有符号整数右移结果
- 应查对应编译器和平台文档

### B16.8 非良构程序

- 违反语言语法或语义要求
- 大多数情况要求编译器给出诊断
- 某些 ODR 违反可能“不要求诊断”
- “编译器接受”不必然说明程序符合 ISO C++11

### B16.9 警告与诊断

- 警告不是 C++ 标准中的一种运行结果
- 不同编译器警告级别不同
- 建议学习阶段启用高警告级别
- 警告不能代替理解语言规则

### B16.10 基础错误检查工具

- `assert`
- C++11 `static_assert`
- 调试器
- 编译器警告
- AddressSanitizer、UndefinedBehaviorSanitizer 等属于工具，不属于 C++11 标准
- 测试只能发现部分错误，不能把未定义行为变成正确行为
