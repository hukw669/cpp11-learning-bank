# GX. 核心语言边角但必要的规则

## GX1 名字查找和命名空间

### GX1.1 命名空间别名

`namespace short_name = very::long::namespace_name;` 为命名空间建立别名，不会复制其中的声明。别名只在自身可见范围内生效，不能像普通命名空间那样重新打开并加入成员。

### GX1.2 限定与非限定名字查找

`ns::name` 是限定查找，`name` 是非限定查找。编译器寻找名字的范围和顺序由作用域规则决定；“某个头文件间接包含后碰巧能找到”不是可靠依赖。

### GX1.3 ADL

参数相关查找会根据函数实参类型，把相关命名空间和类加入非限定函数查找。它使 `operator<<`、`swap` 等泛型调用可找到与类型放在一起的重载，但只对符合条件的函数调用生效。

## GX2 预处理器完整基础

### GX2.1 字符串化 `#`

函数式宏中的 `#parameter` 把实参记号转换为字符串字面量。它发生在预处理阶段，不会先把实参当作 C++ 表达式求值。

### GX2.2 记号粘贴 `##`

`a ## b` 把两侧预处理记号连接为新记号。粘贴结果必须能形成合法预处理记号；它常用于生成名字，但会降低可读性和类型安全。

### GX2.3 可变参数宏

`#define LOG(fmt, ...) ... __VA_ARGS__` 接收可变数量的预处理实参。它与 C 可变参数函数和 C++11 可变参数模板是三种不同机制；宏仍可能重复求值参数。

### GX2.4 条件编译

`#if`、`#ifdef`、`#ifndef`、`#elif`、`#else`、`#endif` 在编译 C++ 语法前选择记号。`defined(NAME)` 只用于预处理条件；未定义标识符在 `#if` 整数表达式中按 `0` 处理。

### GX2.5 预定义宏与 `__func__`

`__FILE__`、`__LINE__`、`__DATE__`、`__TIME__` 等提供翻译环境信息。函数体中的 `__func__` 是预定义的局部字符数组名；以下划线和大写字母等保留形式命名自己的宏或标识符可能侵犯实现保留名称。

## GX3 初始化完整模型

### GX3.1 零初始化

零初始化会把算术类型置零、指针置为空指针值，并按规则递归处理聚合或类子对象。它常作为静态存储期初始化的一部分，也会出现在某些值初始化路径中。

### GX3.2 常量初始化与动态初始化

具有静态或线程存储期的对象若能在常量初始化规则内完成，会在动态初始化之前建立状态。其余非平凡初始化可能在运行期进行；跨翻译单元依赖动态初始化顺序容易产生“静态初始化顺序问题”。

### GX3.3 默认初始化和值初始化

`T obj;` 和 `T obj{};` 可能走不同路径：对基本类型的自动局部对象，前者可能留下不确定值，后者通常得到零值。对类类型，两者又取决于构造函数，不能背成“花括号永远清零所有对象”。

### GX3.4 直接、复制与列表初始化

`T x(args)` 是直接初始化，`T x = value` 是复制初始化，花括号又分直接列表和复制列表初始化。它们会影响 `explicit` 构造函数是否可用、`initializer_list` 重载选择以及窄化检查。

### GX3.5 `initializer_list` 优先与生命周期

花括号初始化在存在合适 `initializer_list` 构造函数时会优先考虑它。`initializer_list` 观察一个只读临时数组，复制列表对象不会复制元素；保存元素地址超过底层数组生命周期会悬空。

### GX3.6 C++11 的 `auto` 与花括号

`auto x = {1, 2};` 推导为 `initializer_list<int>`。花括号中元素必须能形成统一元素类型；C++11 的花括号推导规则与后续标准的部分修订不能混用，出题时必须给出具体声明形式。

## GX4 范围 `for`

### GX4.1 基本展开思想

范围 `for` 会保存范围表达式，并取得 `begin` 和 `end` 后循环。范围表达式通常只求值一次，但具体名字查找、数组处理和临时生存期仍需按 C++11 规则理解。

### GX4.2 `auto`、`auto&` 和 `const auto&`

`auto x` 会复制当前元素；`auto& x` 直接引用元素并可修改；`const auto& x` 避免复制并禁止通过该引用修改。代理引用类型（如 `vector<bool>`）可能让直觉与普通引用不同。

### GX4.3 遍历期间修改容器

会使迭代器失效的插入、删除或扩容同样会破坏范围 `for` 内部保存的迭代器。不能因为语法简洁就忽略容器失效规则。

## GX5 函数和表达式补充

### GX5.1 C 风格可变参数

`void f(const char*, ...);` 配合 `<cstdarg>` 的 `va_list`、`va_start`、`va_arg`、`va_end` 读取额外实参。调用时会发生默认实参提升，类型和数量完全依赖约定，读错类型会产生未定义行为；现代 C++ 接口优先使用可变参数模板。

### GX5.2 默认实参提升

传给省略号的 `float` 会提升为 `double`，`bool`、`char`、`short` 等会发生整数提升。该规则不是普通函数原型参数的通用“自动修复”，也不携带运行期类型信息。

### GX5.3 不求值操作数

`sizeof`、`decltype`、`noexcept` 以及部分 `typeid` 操作数处于不求值语境，通常不会执行表达式副作用。语法和类型仍需有效，模板替换和名字查找也仍可能发生。

### GX5.4 数据成员指针

`T C::*` 表示“指向类 `C` 的某个 `T` 类型数据成员”，必须与具体对象通过 `.*` 或 `->*` 结合使用。它不是对象内普通地址，表示方式由实现和继承布局决定。

### GX5.5 成员函数指针

成员函数指针的类型包含所属类、参数、返回类型以及 `const`/引用限定等信息。调用时同样需要对象；`std::mem_fn`、`bind` 或 Lambda 可把它包装成更普通的可调用接口。

## GX6 程序终止路径

### GX6.1 从 `main` 返回

从 `main` 返回等价于以相应状态调用正常终止流程：自动对象先正常析构，之后执行正常终止处理。`main` 末尾未显式返回时等价于 `return 0`。

### GX6.2 `std::exit`

`exit` 执行已注册的正常终止函数并处理静态/线程相关清理规则，但不会返回调用点，因此不会析构调用栈中仍存活的普通自动对象。它与从深层函数正常返回不同。

### GX6.3 `quick_exit`、`_Exit` 和 `abort`

C++11 的 `quick_exit` 只执行 `at_quick_exit` 处理器，`_Exit` 立即终止且不执行正常清理，`abort` 表示异常终止。服务器代码不能假定所有退出路径都会刷新流、释放锁或运行析构函数。

# ITER. 迭代器与算法完整补充

## ITER1 迭代器工具

### ITER1.1 `iterator_traits`

泛型算法通过 `iterator_traits<It>` 查询 `value_type`、`difference_type`、`pointer`、`reference` 和 `iterator_category`。裸指针也有标准特化，因此可与许多迭代器算法统一工作。

### ITER1.2 `move_iterator`

`move_iterator` 解引用时产生可被移动操作选中的表达式，`make_move_iterator` 帮助构造它。它不会删除源元素或改变源容器长度；移动后源元素状态仍由元素类型规定。

### ITER1.3 流迭代器

`istream_iterator`/`ostream_iterator` 使用格式化流提取和插入；`istreambuf_iterator`/`ostreambuf_iterator` 直接处理字符缓冲区。前者理解目标类型和格式，后者更接近逐字符 I/O。

### ITER1.4 自定义迭代器

自定义迭代器宣称的类别必须与支持的操作和复杂度一致。不能只提供 `operator+` 就声称是随机访问迭代器；算法会基于类别选择实现。

## ALG1 非修改查询

应掌握 `find`、`find_if`、`find_if_not`、`count`、`count_if`、`all_of`、`any_of`、`none_of`、`adjacent_find`、`search`、`search_n`、`find_end` 和 `find_first_of`。它们一般不改变元素，但谓词仍必须满足接口要求且不能破坏区间有效性。

## ALG2 复制、移动和生成

包括 `copy`、`copy_n`、`copy_if`、`copy_backward`、`move`、`move_backward`、`transform`、`fill`、`fill_n`、`generate` 和 `generate_n`。目标区间必须足够大或使用插入迭代器，重叠区间只在相应算法明确支持时安全。

## ALG3 排序、选择和二分

包括 `sort`、`stable_sort`、`partial_sort`、`partial_sort_copy`、`nth_element`、`lower_bound`、`upper_bound`、`equal_range` 和 `binary_search`。二分算法要求输入已按与调用一致的比较规则排序。

## ALG4 分区

包括 `partition`、`stable_partition`、`partition_copy`、`partition_point` 和 `is_partitioned`。`partition_point` 的前置条件是区间已按同一谓词分区。

## ALG5 合并与集合算法

包括 `merge`、`inplace_merge`、`includes`、`set_union`、`set_intersection`、`set_difference` 和 `set_symmetric_difference`。输入区间必须按相容比较规则排序；“集合算法”作用于有序序列，不要求容器类型必须是 `set`。

## ALG6 堆与性质检查

包括 `make_heap`、`push_heap`、`pop_heap`、`sort_heap`、`is_heap`、`is_heap_until`、`is_sorted` 和 `is_sorted_until`。`pop_heap` 只把堆顶移动到区间尾部，不会替容器执行 `pop_back`。

## ALG7 最值、比较和排列

包括 `min`、`max`、`minmax`、对应的 element 算法、`equal`、`mismatch`、`lexicographical_compare`、`next_permutation`、`prev_permutation` 和 C++11 的 `is_permutation`。比较器需维持稳定、相容的关系。

## ALG8 删除和去重

`remove`、`remove_if`、`unique` 只重新排列并返回新的逻辑结尾，不缩小普通容器。erase-remove 和 sort-unique-erase 是由算法结果与容器 `erase` 组合成的惯用法。

# CX. C++11 并发细化

## CX1 线程身份与生命周期

### CX1.1 线程 ID 和提示信息

`thread::get_id()` 与 `this_thread::get_id()` 返回线程标识，`hardware_concurrency()` 返回可用并发度提示且可能为 `0`。ID 可比较和输出，但不能当作稳定的操作系统线程编号协议。

### CX1.2 `yield`、`sleep_for` 和 `sleep_until`

`this_thread::yield()` 只是向调度器提示让出执行机会，不保证其他线程立即运行。睡眠接口至少等待到相应时间条件，但实际唤醒可能更晚。

### CX1.3 创建和 `join` 的同步关系

成功创建线程会把构造前准备的入口参数带入新线程开始；线程完成与成功 `join()` 返回之间建立同步关系。`detach()` 不提供等待结束的同步边，程序必须另行保证共享对象和线程入口所需数据的生存期。

## CX2 锁和条件变量

### CX2.1 尝试加锁

`try_lock` 立即尝试，定时互斥量还提供 `try_lock_for` 和 `try_lock_until`；自由函数 `std::try_lock` 可依次尝试多个锁。失败尝试本身不能被当作已获得同步保护。

### CX2.2 `condition_variable` 与 `condition_variable_any`

`condition_variable` 与 `unique_lock<mutex>` 配合；`condition_variable_any` 可配合满足要求的其他锁类型，通常抽象成本更高。二者都必须用共享谓词抵御虚假唤醒。

### CX2.3 超时状态与线程退出通知

定时等待返回 `cv_status` 或谓词结果。`notify_all_at_thread_exit` 可在线程退出并完成指定解锁后通知等待者，用于把线程结束与共享状态发布连接起来。

## CX3 Future 共享状态

### CX3.1 状态、等待和有效性

`valid()` 判断 future 是否关联共享状态；`wait`、`wait_for`、`wait_until` 只等待，`get()` 还取得结果或重新抛出保存的异常，并通常使普通 `future` 不再有效。

### CX3.2 `future_status`

定时等待可返回 `ready`、`timeout` 或 `deferred`。`deferred` 表示任务采用延迟执行，不能解释成线程正在后台运行但尚未完成。

### CX3.3 `promise` 失败和线程退出设置

若 promise 在没有设置值或异常时销毁，等待方会收到 `broken_promise` 相关 `future_error`。`set_value_at_thread_exit` 和 `set_exception_at_thread_exit` 在线程退出时才使共享状态就绪。

### CX3.4 `shared_future`

`future::share()` 转移共享状态得到可复制的 `shared_future`，允许多个观察者调用 `get()`。这不使结果对象本身的可变访问自动线程安全。

### CX3.5 `async` 的延迟与析构

默认启动策略可以选择异步或延迟；延迟任务若从未等待或取值，可能根本不执行。某些由 `launch::async` 产生的最后一个 future 在释放共享状态时可能阻塞，随手丢弃临时 future 可能让原本看似并行的调用串行化。

## CX4 原子类型与初始化

### CX4.1 原子对象初始化

C++11 不能对所有默认构造的原子对象都假定已具有业务所需初值，应使用明确初始化、`atomic_init`、`ATOMIC_VAR_INIT` 或 `ATOMIC_FLAG_INIT`。初始化必须发生在并发访问开始之前。

### CX4.2 类型和无锁保证

通用 `atomic<T>` 对 `T` 有可平凡复制等要求，整数和指针具有专门操作。`atomic_flag` 是 C++11 唯一保证无锁的原子类型；`is_lock_free()` 只是实现能力查询，不代表算法 wait-free。

### CX4.3 指针原子

原子指针的加减按所指元素步长工作，适合发布和更新指针值。它只保证指针原子操作的语义，不自动管理所指对象生命周期，也不能避免 ABA 等算法问题。

## CX5 内存序合法组合

### CX5.1 `load` 与 `store`

`load` 不能使用 `release` 或 `acq_rel`；`store` 不能使用 `acquire`、`consume` 或 `acq_rel`。默认 `seq_cst` 最容易推理，只有证明需要时再选更弱顺序。

### CX5.2 比较交换顺序

CAS 可分别指定成功和失败顺序。失败顺序不能是 `release` 或 `acq_rel`，也不能比成功顺序要求更强；`weak` 允许伪失败，通常放在循环中。

### CX5.3 Release sequence

从一次 release 写开始，符合规则的同一原子对象后续修改可形成 release sequence；读取该序列相应值的 acquire 操作可继承发布关系。这是无锁算法的重要机制，必须通过具体 happens-before 图推理。

## CX6 标准库并发边界

### CX6.1 容器

不同容器对象通常可并发访问；同一容器不同元素的并发修改在标准保证范围内可行，但 `vector<bool>` 是重要例外。任何会改变容器结构的操作通常都必须与依赖其结构的访问同步。

### CX6.2 `shared_ptr`

不同 `shared_ptr` 实例即使共享控制块，也可并发执行引用计数相关操作；同一个 `shared_ptr` 对象被并发写仍需同步。控制块线程安全不代表所指对象的成员线程安全。

# MX. 数学、字符和 C 兼容库补充

## MX1 `<cmath>` 与浮点环境

应区分 `floor`、`ceil`、`trunc`、`round` 及整数结果版本，并掌握 `fpclassify`、`isfinite`、`isinf`、`isnan`、`isnormal`、`signbit`。`<cfenv>` 提供舍入模式和浮点异常标志，但实际优化选项可能影响对浮点环境的假设。

## MX2 `<cctype>`

字符分类和大小写转换函数的实参必须是 `EOF` 或可表示为 `unsigned char` 的值。直接把可能为负的普通 `char` 传入会越界到未定义行为，应先转换为 `unsigned char`。

## MX3 `<cstring>`

需区分字符串函数与原始字节函数：`strlen`/`strcmp` 依赖 NUL 终止，`memcpy` 不允许重叠，`memmove` 允许重叠，`memset` 按字节填充。按字节清零不能普遍代替任意类对象的正确初始化。

## MX4 安全数值解析

`strtol`、`strtoul`、`strtod` 通过 `endptr` 报告消费位置，并在文档规定的失败情况下配合 `errno`。C++11 的 `stoi` 等封装会抛异常；无论哪种接口，都应检查范围以及是否完整消费输入。

## MX5 信号与非局部跳转

普通 C++ 标准库操作通常不适合在异步信号处理器中调用。`setjmp`/`longjmp` 会绕过正常的 C++ 栈展开，对路径上存在非平凡自动对象的程序尤其危险，不能替代异常。
